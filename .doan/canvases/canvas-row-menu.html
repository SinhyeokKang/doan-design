Canvas row menu — draft

Draft for canvas-row-menu (docs/features/canvas-row-menu/spec.md and design.md, sections ‘행 버튼과 메뉴’, ‘Alert Dialog’, ‘앱 Export 흐름’, ‘viewer shell’ and ‘문구’): a menu button on every sidebar canvas row with Export… and Move to Trash, the confirmation before a canvas goes to the macOS Trash, the export toasts, and the viewer page inside an exported HTML file. All five frames are new and none is in code yet. /design-sync (task T12) compares row-button, row-menu, trash-dialog and export-toast with the app, and viewer-shell with a file written by doan export opened in the same Electron.

Confirmed: the canvas row’s button shows only on hover, focus in the row or while its menu is open, and then takes the status spot’s place (frame 01), unlike the project row’s always-visible button. Still to confirm: the locked button takes the disabled ink (01), the menu’s icons Download and Trash (02), and the viewer hiding its controls where JavaScript does not run (05).

Copied from shipped code: the sidebar rows, project row, group heads, row status spot and error line (ShellSidebar.tsx, styles.css), the project menu’s item styling (.shell-project-menu), the compact alert dialog (Onboarding.tsx Stop dialog, SettingsDialog.tsx, ds/surfaces.css), the toast (Toast.tsx), and the canvas header, frame drawer and zoom menu (CanvasHeader.tsx) that the viewer borrows. The styles.css rules these need are restated at the top of this file as shipped at d2658b49; new CSS is limited to the block marked ‘canvas-row-menu: new, not in code’. Copy is from design.md ‘문구’, settled with Doan’s clarify preset. References: the label “Move to Trash” follows the macOS Finder command of that name (recalled, not checked against Apple documentation); nothing else is borrowed from outside this repository.

01

Canvas row · menu button New, not in code

Every canvas row in both groups gets the project row’s menu button (doan-icon-button shell-more, Ellipsis, named “<canvas> menu”). Confirmed by the user: unlike the project row, whose button is always visible, the canvas row shows it only while the pointer is over the row, while focus is in the row (the row or the button), and while its menu is open. While it shows, it takes the status spot’s place at the row’s end (the row’s end padding goes to 0, as on the project row), and the status spot is hidden visually but keeps its accessible name. Row height stays 32px. Drawn states use .is-hover and .is-focus for :hover and :focus-visible.

02

Canvas row · menu New, not in code

The compact floating menu (two actions: the shared rule for a short list), 204px wide like the project menu, aligned to the button’s end, 4px under it. Items use the project menu’s leading icons in subtle ink (Download, Trash). A disabled item stays focusable: aria-disabled instead of Radix disabled, the disabled ink on its label and icon, and one reason line under the label in caption type and metadata ink, so it stays readable.

03

Move to Trash · confirmation New, not in code

The shared compact alert dialog (role="alertdialog", title and body tied by aria-labelledby/aria-describedby), drawn in place. Actions at the default size, as DESIGN ‘Dialogs’ puts them (the Remove confirmation’s sm actions are still an open decision there), Cancel first and Move to Trash last in prominent: the app has no destructive variant. Results come back in the shared toast.

04

Export · toasts New copy, shipped toast

The shipped toast, unchanged: one message, at most one prominent sm action, bottom right. A later toast replaces an earlier one (the shared rule), so the result toast always comes even if the progress toast is gone. The app never asks the person to run the CLI: a fix goes to their agent.

05

Exported file · viewer New, not in code

What doan export writes: one HTML file whose page is a light Doan viewer around the canvas, in a sandbox="allow-scripts" iframe at the canvas’s doan:width. It copies the app’s canvas header (CanvasHeader.tsx: name, /, frame drawer; zoom out, value menu, zoom in) and drops Reload, the conversation button, the tools row, selection and comments. The board is the app’s inset grey. Tiles are a 960×600 browser viewport; the example canvas colours come from mock.css.

Project feedback — draft

Scope. Feature project-feedback (docs/features/project-feedback/spec.md and design.md, draft request of 2026-10-25). With the Overview shown, the right column becomes the Feedback panel: every comment of the project grouped by canvas and frame, with “Comments without a canvas” first. Comment files whose canvas id no longer exists (orphans) get cards there that can be resolved, reopened and deleted. A canvas whose id just changed tells its Comments panel where its comments went. A file doan ls cannot read turns into a warning on that tree row instead of a project-wide “Config error”. The Home row summary adds “· 3 without a canvas”.

New. feedback-panel, feedback-states and orphan-cards are new surfaces (FeedbackPanel.tsx does not exist yet, so they carry no data-doan-implements); /design-sync compares the main specimen and every labelled tile of these three. tree-errors and home-summary add to shipped screens: only the elements marked “new” there are new; the rest is copied for context and is already measured in docs/DESIGN.md.

Main specimen: acme-web with no canvas open. The center is the shipped Overview, with revision-recheck's “1 resolved to review” on the two cards whose Feedback group shows it; the right column, which showed “Canvas · No canvas open”, is now Feedback (role="region", heading “Feedback”). On top, the Open/Resolved segment (shipped Comments segment) with the project's counts. Below it one tree (role="tree", label “Feedback”): Comments without a canvas first (only when there are some), one group per orphan file (its old id); then one group per canvas in Overview card order; inside a canvas, “Whole canvas” first (canvas targets), then frames in document order, then stored frames doan ls no longer lists as “<id> (not in canvas)” in --text-3. A group shows only when it holds a comment of the chosen status. Rows are the comment's target label without its “ · in <frame>” part, then the first line of its body. Both “Checkout” canvases show their file name; Billing & plans does not. “1 resolved to review” sits under a canvas head when that canvas has resolutions to check. Payment, both orphan files and Billing & plans are collapsed. Keyboard focus is on the “Disable until the form is valid” row; the pointer is over the Whole canvas row.

Behavior (not visible). Arrow keys as in the Sidebar tree: ↑↓ move, Home/End jump to first/last, → expands a collapsed group or moves into it, ← collapses or moves to the parent; Enter or a click opens. The “N resolved to review” buttons and orphan card buttons are Tab stops (not tabIndex=-1). A comment row opens its canvas (draft guard applies), sets the Comments status filter to the row's status and the scope to Canvas, goes to the target and moves focus to that comment's card; the last review time does not change. “N resolved to review” opens the canvas and starts Review (revision-recheck). When a focused row or group disappears, focus goes to the next row, else the previous one, else the “Feedback” heading. Each canvas group is a treeitem with aria-expanded; its accessible name is its title, plus the file name when shown.

01

Ring button New, not in code

The ring is a button at the tray’s right end. Its visible box, margin and every neighbour stay exactly as shipped (first tile); only an invisible hit box grows around it, drawn as ::before with negative insets so no layout box moves. Hover and pressed fill that hit box with the tray triggers’ fills (--affordance-backdrop-hover, -pressed, radius --radius-control); focus-visible draws the focus ring on it. No arrow or other mark is added to the ring. The tooltip (two lines, shipped) still shows on hover, but not while the drawer is open nor on the focus that returns to the ring when it closes.

02

Drawer contents New, not in code

A non-modal dialog on the shared 320 px floating popover. No title row: the first section’s heading “Context window” names the dialog. The Context section repeats the ring’s two lines with a bar in the ring’s band. Below a 1 px divider, the conversation provider’s usage row is the header Agent usage row as shipped (logo, name, “Updated …”, one line per window, notes), with Refresh usage at the end of its head; Refresh reads every usable connection and is busy while any read runs, as in the header. Focus moves to the Context section on open; Tab goes on to Refresh. While open, a sign-out, account change or lost connection removes only the usage section.

Where the drawer opens New, not in code

The drawer opens upward from the ring (side="top", align="end", 8 px from the trigger, 8 px collision padding, as the Permission menu). In the canvas panel it stays inside the panel; in the prototype window’s 280 px panel it is wider than the panel and overlaps the content area to its left, staying inside the window. Only one of it and the header Agent usage popover is open in a window.

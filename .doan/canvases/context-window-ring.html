Draft · context-window-ring

Context window ring

Scope: a 16 px progress ring in the docked composer of the canvas conversation panel (296) and the project Overview (720), directly left of Send / Stop / Queue, showing how full the visible conversation’s context window was at the end of its last turn. Every frame is new (Not in code). /design-sync compares frames place-capsule, place-box, ring-states and ring-tooltip, and the 1× row of ring-geometry; the 8× drawings there are a spec sheet.

Copied from shipped code, not redesigned: the docked composer (capsule and box), its tray and container rules (app/src/renderer/styles.css .docked, .composer-*; DockedComposer.tsx, ComposerParts.tsx SendButton), the header usage ring for scale (.usage-ring, AgentUsageButton.tsx Ring), the shared icon button, chip and tooltip (app/src/renderer/ds/). The tooltip is drawn statically in place of the portalled one; the 296 tiles’ dashed line stands for the window edge.

Settled by the person (design ‘결정’): ring only, no text or number (10); clicking opens nothing, everything is in the tooltip (8); tooltip first line equals the accessible name (11); left of Send / Stop / Queue as a flex group in the send area, no ring = today’s layout (1, 2); colour by the unrounded >= DANGER (70 %) rule (6); 16 px (7); the shared ring primitive from the usage ring (design §3).

03

Ring statesNot in code

All at 296 (canvas panel, capsule). The ring shows the last recorded value of the visible conversation and never changes while a turn runs (decision 3). Colour: below 70 % the value arc is --affordance-prominent; at 70 % or more it is --border-danger, comparing the unrounded ratio with the same >= DANGER as the header usage ring (decision 6). Over 100 % the arc stays full and the name says the real ratio.

No value: a new conversation, a conversation with no recorded value yet (before its first turn, or only turns from before this feature), and providers that send none (Cursor) show no ring (decision 2). The archived conversation keeps its last value.

05

Hover tooltipNot in codeProvisional — needs confirmation

Hovering the ring opens the shared tooltip with two lines. The first line is the ring’s accessible name, word for word: “Context window 42% used · last turn” (“last turn” says when the value is from, decision 11). The second line is the token count, given to assistive tech as aria-description. Tokens: below 1,000 as is, below 1M as “84K”, from 1M as “1.2M”. Clicking the ring opens nothing; there is no dialog or popover (decision 8). The ring is a non-focusable span role="img" trigger (precedent CanvasAgent.tsx), outside the Tab order. A tooltip dismissed with Escape reopens on the next hover (POSTMORTEM 2026-10-23).

Provisional — needs confirmation: the tooltip opens above with a 12 px offset from the 16 px ring, so its bottom sits 4 above Send’s 32 px row — on the same line as Send’s own tooltip (shared default 4 above the button) instead of over the capsule’s top edge. Both lines use the tooltip’s white caption ink; there is no muted on-prominent token.

In the canvas panel the ring is about 76 px from the window’s right edge, so the tooltip is pushed start-ward by the window edge (drawn: the dashed line is the window edge, 8 px gutter and 12 px foot past the composer).

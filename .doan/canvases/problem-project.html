A problem project: the Overview under a blurred overlay.

Draft for docs/features/problem-project-overlay; nothing here is in code. Whether the project broke while its Overview was open or is entered while broken, the Overview shows and a blurred overlay covers the content panel; its centre takes over the status band, which goes, together with the canvas area’s problem sentence, the composer’s reason line and the sidebar’s second problem line. The header and sidebar stay in place and usable.

  • Copied from shipped code: the window (header, sidebar, Overview, right column) is DOM captured from the real app built at 89764cc3 (isolated HOME and userData, a temporary acme-web repository renamed away), drawn with the app’s styles.css inlined and tokens.css and ds/index.css linked. The thread is a sample put into the captured Overview; the right column still shows the “Loading canvas conversations” it had at capture. The composer reads “No agent ready” because the isolated app had no signed-in agent.
  • New copy (user decision, clarify preset): every heading starts from the project’s name and every case has a line with the cause and the way back. Chips and the set of actions are homeCards.ts cardRow’s; the primary action comes first and is the only filled one, Remove from Doan is ghost, and Go Home is gone (the sidebar has Home).
  • Decided by the user in this review: the overlay itself, no container in the centre, the onboarding scene’s column, the Settings title’s type, a 32 px icon per problem kind (FolderX, FolderCog, FileWarning, SquareTerminal) with stroke 1.5, sm buttons, the copy and button order above, focus on the heading on arrival, the reading state past 300 ms without blur, the opaque panel under Reduce transparency, and the sidebar showing the problem as the kind’s icon in the project row’s status slot, with the heading as its tooltip and as the row’s description.
  • Decided by the user in the feature review (frames 09–14 are new, and frames 01–08 take the sidebar row's accessibility): the temporary conversation strip keeps its row above the overlay on a problem workspace and loses only Open; a waiting permission request or question wins the sidebar slot over the problem icon, which wins over working and unseen; Missing and Not set up close an open canvas as today, so the canvas page overlay is drawn for Config error; Retry, Locate and Set Up keep the scene with busy actions instead of flashing; menus and shortcuts that target the covered content are off; covered conversations are not marked seen; the icon is hidden from assistive technology and the row is described by the heading, and a problem row has no disclosure, aria-expanded or group; focus moves to the heading only when the person entered or the focused content went inert, otherwise a live region reads it; the sidebar's reading spinner waits 300 ms; the overlay scrolls when the scene does not fit.
  • Frames: 01 Missing · 02 Not set up · 03 Config error · 04 Config error · Details open · 05 CLI error · 06 Reading · 07 Reduce transparency · 08 minimum window · 09 Config error over the canvas page (new) · 10 Missing with a conversation waiting for an answer (new) · 11 Config error · retrying (new) · 12 long name and Details at 960 × 600 (new) · 13 Sidebar status slot (new) · 14 Focus (new). /design-sync compares the overlay, the scene, the strip's placement and the sidebar rows in every frame; the rest of each window is context.
  • Copied from shipped code for the new frames: the strip is ConversationStripView.tsx's markup in its permission state (conversationStrip.ts copy); the conversation column is ConversationPanel.tsx's empty state; the sidebar's working and permission marks are ShellSidebar.tsx SlotMark; the canvas in frame 09 is a sample drawn with .doan/assets/mock.css.
  • Changes a product rule: PRODUCT §5 item 3 'Problem states' keeps the thread readable and shows a separate problem screen on entry; this proposal does neither.
  • Behaviour: the content behind the overlay is inert (no pointer or keyboard access); the header and sidebar stay usable. Not checked: screen reader output and the blur’s cost over the whole panel (both go to /runtime-test). Long project names and messages are drawn in frame 12. The busy state's ink (disabled ink on the unfilled actions, the filled one keeps its fill) is this draft's proposal.

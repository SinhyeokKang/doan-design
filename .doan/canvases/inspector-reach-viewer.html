inspector-reach-viewer · draft · 8 frames

The inspector in the exported file’s viewer: folded by default, opened from the header, with the app’s selection, rows and element menu.

Scope: docs/features/inspector-reach/ spec (A), 완료 조건 6–13, and design ‘(A) export 파일의 inspector’ and ‘초안 요청’. This draft is drawn before the CSSOM PoC, by the user’s decision (design.md, 2026-11-19). The PoC checks whether the viewer can compute the app’s rows in Chromium and WebKit (stylesheets read in the sandboxed iframe, a stylesheet the file can’t read, the clipboard from a file opened from disk, the added size); when its result changes what a row or state can show, the draft is revised with --revise. Each tile is a browser viewport (the page’s body); 1280 × 800 unless labelled.

/design-sync compares all eight frames with a file written by doan export, in Playwright Chromium and WebKit as the shipped viewer was measured; viewer-copy-status compares the inspector column only. The canvas inside the board, the cursors and the tile labels are illustration.

New, not in code (every frame)

  • The viewer header’s breadcrumb, project / canvas / frame drawer (the project as the app’s thumbnail and name, not a button; “acme-web” gets the sidebar’s amber “A” from shellNavigation.ts projectHue / projectInitial), with its give-way order (project name to its thumbnail, then frame, then canvas name) and width steps (under 720 the project shows its thumbnail only and Zoom out and Zoom in leave; under 600 the project leaves). It comes from docs/features/header-breadcrumb-worktree spec item 9 and matches that canvas’s viewer-header frame; apart from it the header is the shipped viewer chrome. The example project is “acme-web”.
  • The viewer header’s divider and Show inspector after the zoom control, their tooltips, and the unavailable Show inspector with its reason (viewer-folded, viewer-yield).
  • The inspector column inside the viewer’s white panel: 280 fixed, no resize handle, never saved; the header and board narrow beside it and the tools row centres on the board.
  • Selection, hover and the text range on the viewer’s board while the inspector is open; the element menu; the row tooltip; the copy status line.

Copied as shipped (not redesigned)

  • Viewer chrome: window grey, white panel 8 from every edge with its corner cover, header (canvas name, /, frame trigger, zoom; the project crumb before them is the breadcrumb feature’s), inset board, floating tools row with Select and Hand, from cli/internal/export/viewer/shell.html and shell.css (8a999712d) and docs/design/canvas.md ‘Canvas row menu and export viewer’. export-viewer-chrome.html is not edited.

  • Inspector column: head (Inspector, or the selection’s name as the element-menu trigger; Hide inspector panel-right-close), body, groups, rows, token chips, swatches, the empty line, the row tooltip and the element menu tree (kind icons, guides, pressed selection) from InspectorPanel.tsx, inspectorRows.ts, styles.css .doan-insp-* (c1ffb7332), ds/controls.css .doan-code, ds/surfaces.css tree menu, and docs/design/canvas.md ‘Canvas inspector’.

Settled for this draft (lead review)

  • Show inspector after the zoom control behind the app’s divider; its tooltip under the button, end-aligned.
  • Empty-state copy: the app’s line plus “To use the canvas’s own buttons and fields, Option-click (Alt-click) them.” The file opens on any system, so every place that names Option-click adds Alt-click.
  • Copy status line at the column’s bottom (the shared notice: neutral with a check, “Copied <text>”, for success; the error tone with the alert icon, “This browser blocked copying. Open the file in another browser.”, for failure), kept until the next copy, a new selection or Hide inspector.
  • Yield from 657 px wide (a 280 column beside a 360 board, 8 margins) with “No room for the inspector. Widen the browser window.”; while yielding the viewer works as folded and keeps the selection, which comes back with the column.
  • Marks and the text range in the default accent (Doany’s violet): the file carries no buddy.
  • Focus: opening moves it to Hide inspector and Hide inspector returns it to Show inspector, as in the app.
  • A value from a stylesheet the file can’t read (viewer-external-row) looks like any other row: the browser’s computed value, no token name, no mark, no source tooltip and no notice. PoC question 3 decides only whether such rows can show tokens at all.

05

Viewer · values from a stylesheet the file can’t read New, not in code

The canvas links a stylesheet on the web (cdn.example.com/kit.css). The browser applies it when online but does not let the file read its rules, so the viewer cannot tell which token, if any, set a value from it. Such a row looks like any other row: the browser’s computed value only, with no token name, no mark, no tooltip about where it came from and no notice above the list. Here kit.css sets the button’s radius, so Radius reads 10px where viewer-selected’s canvas sets --radius-md; every other row is viewer-selected’s. The pointer rests on Radius and no tooltip opens: a plain value has nothing more to say, as in the app. PoC question 3 decides only whether such rows can show tokens at all.

06

Viewer · copy status New, not in code

A press on a row, or Enter, Space or ⌘C on the focused row, copies what the row shows (the token’s name, else the value), as in the app. The viewer has no toast, so the result goes to a status line at the column’s bottom: a polite live region that is empty until a copy, then holds the latest result until the next copy, a new selection or Hide inspector. A refused clipboard is unlikely to pass on a retry in the same browser (the likely case is a file opened from disk in Safari, PoC question 4), so the failure names the browser and the way out instead of “Try again”. Focus stays on the row. Two tiles: the inspector column cut out of the viewer.

08

Viewer · window too narrow New, not in code

The inspector was open and the browser window narrowed below the width that fits a 280 column beside a 360 board (657 px with the panel’s 8 px margins). The column yields as in the app: it is not shown, Show inspector comes back in the disabled ink, still focusable, aria-disabled, with the reason as its tooltip and description, and a press does nothing. Focus in the column moves to Show inspector, and to Hide inspector when a wider window brings the column back. While it yields the viewer works as folded, with no selection marks or hover, but it keeps the selection: when a wider window brings the column back, the chosen element is selected again and the column shows its rows, so resizing the window never loses it. A selection the canvas’s script removed meanwhile comes back as the empty state. The header follows the breadcrumb’s width steps (docs/features/header-breadcrumb-worktree spec item 9): under 720 header width the project shows its thumbnail only, Zoom out and Zoom in leave and the percent menu stays; under 600 the project leaves, so the second tile reads canvas / frame drawer.

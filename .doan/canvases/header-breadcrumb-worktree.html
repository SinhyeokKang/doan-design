Canvas header breadcrumb and worktree select — draft

Draft for header-breadcrumb-worktree (docs/features/header-breadcrumb-worktree/spec.md and design.md). The canvas header starts with a breadcrumb, project › worktree select › canvas › frame drawer, and the worktree select is one control in three places: the canvas header, the Overview header and the sidebar project row. In a Git project it is always a select, even with one worktree; a project outside Git has none. New, not in code: the breadcrumb, the project button and the canvas header’s select and menu (01–06), the select with one worktree in the Overview header (07) and the select in place of the sidebar’s read-only chip (08). /design-sync compares all eight frames with the app: the closed headers and rows, the open menus, the tooltips and the narrow widths as drawn. Drawn states use .is-hover for :hover and data-highlighted for Radix’s highlighted row; open menus and tooltips are placed with CSS anchor positioning only so the board can show them (Radix places them in the app).

Copied from shipped code (restated at the top of this file from styles.css at fc50b992f): the canvas header, frame drawer trigger, zoom controller, Reload, divider and Show buttons (CanvasHeader.tsx, docs/design/canvas.md ‘Canvas area and right panel’); the Overview header, its branch chip button and its .wt-menu worktree menu with status chips (ProjectOverview.tsx, docs/design/project.md ‘Header’, ‘Worktree chip’); the sidebar project row, its lead, chip place and menu button, the sidebar menus’ opaque fill and the lock ink (ShellSidebar.tsx, docs/design/shell.md ‘Sidebar’, ‘Project menu’); the unavailable item’s reason line (.shell-menu-reason, the canvas row menu); the shared button, chip, menu and tooltip (ds/). New CSS is only the block marked ‘header-breadcrumb-worktree: new, not in code’. No class is named .crumbs or .branch.

Copy (English, checked with Doan’s clarify preset): “Breadcrumb”, “<project> Overview”, “Worktree: <label>”, “Worktrees”, “No <canvas> here”, “Reading…”, the shipped status chips, and the reasons in 05 and 08 (the sidebar’s is the shipped Add Projects lock). References: nothing is borrowed from outside this repository; the breadcrumb follows the app’s own Overview header.

Settled in review:

  • As in the Overview header, the project and the select sit side by side with no separator, and / comes before the canvas and before the frame drawer (01).
  • The project button is the frame drawer’s sm trigger button in the canvas name’s quiet ink (label-sm regular, --text-subtle); its tooltip is its accessible name, shown when the name is cut or hidden (01).
  • The worktree select has no chevron anywhere (sidebar row, Overview header, canvas header); it is still a menu button (01–08).
  • An unavailable worktree row’s reason sits on its own caption line under the path (02); the select’s two unavailable reasons (05).
  • Canvas header give-way order: worktree label (down to the branch icon and about 48px of label, never icon-only), project name, frame name, canvas name last; the 720px (project thumbnail only) and 600px (project and select leave) steps (06).
  • The select’s label shows at most 84px everywhere (sidebar row, Overview header, canvas header), the shipped sidebar chip’s cap; the full label is in the menu and the tooltip. In the Overview it gives way before the project name, down to the same 48px minimum (01, 06, 07, 08).
  • The sidebar select’s menu opens at the select’s start edge, 280 wide, past the sidebar (08).
01

Canvas header · Git project, three worktrees New, not in code

The header now starts with a breadcrumb, nav named “Breadcrumb”: the project, the worktree select, /, the canvas, /, the frame drawer. The zoom controller, Reload and the folded panels’ Show buttons follow as shipped. Project: an sm trigger button (the frame drawer’s button kind) holding the 16px thumbnail and the name in the canvas name’s quiet ink (label-sm regular, --text-subtle), named “acme-web Overview”; it opens that worktree’s Overview, as a press on the project row does. Its 8px inset puts the thumbnail at the Overview header’s 24px. Worktree select: the Overview’s shipped branch chip button (doan-chip shell-branch wt-chip, translucent, 12px GitBranch and the label; no chevron, here or anywhere the select appears), named “Worktree: main”, always a button in a Git project. Its label shows at most 84px everywhere (the shipped sidebar chip’s cap); the full label is in the menu and the tooltip. Like the Overview, the project and its worktree sit side by side with no separator between them, and / comes before the canvas.

02

Canvas header · worktree menu open New, not in code

The same header in a project with five registered worktrees, so every row state shows. The menu is the shipped .wt-menu (280 wide, “Worktrees” head, a row per worktree: GitBranch, label, ~ path in caption, the current row filled and checked), opening 4 below the select at its start edge. Every registered worktree is listed; only those whose list has this canvas (by path) can be chosen. Unavailable rows are aria-disabled (still reached by the arrow keys, no highlight fill), their label and path in the disabled ink, and say why: “No checkout here” when that worktree’s list has no checkout; “Reading…” while its list is being read (a reading worktree has no branch yet, so the label is its folder); a problem worktree keeps the shipped status chip in the check’s place (Missing here) and is repaired from the sidebar or Overview, not from this menu. The reason line sits under the path in the caption metadata ink (the canvas row menu’s .shell-menu-reason), so a long canvas name wraps instead of crowding the label. Picking feat/checkout-v2 opens its checkout at the same zoom and place, with no selection; picking the current row only closes the menu.

03

Canvas header · one worktree New, not in code

A Git project with one registered worktree still gets the select, so the control does not come and go with the worktree count. Its menu has that one row, current and checked; choosing it only closes the menu.

04

Canvas header · project outside Git New, not in code

A project that is not a Git repository has no branch, so there is no select: project, /, canvas, /, frame drawer. The project button is the same as in a Git project.

05

Canvas header · project problem and unlisted page New, not in code

When no listed canvas is shown, the header names no canvas and the frame drawer is the shipped disabled “Frames” (PRODUCT §5 item 2). The breadcrumb keeps the project button, which still opens the Overview, and the select, now unavailable: aria-disabled (still focusable), the disabled ink on its label and icon, the translucent fill kept and no hover fill; the reason is its tooltip and its accessible description (an sr-only line named by aria-describedby), as the canvas tools do. The two reasons pair: “… while the canvas can’t be shown.” for a project problem, “… on a page that isn’t a listed canvas.” for an unlisted page.

06

Canvas header · long names and narrow widths New, not in code

Nothing overlaps; the tools keep their size and place. Order inside the trail, first to last: the worktree label (from its 84px cap down to the branch icon and about 48px of ellipsized label, so the select never becomes icon-only), then the project name (down to its thumbnail), then the frame name (down to the trigger’s chevron), and the canvas name last (down to its icon, at most 40 % of the header as shipped), because the canvas is what the page is about. Two width steps on the header’s own width (a container query, as the docked composer’s tray uses): under 720px the project shows its thumbnail only; under 600px the project and the select leave the header, which keeps canvas, /, frame drawer in the same order. The sidebar’s project row next to it keeps the same select and its menu. Each cut name has its tooltip: the select’s shows the full label and the ~ path.

07

Overview header · select with one worktree New, not in code

The Overview header as shipped, except that the branch chip is the select in every Git project, its label at most 84px as everywhere and giving way before the project name down to the same minimum (the icon and about 48px of label); it has no chevron. With one worktree it is the same button and opens a one-row menu (the shipped rule made it read-only). Rows, check, status chips and the repair actions of a problem row are unchanged; choosing another worktree opens its Overview.

08

Sidebar project row · select beside the menu button New, not in code

The read-only branch chip becomes the select, in the same place, the same size (84px cap) and with no chevron, before the project menu button; only its press, its menu and its pressed fill while open are new. Like that button it takes the tree’s roving tab stop (tabindex 0 only on the active row) and keeps its clicks and keys from the row, so a press does not fold the project and ←/→ and typeahead do not reach the select. Its menu is the same .wt-menu, opening under the select at its start edge, with the sidebar menus’ opaque fill (shell-side-menu); a problem row still turns the menu to its repair actions. Choosing another worktree opens the canvas last viewed there, or its Overview. The “…” menu keeps its Worktrees section. While the page is locked the select is unavailable with the lock as its reason. The menu opens at the select’s start edge, 280 wide, past the 220 sidebar.

FEATURE DRAFT · NEW LABEL LAYER ON THE SHIPPED CANVAS OVERLAY (NOT IN CODE) · 5 FRAMES

Frame names on the board

Every top-level frame shows its name just above its top-left corner, outside the frame, at the same screen size at any zoom. Pressing a name selects that frame; dragging it into the canvas conversation panel's composer adds the frame's chip. Feature documents: docs/features/canvas-frame-label/ (spec, design, tasks). Everything labelled “label” on this canvas is new, not in code; the rest is copied from shipped screens.

/design-sync compares the label (.frame-label: rest, hover, selected, cut, hidden) in every frame: board, drag, states, overlap, viewer. The marks, size bubble, working-frame marker, agent notice, composer, chips and viewer shell are drawn as shipped and are context, not new values.

Implementation notes

  1. Text: “<number>. <name>”, the frame drawer button's words (frameDrawer.ts): the number is the frame's document-order index + 1 among all frames, nested ones included, so top-level labels skip numbers; the name is the title, else the id, else “(no id)”. One text run cut at its end, so a long name loses its end and the number stays while it fits (drawn so); the chip a label drag adds keeps the name alone, as every frame chip does.
  2. Look (.frame-label above): the new caption-sm role, 11/16 regular with its tracking (--type-caption-sm-*, user decision on 11 px), 16 high, padding 0 4, --radius-inline, one line cut with an ellipsis. Rest: --text-subtle on --surface-inset. Hover: --text-accent text (user decision) on the same fill, and an inset 1 px line in --text-accent (box-shadow: inset 0 0 0 1px, user decision), the accent the selection and hover marks use. Text contrast on --surface-inset (#f5f5f6), computed from the tokens: Doany 4.78, Puri 3.91, Dungdung 3.94, Popo 3.89, Dori 3.97 to 1; on white 5.21, 4.26, 4.30, 4.24, 4.33. Only Doany reaches 4.5:1 for 11 px text; the friends stay above 3:1. It takes no space, so nothing moves, and it stays 4.5 px clear of the frame's own dashed mark; never on a selected label. Forced colours remove box-shadow, so a 1 px CanvasText inset outline stands in. Selected (the frame itself is selected): --affordance-accent fill with --text-on-accent, the size bubble's pairing (user decision, over accent text without a fill). Weight and size never change between states, so a cut name keeps its cut.
  3. Place: left edge on the frame's left edge; bottom edge 6 px (--space-1h) above the frame's top edge, which clears the 4 px line the working-frame marker and the jump highlight now share by 2 px (their glows pass under the label). Width is the name's own width, at most the frame's screen width. A frame narrower than 56 screen px has no label (user decision) (a JS constant in labelPlacement, not a token).
  4. Hit area: the visible label stays 16 px high, but its press and hover area reaches 6 px further down into the gap to the frame (22 px in all), so the gap is not a dead strip between the name and the frame. Not drawn; the implementation adds it outside the clipped text box (a wrapper or a transparent strip).
  5. Text inset: the label box starts on the frame's left edge and its text 4 px in (the padding). Kept so because the selected pill must not reach left of the frame and its selection line.
  6. One marker look (user decision): the jump highlight takes the working-frame marker's 4 px travelling gradient line and breathing glow, without its white ring, for frames, elements and the 12 px point; its timing and fallbacks stay its own (CSS above; before/after in overlap).
  7. Marked (user decision): while a top-level frame carries the working marker or a jump highlight, its label is filled with the marker's gradient in white ink (--text-on-prominent), travelling and holding still with the marker, so it never reads as the selected label's solid accent. Marked wins over selected and hover. Forced colours: system colours with a 2 px Highlight inset outline. White on the gradient's accent end is about 2.3:1 for Puri and 2.05:1 for Dungdung (DESIGN.md); the indigo end and the other buddies read.
  8. Play icon (user decision): a playable frame (the frame drawer's Play mark) starts its label with the drawer's lucide Play, 10 px (--size-icon-2xs, user decision), 4 px before the number, in the label's own ink in every state; display only, a press still selects. The name is cut, the number and icon stay. Forced colours: the state's system text colour. Left, before the number (user decision, after trying the right end).
  9. Order inside the overlay: working marker (z −1) < selection and hover marks < labels < size bubble (.overlay .dims gets z-index: 1; keep .measure above it, after it in DOM order or at 2; the Option measurement stays above the labels, a user decision) < tools, notices and toasts. Between labels, the later frame in document order is on top.
  10. Hover: over a label, the frame's dashed hover mark shows (none when that frame is selected); when the canvas's hover target is the frame itself, its label takes the hover look too.
  11. Cursor: the default arrow in Select, the board's crosshair in the Picker. Hand, Space and Capture area: the drag or capture layer is on top, so labels take no press and keep their look.
  12. Dark appearance: the app is light only (DESIGN.md 'Light only'), so the label keeps these roles under a dark macOS appearance; nothing is drawn for it. Forced colours: rest and hover follow the system (CanvasText on Canvas); selected keeps Highlight / HighlightText with forced-color-adjust: none (tile in states).
  13. Accessibility: aria-hidden, out of the Tab order, no tooltip; the name goes in with textContent.

Drag a label into the composer Label drag new, not in code

Past 4 screen px a press on a label becomes a drag of that frame's chip. The drag image, the drop place bar, the drop and the refusal line are canvas-chip's, unchanged; only the chip is a frame chip (lucide Frame, the frame's name). Only this canvas's conversation panel composer takes it. A drop on the board or anywhere else does nothing, Esc cancels, a folded panel takes nothing, and the viewer has no composer, so a drag there does nothing.

Other conditions

States that change behaviour but not the label's look.

Not drawn, look unchanged. Hand, Space drag and Capture area (labels take no press; the drag or capture layer is on top), Hide UI (labels stay: they are board marks), a reload (labels keep their last place; a title change swaps only the text), a dark macOS appearance (the app is light only).

Fit and Responsive in the prototype window

The prototype window’s header takes the mode choice; there is no toolbar row. Left: Back, Forward and Reload prototype as shipped. Centre: the frame name, centred between the groups; where it would be narrower than 80 it takes a second header row and the header grows to 100. Right: Fit and Responsive wrapped together as one toggle, then Export prototype and the conversation button. Fit (default) keeps the frame’s viewport at its marked size and scales it down to fit the panel; Responsive gives the frame the panel, so it follows the window. The window fit is mark width + 16 by mark height + 64 (56 header + 8), or + 108 when that width puts the name on the second row. All eight frames are new. /design-sync compares responsive-toolbar, responsive-header, responsive-play-390, responsive-short, responsive-narrow-mark and responsive-states. This feature merges first, so its app has the toggle alone (R 68): header geometry is compared on responsive-header’s R 68 tiles; other frames compare only the toggle’s own styles and the frame box inside the content panel. It does not compare responsive-conversation, which needs prototype-conversation on develop; responsive-layers is a /runtime-test screenshot check. Windows are drawn with all three right-group controls (R 140); responsive-header also draws the header before each sibling lands.

Mode toggle and header controls · states New, not in code

The mode toggle is a new primitive, .doan-toggle-group: Fit and Responsive as two 32 px chrome icon buttons (lucide Proportions and Expand) wrapped in one 36 px track, 68 wide (2 + 32 + 32 + 2), corner --radius-chip. It reuses the mode tabs’ look (.doan/ds/mode-tabs.html .shell-modes): the --affordance-backdrop-hover track, the pressed item raised on --surface-panel with --shadow-panel and standard ink, the other item in subtle ink with the backdrop hover fill under the pointer. The track sets the pair apart from Export and the conversation button, so there is no divider. It is role="group" named “Viewport”; each item keeps aria-pressed and its own name. Crops show the header and the top 48 px of the content panel of a 406 px window (a played 390 × 844 frame), where the name takes the second header row.

Default · Fit pressed

The first prototype window of a launch is in Fit mode: Fit is raised on the panel fill and holds the toggle’s one Tab stop (Fit tabindex="0", Responsive -1).

Responsive pressed

After the person picks Responsive. The choice lasts until the app quits: Reload, Retry, the frame menu, Back and Forward, a main-window Play and closing and reopening the window keep it.

Hover on Responsive · tooltip

The unpressed item takes the backdrop hover fill on the track. The shared Tooltip, flipped below the header, sits 4 under the item, with no key: the window has no shortcut.

Pointer down on Responsive

The pressed item stays raised under the pointer, as the current mode tab does. Fit’s tooltip names the playing frame’s marked size and what it is fitted to: “Fit 390 × 844 to the window”, with U+00D7 and spaces as PRODUCT and DESIGN write sizes.

Before the first view

Until main’s first view arrives Back, Reload and both items are disabled with disabled ink, no item is raised (both aria-pressed="false"), the toggle has no Tab stop and there is no frame name yet, as shipped. Export’s own states are prototype-cli-export’s.

Hover on Reload · tooltip

Reload is back in its shipped place (x160) with its shipped name, RotateCw icon, tooltip and behaviour; it keeps the window size and the mode. A pointer press on Reload, Fit, Responsive or Export leaves focus where it was. If focus was in the frame or on the page before a Reload press and is still on the page when the new run’s frame is ready, it moves into that iframe; anywhere else (the conversation composer, the header, a control reached by keyboard) it stays put. A failure scene takes page focus to its title instead.

Header widths · one row or two New, not in code

Left group as shipped: Back x88, Forward x124, Reload x160 (32 each, 4 apart), ending at x192. Right group at the 16 px end inset: the toggle (68), Export (32) and the conversation button (32), 4 apart, so R is 140 (104 before prototype-conversation, 68 before prototype-cli-export). The name capsule fills the space between the groups with 8 either side, x200 to W − 24 − R (width W − 224 − R), its text centred there. Its floor is 80: 10 + 36 text + 8 + 16 chevron + 10, where 36 holds three letters and an ellipsis of a typical name (Che… 33.7, Mob… 36.4 in body-sm Geist). Below 80, W < R + 304, the capsule takes a second header row: x16 to W − 16, 36 high at y56, and the header grows from 56 to 100 (56 + 36 + 8), so the content panel starts at y100. Thresholds: one row from 444 with all three, 408 before prototype-conversation, 372 with the toggle alone. The name is always shown. Crops show the header and the top 48 px of the content panel.

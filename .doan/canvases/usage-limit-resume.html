usage-limit-resume · draft revision · 9 frames, all new · decisions settled

Messages queued until a usage limit resets.

When a Claude Code or Codex Doan connection hits its usage limit, a message sent in an existing conversation waits in the queue and goes out when the limit resets; a turn the limit stopped before the agent did anything is queued again by itself. Drawn in the canvas conversation panel at its default 360; the Project Overview’s docked composer is the same component and changes the same way. Sources: docs/features/usage-limit-resume/ spec.md ‘동작’ and design.md ‘초안 요청’.

Usage limit · Queue in the Send slot New, not in code

Accessible name stays “Queue”; the description “Sends when the limit resets at 3:00 PM.” is an sr-only span inside the button, tied by aria-describedby, the way SendButton draws its hint (ComposerParts.tsx). Scheduled rows · status line Status line new, not in code

05

Limit before any work · queued automatically New, not in code

The failed turn stays in the thread as it is, with the new second line (frame 04). Its message (text, chips, attachments reissued from their paths) becomes a queued row and goes out again at the reset, as an automatic Edit and resend. A queue that was waiting behind the failed turn stays queued for the same time instead of returning as the draft.

Decided: Edit and resend is hidden while the turn’s message is queued (pressing it would put the same message out twice) and returns when the row is removed.

06

Stopped again · queued for the later reset New, not in code

The message that went out at the reset shows as a new turn. The limit stopped it again with no reply or step, and the connection’s new reset is later than the last one, so the same message is queued for that time. The earlier failed turn is no longer the last, so it keeps today’s copy. If the new time is unknown or not later, or the agent had already worked, the turn ends as an ordinary failure (frame 04’s comparison tile).

07

Sidebar row slot · scheduled Slot state and StatusMark new, not in code

The sidebar row slot shows Home conversations only (the slot list skips conversations not started from Home, conversationList.ts fromHome). It gains a scheduled state with this priority: permission request or question, (problem), working, a terminal agent’s working spinner, scheduled, unseen ending. It follows the shipped placement rules (bound canvas row, else the project row, and the project row while that canvas row is off screen), hides under hover and focus like the other slots, and a row whose slot shows it opens that conversation, as the permission and unseen slots do. It is not counted in the Show sidebar badge.

Mark: 16 px lucide clock in --text-subtle, the same clock as the queue’s status line; not accent, since it asks nothing of the person. Name: “Queued — sends when the limit resets at 3:00 PM”. Because the sidebar misses conversations started elsewhere, the conversation menus’ StatusMark (Overview conversation dropdown, Canvas conversations list) shows the same clock and name for every scheduled conversation.

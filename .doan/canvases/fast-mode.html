Run a Claude or Codex turn at Fast speed.

Scope: the Fast switch inside the Effort menu of every composer, the Effort trigger when Fast is on (Home’s tool row and the docked tray at its width steps), and the line a Claude turn leaves when Fast was not used or was turned off. Copied from shipped screens (app/src/renderer/styles.css, ds/, ComposerParts.tsx, HomeComposerView.tsx, DockedComposer.tsx, ConversationThread.tsx; read in this checkout): the Home composer and tray, the docked composer and tray with its context ring, the Effort trigger and menu, the terminal session’s fixed triggers, the thread’s messages, folded activity line and end notice.

Decisions come from docs/features/fast-mode/spec.md and design.md (decisions 1–7, §6 copy, §7 request): only Claude and Codex get the switch; it lives in the Effort menu; it is remembered in the conversation and per provider in Last used; Settings › New conversations shows no Fast row; a reason that lasts turns Fast off. 01

Effort menu · Fast switchNot in code

When the chosen model supports Fast (Claude supportsFastMode, Codex a Fast tier), the Effort menu ends with the shared separator and one switch row: “Fast” over the provider’s description, and the switch. The Fast icon in the accent always leads the row; the switch alone shows on or off. With the row the menu is 280 wide (Permission’s menu width), so a description ends within two lines; without it the menu stays 200. The row is a menuitemcheckbox; toggling keeps the menu open and focus on the row, and picking a level still closes it. Codex shows its tier’s own description; Claude shows Claude Code’s own words. A model without Fast (Claude Sonnet here) keeps today’s menu. The head and the menu’s name stay “Effort · <model>”.

02

Effort trigger · Fast onNot in code

With Fast on, the Effort trigger shows the level, then the Fast icon in the accent (Send’s violet), then the chevron. The icon never shrinks or hides. The menu row’s icon and the thread line’s icon take the same accent, so every Fast mark reads alike. Both trigger sizes show the tooltip (its text is the aria-label): “Effort: <level>, Fast on”, or “…, Fast off” for a model that supports Fast with the switch off; a model without Fast reads as today. The trigger shows nothing for Fast while the model list is loading or failed, for a model without Effort levels, and for a Cursor, Copilot or Antigravity conversation.

Docked tray: the shipped width steps stay (below a 384px content width Permission shows its icon only, below 288 Effort does too, the model label ellipsizes last); the tiles use “Extra high” with Fast on, the widest Effort label, so /design-sync can check the boundaries still hold with the icon. Tile widths are the docked composer’s; the tray’s content is 24 narrower. A terminal session’s fixed Effort trigger never shows the icon.

03

Thread · when a Claude turn did not run FastNot in code

A Claude turn that asked for Fast and ended done or failed with fast_mode_state other than “on” leaves one folded activity line inside the turn, under the reply: the Fast icon in the accent and the copy from design §6. A reason that lasts (plan, extra usage, model, organization) turns Fast off for the conversation and for Claude Code’s Last used, so the composer’s Effort trigger loses the icon at once and the next turn goes out standard. A passing reason (a rate-limit pause) or no reason leaves the switch on. A failed turn puts the line before its end notice. The line stays on reopen and after a restart. Codex never leaves one: it does not report the tier a turn ran at.

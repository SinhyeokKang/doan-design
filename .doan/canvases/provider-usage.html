provider-usage · draft round 2 · 4 frames

Agent usage: one ring per connected agent account, one button that opens the details.

Scope: docs/features/provider-usage/ (spec completion conditions 1–5, design §4 and ‘결정할 점’ 1–11, task D0). Every frame is new and not in code: the Agent usage button, its rings, the popover, its rows, every reason line and their copy. A limit window is the provider’s rate-limit window (5-hour, Weekly); an app window is Doan’s window.

Round 3: Antigravity is removed everywhere (‘결정할 점’ 14), the four-provider state replaces the five-provider one, a scene shows Antigravity plus one supported provider as one plain ring, and sample values follow the PoC shapes. Round 2: the person chose the header placement (‘결정할 점’ 10); the two bottom-right candidates and their comparison are removed. Added: Agent settings and Refresh usage in the popover’s title row (‘결정할 점’ 11 and the person’s round-2 note), and a plain ring without a logo when exactly one provider is connected (the person’s round-2 note). The person set the ring and bar colour rule in round 3: neutral below 70%, danger at 70% or more or at a reported limit, no warning band (frame 02). Frame 01 draws the four-provider state on the workspace (canvas page), Home, Settings and Add Projects, with the header drag region, the narrow 960 × 600 window and going from no connection to one. Frames 01–04 are what /design-sync compares.

Provider values are samples, shaped like the responses the PoC read (tasks.md ‘P 결과’ U1–U5, U7): Claude Code 5-hour, Weekly and Weekly · Fable (model_scoped); Codex one 30-day window (a free account, label from windowDurationMins 43200); GitHub Copilot Chat and Completions (premium_interactions has hasQuota false, so it is left out), with a resetDate already past drawn as “Reset · updating”; Cursor Auto and API of the billing cycle (U5 autoPercentUsed, apiPercentUsed, billingCycleEnd). Antigravity is never shown (‘결정할 점’ 14: no ring, row or description); at most four rings. The copy is the design document’s, with two lines fixed here: “Reset · updating” (a limit window whose reset time passed, while Doan reads again) and “Updated just now” (read under a minute ago).

Copied from shipped screens, not redesigned: the shell (header with sidebar toggle, Back, Forward and the page tabs; the Projects and Settings sidebars; the 8px gutters and white body panels) from App.tsx TopBar, ShellSidebar.tsx and styles.css, by way of mcp-connectors.html; the canvas page’s conversation panel, thread and docked capsule composer from styles.css by way of agent-questions.html; the floating popover and tooltip (ds/surfaces.css .doan-floating, .doan-popover, .doan-tooltip); the ghost icon buttons and spinner for Agent settings and Refresh usage (ds/controls.css .doan-icon-button, .doan-spinner; the RotateCw icon and the busy pattern as CanvasHeader.tsx Reload canvas and ComposerParts.tsx SendButton); the Settings › Agents causes for a connection that can’t be used (SettingsAgents.tsx unavailable()); provider names and logos (agentAuthView.ts PROVIDER_NAMES, public/provider-logos/). The bodies of the workspace, Home, Settings and Add Projects are abbreviated: they keep the outline that places the button (panel edges, conversation panel, composer, page column) and leave out content such as Home’s glow and suggestions; they are context, not the compared surface.

References: docs/DESIGN.md ‘Shell layout’, ‘Sidebar toggle and hidden layout’, ‘Home’, ‘Add Projects’, ‘Canvas area and right panel’ (checked in the repo); docs/PRODUCT.md §5 (Escape closes a menu or popover first) as quoted in the design document (checked); the minimum window 960 × 600 from app/src/main/index.ts (checked); The macOS toolbar status-button convention in design §4 is recalled, not checked. 02

Rings · states, counts and colour ruleNot in code

One 24px ring per connected provider (2px stroke) inside one pill button, 4px inset and gap; 32px high. The ring shows the highest used share among the provider’s limit windows whose reset time has not passed. Reading for the first time, unavailable, a connection that can’t be used and unlimited all draw the empty track; the popover says why. With two or more providers each ring has its provider’s 14px logo in the centre; with exactly one provider the ring is plain, with no logo (Counts row). The state tiles show one ring of a button with two or more providers, so they keep the logo. The button’s name stays “Agent usage”; the values go in its description (aria-describedby), for example: “Claude Code 42% used. Codex limit reached. Cursor usage unavailable. GitHub Copilot reading usage.”

Colour rule (the person’s): two states only. Below 70% the value is in the prominent ink; at 70% or more, or when the provider reports the limit reached, it is in the danger border colour (Value · 78% and Limit reached tiles). There is no warning band. The popover text says “Limit reached” only when the provider reports it, so colour is never the only signal. Folding (one ring and “+n”) is drawn for completeness: at the 960 × 600 minimum window all four rings fit in the header.

03

Popover · rows and reasonsNot in code

A non-modal dialog on the shared floating material (doan-floating doan-popover, 320px, 12px inset), titled “Agent usage”. Opening it puts focus on its body (the list, tabIndex −1); Escape or an outside click closes it and focus returns to the button. At the title row’s end, two shipped ghost icon buttons (32px, 16px icons, 4px apart): Agent settings (the Settings tab’s gear), named and tooltipped “Agent settings”, which closes the popover and opens Settings › Agents; then Refresh usage (RotateCw, as Reload canvas), named and tooltipped “Refresh usage”. Tab goes popover body → Agent settings → Refresh usage. Pressing it reads every usable connection now, ignoring the 5-minute interval; a provider already reading joins that read. While any row reads, the button shows the spinner in place of its icon and carries aria-busy; it stays enabled, and the rows keep their previous values with “Updating…”. One row per connected provider in the fixed order, split by 1px hairlines: the 16px logo, the name, and the last read time on the right (“Updated 3m ago”, “Updated just now”; “Updating…” while it reads again, the previous values staying). Under it, one block per limit window: the window’s name and its line (“42% used · resets in 2h 10m”), then a 4px bar. The relative times update every minute while it is open. When it is taller than the window allows it scrolls inside (frame 01, narrow window).

Reason lines replace the windows: “Reading usage…”, “Unlimited”, “Usage isn’t available for <Provider>.”, “<Provider> isn’t on a plan with usage limits.”, “Couldn’t read usage. Doan tries again when you open this.” (error: icon and danger text), and for a connection that can’t be used the Settings › Agents cause with a full stop (warning: icon and warning text). Bars follow the frame 02 colour rule (neutral below 70%, danger at 70% or more or at a reported limit). Provider values are samples in the shapes the PoC read (tasks.md ‘P 결과’ U1–U5): Claude Code 5-hour, Weekly and the model-scoped Weekly · Fable; Codex free one 30-day window named from windowDurationMins; GitHub Copilot Chat and Completions, premium requests left out because hasQuota is false, and a reset date already past drawn as “Reset · updating”; Cursor Auto and API of the billing cycle (autoPercentUsed, apiPercentUsed, billingCycleEnd). The not-supported line is for a provider or CLI version without a usage read (drawn with Codex); Antigravity has no row.

04

Popover · providers change while it is openNot in code

While the popover is open, a provider signed out in Settings loses its row (and its ring); a provider newly signed in gets a row in its fixed place that starts at “Reading usage…”. When the last provider signs out the popover closes, the button goes away, and focus moves to the current tab in the header (the Projects tab here, with the focus ring). A changed account behaves as sign-out then sign-in: the old values are dropped.

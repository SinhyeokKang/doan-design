Notice

One component for every inline message: .doan-notice in app/src/renderer/ds/surfaces.css. Every frame below is live markup on the shipped token and ds CSS, so it renders what the app renders. Screens set only outer margins on a notice (pinned by ds/controls.test.ts).

Anatomy

An icon slot on the first line, then the text: a title and a body, or lines, or a single sentence. Code chips and inline actions keep their own ink. An inline action on the inset fill uses the panel button variant, which rests on white so it keeps its shape. Every item in the row — icon, text and actions — centres on the first text line, so a one-line notice stays 44px and a longer text keeps its actions beside its first line.

Rules

Each rule cites the file that makes it true.

Backdrop decides the surface

Plain opaque white (Settings and other pages, dialogs, popovers, side panels, white cards, the strip band) takes the default inset notice. Anything else — a transparent overlay, a gradient — adds doan-panel.

Every notice has an icon

The alert icon, or a spinner or status mark in the same slot, on the first line of text (.doan-alert-icon).

The tone colours the text

warning, error and ok set the text colour; the icon follows it. Neutral is standard ink. The same tone reads the same on both surfaces.

No coloured edge

A notice is a fill, never a coloured stripe or border.

One style for every notice

Only the tone and the surface differ. Measured in the app at 1238 × 780:

Actions on the inset fill

A secondary button inside a default notice uses data-ui-variant="panel": white at rest, --affordance-panel-hover on hover, --affordance-subtle-pressed when pressed (ds/controls.css). An action or action group centres on the first text line, like the icon (ds/surfaces.css).

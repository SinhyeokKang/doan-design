Terminal work in another worktree — draft

New frame for terminal-work-worktrees (docs/features/terminal-work-worktrees/design.md §3.1 ‘다른 worktree 작업 안내’, spec 완료 조건 4–5): the board notice shown when the person views a canvas in one checkout while an agent in another worktree of the same project works on the same path. Two frames, neither in code: sibling-notice is new and picking-hint moves the shipped picking hint to the bottom (design.md §3.6); /design-sync compares both (the notice, its text truncation and Open; the hint’s place over the tools row). Its last two tiles are shipped notices (this checkout’s own terminal session and app conversation), for comparison only: the column holds one agent notice, and this checkout’s work wins it. The sidebar slot, the worktree lists and the moves when a worktree disappears add no new visuals (design.md §3.2–3.4) and are not drawn.

Drawn with the app’s own styles.css as of 2aa8802f (inlined without its imports, @theme, the jump highlight’s mask and the quick-open height rules, which this frame does not use and which doan check flags on a canvas), tokens.css and ds/index.css. Copied from shipped code: the agent notice, its Open button and the glow (CanvasAgent.tsx), the picking hint (App.tsx), the Canvas tools row (CanvasTools.tsx, markup from canvas-hand-tool.html), the tooltip (ds/surfaces.css). The sibling notice is the shipped .doan-agent with an action button and no glow; new CSS is the picking hint’s leading Crosshair glyph, the bottom column’s width, so the moved hint is not squeezed, and the canvas-only placement of the drawn tooltip. Copy follows design.md, shortened on screen to “Agent is working in <label>” (user decision, recorded in design.md §3.1) and checked with Doan’s clarify and harden presets. The mock canvas and the canvas-only layout are copied from terminal-agent-activity.html; each board slice is drawn at the real board size of the default window (647 × 660 at 1238 × 780 with the conversation panel open).

01

Agent indicator · another worktree New, not in code

When this checkout has no work of its own on the open canvas (no terminal session, no app conversation) and another worktree of the same project has a terminal session on the same path, the top-centre column shows one notice: “Agent is working in <label>” and Open. The shorter text keeps a usual branch whole in the 420px column (“…on this canvas in” left only about 85px for the label); the notice sits on this canvas, so the canvas goes without saying, and the tooltip on the text says it in full: “Agent is working on this canvas in <label>”. The label is that worktree’s branch, or its folder name when it has none; with several, the one that started last. The notice takes no focus when it appears and leaves when that session ends (doan work done or expiry). Open (accessible name “Open this canvas in <label>”) selects that worktree and opens the same canvas there; Back returns here.

02

Picking hint · above the tools Moved, not in code

The picking hint moves from under the agent notice at the top to the bottom column, 8px above the Canvas tools row (.doan-canvas-bottom, its existing 8px gap). Picking is a mode the person turns on, so its hint sits by the tools that switch modes, and the top column is left to agent status: the agent notices coming and going no longer move the hint, and the top column is never two capsules high. The hint now leads with the composer pick button’s Crosshair glyph at 14px (--size-icon-sm, the Stop glyph’s size), 8px before the text, so it reads as the mode that button turned on; otherwise it is unchanged (the agent notice’s 40px capsule, its copy, the Esc key, hidden “Press Escape to cancel”, role="status"); the tools row stays as shipped and keeps its place at the bottom.

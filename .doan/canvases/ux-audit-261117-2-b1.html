As is: App.tsx:1435-1445 confirmTrash calls closeTrash() before trashCanvas; SettingsMcpConnectors.tsx:145-158 confirmRemove calls setDialog(null) before startRemove; failure copy mcpConnectorsView.ts:120, toast copy canvasRowMessages.ts:7-15. Busy model: ConversationDeleteDialog.tsx:54-68.
What changes
Confirm: spinner, aria-busy, aria-disabled, fill kept. Cancel and Esc refused while out (aria-disabled + data-disabled). Success closes the dialog with today's toast (Trash) or live-region line (MCP) and today's focus target. Failure keeps the dialog, shows .doan-notice.error above the actions, and the confirm is available again as the retry; Cancel is available. The Trash failure sentence reuses the toast's sentence; MCP reuses the row's.
States to test
  1. Delay trashCanvas / removeMcpServer: the dialog stays with the confirm busy and focused; Esc does nothing.
  2. Success: the dialog closes, today's toast or announcement, focus as today.
  3. Failure: the error line appears and is announced; pressing the confirm again retries; Cancel closes and focus returns to the trigger.
  4. MCP: the row's own Remove-failed alert is not shown twice while the dialog shows it.

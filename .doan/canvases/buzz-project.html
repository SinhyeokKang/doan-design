buzz-project · confirmed 2026-10-31 · 9 frames

The Overview is where a project’s conversations live.

Scope: docs/features/buzz-project/. The project Overview becomes the project conversation screen: the thread and docked composer in the main panel, a conversation dropdown in its header, and a right panel listing the canvases that have conversations. The thread, docked composer and their states are buzz-conversation.html’s boards, used here as they are. Every frame is new (not in code) except the shell (header, sidebar), copied from buzz-home.html and design-system-canvases.html at the shipped 220 px sidebar width, and the duplicate-ID notice copy (PRODUCT §5 item 3).

/design-sync compares all nine frames, together with buzz-conversation.html’s docked and thread boards. References: the main-conversation / side-panel structure follows the user’s Aside screenshot (2026-10-31; seen in the screenshot only). Decisions (2026-10-31 user): canvas conversations always open their canvas; the right panel lists only canvases with conversations, newest conversation first; the Overview opens the last project conversation seen. Conversation text, titles and times are sample data.

Overview · A project conversationNot in code

The selected project conversation fills the main panel: the buzz-conversation thread and the docked composer at the bottom (existing-conversation mode). The title is the conversation dropdown. The right panel lists canvases that have conversations, newest conversation first; each row has a small thumbnail, the canvas name, the provider and last activity, and the current conversation’s status (needs your answer, working, finished not seen). Each canvas shows its current conversation only; clicking the row opens the canvas. While this turn runs, Send is Stop (empty field). The temporary conversation strip is not shown on the Overview.

Overview · Worktree pickerNot in code

With two or more registered worktrees, the branch chip in the header is a button that opens the same worktree list as the project menu (branch, path, the shown one filled). Choosing one switches the whole Overview to that worktree: its project conversations, its canvas list, and new conversations start there. With one worktree the chip stays read-only text, as in the other frames. A conversation stays in the worktree it started in.

05

Right panel · Row statesNot in code

Rows by status: needs your answer (hovered), working, new changes. A row stands for the canvas and its current conversation only; past conversations open from the canvas (buzz-canvas-conversation). Rows are split by a hairline. The top line carries the provider’s logo, the canvas name, the status mark and the last activity flush right in short form (now, 3m, 1h, 1d, then the date); under it, up to two lines preview that conversation’s latest line: the agent’s last reply as plain text (Markdown stripped), the latest activity while it runs, or the waiting permission request. A long name is cut with an ellipsis. Thumbnails reuse the Overview capture. The thumbnail frame is always there; without a ready preview (waiting, failed capture, no doan:width, unreadable or gone canvas) it shows the empty style, an inset fill with no glyph, and the reason is not spelled out (its accessible name is “Preview loading” or “Preview unavailable”). A row whose canvas is no longer in the project shows only while its conversation has work left (running, waiting or unseen) and cannot be opened; a shared ID gives the reason and cannot be opened; an unreadable canvas keeps the LNB’s note and still opens, since the canvas page shows its own error. The list is one Tab stop (roving): ↑/↓ and Home/End move between rows, Enter opens the canvas and marks its current conversation seen; unopenable rows take focus so their reason can be read.

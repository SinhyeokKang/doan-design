FEATURE DRAFT · REDESIGN OF THE SHIPPED CANVAS OVERLAY + ONE NEW BUTTON (NOT IN CODE)

Canvas marks in accent

Selection and hover marks, the size bubble and the jump highlight move outside the element and take the person's buddy accent. The size bubble gains Add to message, which puts the selection into the canvas conversation's composer as a chip. Feature documents: docs/features/canvas-mark-accent/ (spec, design, tasks). Until this feature merges, this draft is the reference for the overlay; doan-canvas.html, frame-first-selection.html and frame-prototype.html are not edited.

Implementation notes (all frames)

  1. Selection and hover (.mark, .mark.hover): 1.5px --text-accent (the buddy's icon colour, DESIGN.md 'Tokens': accent icons, dots and outlines), solid for selection, dashed for hover. The box is the element's screen rect from boardRectToScreen grown by 1.5px on every side (left −1.5, top −1.5, width +3, height +3), so the line covers no element pixel. No --surface-panel ring. Same in Select and the Picker.
  2. Why not --affordance-accent for the line: Puri's 9 (#55bc98) and Dungdung's 9 (#e8ab00) are about 2:1 on white, too faint for a thin line. --buddy-icon clears 3:1 for all five buddies (tokens.css comment).
  3. Size bubble (.dims): --affordance-accent fill, --text-on-accent text and button ink (the accent button pairing). Always a flex row, gap 4, 24 high: padding 0 4 0 8, or 0 4 0 4 with Play (.dims.playable). 5px below the line's outer edge (above it when sizeBubblePlace says so); the inside/above decision uses the grown rect.
  4. Add to message: doan-icon-button xs, lucide Crosshair 14px, aria-label and tooltip "Add to message". Order: Play, size text, Add to message (Play only for a playable frame, as today; Add to message always ends the bubble). Shown whenever there is a selection.
  5. Press: anchor = targetAnchor(selection) (the same function the pick uses); unfold a folded panel as pickFromCanvas does; focus the composer field, then insert(anchor) at its caret (the order pickEnded explains); if the field is not registered yet because the panel just unfolded, insert once it registers. Selection, the bubble and doan active stay. Pointer events stop at the button, like Play's.
  6. Unavailable: whenever pickerAvailability(...) is not enabled. aria-disabled (not disabled), ink color-mix(--text-on-accent 45%, transparent), no hover fill, tooltip = that reason. Update the same button element; never rebuild it while focused (POSTMORTEM 2026-11-13). When the bubble goes while a bubble button has focus, both buttons follow Play's onFocusLost / closedFocusTarget rule.
  7. Hover fill and focus ring on both bubble buttons: today's Play rules with --text-on-prominent replaced by --text-on-accent (16% fill on hover and press, 2px ring at −2px). The selector must outrank ds/controls.css's icon-button hover and active rules (see the CSS comment); a disabled button takes no fill.
  8. Tooltip: Add to message shows the app tooltip (the shared Tooltip look: above, 4px offset, centred on the button): "Add to message", or the unavailable reason. The bubble buttons are controller DOM, not React; the implementation picks how to anchor the shared tooltip to them. Play keeps today's behaviour (accessible name only).
  9. Jump highlight (chip locate, frame drawer, Quick Open, deep link, doan open) and the working-frame marker: CSS unchanged; the box is the rect grown by 3px on every side, so the 3px line is outside the element and the 1px ring and glow outside the line. Forced colours' 3px Highlight border sits in the same place. The 12px point is unchanged: grow only the rect branch of drawJump, which places rects and points with the same box code.
  10. Line width: 1.5px for selection and hover (was 1px). On a 1x display Chromium draws it as 1px; the box still grows by 1.5px there, which leaves a sub-pixel gap the implementation may round (measure at 2x).
  11. Not changed: .text-range, the prototype window, the jump line's 3px, the point jump, motion and timings.

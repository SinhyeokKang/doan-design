Question card · pendingNot in code

The shipped thread permission notice (doan-notice thread-notice) with the provider mark, but no “<Provider> needs your answer” title: the first question’s sentence takes the title’s place beside the mark (500, wrapping in full), and further questions put their sentence in the same weight above their options. “<Provider> needs your answer” stays in the thread status, the sidebar slot, the agent indicator, toast, notification and the problem-workspace strip. Each question: the sentence, then its options (no header chip: the provider’s short header is used only in the folded line and the group’s accessible name) in the Settings group style (decided while drawing: one box split by hairlines, not separate cards): the shipped .doan-settings-group with .doan-preference-row[data-has-icon] rows (Settings › Agents, the MCP connectors list), the radio or the shipped 20px doan-checkbox in the row’s icon slot, Other’s input in the row’s extra line. Three local overrides: a --surface-panel fill, rows aligned to the first line, the 16px --radius-row corner. The chosen option shows by its radio only.

Option labels and descriptions wrap in full at every width; nothing in an option ellipsizes. Both providers require a label and a description per option, but an empty description is possible, and Doan’s Other has none: such a row is the label line alone. Claude questions always have Other; a Codex question with options and isOther: false has none; options: null is answered with text only; isSecret masks the input. Buttons: Send (prominent), Skip (panel), Stop. Only the title (the first question’s sentence) is the live alert; focus does not move when the card arrives. Sample questions are examples.

Keyboard focusNot in code

macOS conventions (design.md §7): a single-choice question is one radio group (arrows move and choose, Tab enters on the chosen or first option); several choices are checkboxes toggled with Space; choosing Other by click or Space moves focus into its input, arrowing past it only opens it. Return in the Other input sends only when Send is enabled and never while composing (IME). Tab order: options → Other input → Send → Skip → Stop.

The focused row takes the shipped preference-row focus ring (.doan-preference-row:focus-visible: 2px --border-focus, offset −2px, --radius-row), drawn here when its radio or checkbox has keyboard focus. Rows have no hover fill. Focus rings are drawn statically.

Send · disabled, sending, failedNot in code

Send stays focusable while it cannot send (aria-disabled, like New conversation) and its tooltip says what is missing: one question “Choose or type an answer first.”, two or more “Answer each question first.”. Other chosen with an empty or blank input counts as no answer. The disabled prominent fill (--affordance-disabled, --text-disabled) is new.

Sending: Send shows a spinner with aria-busy; the options, Other and Skip are read-only; Stop stays live. A stale refusal looks the same until the card folds (main already settled it). Any other refusal unlocks the card, keeps the choices and shows the shipped answer-error line (.ask-error, danger caption under the actions; no coloured edge).

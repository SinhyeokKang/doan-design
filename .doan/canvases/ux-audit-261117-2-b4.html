Pattern chosen
The window's own failure scene (.problem-overlay › .problem-scene, styles.css 1947-1964 and the .pw-panel > .problem-overlay rule), which stateScene already uses for read-failed with heading “Couldn’t open this prototype” and Retry (prototype/view.ts:35), not a new strip: it is the same structure as the main window's canvas failure block (icon, heading, line, one action) and keeps the header usable, as docs/design/prototype.md describes the overlay. The conductor may instead use the main window's .canvas-status-block; the drawn one adds no CSS.
What changes
A first-read failed state in the renderer (no new phase from main). Heading reuses the existing string; the line “Doan couldn’t start this window. Retry, or close it and play the frame again from the canvas.” is proposed (no Details: there is no detail to show). Retry calls api.read() again and shows the reading state while it runs. Header controls stay as As is (no view yet), and the heading takes focus as the other scenes do. An onChanged that arrives first replaces the scene with the view.
States to test
  1. Make prototype:read reject once: the scene appears, not a blank panel.
  2. Retry while the read still fails: the scene stays, Retry is pressable again.
  3. Retry after the read succeeds: the frame plays, Reload, Fit, Responsive and Export become available.
  4. Read fails, then an onChanged arrives: the view replaces the scene with no Retry.
  5. A screen reader hears the heading and the line; Tab reaches Retry after the header controls.

overview-tabs · draft · 9 frames

The Overview’s right panel gets two tabs: Conversations and Project.

Scope: docs/features/overview-tabs/ (spec, design §3–§5). The right panel’s 56 px head holds a tablist instead of the “Canvas conversations” heading; under it the body scrolls. Conversations is today’s Canvas conversations list, unchanged. Project shows what the app already knows about this worktree (path, branch, registered worktrees, canvas and frame counts, the last changed canvas) and what it reads from its config (token CSS, shared paths), plus where its Doan files are kept, all read-only, with a Project Settings button. A problem worktree shows its recovery there too.

  • New, not in code: the tablist and its status mark, the panel’s fixed head and scrolling body, the Project tab and all its states, the Config error and CLI error sentences in the status band, the panel and handle names. Every frame below is new except the parts named as copied.
  • Copied from shipped code at 5c5aad3e (app/src/renderer/styles.css inlined without its imports, @theme, comments and the jump highlight’s mask; tokens.css and ds/index.css linked): the header (App.tsx), sidebar (ShellSidebar.tsx), Overview header, thread and docked composer (ProjectOverview.tsx, ConversationThread.tsx, DockedComposer.tsx), the Canvas conversations rows and empty state (CanvasConversationList.tsx) and the status band (Home.tsx ProblemActions), at the shipped 220 px sidebar and 280 px right column. The tab capsule is the shipped .group-tabs.shell-modes (.doan/ds/mode-tabs.html filters). The thread and composer are context: a sample exchange and an empty capsule.
  • /design-sync compares all nine frames, for the panel head, tabs, tab mark and the Project tab panel; the shell around them is context (its own drafts and DESIGN 'Project Overview' are its reference).
  • Names (clarify preset): the region is “Overview panel” (it no longer is only canvas conversations) and its handle “Resize Overview panel”; the tabs are “Conversations” and “Project”; the Project tab’s action group is “Fix this worktree”. “Conversations” stays though the title menu heads its list “Conversations in <project>”: the tab’s rows and empty state say canvas, and the menu lists project conversations under its own heading (user decision Q1).
  • References: Quick Open’s filter tabs and their keyboard model (QuickOpenDialog.tsx, checked). The WAI-ARIA Authoring Practices tabs pattern recommends making a tab panel focusable when it holds no focusable element first (recalled, not checked here; design §4.5 asks to check the source before implementation). Values from this repository’s doan ls and doan config on 2026-11-07 (checked); samples are named as such in the captions.
01

Tabs · status mark on Conversations New, not in code

While the Project tab is selected, the Conversations tab shows one mark when a canvas conversation of this worktree waits for an answer (the sidebar’s hand, --affordance-accent) or works (the shared spinner). The hand wins over the spinner. Both are 14 px (--size-icon-sm), 6 px after the label (the filter tabs’ gap). Project conversations, finished-not-seen and a list that is reading or failed show no mark, and the tab never switches by itself.

Measured in this draft (Geist, 280 px panel): the tab capsule is 216 px with the mark (Conversations 135, Project 70) and 196 px without it, inside the head’s 263 px of room (280 minus the 1 px start edge and 8 px insets). The marks are hidden from assistive tech; the tab’s name carries the count instead (shown under each tile).

02

Tabs · minimum window 960 × 600 Tabs new; shell copied

At the minimum window the right column keeps 280 px and both tabs fit its head. The head is fixed at 56 px (--size-chrome, on the head container that always renders); only the body under it scrolls. Here the Project tab is scrolled to its Settings section: the head stays put and the body’s content passes under its edge.

Drawn scrolled by moving the tab panel up 120 px inside the body (the canvas cannot set a scroll position without a script). Switching tabs returns the body to the top.

04

Overview · Project tab New, not in code

The Project tab for this repository (values from doan ls and doan config on 2026-11-07; Doan files from the branch’s CLI, which reports storage: repo for a repository that tracks .doan/). Read-only: four sections, label and value rows, and one button. Short values (Branch, Worktrees and the counts) sit at the row’s end; paths and modes are long, so they go under their label and wrap rather than truncate (the end of a path matters).

Worktrees counts the worktrees registered in Doan (3 is a sample; doan ls lists every Git worktree, registered or not). Last change is the canvas with the newest file time and its short time, spoken in full. Project Settings opens this worktree’s Project Settings page by the project menu’s path; editing stays there.

05

Project tab · value ranges New, not in code

Each tile is the 280 px panel with the Project tab selected, cut where its content ends. Counts use en-US thousands separators. A + after Frames means the sum may be short: a canvas hit the 1,000 static-frame cap or could not be read (its frames are unknown).

06

Project tab · reading settings New, not in code

Token CSS and Shared with canvases come from reading this worktree’s config; the other rows come from the project list and show at once. Re-reading (window focus after 60 s, returning from a page, Retry) keeps the previous values, so it has no frame of its own.

The failure sentence is Project Settings’; the reason under it is the CLI’s message (a sample here).

07

Project tab · recovery for a problem worktree New, not in code

When the open Overview’s worktree turns into a problem, the status band stays and the Project tab shows the problem’s name, the same sentence as the band, the same actions in the same order and with the same handlers, then the path. The actions are a group named “Fix this worktree”, apart from the band’s “Project status” region. Go Home stays in the band only (it moves away, it does not fix). Details opens the error in place and is shared: opening it in either place opens both, and both Details buttons report the same expanded state; it shows no toast.

Config error and CLI error get a sentence in the band and the tab (new copy, one function for both places). Each tile is the window’s right 680 px: the band across the top, the Overview’s header cut, and the right column.

08

Project tab · worktree reading New, not in code

While the worktree is being read there is nothing to fix and no values yet: the path and “Reading project” (the canvas pane’s words for the same state). No actions.

09

Tabs · keyboard and focus New, not in code

The tablist is one Tab stop: the selected tab. ←/→ move between the two tabs and select at once (Quick Open’s and the preset popover’s tabs). Buttons take the shared outer ring (2 px --border-focus, 2 px out); the tab panel, which can scroll and fills the body, takes the inset ring (−2 px) that scrolling lists use. The Project tab panel and an empty or reading Conversations panel are focusable (tabIndex 0); with rows, the rows are the stop. Focus states are drawn with static classes.

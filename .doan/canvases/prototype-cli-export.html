Export a prototype

Draft for docs/features/prototype-cli-export: the prototype window’s Export button, its toasts, and how the exported file looks in a browser. All five frames are new. /design-sync compares export-button, export-header-widths and export-toasts with the app, and the two exported-file frames with a file the built CLI writes (its behaviour is the probe’s, decision 11). doan open --prototype and doan export --prototype have no visual surface and are not drawn.

  • Export’s place: the prototype window’s header, right group, after the Fit/Responsive toggle: [Back, Forward, Reload] · frame name · [toggle, Export prototype, conversation button] (decision 7). There is no toolbar row. Every window here is drawn before prototype-conversation adds its button (the right group is 104 wide), as the app is when this feature merges and is compared.
  • Copied from shipped code (checked on develop): the window and header from frame-prototype.html (.pw, .pw-history, .pw-name, which restate styles.css .shell-history and .shell-search), DESIGN ‘Frame prototype’; Export’s behaviour as the canvas toolbar’s Export (CanvasTools.tsx: Download glyph, aria-disabled with the reason as tooltip and sr-only description), drawn as a header chrome icon button, the reasons “Can’t read this canvas.” and “Exporting” from canvasRowMenu.ts; the toast, Show in Finder and every unchanged failure sentence from Toast.tsx, canvasRowMessages.ts and DESIGN ‘Canvas row menu and export viewer’; the file’s notice from the export viewer’s no-JavaScript notice (cli/internal/export/viewer/shell.html, shell.css).
  • New here: Export in the header with its label, states and third reason; the new toast sentences; the file’s page (frame filling the viewport, hidden until ready, the two lines). Marked New, not in code.
  • Owned by sibling features, drawn to match their drafts: the header (Back, Forward, Reload, the name capsule on one row or two, the right group), the Fit/Responsive toggle (.doan-toggle-group, Proportions and Expand), the name widths at a 104 px right group (312 at 640, 192 at 520, a second row at 360) and the Fit drawing, copied from prototype-responsive.html (responsive-toolbar, responsive-header). The conversation button (prototype-conversation) is not drawn.
  • Decided: on missing, and when no answer comes within 10 seconds, the iframe stays hidden and the page shows only the line, so the rest of the canvas never shows.
  • References: none outside this repository. The header layout and the name widths come from prototype-responsive spec ‘헤더’ and design ‘헤더 배치’ (checked).

Export button · states New, not in code

This feature adds one button to the prototype window’s header: Export prototype, in the right group after the Fit/Responsive toggle, 4 px apart, ending 16 px from the window edge. It is a header chrome icon button (32 px, 16 px Download glyph) with its own Tab stop. Crops of a 520 px window’s top edge: the header and the first 48 px of the content panel. Its tooltip, like every header tooltip, sits 4 px under it; Export is near the edge, so the tooltip is clamped flush with it, as every header tooltip.

Owned by prototype-responsive the header, Reload and the Fit/Responsive toggle; this draft copies prototype-responsive.html. Export is available while the view’s phase is ready, loading or init-failed.

Available · tooltip

Playing (also while loading, and after the start failure): Export opens the save panel. Its accessible name and tooltip are “Export prototype”, as the canvas toolbar’s Export says “Export canvas”. Same Download glyph. A pointer press opens the save panel without moving focus (prototype-responsive decision 10).

Exported prototype file · in a browser New, not in code

What doan export <canvas> --frame <id> --prototype and the window’s Export write, opened in a browser. The page is one sandbox="allow-scripts allow-forms" iframe that fills the viewport and shows only the frame; the rest of the canvas is in the file but hidden. The tab strip is a schematic browser, not Doan UI.

The recipient needs no Doan: links to other pages and default form submits do nothing; same-page links, pushState and handled submits work.

Wide browser window · 960 × 600

The frame fills the viewport; its own layout decides the columns. The mark (390 × 844) sets no size. No header, drawer, zoom or tools: Reload in the browser restarts it. Tab title: “<frame title or id> — Prototype”, without the size. The iframe’s title is the frame’s title or id (“Checkout”), as the app’s prototype window titles its iframe.

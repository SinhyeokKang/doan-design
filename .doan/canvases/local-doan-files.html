local-doan-files · draft · 7 frames · all new

Keep a project’s Doan files in Git, or out of it on this Mac.

Scope: the “Doan files” choice on every setup path (the Set Up dialog, the “Set up this folder for Doan” panel of first run and the Add Projects page, the clone screen) and a new “Doan files” section in Project Settings, with its guidance, its switch results and its disabled reasons, plus the Not set up notice of a worktree whose project keeps its files out of Git (docs/features/local-doan-files/ spec and design §3). All seven frames are new and /design-sync compares all of them. Copied from shipped screens: ProjectSetupDialog.tsx (Set Up dialog), Onboarding.tsx and projectStep.ts (setup panel, clone screen, footers “Clone and continue” and “Clone and add”), ProjectSettingsPage.tsx and projectSettingsRules.ts (header, path line, sections, Saving / Saved, write error, notices), SettingsAbout.tsx (the Copy button: Copy icon, “Copied” with a check), the Agent step’s provider list .ob-provider-list, the thread’s settings radio row .q-pref and About’s setup notice code chips, all from styles.css and docs/DESIGN.md (Onboarding, Add Projects page, Settings, Project Settings page). Placement is the person’s decision of 2026-11-07 (design §3.4): on setup screens the options sit above the changed-files list, and in the panel without a list below its sentence and above its button; in Project Settings the section sits after Shared with canvases and right above Remove from Doan. The option names “Include in Git” and “Keep out of Git (this Mac only)” are fixed by design §3.1. The Git behaviour the copy states (exclude in the common dir, git worktree remove deleting ignored files, tracked files staying tracked) was checked with real git 2.39.5 in the feature review (design §7); this draft did not re-run it. References: none taken from other tools. Everything marked “Not in code” is new; sample paths, branches and CLI messages are illustrative.

04

Project Settings · Doan files sectionNot in code

A “Doan files” section after Shared with canvases and right above Remove from Doan. Its description says the choice applies to every worktree of the project. The two options are radio rows in a settings group: the thread’s shipped settings radio row (.q-pref: the radio in the row’s icon slot, label and caption description) used outside the thread. A press saves at once, with no confirmation (design §3.2), and shows Saving / Saved on its own line (05).

With Keep out of Git, the guidance below the options is always shown (role=status), because Doan does not read the Git index and cannot know whether .doan/ was ever committed. The command is a white code chip on the notice’s inset fill (About’s setup notice) with a Copy button (the notice’s panel variant; Copy icon, then “Copied” with a check, as Settings › About’s Copy details). The header’s path line follows the mode. Config error and Read failed already replace the sections with one notice, so the section is hidden there, as shipped.

Project Settings · switching the modeNot in code

A press writes at once. While the write runs, the page is locked like any other config write (projectSettingsLocked), both options are disabled and the pressed one stays chosen; focus returns to the chosen radio when it ends (design §3.2). Saving, then Saved with one line about what changed outside Doan, sit on a line of their own under the options; a failed write puts its role=alert line in the same place and the options go back to the mode on disk.

Switching never moves or deletes files. Out of Git does not touch .gitattributes; back into Git adds Doan’s two .gitattributes lines first if they are missing.

06

Project Settings · when the mode can’t changeNot in code

When doan config reports the mode as unknown or gives a reason it can’t be changed, the options that can’t be chosen are disabled (the radio takes the disabled role colours, as the checkbox does) and one line under them says why, one sentence per reason (person, 2026-11-07). Outside Git only Keep out of Git is disabled: Include in Git is the current mode and stays enabled. With unreadable Git metadata or an exclude Doan can’t write, both are disabled, since neither switch can be made. The current mode stays chosen when it is known; unknown chooses neither. The guidance is not shown in these states.

The path line keeps the shipped wording when the mode is Include in Git. When the mode is unknown it drops the commit sentence: “Stored in .doan/config.json in this worktree.” (person, 2026-11-07).

subagent-progress · draft · 6 frames

Show what each subagent and background task is doing.

Scope: docs/features/subagent-progress/ (spec ‘확정한 결정’ including ‘자리’ and ‘턴 인디케이터와 작업 인디케이터’, ‘완료 조건’; design ‘드래프트 요청’, ‘드래프트에서 정한 것’, ‘작업 인디케이터’, ‘PoC 결과’, ‘PoC 결과 (T1b)’). Every frame is new, not in code. Frames /design-sync compares: in-turn, expanded, background, history, widths. copy is the wording table.

Model: a running task is an indented one-line task indicator at the bottom, under the turn indicator while a turn runs (the person’s turn or a report turn) and under the background line otherwise. When it ends, it leaves the bottom and an ended row (expandable) appears in the turn that launched it. While it runs, that turn’s activity place shows the Agent call as an ordinary step.

Chosen in the app: one line for both indicator and ended row; a task indicator is a drawn tree line (├, └) turning into a Bot (subagent) or Terminal (command) icon that starts at the parent’s text start, then text in the turn indicator’s own type and sweep; the provider logo appears only on the turn indicator; ended rows: Done is a check only, Failed and Stopped keep their word; Codex rows have no type when collapsed; the background line counts the visible task indicators (“Background work is still running…” when none is visible); the report marker follows the task’s status; type and current tool drop by the thread column’s width (default 347 panel: three facts); ended rows show no current or last tool; the step-group reflow when a task ends is accepted; while the main agent only waits on its subagents, the turn indicator reads “Claude is waiting on N subagent(s)” (“Codex is waiting on N subagent(s)” during wait) and the task indicators name each task; the report-turn marker; every task indicator shown when there are many (no group head); “Background command” for commands; the copy table as drawn. The other candidates were removed.

  • Docked capsule composer, tray and queue row: as restated in .doan/canvases/answer-popover.html from DockedComposer.tsx and styles.css.
  • Icons are Lucide, as the app uses them (Bot, Terminal, Check, CircleStop, CircleAlert, a reply arrow), plus a CSS-drawn neutral tree line (├, └, 1 px, --border-prominent, rounded turn --radius-inline) from under the turn indicator’s logo, or under the background line’s Terminal icon at its start, into each task indicator (new). Task indicators carry a Bot (subagent, Codex too) or Terminal (background command) icon at --size-icon-sm in --text-metadata after the connector, no provider logo, and use the turn indicator’s type size, weight, colour and sweep.

In the turn · task indicators and ended rows New, not in code

When it ends, it leaves the bottom and an ended row appears in the turn that launched it (spec ‘활동 줄과의 관계’). The ended row is the shipped activity head: same height, type, hover and chevron. Unknown values are hidden, never shown as 0. While the main agent’s only running tool is its Agent call(s) and no other stage applies, the turn indicator reads “Claude is waiting on N subagent(s)”; any other stage (a tool of its own, thinking, replying) shows as today.

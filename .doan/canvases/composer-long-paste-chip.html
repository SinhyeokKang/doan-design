FEATURE DRAFT · NOT IN CODE

Pasted text chips

Pasting plain text of 1,000 code points or 10 lines or more into a composer that takes attachments adds one “Pasted text” attachment chip instead of putting the text in the field. Finder files, chip clipboards, a field that starts with a command and composers that take no attachments keep today’s paste. There is no way back to field text.

All three frames are new review material: the “Pasted text” label with its line count, the first-line tooltip, and the pasted-text refusal and problem copy are not implemented. The composer card, tools, tray, thread bubble, queue row, attachment chip and notice are copied from the current renderer through .doan/canvases/folder-attachments.html (checked against ComposerParts.tsx, HomeComposerView.tsx, DockedComposer.tsx, ConversationThread.tsx and styles.css when that draft was made). The canvas panel and the prototype window use the same DockedComposer as the Overview and are not drawn again.

Design-sync targets: paste-home (chip and tooltip), paste-overview (sent bubble, queue row, restored draft chip), paste-states (each named tile). Feature documents: docs/features/composer-long-paste-chip/. Thresholds compared against Orca 1.4.263 and Claude Code 2.1.331, read from the installed builds on 2026-11-24.

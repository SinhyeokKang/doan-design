Background work still running after a done turn, and a message Claude Code never picked up.

Scope: docs/features/claude-turn-end/ (spec ‘완료 조건’ 3 and 5, design §3 and §5 ‘스레드 표시’, ‘사라지는 때’, tasks 2). Every frame is new, not in code: neither the background work line nor the prompt_unread failure exists yet. /design-sync compares background-line, background-widths and prompt-unread; copy is the wording and accessibility reference.

Fixed by the feature documents

  • After a Claude turn ends done while background work it started is still running, one still line sits under the reply, in the turn indicator’s place: “Background work is still running. It stops when you send your next message or press Stop.” No spin, no sweep. A small Stop inside the line (the composer has no Stop after a done turn).
  • Stop pressed: a spinner, not pressable, and the line stays until the process group is gone. Failure: Stop comes back and the toast “Couldn’t stop the background work. Try again.” shows.
  • Stop’s accessible name is “Stop background work”; it is an ordinary Tab stop, reached from the composer with Shift+Tab (Tab in an empty composer takes the suggestion). If the line goes while Stop holds focus, focus goes to the composer field. The line is not a live region; the thread’s sr-only status says “Background work is still running” once when it appears.
  • The line goes on the render where the person’s message enters the thread (a queued message sent at the turn’s end counts), when the work ends on its own or Stop ends it, or on archive, delete, sign-out or app quit. Nowhere else shows the conversation as running: slots, sidebar spinner, Home strip and agent indicator are unchanged.
  • Overview and canvas panel follow the same rule.
  • A turn whose prompt Claude Code never picked up ends failed with “Claude Code didn’t pick up your message. Send it again.” The message stays in the thread and does not return to the queue.

Choices drawn here for the person to confirm

  1. Line form. Provider logo + sentence in the reply’s type and the indicator’s resting ink (--text-metadata), Stop as the xs subtle capsule with the circle-stop icon (Send now’s button size and fill). Alternative: a doan-notice block on the inset fill. Drawn as a plain line because the turn is done and nothing needs an answer; a notice block reads as a problem.
  2. Stop while stopping. The label changes to “Stopping” with the spinner in place of the icon (the running Retry’s pattern, DESIGN.md ‘Read-state failure dot and Retry toast’). Alternative: keep “Stop” beside the spinner.
  3. Failure copy split. The thread notice uses the title “Claude Code didn’t pick up your message” and the body “Send it again.”, with the existing “Edit and resend” action, which every failed turn that began with the person’s message offers (ConversationThread.tsx lastEnd).
  4. Home strip copy. The strip keeps its own recovery body, as for every other failure (conversationStrip.ts FAILURES): “Edit your request on Home and send it again.” with Edit on Home and Dismiss.
  5. Light only. tasks 2 lists light and dark, but the app is light only (DESIGN.md ‘Light only’: main pins nativeTheme light). No dark frame is drawn.

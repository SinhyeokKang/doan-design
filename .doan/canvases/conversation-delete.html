Conversation delete — draft

Draft for conversation-delete (docs/features/conversation-delete/spec.md and design.md §3.1, §3.3, §3.4): a Delete button on every conversation row of the Overview’s Conversation menu and the canvas panel’s Title menu with its unavailable state, the confirmation, the refusal toasts, and the menu after the last conversation is deleted. All five frames are new (frame 05 pins the shipped empty list); /design-sync compares frames 01–05.

Copied from shipped code (8b11484b), not redesigned: the Conversation menu and its rows (ProjectOverview.tsx, CanvasConversationPanel.tsx, ConversationLine.tsx, styles.css .conv-*, .cv-*, .row-slot), the tooltip (.doan-tooltip), the compact alert dialog and its inset notice as drawn for Move to Trash (.doan/canvases/canvas-row-menu.html frame trash-dialog), and the toast (Toast.tsx). Mock rows are invented for this draft.

New here: the row wrapper .conv-row, the 24px button .conv-delete (--size-control-xs, the 16px Trash2 in subtle ink like the canvas row’s button), the moved hairline selector, the time spot that keeps the button’s width, and the reason in the tooltip. Confirmed by the user: a Delete button straight on the row instead of a “…” button with a one-item submenu; the unavailable reason goes in its tooltip. References: icons from lucide-react as installed (Trash2, Plus, ChevronDown, Hand), checked.

01

Conversation row · Delete button New, not in code

Each conversation row (not New conversation) gets a button named “Delete “<title>””, a menu item that is a sibling of the row’s radio item, positioned in the time’s spot. It shows while the pointer is over the row and while the row or the button is highlighted; otherwise it is clipped to 1px (not display: none). ↓ goes row → its button → next row.

02

Conversation row · Delete unavailable New, not in code

Delete is unavailable while the conversation’s agent works or waits for an answer (design.md §3.1 deleteAvailability). The tooltip is the only place the reason shows, so it opens on the button, from the pointer or the keyboard.

03

Delete · confirmation New copy, shared dialog

The compact alert dialog (role="alertdialog", title and body tied by aria-labelledby/aria-describedby), drawn in place, with Cancel first and Delete last in prominent. The body promises only what Doan does: its own record goes, the provider’s session files stay.

04

Delete · refusal toasts New copy, shipped toast

The shipped toast with no action. Shown when main refuses on Delete; the dialog has closed by then.

05

After the last conversation Shipped empty list

Nothing new is drawn for an empty list; this frame pins what the menu shows once the last row is deleted.

canvas-capture · draft for review · 8 frames

Capture an area of the board into the canvas conversation composer.

Scope: docs/features/canvas-capture/ (spec completion conditions 1–8, design §2–§4, tasks D1). The canvas page, its tools row and the docked composer are on main; this draft is a new file and no existing draft is edited. Every frame below is new and /design-sync (task F2) compares all eight: toolbar-default, toolbar-capturing, toolbar-unavailable, board-ready, board-drag, panel-folded, composer-chips, capture-failed.

  • New, not in code: the Capture area button (fourth in the tools row, before the divider; lucide Scan), its pressed and unavailable states, the capture hint above the row, the capture layer (crosshair), the marquee, the “Canvas capture” composer chip, the capture failure toast. Each frame's chip says what in it is new.
  • Provisional — needs confirmation: the icon (lucide Scan), the hint copy “Drag to capture an area”, the marquee look (selection-mark line over the backdrop-hover fill), no size readout while dragging, and the unavailable reason “Capture area isn’t available while the canvas can’t be shown.”. Whether capture also gets an app menu-bar item (as Edit > Pick from Canvas) is not decided and not drawn.
  • Copied as shipped (d7137e85, restated because canvases cannot link styles.css): the tools row, pressed and unavailable looks, divider and Export (CanvasTools.tsx); the picking hint, whose look the capture hint reuses (App.tsx); the selection mark (styles.css .mark); the canvas header (CanvasHeader.tsx); the docked composer, its chips and tray (DockedComposer.tsx, ComposerParts.tsx); the thread's sent file chip (ConversationThread.tsx); the toast (ds/surfaces.css). Tokens and primitives are linked from app/src/renderer/; the example canvas and thumbnails use .doan/assets/mock.css.
  • Not drawn: the snapshot itself (app marks, the tools row, notices and toasts go to opacity: 0 for the round trip; PoC C1 measures whether it flickers), the zoom menu over capture mode (as today), Home and Overview (no capture there).
  • Copy: “Capture area”, “Canvas capture”, “Remove canvas capture”, “Couldn’t capture the canvas. Try again.” and “Only 10 files can be attached. Remove one to add another.” are from the feature documents; “Files can’t be attached to a terminal session”, the duplicate-ID reason, the 50 MB and left-out lines are the app's today. Messages, names and sizes are examples.
  • References: the corner-bracket icon and crosshair drag follow the macOS screenshot area tool (⌘⇧4, recalled from memory, not checked in this session). Everything else follows this repo's shipped Picker (checked in code).

04

Board · capture mode, before the drag New, not in code

The capture layer covers the board in the drag layer's place, so the pointer is a crosshair over frames and margins alike, and a click selects nothing. The hover mark goes away when the layer comes up (hover-leave); the selection mark stays, unchanged. The agent notice, the canvas notices, the status and the tools row sit above the layer and stay clickable. Wheel pans and ⌘/Ctrl-wheel zooms. A click or a drag under 8 CSS px adds nothing and capture mode goes on.

05

Board · dragging the capture area New, not in code

A primary-button drag draws the marquee from the press point to the pointer, in either direction, clipped to the area. Provisional: the marquee is the selection mark's line (1px --border-focus with a 1px white outer line, so it holds on any canvas colour) over the --affordance-backdrop-hover fill; there is no size readout. It may span frames and the board margin. Releasing takes the pixels under it as shown (zoom × screen scale), without any app mark, the marquee, the tools row, notices or toasts; capture mode ends at once and the previous tool is pressed again. Wheel panning during the drag moves the canvas under a fixed marquee. pointercancel, a lost pointer capture or the app losing focus drop the drag only; capture mode stays.

Toast · capture failed First line new, not in code

A failure is something that happened, so it is a toast, never a board notice (POSTMORTEM 2026-11-02). The Checking chip is removed and one line shows in the shipped toast; capture mode has already ended on release. An empty image or a failed save: “Couldn’t capture the canvas. Try again.”. Over 50 MB: the shipped pasted-image line. If the draft reached 10 files between the render and the release, nothing is captured and the shipped limit line shows.

app-update · draft for review · 15 frames

Updates: check, download in the background, restart to install.

Draft for docs/features/app-update (task T1) under the parent decisions D9–D12, D23 and D24 in docs/features/release-0-1-0/design.md. Every frame is new UI and none of it is in code. The notice surface is the header button the person chose (D24 option a, frames 09–14); with it ship the Doan menu item (frame 15) and the update parts of Settings › About (frames 01–08: the Version row and the automatic-check row in the Doan section). There is no macOS desktop notification and no toast (a toast lasts 8 s and loses its slot to the next one).

  • Copied from shipped code: styles.css inlined without its imports, @theme and comments; tokens.css and ds/index.css linked. The header, sidebar and Home body are the hand-written DOM of readme-features.html (written from App.tsx TopBar, ShellSidebar.tsx, HomeComposerView.tsx, not captured); the Settings › About page is written from SettingsAbout.tsx, SettingsPage.tsx and aboutView.ts; the working slot is SlotMark, the folded usage button AgentUsageButton.tsx. The Home stage’s top padding is a sample of the value stageInsets computes. Small spacing differences from the running app are possible.
  • New, from shipped parts: the shipped Version row takes the update state in its description and the update actions on its right; the rows use the shipped preference row, spinner line, error line, notice and switch, without live roles (one page region reads results); the download bar is the usage popover’s .usage-bar as a progressbar; the header button is a grey sm doan-button with the tab capsule’s fill, the shared tooltip and popover; the menu is drawn with the menu primitive. New CSS is in the last block of this file and uses tokens only.
  • Copy (clarify preset, from the starting points in design.md ‘상태’): the Version row’s description is “0.1.0 · ” and the state, with “Doan” before every new version; a phrase has no full stop, a sentence has one. Progress labels have no ellipsis (DESIGN ‘Label ellipsis’), so the percentage sits beside the bar. Failures name the step and say the code’s cause and recovery without claiming more than the code knows. Copy details adds the line Updates: up to date, last checked today at 2:41 PM.
  • States (harden preset): every row of design.md ‘상태’ is a tile, plus a failed version read, a failed save of the automatic-check switch, 0% before the first progress, rc versions at 960 × 600, and the header button in every state (ready, blocked, restarting, stopped, the minimum window, unavailable).
  • Not decided by the documents, drawn here as a proposal: the automatic-check row right after Version; Restart to Update as the only filled button on the About page; the menu item under About Doan and what a blocked press does; the header button’s grey fill, version tooltip and the popover that reads the reason or the stopped line; the icon (lucide CircleFadingArrowUp).

Version row · download, ready and restartNot in code

Downloads start on their own. The bar under the description is a progressbar named by the state text (aria-valuenow); progress is never announced. Before the first progress event the bar is empty and the value reads 0%. Ready puts Release Notes (the GitHub release page for that version, in the browser) and Restart to Update, the About page’s one filled button, on the right. 06

Version row · failures (manual check, download, install)Not in code

Only a manual check, a download or the install shows an error. The state carries the step and, once known, the version (failed(code, stage, version?)): the description names the step, the line under the row says why only as far as the code knows and how to recover. offline and other occur in both check and download. Retry is named for what it repeats (“Check for updates again”, “Download Doan 0.1.1 again”); a failure that knows the version adds Release Notes; an install failure repeats Restart to Update instead of Retry. The renderer gets the fixed code, never the updater’s message.

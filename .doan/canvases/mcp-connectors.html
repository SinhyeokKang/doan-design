mcp-connectors · draft round 5 · 11 frames

MCP Connectors: let Claude Code and Codex use remote MCP servers in Doan conversations.

Scope: docs/features/mcp-connectors/ (spec completion conditions 1–10, design ‘초안 요청’). A new Settings category, MCP Connectors, between Agents and Notifications, shown only while Claude Code or Codex is signed in to Doan. One section per signed-in agent lists the MCP servers that agent can use: the presets Notion, Atlassian and Figma are always there, and servers added by URL (Add server by URL in the page header) are shared by every section. Each item connects that agent with its own official MCP sign-in or disconnects it; only URL servers can be removed, from their … menu. Plus three additions to shipped surfaces: a failure toast, one sentence in Agents’ sign-out confirmation, and two items in a Codex conversation. Everything on this canvas that belongs to MCP Connectors is new and not in code: the category and its sidebar row (Plug icon), its lead, the agent sections, the server items, every state line and its notices, the … menu, the Add server by URL dialog, the Remove confirmation and all their copy. The preset marks are local assets in .doan/assets/mcp-logos/ (sources in its README.md). Copy and connector data are real English UI text; account data, conversation text and the long URL connector are illustrative.

Progress labels are present participles without an ellipsis (Checking, Connecting, Disconnecting, Removing, Waiting for Notion; design ‘문구 규칙: 진행 상태’); command labels that open further input keep theirs. States added after the confirmed draft (Disconnecting, Removing, the busy section, Remove disabled while connecting, the Claude timeout and busy failures, the deferred-logout line, Waiting for Notion) are drawn as tiles or items in the nearest frame and are not compared by /design-sync.

/design-sync compares frames 1–8 (agents, one-agent, custom-url, server-menu, connecting, failed, remove-alert, running-notice), the windows and the tiles inside them. Frames 9–11 (file-error, elsewhere, conversation) add to shipped surfaces and follow their measured values; they are not compared.

Copied from shipped screens, not redesigned: the Settings shell (header with sidebar toggle, Back, Forward and the page tabs; the Settings sidebar; Home’s white panel; the 48rem column, title, lead, sections, groups and rows), from app/src/renderer/SettingsPage.tsx, ShellSidebar.tsx, App.tsx TopBar and styles.css, checked against docs/DESIGN.md ‘Settings’ and zero-setup-agents.html (agents frame). Server items are Settings’ shared preference rows in a settings group, built as Settings › Agents builds its provider rows (SettingsAgents.tsx; ds/surfaces.css .doan-settings-group and .doan-preference-row with a medium-weight label; styles.css .doan-preference-row-icon and -extra; DESIGN.md ‘Settings’). Waiting and error notices, Retry and the stop confirmation follow Settings › Agents (SettingsAgents.tsx, agentAuthView.ts, Onboarding.tsx NoticeView, StopDialog, PasteDialog). The toast follows Toast.tsx; the conversation panel and thread follow styles.css (buzz-canvas-conversation) and ConversationThread.tsx; Codex’s permission options and their order (Allow, Deny, Allow for this session) come from main/conversation/transport.ts. Shared primitives come from the linked tokens.css and ds/index.css. Not copied: the sidebar row height and colours were not re-measured here; the shell CSS was read from source, not measured.

References: docs/DESIGN.md ‘Adopted rules’, ‘Doan adjustments’ (no coloured edge stripes; errors with an icon), ‘Notices’, ‘Settings’, ‘Canvas conversation panel’ (checked in the repo); docs/PRODUCT.md §5 item 0 (Settings) (checked). Lucide icon paths (Plug, Server, Ellipsis, PanelLeftClose, PanelRightClose, SquarePen, Terminal, CircleStop) were read from the installed lucide-react 1.61.0 (app/node_modules); the others are copied from zero-setup-agents.html. Design presets read: shape, clarify, harden (by the lead), critique, polish.

MCP Connectors · Both agents signed inNot in code

One section per agent signed in to Doan, Claude Code then Codex; each section is a group labelled by the agent. It lists the three presets (always there) and then the servers added by URL, which every section shares. An item is a Settings preference row (20px logo, medium label, caption status line, trailing buttons, lines under it) in a settings group, a focusable row group (tabIndex −1) named “Notion for Codex”; its buttons are named with server and agent (“Connect Notion for Codex”). All six states appear: Connected, Checking (actions disabled), Not connected, Connecting (Agents waiting notice), Reconnect needed (helper line), Couldn’t check (Agents alert + Retry). While Claude Code connects the URL server, its other Connect buttons are disabled (Figma here) with the tooltip “Finish or cancel the connection first.” Progress labels are present participles without an ellipsis. The page has one hidden live region; it reads connected, disconnected, failed, added and removed with the agent’s name, and background Reconnect needed or Couldn’t check, never the first Checking result. Focus follows Settings › Agents: when a focused button goes away or is disabled, focus moves to its item’s row group. The window is drawn taller than 780 so nothing is cut.

MCP Connectors · Add server by URLNot in code

Add server by URL, at the right of the page header, opens a compact dialog like the shipped Paste dialog: title, one line of description, the URL field (labelled for screen readers, placeholder when empty), Cancel and Add. Enter submits; Escape and Cancel close it and return focus to Add server by URL. Add is disabled only while the field is empty. A well-formed URL is added even when the server can’t be reached; that shows at Connect as the CLI failure with the host’s name. After Add, focus goes to the new item’s row group in the first section, scrolled into view, and the live region reads the addition once. The page is locked behind the scrim.

MCP Connectors · Connection failedNot in code

A failed attempt returns the item to its previous state (here Not connected) and adds the Agents alert under it: what happened and what to do, Retry on the right. The alert stays until the item’s next Connect, Retry or Cancel, also after leaving the page and coming back. Four reasons in the window: Claude Code · Notion, no link arrived (a browser set in Claude Code’s settings overrides Doan’s); Claude Code · Atlassian, a plaintext token file appeared and Doan deleted it (storage_failed); Codex · Notion, the approval timed out; Codex · Atlassian, the CLI failed (a URL server’s CLI failure names its host). A cancel says nothing. The tile adds the Claude timeout, the busy failure and the deferred-logout line.

work-update — draft

What the canvas board shows between doan work start and doan work done when the agent runs doan work update <canvas> --frame <id> --note "…" each time it starts editing a frame (docs/features/work-update/spec.md, design.md §1 ‘UI flow’ and decisions 1–19). It applies to terminal sessions and to Doan’s own conversations (this canvas’s conversation, a project conversation, a conversation bound to another canvas). All six frames are new; /design-sync compares notice-states, notice-typing, marker-states, marker-moves, follow and reduced-motion.

01

Working notice · its text becomes the note New, not in code

The working notice is the shipped “Agent is working” card (CanvasAgent.tsx, .doan-agent); doan work update changes only its text. No second notice and no second line. Order: the note as the agent wrote it (text only, one line, at most 120 characters) → “Working on <frame title>” when there is a frame but no note → “Agent is working”. This canvas’s own conversation keeps Stop and its waiting state (“Agent needs your answer” with Open) unchanged. A project conversation, a conversation bound to another canvas, and a terminal session show the card without Stop. The glow is drawn; the dot field is the app’s script and is not.

02

Working notice · erase, then type New, not in code

When the card’s text changes (a new note or a new frame), the beginning the old and new text share stays, the rest of the old text erases one character at a time from the end, and the rest of the new text types in. A text cursor sits right after the last visible character for as long as the card shows (not at the card’s edge: it moves left while erasing and right while typing; when the card is held wider, the space after it stays empty; when the text is cut, it follows the ellipsis): solid while text erases or types, blinking (1 s, on and off, no fade) when the text rests, still under reduced motion. It is decorative (aria-hidden), in the notice’s text colour, half of --space-1 wide, --type-body-sm-size high, --space-1 after the text, and outside the width rule below. Characters are grapheme clusters, so a Korean syllable or an emoji never shows half. Timing (a starting value the implementation may tune): erase 20 ms and type 35 ms per character; past 1,000 ms in all, both shrink by the same ratio, so a usual change takes about 800–1,000 ms and a short one less. A newer update mid-animation drops the remaining steps and restarts from the text on screen. Width: the text box is max(the shown text, min(old text, new text)), within the card’s 420px column, so the card never collapses while erasing: a shorter new text lets it shrink only to that text’s width, a longer one keeps the old width until the typing passes it. The app measures the old and new text once per update in a hidden node and sets that floor as min-width until the change ends (here it is drawn with a hidden copy of the shorter text). Accessibility: the visible line is aria-hidden; the card’s visually hidden role=status holds the final text from the first moment, and the tooltip shows the final text. Under prefers-reduced-motion the text and width change at once.

03

Working-frame marker New, not in code

The marker is the canvas’s frame-jump highlight (.mark.jump-highlight, DESIGN.md ‘Overlay marks’: 3px --affordance-accent → --indigo-600 line at 135°, 1px --surface-panel ring, accent glow at 45 %), kept while the agent works on that frame instead of fading after 1.2 s. To feel alive, its gradient travels along the line (one loop in 4.8 s, linear) and its glow breathes between 45 % and 25 % accent over 2.4 s (--ease-state, the notice dot’s period). A reload removes it while the document is replaced and puts it back on the same id. It sits under the selection and hover marks and never takes the pointer.

04

Marker moves to the next frame New, not in code

When the agent’s next update names another frame, the marker moves there: position and size slide together, the line keeps travelling. The text changes at the same moment. Under prefers-reduced-motion the marker is placed on the new frame at once (frame 06).

05

Follow the working frame New, not in code

The view follows only when the person has stopped: a new working frame, no pan, zoom, drag, drawer or Quick Open jump, chip locate or doan open --frame by the person for 5 s, and no pick or drag in progress. A person’s move stops following until the turn ends (a terminal session’s done or expiry, an app conversation’s turn end). The app’s own follow moves, a reload and a restored view do not count as the person’s. It never opens another canvas.

06

Reduced motion New, not in code

Under prefers-reduced-motion the marker keeps its shape and loses all three motions (travel, breathing, slide). Under reduced transparency the glow drops and forced colours draw a 3px Highlight border, as the jump highlight does today. The app is light only, so no dark variant is drawn.

buzz-canvas-conversation · draft for review · 15 frames

The canvas conversation: read, continue and point at the canvas.

Scope: docs/features/buzz-canvas-conversation/. The conversation panel shell of buzz-canvas.html (confirmed) gets its content: the title as the conversation menu (that draft’s conversation-menu reference), the thread and the docked composer of the project Overview (shipped, buzz-project.html and buzz-conversation.html), inline anchor chips, Pick from canvas, Add to conversation and chip locate. New conversations follow the Overview’s new-conversation pattern (2026-11-01 user). An existing or archived conversation keeps its provider (the shipped dockedPicker rule); a terminal session takes no model, effort or attachments. The canvas page has no conversation strip and no comment UI.

/design-sync compares every frame. Copied as shipped: shell, canvas header, board and tools row (buzz-canvas.html), composer, thread, notices and markers (buzz-project.html, buzz-conversation.html). Conversation text, titles and times are sample data; the example canvas uses .doan/assets/mock.css.

Canvas conversationNot in code

New conversation · canvas without oneNot in code

A canvas with no conversation opens on the Overview's new-conversation pattern: an empty panel with suggestions right above the composer (the shipped quiet suggestion buttons of Home and the Overview, presets aimed at this canvas; a chip fills the composer and the person sends), the provider and model picker with the Settings defaults, and the placeholder “Ask about this canvas, / for presets”. 03

New conversation · from a conversationNot in code

On a canvas that already has a conversation, New conversation in the title menu opens the same new-conversation state (the Overview's pattern, nothing added). The first send makes the new conversation current; the previous one moves to the menu's earlier conversations (archived, readable, and current again if the person sends to it). While the current conversation works the send waits with the shipped busy line.

04

New conversation · terminal sessionNot in code

A canvas a terminal Claude Code or Codex drew, with a session association (doan check), offers to continue that session; it is the default. Continuing runs on the installed CLI's own profile, so the person can't choose a model or effort: the row keeps the same agent and effort triggers, without chevrons and not interactive (“Terminal session”, “Default”, title “Set in your terminal”). Choosing Start a new conversation brings back the provider picker. Without an association, or when it can't be used, only the new conversation shows.

10

Composer with anchor chipsNot in code

Chips sit inline in the text at the caret: a frame, an element (tag and doan-id or text, up to 40 characters) and a point (an empty spot, named by its frame). Each chip is one unit: the caret stops before or after it, Backspace removes it whole, and the full target is its title. A chip turns the capsule into a box. The message goes out as {{1}}, {{2}}, {{3}} with the anchors.

11

Pick from canvasNot in code

Pick from canvas puts the canvas in a one-time picking state: the instruction at the top centre, a crosshair, hover candidates as usual. Clicking a frame or an element puts its chip at the caret; clicking an empty spot puts a point chip. Focus returns to the composer. Picking does not change the selection or doan active. Esc, the button again or leaving the canvas cancels.

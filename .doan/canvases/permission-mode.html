permission-mode · draft round 1 · 6 boards

Choose how much the agent may do without asking.

Scope: the permission mode picker beside model and effort in every composer, its menu, the docked tray when it runs short of width, the terminal session’s fixed trigger, the switch after a Claude plan is approved, and the Permission row in Settings › Agents › New conversations. All six boards are new; /design-sync compares all six. Copied from shipped screens: the Home composer and tray, the docked composer and tray, the Effort trigger and menu, the thread permission notice, and the Settings group and rows (app/src/renderer/styles.css, ds/, HomeComposerView.tsx, DockedComposer.tsx, ComposerParts.tsx, SettingsAgents.tsx; read in this checkout).

Decisions come from docs/features/permission-mode/spec.md and design.md: four modes for every provider (Default, Accept edits, Plan (read-only), Full access), a description under each menu row, Full access marked by icon, label and warning ink (--text-warning on --affordance-warning), never by colour alone and never by an edge stripe. Mode icons are lucide-react 1.61.0 (shield, file-pen-line, eye, shield-alert), read from app/node_modules. Menu descriptions are draft copy; Default’s may change with PoC P1/P2. The plan-approval choices in board 05 are sample text: Claude Code supplies its own (PoC P1). Presets read: none (the command was listed; the feature documents already fix the states).

Picker · menuNot in code

The shared doan-floating doan-menu with a radio group, like Effort: the head “Permissions · <provider>”, one row per mode with its icon, its name over a one-line description, and the check on the chosen row. 280 wide. Picking closes the menu, applies to the next message (also while a turn runs, without a notice) and remembers the mode for the provider. An ACP provider lists only the modes its agent maps; with none it has no picker.

03

Docked tray · when it is short of widthNot in code

In the Overview and the canvas panel the picker sits in the tray after Effort, at the xs trigger size. The panel’s minimum is 320 (DESIGN.md ‘Panel width’), where Pick, model, Effort and Permission do not all fit with labels. The tray is a size container and gives way in order, never wrapping: 1 below a 384px content width Permission shows its icon only; 2 below 288 Effort does too; 3 the model label ellipsizes last. Pick, logos and chevrons never shrink. Each mode has its own icon, so an icon-only trigger still names the mode, and Full access keeps its warning icon, ink and fill. A hidden label stays in the tooltip and the aria-label.

Tile widths are the docked composer’s; the tray’s content is 24 narrower (12 inline padding each side). The boundaries are this draft’s estimates from its widest labels (“Plan (read-only)”, “Medium”); /design-sync measures them.

06

Settings · New conversations · PermissionNot in code

A Permission row after Effort, shown only when Agent is a provider; with Last used it hides like Model and Effort, and Home starts from the provider’s last mode. Its menu is the composer’s menu, below the trigger. A pick in any composer replaces the saved mode, as it does model and effort. A file from a newer Doan disables it with the others; a saved provider that cannot run keeps the row and its value (Agent’s row carries the warning).

Queue row: Send now

Scope: the queued-message rows above the docked composer, in the project Overview (720) and the canvas conversation panel (360). New: the Send now button, its Sending… state and the refused status line (frames 01–03, all Not in code). /design-sync compares frames queue-row, queue-rows and queue-unsupported.

Copied from shipped code, not redesigned: the queue row (app/src/renderer/styles.css .queue, .queue-item; DockedComposer.tsx), the docked capsule composer and its tray (Attach, Pick from canvas, model, effort, permission), the shared xs button, icon button, tooltip and focus outline (app/src/renderer/ds/). Hover, focus and the tooltip are drawn statically with classes the app does not use (is-hover, is-focus).

Sources: docs/features/queue-send-now/spec.md (completion conditions 1, 2, 7, 8, 10, 11; decisions 1, 8, 11) and design.md §8 (checked). Copy: “Send now”, “Sending…”, “Send queued message now”, “Add to the current turn without stopping it”, “Couldn’t send now. It stays queued.” are from those documents. Sample message text and model names are examples. Whether Send now shows while a permission answer is pending waits for the T0 PoC (spec decision 3) and is not drawn.

01

Queue row · Send nowNot in code

One queued message while a turn runs, with a provider that can take it (Claude Code or Codex, stored on the conversation). The row is the shipped queue row (styles.css .queue-item) with an xs text button Send now between the text and Remove. The tooltip says what it does, so it is not read as stop-then-send. Both buttons are described by the row’s text (aria-describedby), so their names stay short but each row is told apart.

While the message waits to be read, the same button reads Sending…: aria-disabled (not disabled), clicks ignored, focus kept. When the agent reads it the row leaves the queue and the message shows in the thread; focus goes to the next row’s Send now, else its Remove, else the field.

02

Several queued messages · refusedNot in code

Each row has its own Send now, and only the pressed row goes into the turn; the others keep the existing queue rule (sent as one message after a done turn, back to the draft after a failed or stopped one).

If the provider refuses while the turn is still running, the row stays where it was, keeps focus, and a status line (role="status") shows under it for a short time: Couldn’t send now. It stays queued. No line shows when the refusal came because the turn ended. How long the line stays is not decided in the feature documents; the tile shows it present.

03

Provider without Send nowNot in code

Cursor, Antigravity and Copilot (ACP) cannot add a message to a running turn, so their rows keep Remove only and the queue works as it does now. The same applies to a provider that fails the T0 PoC. Send now is also absent while no turn is running (preparing, or a finished turn waiting for its judgement and queue flush).

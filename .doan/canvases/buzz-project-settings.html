Project Settings — a page

Project Settings as a page in the white body (formerly Alt 2), with its states, the workspace status line and the unchanged removal toast. Drawn with the app’s own styles.css; the page and its states are a proposal, not in code.

01

Project Settings page Proposal · not in code

The project menu’s Project Settings opens a page in the white body with the Settings column, title and sections, so a worktree’s settings sit where Agents and Notifications already do. The header names the project with its thumbnail, branch and path; Show in Finder is at hand. Changes save at once; there is no Done. Remove from Doan joins the page. Button labels drop the trailing ellipsis. Changes PRODUCT §5 item 0 (dialog → page) and the guide’s pointer.

03

States · healthy worktree Proposal · not in code

Every state the page draws, each as the settings column of the white body. Read failed keeps Remove; a pick outside the repository fails inline under its row. Adding a path asks first, over the page.

04

States · problem worktree Proposal · not in code

The page for each folder state: one notice with its recovery actions in place of the Token CSS and Shared sections, and Remove kept below it. Show in Finder appears only when the folder exists. Set Up opens the set-up dialog over the page.

05

Workspace status line Proposal · not in code

A loaded workspace whose worktree becomes unhealthy keeps showing, with this line across the top of the workspace. As shipped, except that Locate and Set Up drop the trailing ellipsis to match the page. Drawn at the workspace width; the area under it is left blank.

06

Removal toast · unchanged

Remove from Doan (project menu or the Project Settings page) shows this for eight seconds at the window’s lower right. Drawn as shipped.

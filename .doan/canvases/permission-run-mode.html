permission-run-mode · draft round 2 · 4 boards

Show the mode Claude Code settings run when Ask first is picked.

Scope (docs/features/plan-approval-and-effective-mode/spec.md and design.md): a Claude Ask first turn passes no mode, so defaultMode in Claude Code settings applies. When the turn’s first top-level system/init reports auto, dontAsk, acceptEdits, plan or bypassPermissions, the permission trigger of that conversation reads “Ask first · Auto”, “Ask first · Don’t ask”, “Ask first · Accept edits”, “Ask first · Plan (read-only)” or “Ask first · Full access”, its aria-label says “Permission: Ask first, Claude Code settings run <name> mode”, and the menu’s Ask first row says “Your Claude Code settings run <name> mode”. A reported default adds nothing. Full access also carries the Full access warning (shield-alert icon, danger ink, “, no approval requests” in the aria-label) although the stored mode stays Ask first. The value is stored with the conversation and shows only while Ask first is the stored mode. All four boards are new; round 2 adds the Accept edits, Plan and Full access names that PoC P1 confirmed, and moves the docked label step. /design-sync compares all four.

Copied from shipped screens (read in this checkout): the docked composer and tray, the permission trigger, menu and colours (app/src/renderer/styles.css, ComposerParts.tsx, DockedComposer.tsx), and the thread permission notice and its folded line (ConversationThread.tsx). Shared CSS and icons come from .doan/canvases/permission-mode.html, whose own copy of the trigger predates the shipped “Ask first” label and danger ink; this draft follows the shipped values. Reference (checked, design.md ‘PoC 의존’ P1, recorded on Claude Code 2.1.312 and Agent SDK 0.3.312): Ask first turns report all five values; a project’s auto and bypassPermissions start as default, so those two come only from Doan’s connected profile settings; approving a plan always reports default. Docked step widths were measured in Chrome with the shipped tray and tokens. Presets read: clarify (copy, only checked against the strings decided in design.md; none changed).

01

Trigger · the mode the last Ask first turn ran inNot in code

The docked composer of an existing Claude conversation (Project Overview and the canvas panel). The trigger keeps the picked mode and adds the observed one after a middle dot; icon and ink stay Ask first’s. It changes when the turn’s first top-level system/init arrives, so during the turn that sets it. A conversation with no observed value, or whose last Ask first turn reported default, shows plain “Ask first”, as shipped. Picking another mode hides the value without clearing it; picking Ask first again shows it at once.

Full access (bypassPermissions, reported only from Doan’s connected Claude Code profile settings) is the one value that changes the trigger’s look. The stored mode stays Ask first, so the shipped data-mode="bypass" never applies; a separate data-warning marker gives the trigger the shield-alert icon and the danger ink of today’s Full access trigger, and its aria-label ends with “, no approval requests”. Board 03 moves the docked label step, so these tiles are 540 wide (tray content 516, above the step).

When the value changes, the composer’s existing sr-only status announces “Claude Code settings run Auto mode” once; the same value again, or a cleared value, announces nothing.

03

Docked tray · when it is short of widthNot in code

The shipped order stays: Permission shows its icon first, then Effort, and the model label ellipsizes last. The shipped 432 step fits “Ask first” beside the widest model and effort labels (“GPT-5.6-Terra”, “Extra high” with Fast). With those, the natural tray width is about 475 with “Ask first · Don’t ask”, 484 with “Ask first · Full access”, 492 with “Ask first · Accept edits” and 510 with “Ask first · Plan (read-only)”, the longest. The step moves to below a 511 content width (this draft’s estimate, measured in Chrome with the shipped tray; tile widths are the composer’s, the tray’s content is 24 narrower). It stays one step for every value, as the shipped 432 is one step for every label, so a shorter label also hides at that width.

Icon-only, the shield cannot tell Ask first from Ask first · Plan (read-only), so the tooltip and aria-label carry the observed mode. For Full access the icon is the shield-alert in the danger ink, so it still differs from plain Ask first without the label; its tooltip and aria-label end with “, no approval requests”.

04

Claude plan · approved, back to plain Ask firstNot in code

A turn sent in Plan ends its plan with an ExitPlanMode request in the shipped permission notice (Allow, Deny, Stop; Claude sends no suggestions). After Allow, Claude reports the mode it now runs, and PoC P1 showed that is always default, whatever the settings say. The stored mode becomes Ask first as shipped and the observed value is cleared in the same update, so the trigger reads plain “Ask first” and never shows a value from an earlier turn. Approving an Ask first turn that settings ran in Plan ends the same way.

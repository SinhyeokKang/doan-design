Onboarding — draft

Scope. Feature #8 onboard (docs/features/onboard/spec.md completion conditions 3–10, design.md flows 3–11 and “초안 요청”). The four-step first-run wizard (CLI · Agents · Project · First prompt), the replace confirmation, the project setup dialog opened from the sidebar, and the new sidebar rows for Not initialized and No canvases.

New. All eight frames are new. The wizard (wizard-*), confirm-replace and project-setup-dialog are not in code yet (design.md names the future files Onboarding.tsx and ProjectSetupDialog.tsx; they do not exist, so these frames carry no data-doan-implements). In sidebar-setup and sidebar-first-prompt only the parts marked with a dashed yellow label are new. Headings, lead sentences, dialog titles and a few status words that the feature documents do not give were drawn by this draft and accepted with it (design.md “초안 요청”, 2026-10-24 user); they carry a “draft decision” mark in their frame label so reviewers can find them.

Copied from shipped screens. Window size 1238 × 780, top bar 40 px, traffic lights, buttons, keys, sidebar rows, hints, recovery buttons, canvas status text, the focus ring and the dialog surface come from app/src/renderer/styles.css and docs/DESIGN.md (App shell, Comments). The tooltip copies the shadcn tooltip in app/src/renderer/components/ui/tooltip.tsx (foreground on background, 12 px, 6 × 12 padding). Copy button states copy the comments-ui copy labels (CommentsPanel.tsx copyLabel).

/design-sync compares all eight frames: the main specimen of each wizard step, every labelled tile below it, the dialogs, and the new sidebar parts. The shipped sidebar rows inside the sidebar specimens are already measured (DESIGN.md) and are drawn only for context.

Decisions applied (2026-10-24). Full-window wizard with top title and Close, a four-step indicator whose steps are buttons that move to that step (a completed step shows a check instead of its number, a skipped step keeps its number; design.md flow 4, user), a centered form up to 640 px wide, and a bottom bar with “Step N of 4” and Check Again on the left (steps 1 and 2) and Skip / Continue on the right on steps 1–3, Done alone on step 4 (user). With MCP unknown, an agent row’s Connect still runs the stub and (Claude Code) link and stops at MCP (design.md flow 6, user). Confirm buttons Replace Link / Replace Skill / Replace MCP Registration. State words: Not installed / Not registered, Installed / Registered, Needs replacement, Unavailable, Couldn’t check. App name is lowercase doan (“Set Up doan…”).

References. Orca’s relative skill link ~/.claude/skills/orca-cli and its bundled CLI layout are cited from design.md (checked on this machine on 2026-10-24 by the feature author, not rechecked for this draft). Step indicator and bottom bar follow the decisions above; the general macOS setup-assistant shape is from memory and was not rechecked against screens.

Revision (2026-10-24). The base is the Opus draft (commit adc9c03). The shell-specific PATH tiles and the PATH line copy feedback come from the Astra draft (commit b0f4ce3) in this draft’s tile style with the Astra copy.

Example data. User alex, app at /Applications/doan.app, project acme-web at /Users/alex/code/acme-web. Paths in the tiles include long values on purpose.

Wizard — Step 1 · CLI

new · not in codedraft decision: heading and lead

Main specimen: first run, nothing at ~/.local/bin/doan, PATH already contains ~/.local/bin. Install creates ~/.local/bin, makes a temporary link and renames it. The link target is the CLI the app uses (DOAN_CLI or the bundled one). Install is the primary action until the link is ours; then Continue becomes primary. Opening the wizard focuses its title; Tab stays inside the wizard; Escape and Close close it (inactive while an action runs).

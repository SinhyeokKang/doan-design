FEATURE DRAFT · NEW BEHAVIOR, NOT IN CODE

Frame-first selection

Click once for the outer frame, then click to move inward. Existing solid selection outlines, dashed hover outlines, size capsules, toolbar and frame drawer stay unchanged. Labels above each crop explain the input and result; they are not new canvas UI.

All four frames are design-sync targets. Every board is a 520 × 400 crop at 100% scale, except three: the selection-lost crop spans both columns so the toast sits at the window’s bottom right beside the tools, and the drawer-result and Picker crops are 560 high so the bottom tools do not cover “Review copy”. A contains B and C; D is a different outer frame. The blank field is an empty div, and “Review copy” is outside all frames. This is illustrative HTML, not an app screen proposal.

Checked references: CanvasController.ts drawMarks, selection.ts sizeLabel and SELECTION_LOST, CanvasTools.tsx, CanvasHeader.tsx FrameDrawer, current styles.css, DESIGN.md “Canvas area and right panel”. Current code overrides historical drafts. Mock content colors use mock.css; UI uses current tokens and primitives. No Inspector or prototype control is added.

Static state review only: click order, modifier timing, reload recovery, focus and doan active agreement still require implementation probes. No undecided visual change is introduced.

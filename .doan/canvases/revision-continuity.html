Revision continuity — draft

Scope. Feature revision-continuity (docs/features/revision-continuity/spec.md, design.md, 2026-10-25): review keeps going while an agent edits files. A new comment blocked by a reload of the same canvas can continue on the current version; a moved or renamed open canvas with the same ID is followed instead of closed; two canvases with the moved canvas's ID stop the follow with a notice; comments on a canvas with no rendered document stop claiming “Location unavailable”.

Frames. continue-draft, selection-gone, moved, duplicate-id, no-document, in the order of the draft request. Not drawn, as the request says: Escape and blank-click without a dialog, Comments scope kept across reload and move (nothing on screen changes), and the reload flicker hold (T-11, only if measurement reproduces it).

New versus shipped. New elements carry a dashed “new” label. New: the blocked-editor notice, “Continues on …”, “Continue on current version” with its Starting…, failure and disabled states, the selection-gone notice with “Continue on canvas”, the Activity “Moved · from …” row, the duplicate-ID toast and Overview notice, and the text-only target line with no “Location unavailable” badge when no document is rendered. Everything else — window 1238 × 780, top bar and breadcrumb, the design tree rows, canvas area, zoom, canvas status messages, Canvas info, Activity rows, the Comments panel head, composer, cards and badges, the toast and the Overview cards — is copied from app/src/renderer/styles.css, App.tsx, Sidebar.tsx, RightPanel.tsx, CommentsPanel.tsx, ProjectOverview.tsx, Toast.tsx and docs/DESIGN.md (App shell, Comments, Design navigation). The “unavailable” blocked editor is the shipped one, unchanged.

Target lines. “To: …” lines and card target lines use the comments-readability target format (docs/features/comments-readability/design.md §1): Canvas, Frame · Payment, Element · label “Address” · in Shipping. That feature is not on main yet; until it ships, the implementation shows today's targetText in the same place. The card target line here is the comments-readability text style (--text-2, no action) wherever it cannot locate.

/design-sync compares the new elements in continue-draft, selection-gone and duplicate-id (feature design 'Draft request'). moved and no-document show shipped screens with one new row or one removed badge; their checks are the feature's tests. Copy that the feature documents do not give is labelled “draft copy” in the frame label and listed in the handoff; the implementation matches it.

Confirmed with the conductor (2026-10-25): a duplicate ID returns to the Overview as today; the sentence appears both in a toast and in a .canvas-notice band (role="status") at the top of the Overview; at restart the same sentence takes the place of the shipped restore toast, with the same band. When the band goes away is not in the feature documents; this draft proposes “when another canvas opens or the Overview is left”.

References. Sorcerer, Orca, Claude Design, ego-browser and Storybook were not checked for this draft: every element is either a shipped doan pattern (toast, canvas notice, composer helper, Activity row) or copy fixed in spec.md. Nothing is recalled from another tool.

Example data. Repository acme-web on main. Canvas “Checkout”, ID checkout, 1440 px, frames Shipping, Payment, Review. The draft comment by alex reads “The address label reads as optional. Mark the required fields and keep the hint under the input.” The agent moves doan/checkout.html to doan/flows/checkout.html.

new: reload notice, “Continues on …”, Continue on current versiondraft copy: disabled reasons

The primary slot holds a separate button, “Continue on current version” (its own React key, never the Save node), in place of Save comment. Under the tools, the notice is role="status"; the next line previews where the draft will continue. The body stays editable in every blocked state. Selection gone after reload

new: notice, Continue on canvas

A selection draft is blocked as reloaded and the current version has no selection (the agent removed the label). Continue on current version is disabled with the notice as its reason, and a secondary “Continue on canvas” continues on the whole canvas. While this blocked draft exists, clicking an element or frame in the same canvas (or the tree's Select, the ancestor path, a pin) changes the selection with no “Save your comment first?” dialog, and the body stays. Another canvas, Home, another project or Reload still ask as today. Keyboard: Tab order is textarea → Cancel → Continue on canvas → Continue on current version.

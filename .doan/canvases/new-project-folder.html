FEATURE DRAFT · new-project-folder · NOT IN CODE

New folder on the Project step

Scope: a New folder button on the local folder card of first run’s Project step and the Add Projects page (docs/features/new-project-folder/). It opens the macOS save panel; Doan creates the empty folder there and continues exactly as Choose folder does. The Choose folder panel also gains macOS’s own New Folder button (createDirectory), which is native and not drawn.

New in this draft (not in code): frames card-add-projects, card-first-run, card-busy, save-panel (native, options only), notice-exists-folder, notice-exists-file, notice-inside-project (the clone sentence reused), notice-create-failed. after-create is shipped and copied. Frames shipped-notices-choose, -url, -setup, -clone and -complete redraw every shipped Project-step notice in the new shape (actions inside; folder notices under the card) and are marked “Shipped, changed by new-project-folder”; /design-sync compares them too. /design-sync compares card-add-projects, card-busy and the four notice frames on the Add Projects page; card-first-run only by unit tests (an isolated app cannot reach first run’s Project step).

Copied from shipped screens: ProjectScreen, LocalFolderCard, projectNotice and ProjectNoticeView in app/src/renderer/Onboarding.tsx, StorageCard in StorageChoice.tsx, the .ob-*, storage and thumbnail rules of app/src/renderer/styles.css at f01ae5f16 (restated below, since canvases cannot link it), ds primitives linked in place. The glass behind first run is the wallpaper fixture of local-doan-files.html, not a measurement. Names and paths are illustrative.

Open item: the PoC (tasks 1) has not run. macOS may ask “Replace?” for an existing folder name before Doan sees the path; Doan replaces nothing, and the exists notices are written to read right after that click. The PoC also checks whether the sheet shows title.

Footer change to shipped (user decision), Add Projects page only: the footer’s right is always one button, “Add project”, in every unlocked phase, with Cancel on the left; while the page is locked (setup writing, cloning, stopping a clone) the footer stays hidden, as shipped (D3). It is enabled only when the chosen source can be added: a folder chosen or created whose check finished (to set up, or already set up), a repository URL found and cloneable, or a candidate picked; otherwise it is disabled, never hidden (the first choose screen, while checking, while a panel is open, while any notice shows). Clicking finishes the add by that path: a set-up folder or candidate is registered and the page goes Home (D1; it was added at once before); a candidate that needs setup opens the setup panel (D2); on the setup panel it sets up, with the Doan files choice shown (and the git init line, when shown) as the consent; a found repository is cloned. “Use this folder”, “Clone and add” and “Set up and add” go away, and so does the setup card’s own submit button on the page. “Find repository” stays the URL check. First run is unchanged: Open Doan on the right, “Set up and continue” inside the card.

Button sizes (spec decision 12, user decision): buttons for intermediate steps use the DS small size, data-ui-size="sm": Choose folder, New folder, Find repository, Choose another folder, Choose local folder, Edit repository URL and the other in-step actions, and every action inside a notice. The buttons that finish or leave the step keep the default size: the page’s Cancel and Add project, first run’s Back and Open Doan. The Project step is shared, so first run follows the same rule. Shipped Choose folder and Find repository were default size, so this changes them too.

Only error and status notices’ own actions move inside the notice (D4): progress rows (“Checking repository” with Cancel and the disabled Find repository, “Cloning …” with Cancel), the cancelling pair, and invalid_url’s Choose local folder / Find repository row stay screen buttons outside, as shipped. In-notice buttons all have the same weight (D5): panel on inset notices, subtle on first run’s white notices; Retry keeps data-consent. A notice’s actions are never repeated beside it (shipped repeats()).

Notice shape: Every Project-step notice now holds its actions inside it, on the right, as Project Settings’ notices do (DS .doan-notice lays out child buttons); the separate action row under the notice is gone. This changes shipped notices too: the URL and clone notices, and Choose folder’s. A notice with two or more actions stacks them on their own row at its end, --space-2 under the text, with no negative block margin so the notice keeps its full --space-3 bottom padding: a new stacked-actions variant of the DS notice (a change to a shipped component, for /design-sync). One action beside the text keeps the shipped one-row layout (frame 05). The path detail moves inside the notice as a second line.

Notice placement: Placed by source (user decision): a folder error from Choose folder, New folder or a drop sits directly under the card, in the slot the drop notice uses today, before “or use GitHub”; the drop notice and a folder error share that one slot and the later replaces the earlier; URL errors stay after the URL field. This deliberately changes shipped: Choose folder’s failure notices, now after the URL field, move under the card too.

Redesign shared by two features: this draft redesigns the shipped Project step (first run and the Add Projects page); the shipped drafts doan-onboarding.html and doan-add-projects.html are not edited. project-step-actions (merged first) owns frames card-busy and all shipped-notices-*, plus the footer, button sizes and notice shape in every frame; they are the /design-sync source until project-step-actions merges, and its /design-sync records the New folder elements (the New folder button, the card title and lead, the New-folder notices) as “comes with new-project-folder”. new-project-folder owns the New-folder frames (card-add-projects, card-first-run, save-panel, notice-exists-folder, notice-exists-file, notice-inside-project, notice-create-failed, after-create) in their project-step-actions-applied form; they are its /design-sync source until new-project-folder merges.

Focus: Every New folder notice (an error) takes focus when it appears, and Cancel in the save panel returns focus to New folder (spec decision 8); a failed Choose folder now also moves focus to its notice.

Design presets read: shape, harden, clarify (copy) and critique (the finished draft).

References: Onboarding.tsx, AddProjectsPage.tsx, projectStep.ts, styles.css, StorageChoice.tsx (checked at f01ae5f16); Electron SaveDialogOptions (message, nameFieldLabel, buttonLabel, showsTagField, createDirectory) from app/node_modules/electron/electron.d.ts (checked); NSSavePanel’s Replace prompt (recalled from macOS, unchecked).

FEATURE DRAFT · NEW BEHAVIOUR, NOT IN CODE (frames linked by data-doan-goto)

Prototype links

Child 2 of docs/features/prototype-frame-links/; decisions and copy in docs/features/prototype-link-play/ (spec, design). Three frames, all new behaviour on shipped screens: drawer-groups (the prototype window’s frame drawer in groups), link-toast (a link move and a link to a frame that can’t play), toolbar-play (the main window’s toolbar Play in every state and its drawer). /design-sync compares all three.

Copied from shipped screens: the prototype window header and panel, the frame drawer rows and the canvas toolbar from .doan/canvases/frame-prototype.html (its CSS reused as-is) and PrototypeWindow.tsx/CanvasTools.tsx; the toast is the shared doan-toast (DESIGN.md 'Toast'); the empty-drawer line is EMPTY_DRAWER in prototype/view.ts (checked 2026-11-15). The header’s right group (mode toggle, Export, conversation) is unchanged and left out. Selection marks are today’s; canvas-mark-accent restyles them separately. Example screens are mock content (.doan/assets/mock.css).

Group names: groups have no visible heading. Each group’s accessible name is “<first frame> and N more”, or “Frames without links” for the frames with no links. The playing group is shown only by its playing row’s Eye icon. All three drawers (main header, prototype window, toolbar) mark the current row with the same Eye icon.

Frame drawer in groups

Playable frames grouped by their links (child 1’s groups: links followed in either direction).

Linked groups · drawer open

The window’s frame drawer lists playable frames in groups: each group is a role="group"; a 1 px doan-menu-sep (aria-hidden) separates groups. Linked groups come first, in the document order of their first frames; then every frame without links, together in document order with no separators between them (a drawer display rule; child 1’s group calculation is unchanged). Rows keep the canvas numbers; the playing frame carries the Eye icon (screen-reader text “Playing”, aria-current="location") and holds the tab stop. Arrows, Home/End and typeahead move across groups in visual order.

Drawer open from the toolbar

The same list body as the prototype window’s drawer, above the Play button (side top, 4 px offset, 8 px collision padding). While the prototype window plays a frame of this canvas, that row carries the Eye icon (“Playing”) and holds the tab stop (here Checkout); otherwise no row has it and the first row holds the tab stop. Picking plays it; the main window’s selection, view and doan active do not change. While open, every unmodified printable key goes to the list (typeahead; V and H do not switch tools) and Esc only closes it, returning focus to Play.

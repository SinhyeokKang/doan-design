The prompt is exactly what the Doan app sends for a Home conversation's turn (built by `turnPrompt` from turn.json with the Home and handoff lines). The person dragged the `plans` canvas into the message as a canvas chip, so the request carries one canvas anchor, `{"canvas": {"path": ".doan/canvases/plans.html", "id": "plans"}}`, as `anchorData` in each place the text says `{{1}}`; the text itself never names the canvas. They ask for a new canvas, `checkout`, for the step after someone chooses Team on that canvas: the same header, footer and card style, one order summary card for the Team plan at its price, and a Pay button, with the anchored canvas left as it is. The seed also has `plans-2025.html` (a retired pricing page with another brand, price and support address), so only the anchor's path leads to the right canvas. The Home line says not to take the target from `doan active`. The handoff line asks the agent to run `doan handoff` for every new canvas in `.doan/canvases/` as its last step and to reply in one line. The fake app stands for the Home conversation and accepts the handoff; the app's later steps are not simulated.

- pass: the agent read `.doan/canvases/plans.html` (the anchor's path), drew one new canvas that carries its brand (`Northwind Cloud`), the Team price (`$24`) and its support address in the same header, footer and card style, with one order summary card and a Pay button; `plans.html` is byte-identical to the seed and nothing else changed; `doan check` is clean; the agent handed the new canvas off once as its last step with a message another agent can continue from; the final answer is one line and does not offer to open the canvas in Doan or run `doan open`. A `doan:` location link is allowed.
- partial: all automatic checks pass, but the agent did not hand the new canvas off (or handed it off with an empty or thin message, or not as its last step), the final answer is long, it offers to open the canvas in Doan, or the layout departs from the reference's style in a way the automatic checks do not see (for example, a different card shape or button color).
- fail: no read of the anchor's path (`anchor_path_read`), any change to `plans.html` (`reference_unchanged`), a change to any other file or more than one new canvas (`only_new_canvas_added`), a new canvas built from `plans-2025.html` or without the anchored canvas's brand, Team price and support address (`new_canvas_from_reference`), `doan check` errors, or `doan open`. Asking the person which canvas they meant is also a fail: the anchor names it.

Automatic checks read the transcript (Claude stream-json and the Codex commands, rollout included) only for the read of the anchor's path; everything else comes from the final repo and the fake app. `anchor_path_read` counts a Claude Read of the path, a non-`doan` command any of whose words contains `plans.html` (a path inside a `python -c` script included), and an interpreter command (`python`, `node`, `ruby`, `perl`) whose text names it, as with a heredoc script. Its limits: a glob read that never spells the path (`cat .doan/canvases/*.html`) is not counted, and a command that only names the path (`ls`, `shasum`) counts as a read; `new_canvas_from_reference` still fails a run that never read the canvas. Whether the agent understood the anchor as the canvas (rather than finding `plans.html` by name) is scored by the judge from the transcript; the text alone does not name it. The handoff is in the prompt because the app adds that line to every Doan conversation's turn; it is judged here, and measured automatically in R12.

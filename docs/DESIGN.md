### Adopted rules

- **Tokens first** (2026-10-28 user). Every app value that a token in `app/src/renderer/tokens.css` covers — color, type size/line height/tracking/weight, spacing, radius, control and icon size, shadow, motion — is written as that token in drafts, app CSS and TSX, never as a literal. Type roles are applied whole (size, line height and tracking together). A literal is allowed only when no token has that value; it is then either a component constant (one component or screen uses it, e.g. a wordmark size or a layout width) or a new token. A new token may be added at any time (2026-10-28 user) when it follows the existing rules: a purpose-named family that already exists (`--space-n` = n×4px, `--size-*`, `--radius-*`, `--type-weight-*`, a complete `--type-<role>-size/line-height/letter-spacing` set, role colors rather than palette steps), a value that does not duplicate an existing token, no change to existing tokens' values, and a line in this section's token list. Moving a literal to a token must not change the computed value; when only an approximate token exists, the change is a design decision for the user, not a silent substitution. Seen in buzz-onboarding F4: 12px text on a 20px line height looked like extra space under a title until it used caption 12/16.
- **Roles.** Code reads roles named by purpose (`surface-*`, `text-*`, `border-*`, `affordance-*`, `bg-*`), never palette steps. Text has three reading levels: `text-standard`, `text-subtle`, `text-metadata`; `text-disabled` is below the contrast targets on purpose. The primary button is the neutral prominent fill (black, white text). Status colours use the reference status roles (`text-danger`/`-warning`/`-success`, `affordance-danger`/`-warning`/`-success`, `border-danger`/`-warning`).
- **Type roles.** Size, line height, tracking and weight travel together: caption 12/16, body-sm and body 14/20, label-sm 14/20 500, label 16/24 500, body-lg 20/28, heading 24 and title 32 at line height 1.1. Regular 400 is for reading and form labels, medium 500 for actions and structure. One system sans stack; no monospace role.
- **Onboarding token additions** (2026-10-29, buzz-onboarding T1; approved 2026-10-28). `--size-chrome` 56px is the shell chrome height, `--size-control-lg` 48px is the large control height, and `--size-row` 72px is the minimum provider/project/destination row height. `--space-10` 40px and `--space-12` 48px extend the 4px spacing scale; `--type-weight-semibold` 600 covers semibold text. Existing token values stay unchanged. These tokens replace matching literals without changing computed values; the shared large button variant is implemented separately in B2.
- **Home token additions** (2026-10-29, buzz-home draft; in `tokens.css` since 2026-10-30). `--surface-accent-subtle` (violet 3) and `--text-accent-subtle` (violet 11) colour the chosen design preset chip in the Home composer. They extend the accent places of the buzz-restyle common decision 2 (PRODUCT §7, 2026-10-29). Existing token values stay unchanged.
- **Home size additions** (2026-10-29, buzz-home draft; in `tokens.css` since 2026-10-30). `--size-icon-sm` 14px is the icon inside chips, triggers and tabs; `--size-icon-lg` 20px is a project thumbnail in a picker, a provider mark in the conversation strip and a strip status icon; `--size-control-xs` 24px is the proposed `xs` icon button (a chip's remove button). They replace literals in the buzz-home draft without changing computed values.
- **Radii.** `chip` 12, `row` 16, `control` 20, `container` 24, `panel` 28px; capsules (34px) and pills are separate shapes. A nested corner is `max(0, outer − inset − border)` and is not rounded to a step (`nestedRadius`: a menu row in a 24px menu with a 4px inset and a 1px border is 19px).
- **Focus.** An outer 2px `border-focus` ring at a 2px offset on buttons, icon buttons, checkboxes and chips; the ring does not change geometry. Rows inside a scrolling list (tree rows, `.wt`, Feedback items, menu rows, Settings project rows) use an inset ring at −2px so the list does not clip it. Text fields show focus with their own border (`border-prominent`), not a ring.
- **States.** Pressed changes the fill only, never the position. Selection stays visible apart from hover. Disabled is a role (`text-disabled` on `affordance-disabled`), never `opacity`.
- **Motion.** `time-fast` 120ms, `time-state` 150ms, `time-panel-enter` 180ms, `time-settle` 220ms; `ease-enter`, `ease-settle`, `ease-state`. A dialog rises 12px over 220ms as it opens and drops 4px over 120ms as it closes (`@starting-style`, `transition-behavior: allow-discrete` on `display` and `overlay`). A tooltip that waited for its delay settles in (fade, 2px rise, scale 0.97, 2px blur); one opened instantly from a neighbour does not animate. Under `prefers-reduced-motion: reduce` the fades stay and every movement, scale and blur goes.
- **Floating material** (menus, popovers): 24px corner (16px compact), 4px list inset (2px compact), a transparent 1px border that still counts in the nested-corner arithmetic, `shadow-panel` drawing the visible edge (`CanvasText` border under forced colours). Glass (`surface-elevated-glass`, 90% white with an 8px blur) applies only under `prefers-reduced-transparency: no-preference`, outside forced colours, where `backdrop-filter` is supported; otherwise the surface is opaque. Menu rows are 32px with the derived 19px corner (13px compact). Menus are capped at 320px.
- **Dialogs.** Four widths: compact 400px, standard 640px, wide 880px, expanded 1152px. Compact is centred; the others hang 128px from the top and may grow to 16px above the window edge. 32px padding (16px in a window 480px wide or less), 28px corner, opaque `surface-popover`, 16px between parts. The header is the title over an optional description; actions sit at the end of the row, Cancel first and the completing action last. There is no Close button; Cancel and Escape close every Doan dialog. The modal scrim is `bg-scrim` (black at `#00000060`).
- **Tooltip.** A near-black capsule (`affordance-prominent`, `text-on-prominent`): caption type, 4/8px padding, corner half its one-line height (12px), no arrow, at most 384px wide with long paths wrapping.
- **Toast.** Floating material, 384px wide, 12px inset; the message and its one action share a row, the action a `prominent` sm button on the right that stays vertically centred while only the message wraps. It sits at the window's bottom right, `--space-4` (16px) from both edges, on Home and over a workspace or canvas (buzz-home, 2026-10-30; until then the message sat over its action, bottom centre, 64px up over a canvas).
- **Shared variants** (buzz-home, 2026-10-30, common decision 10: screens add variants instead of overriding shared sizes or fills). `doan-button` `quiet` (sm suggestion chip): `--affordance-backdrop-hover` fill with a `--blur-md` backdrop blur (`--affordance-subtle` without blur under reduced transparency); hover adds one inset `--affordance-backdrop-hover` layer, pressed or open one `--affordance-backdrop-pressed` layer. `doan-button` `trigger` (a value that opens a menu): 8px inline padding, no fill at rest, `--affordance-backdrop-hover` on hover and while open, `--affordance-backdrop-pressed` on press. `doan-icon-button` size `xs`: 24px (`--size-control-xs`), pill corner, 14px icon; its ink comes from the screen (a chip × is `--text-metadata`). `doan-icon-button` `accent` (Home Send): pill on `--affordance-accent` with `--text-on-accent`, hover and pressed on the accent hover/pressed roles; disabled takes the shared disabled fill, and `accent` is excluded from the ghost disabled transparent rule. A disabled `quiet` button is transparent like a ghost.
- **Scrollbars.** Native and thin (`scrollbar-width: thin`, `scrollbar-thumb-quiet` on a transparent track) through `.doan-scroll`; Radix ScrollArea stays forbidden (2026-10-22).

### Doan adjustments

- **Accent ramp.** Doan has its own violet ramp, not a reference family. Each step takes the per-step OKLCH lightness and chroma share (relative to step 9) of the reference's twelve-step light ramp whose step 9 carries white text, at hue 305, gamut-clamped by reducing chroma. Steps 1–12: `#fdfbfe`, `#fbf8fe`, `#f5f0fd`, `#efe7fa`, `#e9ddf9`, `#e2d2f7`, `#d6c1f0`, `#c7aee6`, `#973be1`, `#9033d9`, `#543871`, `#342743`; pair values: contrast and ink `#ffffff`, pressed `#8a2dd2`, link `#63019d`.
- **Why step 9 is `#973be1` with white text.** The user picked violet from a comparison of orange, magenta, iris, jade, violet, teal, cobalt and mono (2026-10-26). The earlier orange attempts failed on text: black on `#f0773a` reached only APCA Lc 50, under the body target of Lc 60, and the brighter `#ff915e` left hover and pressed almost indistinguishable from step 9. White on `#973be1` is 5.21:1 (APCA Lc −80), and hover (`#9033d9`) and pressed (`#8a2dd2`) are darker than 9, so white only gains contrast.
- **Accent places.** Before buzz-shell, violet was read by the current sidebar row (`surface-sidebar-selected` violet 9 with `text-sidebar-selected` white, including its glyphs, count and selection mark), sidebar row hover (`affordance-sidebar-hover`, violet 2), comment pins (`.comment-pin`), the comment submit buttons (`.comments-btn.primary.submit`: Save, Save and reopen, Save and continue) and the comment card roles (`surface-comment` violet 4, `text-comment` violet 12; defined, applied by `buzz-comment`). buzz-shell (2026-10-27) replaces sidebar selection/hover with neutral backdrop roles; the retained accent checks cover the remaining surfaces. Every other former accent use is neutral. buzz-onboarding (2026-10-29) adds one place: the Welcome glow `.ob-atmosphere` (accent radial gradient under a grain mask). buzz-home (2026-10-30) adds Send (`doan-icon-button` `accent`) and its spinner ink, the chosen preset chip (`.preset-chip`), the suggested prompts' group icons (`.suggestion svg`), the Home-only glow `.home-atmosphere` (a wide violet ellipse without grain), the composer drop outline (`.drop-target`) and the sidebar status slot (`.row-slot.permission`, `.row-slot.unseen i`); `accentPlaces` pins the list.
- **Black pin rim.** `border-pin` is `neutral-12` (black), not violet 11: violet 11 is 1.85:1 against the violet 9 fill, under the 3:1 non-text target, and darkening 11 enough would put it below step 12. Black is 4.03:1 against violet 9; the white `halo-pin` keeps pins visible on dark canvases. A focused pin adds the 2px `border-focus` ring and a 4px white halo.
- **No coloured edge stripes.** No message, notice, card or row uses a coloured or thick start-side border (`edgeStripes` checks it). Errors take one of three forms, each with the lucide `CircleAlert` icon so colour is not the only signal: a panel-level failure is a status block (1px `border-standard`, `radius-container`, centred 20px icon, label-sm title, body-sm `text-subtle` description, centred actions, opened detail on `surface-inset`); an inline error is a 16px icon with one body-sm `text-danger` line (`text-warning` for warnings), which adds the icon to the reference's text-only field error; a neutral notice is a `surface-inset` fill with `radius-row` and body-sm `text-subtle` (icon and `text-warning` when it warns).
- **Status pill.** `.ob-chip` is a 20px pill in caption type on the status `affordance-*` fill with the matching `text-*`. The reference has no such pill; Doan keeps it for connection and wizard status.
- **Shared dialog sizes.** The `.ob-dialog` confirmations (SetUpFolderConfirm, link replacement, Settings confirmations) and the three comment confirmations are compact and centred; Project Setup, Add Projects and Hand off are standard, 128px from the top.
- **Toast without a type.** Success, error and undo toasts share the one neutral floating toast and differ only by their text; there is no type colour and no close button.
- **Focus ring colour.** The ring is `border-focus` (`neutral-12`, black, 21:1 on white); the reference ring uses `text-standard`. Inset rings are −2px, matching the draft and the menu rows.
- **Tooltip offset.** The shared tooltip defaults to `sideOffset` 4.
- **Drop scrim.** `--bg-scrim-drop` is `color-mix(in srgb, var(--bg-scrim) 50%, black)`, which works out to black at about 69% opacity (calculated, not measured): the drop target is the whole window, so it recedes the content further than a modal scrim. Text and the dashed outline on it are `text-on-prominent`.
- **Type family.** `--type-family` (locally bundled Geist since buzz-shell, 2026-10-27, followed by the system sans stack with `Apple SD Gothic Neo`) is the role the renderer reads; `--font-sans` is only a legacy alias.
- **Light only.** `nativeTheme.themeSource = "light"` and Settings' `backgroundColor` `#f1f1f2` (`bg-app`) are set in main; buzz-shell (2026-10-27) makes main transparent with native sidebar material and an opaque reduced-transparency fallback. Main-window options are pinned by `app/src/main/index.test.ts`. The canvas iframe stays light under a dark macOS appearance by two routes: the renderer's `color-scheme: light` on the `<iframe>` element decides the canvas's `prefers-color-scheme` (B1 measured: dark on the element gives dark, light gives light, `normal` follows `nativeTheme`), and main pins `nativeTheme` light. `page.emulateMedia` cannot stand in for the OS because it overrides every frame, the canvas included, so `app/e2e/presentation.ts` drops emulation, forces `nativeTheme.themeSource = "dark"` (the app page then matches dark), and checks that the canvas still matches light live and after the iframe is recreated. Rechecked 2026-10-26 in production and DEV (see 'UX audit recovery update').

### Intended exceptions

- **Dimension label = tooltip capsule.** The canvas dimension label (`.dims`) is the same black prominent capsule as a tooltip.
- **Sidebar hover.** buzz-shell (2026-10-27) replaces the earlier violet-on-white exception with neutral backdrop fills; the final shell measurements below apply.
- **Drop scrim value** as above, darker than `bg-scrim`.
- **Below 3:1 on purpose.** The non-text 3:1 target applies to `border-prominent`, focus rings and pins only. The decorative hairline (`border-standard` `#e8e8e8`, 1.23:1 on white) and fill-edged inputs (`surface-inset` `#f5f5f6`, 1.09:1 on white) follow the reference values (2026-10-26 user).
- **Subtle buttons on inset bands (interim).** `--affordance-subtle` and `--surface-inset` are both `--neutral-2`, so a subtle button on an inset band loses its resting fill and reads as plain text until hover. Affected: the Review bar and banner (`.review-bar`, `.review-banner`), Home's status bands (`.ws-status`) and connection details (`.cn-details`: Copy, the default `.ob-chip` pill). The draft `shared-connection-rows` draws the same pairing. Changing a band's surface is a screen-layout decision: `buzz-comment` owns the Review bar and banner, `buzz-home` owns `.ws-status`; `.cn-details` sits in the shared connection rows, which a screen child changes only after asking the user (buzz-restyle spec 10).
- **`.tree-hint`** keeps 11.5px `text-metadata` and padding 2/12/6/46px against the draft's body-sm `text-warning` and 4/12/8/34px; the `.tree-detail` margin is also the tree host's. Both are left to the project-list child (`buzz-project`).
- **`.warn-mark` on the current row** turns white with the rest of the row (`text-sidebar-selected`), so the warning colour is lost there; the text mark itself stays.
- **Hand off dialog scrolls itself.** In a short window the whole dialog scrolls instead of only its list.

Measured with `/design-sync` against `.doan/canvases/buzz-ds.html` (frames `buttons`, `icon-button`, `panel`, `tooltip`, `menu`, `popover`, `dialog-sizes`, `dialog-anatomy`, `toast`, `spinner`, `forms`, `focus-disabled` for the components; `shared-project-setup`, `shared-add-projects`, `shared-first-prompt`, `shared-connection-rows`, `shared-error-details` for the shared elements). **Method.** The production build runs through Playwright `_electron` with a temporary userData and the e2e environment isolation; this checkout is added as a project and the draft is opened as a served canvas. Draft values are read inside the canvas iframe. Implementation values come from two sources: the draft component's markup inserted into the renderer page, with the draft-only state classes removed and each state created for real (pointer hover and press away from the header drag region, keyboard focus, `data-highlighted`, `indeterminate`, reduced motion, inline styles reapplied through CSSOM because the renderer CSP blocks style attributes), and real screen elements (top bar Go Home, Zoom out, Fit, Reload, the Fit tooltip, the project row menu, Project Setup, the Undo toast). Sizes are read from `offsetWidth`/`offsetHeight` so a rotating spinner is not measured by its bounding box. The inserted markup is given the class compositions the app's own markup has around it (the draft parent's app classes, `ob-dialog` on shared dialogs, `ob-card` on the connection card, `fp-field` around the subject field, `err` on the length count, `token-path` on a token value, `error` on an alert message).

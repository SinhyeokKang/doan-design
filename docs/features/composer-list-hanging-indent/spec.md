# composer 목록 hanging indent — spec

## 사용자

- **사람**: composer(Home, Overview의 docked composer, 캔버스 대화 패널, 프로토타입 창 패널)에 목록을 쓴다.
- **에이전트**: 바뀌는 것이 없다. 보내는 텍스트는 지금과 글자 하나까지 같다.

## 문제

- composer 입력란에서 목록 항목이 줄 끝에서 자동으로 줄바꿈되면, 다음 줄이 항목 본문 시작점("3. " 뒤)이 아니라 입력란 왼쪽 끝에서 시작한다(PRODUCT §5 item 1 'Lists': "the field has no hanging indent"). 긴 항목은 번호 아래로 글자가 파고들어 목록이 읽히지 않는다.
- 보낸 말풍선은 이미 줄을 본문 시작점에 맞춘다. 입력란과 말풍선의 모양이 다르다.
- 입력란이 평평한 텍스트 노드에 줄바꿈 문자를 담고, 글자 입력을 브라우저가 직접 처리해서, 줄마다 들여 맞출 수 없었다(`docs/design/canvas-conversation.md` 'No hanging indent'). Electron 프로브 결과는 `docs/BACKLOG.md` 'Undecided'에 있다.

## 완료 기준

- 네 composer 모두, 목록 항목의 자동 줄바꿈된 줄이 그 항목 본문 시작점에서 시작한다. 깊이마다, 번호 폭이 다른 항목("1. ", "10. ")마다 그 항목의 본문 시작점에 맞는다.
- 목록이 아닌 줄, 칩으로 시작하는 줄은 지금처럼 입력란 왼쪽 끝에서 줄바꿈된다.
- 마커(•, 번호)의 위치와 본문 시작점은 지금 측정값과 같다: 깊이 0에서 마커 20px, 본문 32px, 깊이마다 20px씩 더한다("1. "처럼 12px보다 넓은 번호는 그 폭만큼 본문이 밀리는 지금 규칙 그대로).
- 아래가 지금과 똑같이 동작한다(실제 Electron DOM 테스트로 확인):
  - 보내기와 복사의 텍스트가 입력한 글자와 같다(마커, 들여쓰기 공백, 줄바꿈 포함).
  - 위·아래 화살표가 자동 줄바꿈된 줄을 하나씩 지나고, 목록 항목으로 들어가고 나올 때 가로 위치를 지킨다.
  - 좌·우 화살표가 마커와 들여쓰기를 지금처럼 건너뛴다.
  - Backspace·Delete가 줄 경계를 넘을 때 줄바꿈을 정확히 하나 지우고, 본문 시작점의 Backspace는 지금처럼 마커를 지운다.
  - ⌘⌫·⌘⌦가 그려진 줄 단위로 지운다.
  - 선택 후 입력·붙여넣기·잘라내기가 줄 경계를 넘어도 텍스트가 맞다.
  - 실행 취소·다시 실행이 같은 단계로 동작한다.
  - Shift+Enter(목록 이어가기), Tab·Shift+Tab(들여쓰기)이 지금처럼 동작한다.
  - 칩이 줄 시작이나 본문에 있어도 위 동작이 같다.
- 한글 IME로 조합하는 동안과 조합이 끝날 때 텍스트가 바뀌지 않는다. 목록 줄을 걸친 선택 위에서 조합을 시작해도 줄바꿈을 잃지 않는다. 이 항목은 실제 입력기로만 확인할 수 있으므로 사람이 개발 빌드에서 확인한다.
- 최대 높이에서의 스크롤(커서가 보이게)이 줄 블록 구조에서도 동작한다.
- 새 시안의 입력란 프레임을 사람이 확정했고, 구현이 `/design-sync`로 그 시안과 일치한다.
- PRODUCT §5 item 1 'Lists', ARCHITECTURE §7(chip field, 목록 span), `docs/design/canvas-conversation.md`가 새 규칙으로 바뀐다.

## 하지 않는 것

- 굵게, 코드, 제목, 인용, 링크, 표, 체크리스트 같은 다른 Markdown 표시. 지금처럼 목록만 그린다.
- 말풍선의 목록 표시 변경.
- 글자 입력 전체를 입력란이 처리하도록 바꾸는 일. 글자 입력은 지금처럼 브라우저가 처리한다.

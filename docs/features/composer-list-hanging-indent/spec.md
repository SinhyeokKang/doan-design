# composer 목록 hanging indent — spec

## 사용자

- **사람**: composer(Home, Overview의 docked composer, 캔버스 대화 패널, 프로토타입 창 패널)에 목록을 쓴다. 네 composer는 같은 입력란을 쓴다.
- **에이전트**: 바뀌는 것이 없다. 보내는 텍스트는 지금과 같다.

## 문제

- composer 입력란에서 목록 항목이 줄 끝에서 자동으로 줄바꿈되면, 다음 줄이 항목 본문 시작점("3. " 뒤)이 아니라 입력란 왼쪽 끝에서 시작한다(PRODUCT §5 item 1 'Lists': "the field has no hanging indent"). 긴 항목은 번호 아래로 글자가 파고들어 목록이 읽히지 않는다.
- 입력란(`chipField.ts`)이 평평한 텍스트 노드에 줄바꿈 문자를 담고, 글자 입력을 브라우저가 직접 처리해서, 줄마다 들여 맞출 수 없었다(`docs/design/canvas-conversation.md` 'No hanging indent'). 줄을 블록으로 감싸면 DOM과 텍스트를 직접 맞춰야 하는 경우가 많아진다(`.scratch/composer-indent/poc-result.md`). 그래서 입력란을 ProseMirror 위에 다시 만든다(`.scratch/tiptap-poc/poc-result.md`의 D 모델).

## 완료 기준

- **줄바꿈 위치**: 네 composer 모두, 목록 항목의 자동 줄바꿈된 줄이 그 항목 본문 시작점에서 시작한다(차이 0.5px 이하). 번호 폭이 다른 항목("9. ", "10. ", "100. ")은 각자 자기 본문 시작점에 맞는다. 한 목록을 가장 넓은 번호에 맞추는 말풍선과 다르며, 이는 의도한 차이다(입력 중에 항목이 늘거나 줄어도 다른 항목의 줄이 움직이지 않게).
- **깊이**: 깊이 상한을 두지 않는다. 깊이마다 본문 시작점이 20px씩 밀리고, 깊은 항목은 좁은 composer에서 줄바꿈 폭이 좁아진다(사람이 정했다).
- **마커와 본문 위치**: 깊이 0에서 마커 x 20, 본문 x 32, 깊이마다 20px씩 더한다(12px보다 넓은 번호는 그 폭만큼 본문이 밀리는 지금 규칙 그대로). 깊이 0 항목 앞에 입력한 공백은 폭이 0이고, 항목 아래 세 칸 들여쓴 줄은 지금처럼 깊이 1이다. 입력한 깊이 공백이 두 칸이든 네 칸이든 같은 깊이면 같은 x에 놓인다.
- **줄 시작 커서**: 목록 항목의 줄 시작(마커 앞)에 둔 커서는 모든 깊이에서 마커 앞에 그려진다(깊이 0 x 20, 깊이 1 x 40, 깊이 2 x 60). 지금 중첩 항목의 x 0 규칙을 바꾼다(사람이 정했다).
- **목록이 아닌 줄**: 목록이 아닌 줄, 칩으로 시작하는 줄, 들여쓴 일반 줄은 지금처럼 입력란 왼쪽 끝에서 줄바꿈된다.
- **구조 변화**: "1. "을 입력해 일반 줄이 항목이 되거나 마커를 지워 항목이 일반 줄이 되면, 그 줄의 줄바꿈 위치가 바뀌고 입력란 높이가 달라질 수 있다. 애니메이션 없이 바로 바뀌고, 실행 취소가 이전 모양으로 되돌린다. 이는 의도한 동작이다.
- **텍스트**: 보내는 텍스트는 지금과 같다(앞뒤 빈 줄을 지우는 규칙 포함). 복사 `text/plain`은 입력한 글자와 같다(마커, 들여쓰기 공백, 줄바꿈 포함). CDP의 textbox 값은 빈 줄을 뺀 나머지에서 입력한 글자와 같다(• 없음). Look Up과 선택 텍스트가 칩 화면 읽기 텍스트를 끼워 넣지 않고, 줄 사이에 줄바꿈을 더하지 않는다.
- **편집**(실제 Electron DOM 테스트로 확인):
  - 위·아래 화살표가 자동 줄바꿈된 줄을 하나씩 지나고, 목록 항목으로 들어가고 나올 때 가로 위치를 1px 안에서 지킨다. 마지막 항목의 마지막 줄에서 ↓가 지금처럼 동작한다.
  - 좌·우 화살표가 마커와 들여쓰기를 지금처럼 건너뛴다. ⌥←가 지금처럼 단어 단위로 움직인다.
  - ⌘←/⌘→와 Shift+⌘←/⌘→가 줄바꿈된 줄의 시작(본문 시작점)·끝에서 멈춘다.
  - Shift+↑/↓, 마우스 드래그, 세 번 클릭, 두 번 클릭의 선택이 지금의 일반 줄과 같은 결과를 낸다(세 번 클릭 뒤 입력, 두 번 클릭이 숨긴 줄바꿈을 포함하지 않음).
  - Backspace·Delete·⌥⌫·⌥⌦·⌃K·⌃H·⌃D가 줄 경계를 넘을 때 줄바꿈을 정확히 하나 지운다. ⌘⌫·⌘⌦가 그려진 줄 단위로 지운다(둘째 줄에서의 결과 포함).
  - 본문 시작점의 Backspace는 한 단계 내어 쓰고, 깊이 0에서는 마커를 지운다. 줄 시작(마커 앞)에 입력하면 그 줄이 일반 줄이 된다.
  - 선택 후 입력·붙여넣기(여러 줄 포함)·잘라내기·⌃T가 줄 경계를 넘어도 텍스트가 맞다. ⌘A 뒤 입력·Backspace도 맞다.
  - 실행 취소·다시 실행의 단계가 지금과 같다. 줄 경계를 넘는 삭제는 칩이 없으면 앞뒤 글자 입력과 한 단계로 묶이고, Shift+Enter(목록 이어가기), Tab·Shift+Tab(들여쓰기), 본문 시작 Backspace는 각각 한 단계다. 일반 줄 ↔ 항목 구조가 바뀌는 편집도 실행 취소로 되돌아간다.
  - 칩과 스킬 강조가 줄 시작, 본문, 줄바꿈된 줄에 있어도 위 동작이 같다. 칩으로 시작하는 줄바꿈 줄은 본문 시작점에 놓인다.
  - 맞춤법 제안(`insertReplacementText`)이 항목 안에서 구조를 깨지 않는다.
  - 이모지·서로게이트 쌍·ZWJ가 줄 경계에 있어도 삭제 범위가 맞다. 끝에 줄바꿈이 있는 항목, 마지막 빈 줄의 커서, 긴 단어(`overflow-wrap: anywhere`)의 줄바꿈이 맞다.
- **IME**(사람이 실제 한글 입력기로 개발 빌드에서 확인):
  - 목록 항목 안 조합에서 조합한 글자가 빠지거나 겹치지 않는다. 조합 중 Shift+Enter·Tab, 조합 중 Enter로 보내기가 지금처럼 동작한다.
  - 목록 줄을 걸친 선택 위에서 조합을 시작하면, 결과는 선택한 글자만 지우고 조합한 글자를 넣은 텍스트와 같다(예: "- ab\n- cd"에서 "b\n- c"를 선택하고 '한'을 조합하면 "- a한d"). 선택 밖의 줄바꿈은 남는다. 실행 취소 한 번에 원래 텍스트로 돌아간다.
  - 걸친 선택이 있는 상태에서 ⌘C, Shift+→, Esc는 아무것도 지우지 않는다.
  - 걸친 선택 위 조합이 실패하면 BACKLOG 'Known defects'에 재현 조건을 남긴 채 출시한다(사람이 정했다).
- **받아들인 차이**(두 PoC 모두에서 남았고 사람이 받아들였다. PRODUCT·design 문서와 BACKLOG 'Known defects'에 기록한다):
  - ⌥→가 줄 끝에서 다음 줄로 넘어갈 때 다음 줄의 줄 시작과 본문 시작에서 한 번씩 더 멈춘다. 구현 중 keymap으로 지금 동작에 맞출 수 있으면 맞추고, 안 되면 기록한다.
  - CDP textbox 값(스크린리더가 받는 값)에 빈 줄마다 줄바꿈이 하나 더 들어간다. 보내는 텍스트와 복사 텍스트는 정상이다.
- **기타**: 최대 높이에서 커서가 보이도록 스크롤하는 동작(`revealCaret`)이 줄 블록 구조에서도 동작한다. placeholder(입력란이 완전히 빌 때만)와 읽기 전용 입력란은 지금과 같고, 읽기 전용에서도 선택·복사가 된다. 입력란 폭이 좁아져도(프로토타입 창 패널) 줄바꿈 위치가 맞다.
- **의존성**: ProseMirror 패키지를 앱 런타임 의존성으로 정확한 버전에 고정해 추가한다(사람이 요청했다). 번들은 gzip 약 55KB 늘어난다.
- **호스트 인터페이스**: 네 composer가 쓰는 입력란 API(`setValue`, segment, `insertChip`·`insertSkill`·`insertText`, `composing()`, 포커스, `onChange`, 메뉴 실행 취소용 `data-chip-field`)는 그대로라 호스트 코드는 바뀌지 않는다.
- **시안·문서**: 새 시안의 입력란 프레임을 사람이 확정했고, 구현이 `/design-sync`로 그 시안과 일치한다. PRODUCT §5 item 1 'Lists', ARCHITECTURE §7 chip field, `docs/design/canvas-conversation.md`가 새 규칙으로 바뀐다.

## 하지 않는 것

- 굵게, 코드, 제목, 인용, 링크, 표, 체크리스트 같은 다른 Markdown 표시.
- 말풍선의 목록 표시 변경. 기존 말풍선 테스트와 `plainTitle` 테스트는 그대로 통과해야 한다.
- 목록을 구조(`ul/ol/li`)로 바꾸는 일. 마커와 깊이는 지금처럼 입력한 텍스트로 남는다(PRODUCT 'Lists': the text stays ordinary text).
- TipTap 같은 ProseMirror 위 상위 라이브러리.
- 오른쪽에서 왼쪽으로 쓰는 글(RTL).
- 깊이 상한.

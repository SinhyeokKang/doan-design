# 프로토타입 작성 계약 — spec

## 사용자

- **에이전트**(주 사용자): `data-doan-prototype`를 단 프레임을 만드는 에이전트. 가이드(`doan skill`)와 `doan check`만 보고도 캔버스 보기, 재생, 창 크기 변화에서 같은 프레임이 어떻게 놓이는지 알고, 한 번에 맞는 레이아웃을 쓴다.
- **사람**: 직접 쓰는 것은 없다. 에이전트가 짐작으로 여러 번 고치는 일이 줄고, 큰 모니터나 Responsive 모드, 휴대폰 브라우저에서 연 export 파일에서도 헤더 고정과 내부 스크롤이 있는 앱 화면이 재생된다.

## 문제 (관찰)

에이전트가 프로토타입을 만들면서 남긴 피드백과 코드 확인 결과다.

1. **재생 중 크기 규칙이 가이드에 없다.** 가이드 규칙 14는 "The frame fills the viewport and elements outside it are hidden" 한 줄뿐이다.
   - 실제 재생에서 프레임은 `width:100%; min-height:100vh`를 받고 height는 정해지지 않는다. 조상 요소도 `height:auto`가 된다(`app/src/main/prototypeScript.ts`, `cli/internal/export/viewer/isolate.js`). 그래서 프레임 안의 `height:100%`는 기준이 없어 풀리지 않는다.
   - WxH는 첫 viewport 크기다. Fit 모드는 그 크기를 viewport로 두고 축소만 하고, Responsive 모드와 export 파일은 창을 채운다. 이것도 가이드에 없다.
   - 결과: 에이전트가 레이아웃을 네 번 바꿨고, 마지막에는 "프레임이 (0,0)에 있으면 재생 중"이라는 추측 스크립트로 창 크기를 직접 맞췄다.
2. **창 높이에 맞춘 앱 레이아웃을 쓸 수단이 없다.** 규칙 11은 vh를 금지한다. 보드에서 vh가 보드 전체 높이로 풀려 캔버스 높이가 자기 자신을 쫓기 때문이다. 그런데 헤더 고정과 내부 스크롤을 쓰는 실제 앱 레이아웃(`height:100vh`)을 픽셀로 바꾸면, 재생 창이 커져도 그 높이에 고정된다. `doan check`의 `viewport_height_unit` 메시지도 "Use a pixel value instead."라고만 한다.
3. **프레임 안 상호작용 안내가 없다.** 토글, 모달, 토스트, 목록 추가·삭제를 스크립트로 만들 때 다음을 짐작했다.
   - 모달 위치
   - 실행 중에 복제한 요소의 `data-doan-id` 중복
   - 프레임이 여러 개일 때 스크립트 범위
   - 재생을 다시 시작하면 상태가 초기화되는지
4. **캔버스용 설명 상태와 재생 시작 상태가 섞인다.** 정적 프레임에 펼쳐 둔 툴팁을 재생 때문에 없애자 캔버스에서도 사라졌다.
5. **WxH를 무엇으로 정할지, 상호작용 범위를 어디까지 만들지 안내가 없다.** 에이전트는 1440×1280을 1440×960으로 바꿨고, 범위가 정해지지 않은 채 작업이 커졌다.

## 완료 조건

1. **높이 변수**
   - 재생 문서(프로토타입 창의 Fit·Responsive, export한 프로토타입 파일)의 `:root`에 `--doan-viewport-height`가 정해진다. 값은 `100vh`이고, `100dvh`를 지원하는 브라우저에서는 `100dvh`다.
   - 그 밖의 표면(보드, 캔버스 export 뷰어, 썸네일)에서는 정하지 않는다.
   - 재생 중 body에 붙인 요소도 같은 값을 받는다.
2. **가이드 규칙 14**는 다음을 말한다.
   - WxH는 대상 화면의 viewport다(예: 데스크톱 1440x900, 모바일 390x844). 내용 높이가 아니다.
   - 재생 배치: 프레임은 viewport 너비를 채우고 높이는 최소 viewport 높이다. 확대는 없다. Fit은 WxH를 viewport로 두고 넘치면 축소만 하며, Responsive와 export 파일은 창을 채운다.
   - 창 높이에 맞추는 레이아웃은 프레임이나 앱 루트의 `height`를 `var(--doan-viewport-height, <H>px)`로 쓰고, 대체값은 WxH의 H다. 캔버스와 썸네일은 대체값으로 WxH 화면 크기를 보여주고, 재생은 창 높이를 따른다.
   - 이 변수는 Doan이 정한다. 캔버스가 직접 정의하지 않는다.
3. **가이드 규칙 11**은 표시된 프레임에서 vh 대신 쓸 수단으로 규칙 14를 가리킨다. vh 금지는 그대로다.
4. **`doan check`**
   - `--doan-viewport-height`를 정의되지 않은 토큰(`undefined_token`)으로 보고하지 않는다. 링크된 스타일시트를 포함한 전체 범위에 적용한다.
   - 캔버스 자신의 스타일(`<style>`과 `style` 속성)에서 대체값 없이 쓰면 경고한다(새 코드 `viewport_height_no_fallback`). 그대로 두면 보드와 썸네일에서 그 높이가 풀리지 않는다.
   - `viewport_height_unit` 메시지가 표시된 프레임에서는 이 변수를 쓰라고 가리킨다.
5. **상호작용 패턴**: 가이드에 권장 패턴으로 들어간다. 재생 창에서 캔버스 스크립트가 동작한다는 보장으로 쓰지 않는다(PRODUCT §5 item 2 'Prototype window').
   - 모달과 토스트는 프레임 기준 `position:absolute`로 프레임 안에 둔다(프레임은 `position:relative`).
   - 스크립트는 자기 프레임 요소 안에서만 찾고 바꾼다.
   - 실행 중에 만든 요소에는 `data-doan-id`를 달지 않는다.
   - 재생을 시작할 때마다 문서를 새로 읽으므로 상태가 초기화된다.
6. **상태 분리**: 재생 프레임은 기본 상태에서 시작하고, 설명용으로 펼친 상태(열린 툴팁, 모달)는 별도 프레임으로 둔다.
7. **범위 확인**: 요청이 말한 상호작용을 만들고, 범위가 결과를 바꿀 때만 묻는다. 끝낼 때 동작하지 않는 상호작용을 말한다(가이드의 기존 질문 기준 "ask only about ambiguity that changes the result"와 같다). 한 번에 끝내는 요청에서 질문하느라 멈추지 않는다.
8. 조건 2·3·5·6·7의 문장은 가이드 계약 테스트로 고정한다. 가이드 출력 예산 테스트(`skillOutputBudget`)도 통과한다.
9. 기존 프로토타입(변수를 쓰지 않는 캔버스)의 재생은 지금과 같다. 프레임의 `min-height:100vh` 규칙은 바뀌지 않는다.

## 범위 밖

- 재생 상태 스크린샷 명령(`doan screenshot … --prototype`)과 검증용 export 허용: 새 CLI 기능이다. BACKLOG에 남긴다.
- 재생 중 외부 링크 동작("do nothing"): PRODUCT 결정이다. 바꾸려면 따로 정한다.
- 재생 중임을 알리는 공개 속성(`data-doan-playing` 등): 두지 않는다(사용자 결정). 내부 속성 `data-doan-proto-*`는 계약이 아니다.
- 재생 시작 상태를 지정하는 속성(`data-doan-prototype-start` 등).
- 캔버스가 변수를 직접 정의하는 경우의 `doan check` 규칙. 가이드 문장으로만 막는다.
- 대체값이 WxH의 H와 같은지 `doan check`로 검사하는 일. CSS 선택자와 프레임을 정적으로 이을 수 없다.

# 코드베이스 감사 1라운드

2026-11-20, `develop`의 `e5f4318967f0a64bd4dc9922ea8251ff399dfb29`에서 시작했다. 당시 추적 파일 변경은 없었다. 계약·경계·수명주기·회귀 방지 담당자 네 명의 검토와 Go·renderer·main·배포·eval 보충 검토를 마쳤다. 아래 항목은 정적 검토 결과다. 이 라운드에서 실행 재현이나 수정 검증은 아직 하지 않았다.

## 판정과 실행 한계

- 높음은 A02다. 마지막 응답을 썼어도 종료 알림이 먼저 전달되면 정상 대화 턴이 실패로 끝난다. 수명주기 담당자가 종료와 출력 소비 순서를 추적했다.
- 중간은 A01·A03·A04·A05·A06·A07·A10이다. 경계 담당자가 eval 입력을, 계약 담당자가 inspector와 인증 응답을, 수명주기 담당자가 프로젝트 제거를, 회귀 담당자가 검색·테스트 제한 시간·메뉴 전환을 확인했다. A09는 실패 때만 발생하는 정리 누락으로 낮음이다.
- A01~A07 및 A09~A10은 기존 계약을 복구하거나 내부 검증을 고치는 배치에 넣었다. A08은 실제 비활성 창에서 재현한 경우에만 고친다. 정책 변경이 필요한 확정 항목은 없어 이번 감사에서 BACKLOG에 추가한 항목은 없다.
- 실행으로 확인하지 않은 후보도 있다. 프레임의 스크롤 영역 밖 텍스트가 측정 범위에 포함되는지, 파일 서버의 초기 연결 취소가 핸들을 남기는지, Go 링크 그룹 중복 순회가 실제 지연을 일으키는지는 미확인이다. Go onboarding은 완료 작업 20개를 보관하지만 각 검사의 후보 경로 수는 제한하지 않는다. `onboarding/projects.ts`와 `operations.ts`에서 만든 상태 응답이 Go `active.go`의 64KiB 한도를 넘을 수 있다. 어느 작업의 후보를 계속 제공해야 하는지까지 포함해 확인할 대상으로 남겼다.

추가 확인이 필요한 후보는 서버가 파일 정보를 기다리던 중 연결이 끊긴 경우의 핸들 정리와, Go의 프로토타입 링크 그룹 계산에서 중복되는 전체 프레임 순회다. 전자는 파일 소유권이 넘어가는 순서, 후자는 실제 비용을 확인해야 한다. CLI 런타임 파일을 검사한 직후 파일 종류가 바뀌는 경우는 ARCHITECTURE §4에 명시된 허용 제약이어서 수정 대상에서 제외했다.

보충 검토에서 다음 근거를 확인했다.

- A02와 같은 순서가 `agentAuth/manager.ts:749`의 Codex 이메일 조회에도 있다. 이 경우 연결은 유지되지만 마지막 응답을 놓치면 이메일이 표시되지 않는다.
- A03과 관련해 `app/src/renderer/homeRun.ts:328`은 Edit on Home의 첨부를 다시 발급한 뒤 화면이 바뀌면 결과를 폐기한다. 이때 이미 발급한 핸들을 반환하지 않는다. 복구에 필요한 provider가 사라진 분기도 같은 검증이 필요하다.
- A05. `app/src/renderer/quickOpen.ts:126`과 `:141`이 앞 문자를 UTF-16 한 단위로 읽는다. `𠮷art`에서 `art`는 단어 중간이지만 두 번째 서로게이트를 구분자로 판단한다. PRODUCT §5의 검색 순위와 일치하도록 실제 단어 시작인 `x art`와의 정렬·강조를 함께 검증한다.
- A06. `cssomMatched.test.ts`, `WorktreeSwitch.dom.test.ts`, `chipField.dom.test.ts`, `ConversationThread.lists.dom.test.tsx`는 훅에만 별도 제한 시간을 둔다. 테스트 본문은 기본 20초이며, DOM 로드 하나에 최대 15초를 쓰는 테스트가 후속 입력을 기다리다 시간이 끝날 수 있다. 10월 회고의 11월 19일 재발 기록은 이러한 테스트 본문에 60초를 배정한다. 이번 실행에서 CI 실패를 재현한 것은 아니다.
- A07. `app/src/renderer/WorktreeSwitch.tsx:39`은 메뉴를 연 순간 이동할 수 있던 행만 기억한다. 열어 둔 메뉴에서 목록 읽기가 끝나 새로 이동 가능해진 캔버스가 사라지면 `:65`가 클릭을 버려 PRODUCT §5의 알림이 나오지 않는다. 두 상태 전환을 한 테스트에서 이어서 검증한다.
- A08. `app/src/renderer/App.tsx:538`이 프로젝트 문제 화면의 제목에 직접 포커스를 준다. 창이 비활성인 동안 기존 포커스 대상이 가려질 때, 다시 활성화된 창에서 제목 포커스를 보장하지 않는다. 이전 macOS 회고의 재발 가능성이며 실제 창의 포커스 전환 결과는 미확인이다.
- A09. `eval/run.ts`는 self-test용 임시 디렉터리를 만들고 Go 빌드에 실패하면 정리용 `finally`에 진입하기 전에 반환한다. 또한 증거 보존 오류를 기록하는 쓰기까지 실패하면 `ws.dispose()`를 건너뛴다. 작업 디렉터리·fake app 정리를 항상 수행하는지 오류 경로에서 확인한다.
- A10. `app/src/main/agentAuth/ipc.ts:142`가 같은 provider의 도구 검사 결과를 완료 순서대로 저장한다. 먼저 시작한 검사가 시간 초과로 끝나면 그사이 성공한 Retry 결과를 덮어쓴다. 두 결과를 역순으로 반환해 최신 버전과 기존 호환성 판정이 유지되는지 검증한다.

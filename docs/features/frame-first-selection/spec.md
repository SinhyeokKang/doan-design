# 프레임 우선 선택

## 순서와 사용자

다섯 기능 중 2번이다. 앞은 `folder-attachments`, 뒤는 `canvas-rendering-stability`이다. 사람의 Select 선택 흐름을 바꾸며 에이전트는 기존 `doan active`로 현재 선택을 읽는다. 4번 `frame-prototype`이 이 선택 흐름을 사용한다.

## 문제

현재 Select는 클릭한 요소나 프레임을 곧바로 선택한다(PRODUCT §5 item 4). 프레임 전체를 먼저 고르고 그 안의 요소로 좁혀 들어가는 단계가 없다.

## 확정 동작과 완료 조건

1. 첫 클릭은 프레임을 선택하고, 같은 프레임의 다음 클릭부터 내부 요소를 선택한다. 더블클릭을 요구하지 않는다.
2. 중첩 프레임은 바깥부터 클릭마다 한 단계씩 진입한다. 아직 진입하지 않은 프레임의 내부 요소로 건너뛰지 않는다.
3. Esc는 요소 → 소속 프레임 → 바깥 프레임 → 전체 해제 순서로 한 단계씩 돌아간다. 프레임 밖 노트는 바로 선택하고 Esc로 해제한다.
4. 다른 프레임을 클릭하면 이미 진입한 공통 조상은 유지하고 그 아래의 새 대상 프레임을 먼저 선택한다. 다른 최상위 프레임은 그 프레임부터 시작한다. 프레임 자신의 배경을 클릭하면 그 프레임을 선택하고, 내부의 빈 div 등은 요소로 선택한다. 모든 프레임 밖 빈 공간은 전체 해제한다.
5. 가리킴 강조는 다음 클릭으로 선택할 대상을 보여준다. `doan active`와 화면의 선택은 일치한다.
6. 대화용 Picker는 기존 동작을 유지한다. 프레임·요소·Shift 점 칩을 바로 넣으며, Select의 진입 단계를 공유하지 않는다.
7. 기존 Hand·Option-click·Locate·새 캔버스로 이동·재로드의 역할을 보존한다. 재로드에서 선택 노드를 기존 anchor 규칙으로 복구한 뒤 현재 DOM의 조상 프레임을 다시 계산한다. 선택 요소의 부모가 바뀌어도 복구된 선택은 유지한다. 사라진 선택은 기존 소실 안내로 처리한다.
8. 프레임 서랍은 이동과 해당 프레임 선택을 함께 수행한다. 중첩 프레임도 직접 선택하고 다음 클릭부터 내부로 진입한다. Esc는 현재 바깥 프레임으로 돌아간다. Quick Open·Locate는 기존처럼 선택을 바꾸지 않는다. 서랍 자체에서 프로토타입을 실행하지 않는다.
9. Select의 ⌘클릭은 프레임 단계를 건너뛰고 포인터의 선택 가능한 DOM 대상 하나를 직접 선택한다. ⌘를 누른 hover도 그 대상을 보여준다. 이후 일반 클릭·Esc는 선택 대상의 현재 소속 프레임을 기준으로 이어간다. Option을 함께 누르면 기존 캔버스 조작을 우선한다. Picker·Hand·Capture·Space 드래그 동작은 유지한다.

## 상태 전이

| 현재 상태와 입력 | 결과 |
|---|---|
| 선택 없음, A 안 B 안 요소 클릭 | A 선택 |
| A 선택, B 안 요소 클릭 | B 선택 |
| B 선택, B 안 요소 클릭 | 요소 선택 |
| A 안 B의 요소 선택, 형제 C 내부 클릭 | A는 유지하고 C 선택, C 내부 요소는 다음 클릭 |
| B 내부 요소 선택, B 자신의 배경 클릭 | B 선택 |
| B 내부 요소 선택, A 자신의 배경 클릭 | A 선택 |
| 어떤 선택에서든 다른 최상위 D 내부 클릭 | D 선택 |
| 프레임 밖 노트 클릭 | 노트 선택, 이전 프레임 진입 기준 폐기 |
| 요소 선택 후 Esc | 현재 소속 프레임 선택, 다음 Esc는 조상 프레임을 거쳐 해제 |
| Hand·Picker 시작, 캔버스 전환, 빈 공간, 선택 소실 | 선택과 진입 기준 모두 해제. Picker 종료 후 복원하지 않음 |
| ⌘클릭으로 내부 요소 직접 선택 | 대상 요소 하나 선택, Esc는 현재 소속 프레임 선택 |
| 포인터 정지 상태에서 선택·Esc·⌘누름/해제 | 다음 클릭 대상 hover를 즉시 다시 계산 |

## 비목표

Inspector 복원, 다중 선택, 드래그 선택, 캔버스 내용 편집, Picker 개편, 가려진 요소 순환 선택, 중첩 iframe 내부 선택 확대는 하지 않는다.

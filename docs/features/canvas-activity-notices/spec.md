# 캔버스 변경 Dot과 대화 종료 표시

## 순서와 사용자

다섯 기능 중 5번이다. 앞은 `frame-prototype`이다. 사람은 사이드바에서 캔버스 변경과 읽지 않은 대화 종료를 구별하고, 캔버스와 읽음 메타데이터를 다른 머신으로 함께 옮긴다.

## 문제와 증거 수준

현재 버디 accent 색의 Dot이 캔버스 생성·변경과 읽지 않은 대화 종료를 모두 뜻한다(PRODUCT §5 item 1). 캔버스 읽음 기록은 로컬 `canvas-seen.json`에 루트·경로·mtime으로 저장한다. `app/src/main/shell.ts`는 캔버스 HTML 자체의 mtime을 읽고 `canvasSeen.ts`가 비교한다.

사용자는 읽기만 한 작업이나 공유 CSS·에셋 수정 후 Dot이 대량 발생했을 가능성을 보고했다. 실제 재현은 하지 않았으며 공유 파일 변경이 직접 원인이라고 확정하지 않는다. HTML 재저장, 목록 재조회, 기존 미읽음, 대화 종료 표시를 분리해서 조사한다.

## 확정 동작과 완료 조건

1. 버디 accent 색의 Dot은 새 캔버스 또는 마지막으로 확인한 때와 HTML 내용이 다른 캔버스에만 쓴다. mtime만 바뀐 저장, 단순 읽기, CSS·이미지 등 참조 파일만 변경한 경우는 켜지 않는다.
2. 읽지 않은 대화 종료는 사이드바·Show sidebar·접힌 대화 패널 버튼 모두 말풍선 아이콘으로 표시한다. 각 표시의 기존 집계 범위와 답변 요청 → 작업 중 → 읽지 않은 대화 종료 → 캔버스 변경 Dot의 우선순위를 유지한다. 오류·터미널 작업 등 다른 기존 우선순위는 변경하지 않는다. Show sidebar에 캔버스 변경 Dot·저장 오류를 새로 집계하지 않는다.
3. 대화 종료를 읽어도 캔버스 변경을 아직 안 봤다면 Dot은 남는다. 두 읽음 상태는 독립이다.
4. 캔버스 읽음 상태는 HTML 밖의 별도 메타데이터로 함께 이동한다. 사람을 구분하지 않고 캔버스별 마지막 확인 내용을 공유한다. 다른 사람이 받은 기록도 동일하게 적용한다.
5. 메타데이터를 함께 옮겼고 HTML 내용이 같다면 머신·절대 경로·mtime이 달라도 Dot이 켜지지 않는다. HTML 내용이 다르면 켜진다.
6. 캔버스 화면에 실제 표시했을 때 읽음 처리한다. 열어 둔 동안 변경도 읽음 처리한다. Overview 썸네일과 프로토타입만 보는 경우는 제외한다.
7. 메타데이터가 없는 프로젝트를 처음 등록하면 기존 캔버스는 읽음으로 시작한다. 그 뒤 새로 생긴 캔버스에는 Dot을 켠다. 함께 온 메타데이터가 있으면 기록된 내용과 비교한다. 최초 baseline 저장 실패는 기존 캔버스에 새 Dot을 만들지 않고 실패·Retry 토스트로 안내한다.
8. 기존 미읽음의 공유 읽음 저장 실패 시 저장 성공 전까지 Dot을 유지한다. 열람을 막지 않고 실패 이유와 Retry가 있는 일시적인 토스트를 제공한다. 로컬 기록만으로 성공한 것처럼 숨기지 않는다. 이미 본 캔버스의 실패 Dot은 ‘변경 후 안 봄’ 대신 읽음 상태를 저장하지 못했다고 설명한다.
9. 기존 Doan 파일의 Git 제외 정책을 따른다. 제외한 프로젝트는 캔버스와 메타데이터를 함께 복사한 경우에만 기록이 이동한다. Doan이 Git 명령이나 서버 동기화를 실행하지 않는다.
10. 기존 로컬 기록의 최초 전환에서는 현재 캔버스 변경 Dot을 보존하고, 나머지는 현재 HTML의 읽음 지문을 기록한다. 이 전환에서만 기존 mtime 판정을 사용하고 이후에는 내용 지문으로 비교한다. 대화 종료 Dot은 별도 대화 기록이므로 캔버스 미읽음으로 변환하지 않는다.
11. 등록 후 공유 메타데이터가 삭제·손상됐거나 읽기 실패·미지원 버전이면 마지막 판정을 유지하고 오류·Retry 토스트로 안내한다. 기존 판정이 없으면 변경이라고 추측해 Dot을 만들지 않는다. 정상적인 첫 등록으로 간주해 자동 읽음 초기화하지 않는다.
12. 프로젝트 등록 해제·일시 목록 실패·캔버스 이동·일시 소실로 공유 읽음 기록을 자동 삭제하지 않는다. 저장소의 기록은 앱 목록과 독립적으로 남는다.
13. 캔버스 ID가 없거나 중복돼 대상을 확정할 수 없으면 공유 저장을 보류하고 ID 수정 후 처리한다. 경로나 추측한 ID로 대신 저장하지 않는다.

## 오류 복구와 표시

- 토스트가 사라진 뒤에는 해당 캔버스를 다시 열거나 프로젝트에 재진입할 때 읽기·저장을 다시 시도한다. 실패하면 Retry 토스트를 다시 보여준다. 같은 화면에서 반복 토스트나 자동 재시도 루프를 만들지 않는다.
- Retry 중에는 진행 상태를 알리고 중복 실행을 막는다. 실패하면 이유와 Retry를 유지하고 성공하면 토스트를 제거한다. 사라지는 Retry에 포커스가 있었을 때만 캔버스 영역 또는 Overview의 안정된 기존 컨트롤로 돌린다. 다른 포커스는 빼앗지 않는다.
- 실패 Dot의 tooltip·행 접근성 설명은 읽음 상태 저장 실패를 명시한다. 메뉴 버튼이나 더 높은 우선순위 신호가 Dot을 가려도 실패 상태를 잃지 않는다.
- 손상·삭제·미지원 버전은 기록 복구 또는 호환 버전 사용 후 Retry로 다시 판정한다. Retry가 손상 기록을 초기화하거나 덮어쓰는 기능은 아니다.

## 비목표

개인별 계정·읽음 동기화 서버, 의존 CSS·에셋의 변경 Dot, 캔버스 HTML에 읽음 속성 쓰기, 프레임별 읽음 기록은 만들지 않는다.

# 구현 순서와 검증

각 단계는 앞 단계의 검증 결과를 이어받는다. 최신 develop에서 시작한다. 앱 기준과 비교할 때 같은 캔버스에 재생 가능한 프레임, 중첩 프레임, 링크, 일반 입력, 잘못된 마크, 스크립트로 생긴 프레임을 넣는다.

| 순서 | 작업과 커밋 경계 | 검증 |
|---|---|---|
| 1 | 브라우저 PoC. 일반 Export 파일 하나로 새 창을 열어 격리된 프레임을 재생하고 연결된 단독 HTML을 저장한다. 실험물은 .scratch에 둔다. | 저장소 밖 임시 디렉터리에서 Chromium·WebKit으로 실제 파일을 연다. 팝업 허용·차단·재시도, 창 재사용, 다운로드한 파일의 오프라인 링크 이동을 기록한다. 보드 탭을 닫은 뒤 재생창에서 입력하고 링크로 다른 프레임으로 이동한 다음, 그 프레임을 내려받아 열 수 있어야 한다. 브라우저별 차이나 미검증 항목은 구현 전에 보고한다. |
| 2 | 시안 확정. feature-review 후 design.md에 지정한 보드·서랍·재생·복구 상태를 그린다. | 설치된 CLI로 `doan check --repo . --json`과 `doan ls --repo . --json`을 실행한 뒤 앱에서 사용자가 시안을 확인한다. |
| 3 | TDD. 기존 마크·링크 fixture에 선택과 재생 대상, 서랍 그룹, 기록·모드, 내보내기 거절 사례를 연결하고 앱 결과와 Export 결과를 비교한다. 공개 스키마 변경은 없다. 테스트를 먼저 커밋한다. | `go test ./...`와 `npm --prefix app test`에서 의도한 새 단언이 실패하고 기존 앱 기준은 통과하는지 확인한다. |
| 4 | 일반 Export 조립. 원본 리소스는 한 번만 담고, 보드·재생기·개별 Export가 필요한 정적 프레임과 링크 정보를 전달한다. 이 단계에서 조립 변경을 커밋한다. | `go test ./...`로 CLI 출력 계약, 일반·단독 파일 구분, 50 MiB 경계, 링크 그룹, 중복·긴 ID, 이스케이프, 기존 단독 파일 호환을 확인한다. |
| 5 | Select와 보드의 재생 진입점. 인스펙터에서 선택을 분리하고 앱의 버블, 툴바, 서랍, 마크와 포커스 동작을 연결한다. 한 커밋 단위다. | `npm --prefix app test`와 실제 파일에서 접힌 상태·열린 상태·너비 부족 상태의 클릭, 중첩 선택, 거리 측정, 텍스트 드래그, 키보드·포인터, 서랍의 Fit과 Play 차이를 확인한다. 항목을 선택하고 인스펙터를 연 뒤 창을 655px로 줄이면 열이 숨고, 656px로 넓히면 같은 선택으로 열이 다시 보이는지 확인한다. 아래 보드 입력 검증도 수행한다. |
| 6 | 브라우저 재생창. 창 열기·재사용과 분리된 프레임 렌더링, Fit·Responsive, 링크·서랍·기록·Reload, 실패·재시도와 포커스를 구현해 커밋한다. | `npm --prefix app test`와 같은 fixture의 앱·브라우저 비교로 뷰포트 치수, 모드 전환 후 입력 보존, 프레임 변경 후 초기화, 자기 링크 재시작, 링크 취소, 팝업 차단 후 보드 상태 보존을 확인한다. 아래 재생창 검증도 수행한다. |
| 7 | 현재 프로토타입 내보내기. 클릭 시점의 프레임·링크 그룹으로 독립 파일을 내려받게 한다. 성공·거절·진행 안내와 함께 커밋한다. | `go test ./...`와 `npm --prefix app test`를 실행한다. Chromium·WebKit에서 실제 받은 파일을 빈 폴더로 옮겨 원래 뷰어를 닫고 열어 시작 프레임·링크·브라우저 기록을 검증한다. 파일에서는 시작 프레임과 연결된 그룹 안에서만 이동한다. 원문에 유효하게 표시된 단독 프레임은 내보내기에 성공하고 그 프레임 하나를 재생한다. 스크립트로만 생긴 프레임은 내보내기를 거절하고, 보낸 사람에게 수정본을 요청하도록 안내한다. 아래 링크 그룹 경계도 확인한다. |
| 8 | 통합 검증. 두 브라우저의 일반 Export와 앱이 만드는 단독 Export에서 같은 시나리오를 재생하고 증거를 남긴다. | `node .agents/skills/verify/scripts/verify.mjs`와 짧은 실제 앱·파일 검증을 수행한다. 실제 macOS Safari에서 팝업 차단 해제 후 Play로 재시도하고 현재 프레임을 내려받는다. 받은 파일을 오프라인에서 다시 열어 시작 프레임과 링크 이동까지 확인해야 통과한다. Playwright WebKit 결과는 따로 기록한다. 마지막 통합 전에 `/agent-eval`을 수행한다. 가이드·CLI 출력·검사 규칙을 바꾸는 PR에서도 저장소 규칙에 따라 수행한다. |
| 9 | 구현된 동작을 영문 PRODUCT·ARCHITECTURE 및 해당 DESIGN 절에 반영하고 이 기능 디렉터리를 삭제한다. 각 기준 문서는 따로 커밋한다. | 공개 문서·가이드에서 일반 Export의 접힌 Select, Option 클릭, 거리 측정, 재생·복구 및 단독 파일 설명을 구현과 대조하고, 문서 링크 및 기능 디렉터리 삭제를 확인한다. |

## 단계별 추가 검증

- **5단계 · 보드 입력** — 준비 신호를 늦춘 실제 파일에서 Select의 첫 클릭이 프레임을 한 번만 선택하는지 확인한다. 버블의 Play에 키보드 포커스가 있을 때 선택을 바꿔 Play만 사라지게 하면 툴바의 Play prototype이 포커스를 받는다.
- **6단계 · 창 재사용과 포커스** — 재생 중인 프레임에 값을 입력한 뒤 보드에서 같은 프레임을 다시 열면 값이 남는다. 재생창을 닫았을 때 보드에 버블 Play가 있으면 그 버튼이, 없으면 툴바 Play가 포커스를 받는다. Responsive를 선택하고 다른 프레임으로 이동한 뒤 재생창을 닫았다 열면 Responsive가 유지되고 Back·Forward가 비활성이다. 보드 파일을 새로 열면 첫 재생은 Fit이다.
- **6단계 · 지연과 실패** — A에서 B로 옮긴 뒤 A의 늦은 응답이 도착해도 제목, Playing 행, 내보낼 대상은 B다. 실제 로컬 HTML에서 재생창은 계속 응답하고 프레임만 10초간 응답하지 않으면 실패 사유와 Retry·Close가 보인다. Retry를 누르면 새 iframe에서 같은 프레임이 처음부터 열린다. 깨진 링크를 누르면 파일을 보낸 사람에게 수정본을 요청하라는 안내가 보인다.
- **7단계 · 링크 그룹 경계** — 원문에 유효하게 기록된 첫 프레임과 1,001번째 프레임을 연결한다. 1,001번째 프레임은 재생창 서랍에 나타나지 않는다. 첫 프레임을 단독 HTML로 내려받아 열면 링크로 1,001번째 프레임까지 이동할 수 있다.

# 보드에서 재생하고 현재 프레임을 다시 내보내기

## 기준과 구성

보드의 선택은 [PRODUCT §5 항목 4](../../PRODUCT.md), 재생 버튼·서랍·창은 같은 문서의 항목 2와 3이 기준이다. 보드와 재생기 치수·조작부는 [캔버스](../../design/canvas.md)와 [프로토타입](../../design/prototype.md)을 따른다. 앱에 해당 동작이 이미 있으면 앱과 일반 Export에 같은 입력을 주고 결과를 대조한다. 파일을 편집하는 앱과 달리 브라우저는 받은 HTML에 담긴 시점의 캔버스를 사용한다. 별도 서버나 로컬 앱 연결을 추가하지 않는다.

변경 대상은 Go의 일반 Export 조립부, 내장 뷰어의 자바스크립트·HTML·CSS, 앱과 뷰어가 공유할 수 있는 순수 판정 및 테스트다. 기존 생성 스크립트가 내보낸 인스펙터 코드를 손으로 고치지 않는다. 캔버스 형식, CLI 응답, 소켓, JSON Schema와 버전, 에이전트 스킬, doan check 규칙은 그대로다. 기존 [ARCHITECTURE §1 규약 14·15와 §3 Exported canvas and viewer](../../ARCHITECTURE.md)를 적용한다.

## 선택과 재생 진입점

- Select는 인스펙터 표시 여부와 독립적으로 작동한다. 클릭·⌘ 클릭·Esc의 선택 경로, 잘린 요소의 호버·윤곽선과 버블, 텍스트 드래그, Option 거리 측정과 Option 클릭 통과를 앱과 대조한다. Hand 전환은 선택을 지우고 Space 임시 이동은 보존한다. 접혔거나 너비가 부족해 숨은 인스펙터에서는 스타일을 수집하지 않는다.
- 크기 버블의 Play는 재생 가능한 프레임 자체를 선택했을 때만 크기 앞에 놓는다. 키보드 포커스가 버블의 Play에 있는데 선택이 바뀌어 Play만 사라지면 포커스를 툴바의 Play prototype으로 옮긴다. Show inspector는 앱 규칙에 따라 노출한다. 대화용 Add to message는 제외한다.
- 툴바의 Play prototype은 항상 같은 버튼이다. 앱의 판정 순서를 재사용한다. 캔버스 준비 전이나 재생할 프레임이 없으면 이유를 제공한다. 프레임 자체나 재생 가능한 상위 프레임이 대상이면 바로 재생하고, 대상이 없거나 선택한 마크가 잘못됐으면 재생 서랍을 연다. Enter·Space·방향키·Esc와 포커스 복귀도 테스트한다.
- 보드의 프레임 서랍에는 앱과 같은 프로토타입 마크와 Viewing을 표시한다. 이 서랍에서 행을 고르면 보드가 이동한다. 툴바의 재생 서랍에서 행을 고르면 보드의 선택을 유지한 채 재생한다. 재생 서랍은 링크 그룹, 문서 순서, Playing 행과 키보드 탐색을 앱과 공유한다.
- 앱의 재생 판정을 따른다. 처음 1,000개 프레임, 유효한 마크, 비어 있지 않은 고유 ID와 200 UTF-16 단위 한계를 포함한다. 실행 중 재생 후보와 파일에서 별도 내보낼 수 있는 후보를 구별한다. 스크립트가 파싱 또는 load 중 만든 프레임도 앱과 같은 조건에서 재생할 수 있지만, 파일 원문에 없는 프레임은 별도 내보내기를 거절하고 파일 원문에 프레임이 없다고 설명한다.

## 브라우저 재생기

신뢰할 수 있는 뷰어 버튼의 사용자 입력으로 창을 열고, 원래 파일의 보드와 재생 화면을 독립시킨다. 캔버스 iframe에는 팝업·같은 출처 접근 권한을 추가하지 않는다. 사용자가 승인한 새 창을 여는 주체는 뷰어다. iframe에서 올라온 메시지는 현재 창·현재 프레임에서 온 것인지 확인한다. 재생창은 보드가 닫힌 뒤에도 자체 자료로 입력, 링크 이동, 현재 프레임 내보내기를 처리한다. 클릭 한 번에 창 하나만 열고, 재생창을 닫고 다시 열 수 있게 한다. 재생창을 닫았을 때 보드가 남아 있으면 버블의 Play에 포커스를 돌려주고, 그 버튼이 사라졌으면 툴바의 Play prototype으로 돌려준다. 차단 시 보드의 재생 진입점 가까이에 차단 사유와 재시도 방법을 표시한다.

- 보드 파일을 새로 열면 Fit으로 시작한다. 같은 보드에서 재생창을 닫았다 다시 열면 직전에 선택한 Fit·Responsive 모드를 유지하고 이전·다음 방문 기록은 비운다. 마크의 뷰포트와 미디어 쿼리를 유지하며 필요할 때만 축소한다. Responsive는 창 크기로 다시 배치한다. 모드 전환은 입력·모달·스크롤을 보존한다. 브라우저가 요청한 외부 창 크기나 포커스를 허용하지 않아도 내부 프레임 크기와 조작은 지킨다.
- 같은 보드에서는 재생창 하나를 재사용한다. 같은 프레임을 다시 요청하면 창을 앞으로 가져오고, 다른 프레임이면 처음부터 재생한다. 창 안의 링크로 자기 자신을 가리키면 다시 시작한다. Back·Forward·Reload의 기록 생성 여부, 서랍의 Playing 표시, 키보드 포커스와 로딩·실패·Retry·Close·Details는 앱의 재생 상태를 기준으로 검증한다.
- 앱에서 재생과 탐색에 사용하는 헤더, 좁은 창에서의 줄바꿈, 단축키와 접근 가능한 이름을 유지한다. 파일에 포함된 자료만으로 재생하며, 원래 저장소의 변경을 감시한다고 표시하지 않는다. 재생창은 응답하지만 프레임이 시작한 지 10초가 지나도 응답하지 않으면 실패 사유와 Retry·Close를 표시한다. Retry는 새 iframe에서 같은 프레임을 처음부터 연다. 재생 대상을 교체할 때마다 새 iframe을 만들고 현재 실행의 응답만 적용한다. 깨진 링크, 원문에 없는 프레임이나 유효한 마크가 없는 프레임처럼 파일을 고쳐야 하는 경우에는 무엇이 잘못됐는지 밝히고 보낸 사람에게 수정본을 요청하도록 안내한다. Electron의 프로세스 강제 종료와 마지막 화면 캡처는 브라우저 검증 범위에서 제외한다.
- Export prototype은 클릭한 순간의 프레임과 그 링크 그룹을 대상으로 한다. 기존 단독 프로토타입 파일의 시작 프레임, 제목, 파일 이름, 링크 범위, 캔버스 원문 포함 안내, 크기 한계와 실패 규칙을 재사용한다. 저장은 브라우저에 맡긴다. Go에서 매 프레임마다 완성 파일을 미리 복제하지 않고 원본 자료 한 벌과 그룹 정보로 필요할 때 조립한다. 브라우저가 저장 완료를 알려주지 않으면 다운로드 요청을 디스크 기록 성공으로 표시하지 않는다.

## 순수 판정과 선행 실험

1. 선택·상위 프레임·유효 마크에서 버블과 툴바의 대상, 서랍 행·그룹·마크를 구하는 판정은 앱의 prototypePlay와 기존 양 런타임 fixture에 같은 입력을 넣는다.
2. 현재 프레임·재생 요청·링크·기록 위치에서 다음 프레임과 재시작 여부를 구한다. 뷰포트 모드와 표시 영역에서 콘텐츠 크기·배율을 구하는 규칙은 앱의 값을 기준으로 삼는다.
3. 원본에 기록된 프레임과 링크로 단독 파일의 시작점·그룹·거절 사유를 구한다. Go가 기존 CLI로 내보낸 결과와 브라우저에서 저장한 파일을 각각 독립적으로 열어 비교한다.
4. 선행 PoC에서 실제 file URL의 Chromium·WebKit으로 새 창 열기·재사용·닫기, 차단과 재시도, 창 내부의 격리된 재생, 독립 HTML 다운로드와 오프라인 재개방을 확인한다. 창 통신과 사용자 입력 인정 방식은 이 결과로 정한다. 복제한 테스트 DOM만으로 이 항목을 통과 처리하지 않는다.

## 회귀 근거와 시안

- [11월 회고](../../postmortem/2026-11.md)의 “Export viewer tests sent input before the canvas inspector opened”는 호스트 버튼을 누른 시점과 iframe이 입력을 처리하는 시점이 달랐던 사례다. 준비 완료 뒤 조작하는 테스트와 준비 메시지를 늦춘 첫 클릭 테스트를 함께 둔다.
- 같은 회고의 “An exported prototype lost a followed link when the frame navigated before the viewer read the goto”와 “The canvas export viewer kept the srcdoc navigation bugs the prototype page had already fixed”를 기준으로 취소된 링크, 이동 직전의 링크, 같은 문서 해시와 History 동작을 두 엔진에서 확인한다.
- 같은 회고의 “An eval check that compared a prototype export only with a regenerated one accepted the canvas viewer”에 따라 생성 결과끼리 비교하는 검사에 더해, 원래 뷰어 없이 다운로드한 파일의 첫 화면과 실제 링크 이동을 검증한다.

시안은 기존 Export 화면을 확장하는 새 파일 `.doan/canvases/export-prototype-player.html`에 그린다. 캔버스 ID는 `export-prototype-player`다. 상태는 `board-selection`(버블·툴바), `frame-drawer`(프로토타입 마크), `play-drawer`(그룹·Playing), `player-fit`, `player-responsive`, `player-narrow`, `play-blocked`, `player-failure`, `export-result`다. 앱과 같은 조작부에는 기존 토큰과 배치를 사용하고, 브라우저 고유의 차단·다운로드 안내는 영문으로 그린다. 적용한 디자인 프리셋은 shape이다.

### 브라우저에서 달라지는 표시

- 팝업이 차단되면 누른 Play 바로 위에 “Your browser blocked the prototype window. Allow pop-ups, then press Play again.”을 표시한다. 같은 버튼으로 재시도한다.
- 다운로드를 요청하면 재생창 오른쪽 아래 토스트에 “Download requested for ‘Checkout’ and 1 linked frame. The file also contains the rest of the canvas.”를 표시한다. 프레임 이름과 연결된 프레임 수는 클릭한 대상에 맞춘다.
- 브라우저가 창 버튼을 제공하므로 재생기 헤더는 왼쪽 16px에서 Back으로 시작한다. 프레임 이름 양옆에는 40px씩 남기고 이름에 120px를 확보할 수 없으면 두 번째 줄로 옮긴다.

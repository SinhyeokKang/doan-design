# 스레드 모션 — spec

## 사용자

- **사람**: 캔버스 패널, Overview, 프로토타입 창에서 에이전트와 대화하는 사람이다. 보낸 메시지가 스레드로 자연스럽게 들어가고, 에이전트의 답이 끊기지 않고 부드럽게 나타나는 것을 본다.
- **에이전트**: 바뀌는 것이 없다.

## 문제

- 보낸 메시지는 스레드에 갑자기 나타난다. 바로 보내기는 main이 `user.message`를 쓴 render에서, Send now는 `withSending`(`threadItems.ts:358`)이 넣는 render에서 나타나고, 둘 다 전환이 없다.
- 스트리밍되는 답은 provider가 보낸 조각 단위로 뭉텅이씩 늘어난다. 지금은 프레임마다 받은 만큼을 통째로 보여준다(`useFrameText`, `ConversationThread.tsx:322`). 그래서 조각이 크면 몇 줄이 한 번에 튀어나온다.
- 바닥을 따라가는 스레드는 높이가 늘 때마다 즉시 바닥으로 점프한다(`threadScroll`, `threadItems.ts:399`, `ConversationThread.tsx:829`). 조각이 크거나 새 항목이 생기면 화면이 계단처럼 움직인다.

## 확정한 결정 (사용자)

- 사용자 메시지가 스레드로 들어가는 모션과 스트리밍 출력이 부드럽게 나타나는 모션을 추가한다.
- 스크롤 조정도 부드럽게 한다. 바닥을 따라가는 동안 높이가 늘면 바닥으로 점프하지 않고 짧게 감속하며 따라간다.
- 구현은 thread-edit-lines와 handoff-card-emphasis가 develop에 머지된 뒤에 한다. 같은 스레드 렌더링 파일을 쓰기 때문이다.
- 모션의 모습(들어오는 방식, 출력이 나타나는 방식)은 드래프트에 여러 안을 그려 놓고 사용자가 고른다.

## 완료 조건

1. 이 창의 composer에서 보낸 메시지(바로 보내기와 Send now)는 스레드에 처음 나타날 때 확정된 드래프트의 진입 모션으로 들어온다. 대화를 열 때 이미 있던 메시지, 대화를 바꿀 때, 다른 창이나 터미널에서 온 메시지, 핸드오프 카드에는 모션이 없다.
2. 스트리밍되는 답은 받은 조각을 한 번에 보여주지 않는다. 확정된 드래프트의 방식으로 일정한 속도에 가깝게 나타난다. 이때 보여주는 텍스트가 받은 텍스트보다 일정 시간(design.md '출력 점진 표시'의 `MAX_LAG_MS`) 넘게 뒤처지지 않는다.
3. 답이 끝나면(`message.done`, 턴 종료, Stop, 실패) 남은 텍스트를 곧바로 모두 보여준다. 끝난 답이 계속 타이핑되지 않는다.
4. 바닥을 따라가는 동안 높이가 늘면(보낸 메시지의 진입, 답의 증가, activity 행·카드·노티스 같은 새 항목), 스크롤은 바닥으로 점프하지 않고 확정된 드래프트의 시간과 easing으로 감속하며 따라간다. 따라가는 도중 더 늘어나면 목표를 새 바닥으로 바꿔 이어서 따라가고, 되돌아가거나 멈칫하지 않는다. 대화를 처음 열 때는 지금처럼 즉시 바닥에 있다. 사람이 위로 스크롤해 따라가기를 멈춘 경우(`behind`)의 규칙과 Jump to latest는 지금과 같다.
5. `prefers-reduced-motion: reduce`에서는 진입 모션, 점진 표시, 부드러운 스크롤을 모두 끈다. 메시지는 바로 나타나고, 답은 지금처럼 받은 만큼 보이고, 스크롤은 즉시 바닥으로 간다.
6. 모션 중에도 스레드의 기존 규칙이 그대로다.
   - 선택과 복사, 칩 위치 찾기(locate), 링크 클릭
   - 스크린리더는 점진 표시 중의 글자를 하나씩 읽지 않는다(지금의 상태 줄 규칙)
   - 턴 인디케이터의 자리와 높이, 질문·권한 카드로 가는 포커스와 스크롤
7. 긴 답(예: 1만 자, 코드 블록 포함)에서도 점진 표시가 프레임을 떨어뜨리지 않는다. 기준은 design.md 'PoC'에서 측정해 정한다.

## 비목표

- 에이전트 작업(activity 행, 캔버스 카드, 권한·질문 카드)의 등장 모션. 이번에는 사용자 메시지와 답 본문만 다룬다.
- 대화 전환, 패널 열기·접기, 목록의 모션.
- 답의 속도를 사람이 조절하는 설정.
- 보낸 메시지가 composer에서 스레드까지 날아가는 모션은 드래프트 후보에 그리되, 고르면 별도 PoC를 거친다(design.md 'PoC').

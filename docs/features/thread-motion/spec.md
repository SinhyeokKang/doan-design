# 스레드 모션 — spec

## 사용자

- **사람**: 캔버스 패널, Overview, 프로토타입 창에서 에이전트와 대화하는 사람이다. 보낸 메시지가 스레드로 자연스럽게 들어가고, 에이전트의 답이 끊기지 않고 부드럽게 나타나고, 스레드가 계단처럼 튀지 않고 따라가는 것을 본다.
- **에이전트**: 바뀌는 것이 없다.

## 문제

- 보낸 메시지는 스레드에 갑자기 나타난다. 바로 보내기는 main이 `user.message`를 쓴 render에서, Send now와 Overview의 바로 보내기는 `withSending`(`threadItems.ts:358`)이 넣는 render에서 나타나고, 둘 다 전환이 없다.
- 스트리밍되는 답은 provider가 보낸 조각 단위로 뭉텅이씩 늘어난다. 지금은 프레임마다 받은 만큼을 통째로 보여준다(`useFrameText`, `ConversationThread.tsx:322`). 그래서 조각이 크면 몇 줄이 한 번에 튀어나온다.
- 바닥을 따라가는 스레드는 높이가 늘 때마다 즉시 바닥으로 점프한다(`threadScroll`, `threadItems.ts:399`, `ConversationThread.tsx:819-830`). 조각이 크거나 새 항목이 생기면 화면이 계단처럼 움직인다.

## 확정한 결정 (사용자)

- 보낸 메시지의 진입, 스트리밍 출력의 점진 표시, 스크롤 따라가기를 모두 부드럽게 한다.
- 진입 모션의 대상은 이 창에서 보낸 모든 메시지다: 바로 보내기, Send now, 턴이 끝난 뒤 나가는 큐 메시지(여러 개면 함께), 새 대화의 첫 메시지. 히스토리, 다른 창·터미널의 메시지, 핸드오프 카드는 제외한다.
- reduced motion에서는 앱 공통 규칙(DESIGN.md 'Motion': 페이드는 남기고 움직임·크기·블러는 끈다)을 따른다. 진입은 제자리 페이드만 하고, 점진 표시와 부드러운 스크롤은 끈다.
- 진입 모션은 A(아래에서 16px 올라오며 400ms에 페이드, 새 토큰 `--time-thread-enter`)다. 드래프트에서 날아오기와 제자리에서 커지기와 비교해 골랐다.
- 점진 표시는 B(단어 단위로 펼치며 새 단어가 투명에서 진해짐)다. 속도는 처음 그린 250ms보다 느린 400ms 상한이다(사용자 결정).
- 구현은 thread-edit-lines와 handoff-card-emphasis가 develop에 머지된 뒤에 한다. 같은 스레드 렌더링 파일을 쓰기 때문이다.

## 완료 조건

1. 위 대상 메시지는 스레드에 처음 나타날 때 확정된 드래프트의 진입 모션으로 들어온다. Send now처럼 화면에 먼저 나타난 뒤 `user.message`로 바뀌는 메시지도 진입은 한 번이다.
2. 스트리밍되는 답은 받은 조각을 한 번에 보여주지 않는다. 보여주는 텍스트가 받은 텍스트보다 400ms(가장 오래 숨겨진 글자의 나이) 넘게 뒤처지지 않는다. 받은 조각이 작으면 받은 만큼만 보인다. 이 조건은 `revealStep` 테스트로 확인한다.
3. 답이 끝날 때:
   - `message.done`이면 남은 끝을 약 150ms에 마저 보여준다.
   - Stop(누른 순간), 실패, 턴 종료면 남은 텍스트를 즉시 모두 보여준다.
   - 답 뒤에 다른 항목(권한·질문 카드, activity 행, 캔버스 카드, 노티스)이 오면 그 render에서 답을 즉시 모두 보여준다. 그래서 카드를 누르려는 순간 위 텍스트가 늘어나 카드를 밀어내지 않는다.
   - 숨겨져 있던 창이 다시 보이면 그동안 받은 텍스트를 즉시 보여준다.
4. 바닥을 따라가는 동안:
   - 답이 펼쳐지는 중에는 매 프레임 바닥에 붙인다. 펼침이 이미 부드러워서 쓰고 있는 줄이 화면 아래로 숨지 않는다.
   - 메시지 진입, 새 항목처럼 한 번에 늘어날 때는 바닥으로 점프하지 않고 지수 감속으로 따라간다. 따라가는 도중 더 늘면 목표만 바꿔 이어 간다.
   - 대화를 처음 열 때는 지금처럼 즉시 바닥에 있다.
5. 사람이 스크롤하면(휠, 트랙패드, 스크롤바 드래그, 스레드 안의 스크롤 키) 따라가기를 즉시 멈추고, 사람이 바닥 근처로 돌아올 때까지 쉰다. 관성 스크롤이 끝날 때까지 따라가기를 다시 시작하지 않는다. 질문·권한 카드로 가는 스크롤(`scrollToItem`)도 따라가기를 멈춘다. `behind`와 Jump to latest의 규칙은 지금과 같다.
6. reduced motion에서는 진입이 제자리 페이드만 하고, 답은 지금처럼 받은 만큼 보이고, 스크롤은 즉시 바닥으로 간다.
7. 모션 중에도 지켜지는 것:
   - 끝난 항목의 선택과 복사, 칩 위치 찾기(locate), 링크 클릭. 답 안에서 텍스트를 선택하면 그 답을 즉시 모두 보여주고 따라가기를 멈춘다. 코드 블록의 Copy는 받은 전체 텍스트를 복사한다.
   - 스크린리더는 점진 표시 중의 글자를 하나씩 읽지 않는다(지금의 상태 줄 규칙).
   - 턴 인디케이터, 큐 알약, 다음 메시지 제안, 백그라운드 작업 줄은 모션 없이 나타나고, 진입하는 말풍선과 함께 움직이지 않는다. 인디케이터의 자리와 높이 규칙은 그대로다.
8. 1만 자 답(코드 블록, 표 포함)을 347 패널에서 점진 표시할 때, 프레임당 렌더 시간이 p95 16ms 이하, 최댓값 50ms 이하다. 이 기준을 넘으면 끝난 블록을 다시 그리지 않도록 나눈 뒤 다시 잰다.

## 비목표

- 에이전트 작업(activity 행, 캔버스 카드, 권한·질문 카드)의 등장 모션.
- 대화 전환, 패널 열기·접기, 목록의 모션.
- 답의 속도를 사람이 조절하는 설정.
- 메시지가 스레드에서 나가는 모션(Send now가 거부되어 큐로 돌아갈 때 등).

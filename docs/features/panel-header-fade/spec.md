# 패널 헤더 페이드 — 명세

## 사용자와 문제

Doan에서 대화를 읽고 목록과 인스펙터를 탐색하거나 캔버스 보드를 이동하는 사람이 대상이다. 현재 헤더와 본문이 맞닿는 곳에서 콘텐츠가 끊겨 보인다. 특히 대화의 말풍선이나 캔버스 프레임이 헤더 경계를 지나면 잘리는 경계가 드러난다. 헤더의 제목과 버튼은 제자리에 선명하게 두고, 뒤로 지나가는 콘텐츠는 위로 갈수록 패널 배경에 가까워지는 효과를 적용한다.

## 범위

| 화면 | 적용 헤더 | 헤더 아래를 지나는 콘텐츠 |
|---|---|---|
| 오버뷰 | 대화 헤더 | 대화 스레드 |
| 오버뷰 | Conversations 목록 헤더 | 대화 목록 행 |
| 캔버스 | 보드 헤더 | 이동하거나 확대·축소한 실제 캔버스 보드 |
| 캔버스 | 인스펙터 헤더 | 인스펙터 행 |
| 캔버스 | 대화 헤더 | 대화 스레드 |
| 프로토타입 창 | 대화 패널 헤더 | 대화 스레드 |

`PRODUCT.md` §3의 Show 및 Conversation 범위에 해당한다. §5의 오버뷰, 캔버스, 인스펙터, 프로토타입 창 동작을 따른다.

## 완료 조건

- 6곳에서 헤더의 제목과 버튼이 제자리에 선명하게 보인다. 콘텐츠가 헤더 아래를 지날 때 위쪽으로 점차 옅어진다. 대화·목록·인스펙터에서 맨 위에 있거나 콘텐츠가 짧으면 첫 항목을 온전히 읽을 수 있다. 빈 상태와 첫 읽기·읽기 실패의 안내는 현재 위치에서 읽을 수 있고, Retry가 있는 경우 사용할 수 있다.
- 헤더 메뉴, 버튼, 키보드 포커스 표시, 패널 크기 조절을 평소처럼 쓸 수 있다. 키보드 탐색이나 받은 핸드오프를 열어 이동하면 대상과 포커스 표시가 페이드 아래에 드러난다. 스트리밍 중 위로 스크롤해 이전 내용을 읽으면 그 위치가 유지된다. 표시할 공간이 있을 때 Jump to latest를 누르면 최신 위치로 돌아가 자동 따라가기가 다시 시작된다.
- 대화 영역이 낮으면 기존 제품 규칙대로 답변 팝오버가 헤더 위에 보인다. 가장 작은 프로토타입 창에서도 키보드로 선택지에 접근하고 스크롤할 수 있으며, 팝오버를 접거나 닫으면 헤더가 다시 보인다. 화면이 좁아 인스펙터가 숨겨질 때와 다시 나타날 때는 기존 가용 폭과 포커스 이동을 따른다.
- 캔버스에서는 실제 보드가 헤더 아래에 이어져 보인다. Fit과 프레임 이동, 선택 표시, Pick, Capture area, 작업 안내가 기존 뷰포트와 기준 좌표를 따른다. 보드가 비쳐도 헤더의 기존 입력 영역은 헤더가 받는다. 캡처에는 페이드가 찍히지 않는다.
- 투명도 줄이기나 강제 색상에서는 6곳이 불투명한 헤더를 쓰고, 제목과 버튼, 키보드 포커스 표시를 읽을 수 있다. 페이드 자체에는 시간에 따른 애니메이션이 없다.

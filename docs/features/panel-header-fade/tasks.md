# 패널 헤더 페이드 — 작업

## 선행 검증과 드래프트

1. `/design-draft panel-header-fade`에서 `design.md`의 네 프레임을 프로토타입으로 그린다. 사용자가 앱에서 확인한 페이드 길이·농도·범위를 기록한다.
   - 확인: `doan check --json --repo .`에서 기준 실행 대비 새 오류가 없고 새 캔버스의 오류는 0건이다. 새 경고는 `.doan/assets/mock.css`의 `hardcoded_color`만 허용한다. `doan ls --json --repo .`에서 캔버스 id `panel-header-fade`, 너비 1440, `design.md`의 프레임 id 네 개가 일치한다. `doan open --prototype`으로 각 프레임을 열어 마커에 지정한 크기와 본문 스크롤을 확인한다.
   - 커밋 경계: `docs(design): panel-header-fade draft`.

## 구현

2. `/tdd`로 고정 헤더, 콘텐츠가 통과할 때의 페이드와 접근성 대안, 헤더 밑에 가려진 포커스 대상의 처리를 고정한다. DOM 밖으로 꺼낼 계산이 있을 때 계산부터 테스트한다.
   - 확인: `npm --prefix app test`에서 새 검사가 변경 전 실패한다.
   - 커밋 경계: `test:`.
3. 오버뷰 대화·목록, 캔버스 인스펙터·대화, 프로토타입 대화의 헤더 5곳에 적용한다. 오버뷰 목록 헤더는 고정하고 대화 패널 두 창은 기존 공용 구조를 쓴다.
   - 확인: `npm --prefix app test`, `npm --prefix app run typecheck`를 통과한다.
   - 커밋 경계: `feat:`.
4. `/design-sync`와 `/runtime-test`로 스크롤 헤더 5곳을 확인한다.
   - 맨 위와 짧은 본문에서 첫 항목은 온전히 보이고, 중간에서는 본문이 헤더 뒤로 페이드한다. 빈 상태·첫 읽기·읽기 실패의 안내와 Retry를 확인한다. 항목이나 대화가 사라질 때는 기존 위치와 포커스 복구를 확인한다.
   - 오버뷰 목록에서 키보드로 이동한 행은 페이드 아래에 온전히 보인다. 행 삭제 후 다음·이전 행 또는 제목으로 포커스가 돌아오고, 가려진 행이 화면에 보이는 행보다 썸네일 우선순위를 앞서지 않는다. 좁은 캔버스 인스펙터가 공간 부족으로 숨겨졌다가 나타날 때 Show inspector와 Hide inspector 사이의 포커스 이동을 확인한다.
   - 각 대화 패널에서 받은 핸드오프를 열면 헤더 아래에 메타 줄과 포커스가 드러난다. 스트리밍 중 위로 스크롤하면 읽던 위치와 Jump to latest가 유지되며, 버튼을 누르면 최신 위치에서 따라가기가 재개된다. 사람이 스크롤하지 않은 상태로 답변이 펼쳐지던 중 권한 요청이 도착하면 따라가기가 유지된다.
   - 가장 작은 프로토타입 창에서 답변 팝오버가 헤더를 덮으면 Jump to latest가 숨고, Tab으로 선택지에 접근할 수 있다. 팝오버를 접거나 닫으면 헤더가 다시 보인다. 메뉴를 실제로 열고 조작하며, 패널 접기와 크기 조절 후 제목·포커스 표시가 보이는지 확인한다.
   - 확인: `node .scratch/design-sync/panel-header-fade/measure.mjs`에서 네 프레임의 헤더 높이와 전환 위치가 드래프트와 맞는다. 격리 앱의 스크린샷과 로그에 상태별 결과 및 투명도 줄이기·강제 색상 각각에서 불투명 헤더와 포커스가 보인 결과가 있다. 실제 macOS 설정과 미디어 에뮬레이션 결과를 구별한다.
   - 커밋 경계: 측정값과 드래프트 차이 기록.

## 통합

5. `/deliver` 한 건에서 4단계의 실측과 런타임 확인, 코드 리뷰, 문서 승격, 최종 게이트, PR 순으로 진행한다.
   - 확인: `node .agents/skills/verify/scripts/verify.mjs`와 GitHub `gate`가 통과하고, PR에 런타임 확인 범위가 기록된다.
6. 최종 게이트와 푸시 전에 구현한 규칙을 영어로 옮긴다. `docs/PRODUCT.md` §5에는 적용 표면, 헤더 아래 표시와 불투명 대안을 기록한다. `docs/ARCHITECTURE.md` §7에는 새로 생긴 비자명한 스크롤·포커스 경계를 기록한다. `docs/design/project.md`, `docs/design/canvas.md`, `docs/design/prototype.md`에 실측을 기록하고, `docs/features/panel-header-fade/`를 지운다.
   - 확인: 푸시할 커밋에서 `node .agents/skills/verify/scripts/verify.mjs`를 통과한다. 실측 문서에 다섯 헤더의 확인 범위가 있고 지운 기능 문서를 가리키는 링크가 없어야 한다. 병합한 커밋에서 실측 근거가 여전히 적용되는지 확인하고, PR에서 남긴 미확인 항목을 검증한다.
   - 커밋 경계: 제품·구조·실측 문서를 업데이트하고 기능 문서를 정리한다.

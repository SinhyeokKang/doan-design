# multi-handoff — spec

## 사용자

- **사람**: 캔버스 대화에 "새 캔버스 n개를 만들어 줘"라고 요청한 사람. 턴이 끝나면 새 캔버스마다 새 대화가 시작되어 있고, 각 대화의 첫 메시지는 이전 에이전트가 쓴 핸드오프다. 소스 대화의 스레드에서 캔버스마다 핸드오프가 됐는지 안 됐는지 볼 수 있다.
- **에이전트**: 앱 대화의 턴 프롬프트에서 "새로 만든 캔버스마다 `doan handoff`를 한 번씩 실행하라"는 안내를 받는다. 같은 턴에서 서로 다른 새 캔버스에 대한 두 번째 요청도 받아들여진다.

## 문제

- 지금 Doan은 턴마다 핸드오프를 하나만 받는다(PRODUCT §5 item 2 'Handoff': "Doan accepts one per turn"). 두 번째 `doan handoff`는 `already_requested`로 거절된다(`app/src/main/conversation/handoff.ts` `handoffEligibility`).
- 턴 프롬프트의 `HANDOFF_GUIDANCE`(`app/src/main/conversation/prompt.ts`)는 "작업이 이어질 새 캔버스"가 하나라고 전제한다. 그래서 새 캔버스를 여러 개 만든 턴에서는 에이전트가 이어갈 캔버스를 고르지 못해 핸드오프를 아예 하지 않을 수 있다. 실제로 그런 일이 있었다(사용자 관찰).
- 에이전트가 핸드오프를 하지 않으면 사람에게는 아무 표시도 보이지 않는다. 새 캔버스에 대화가 없다는 사실을 사람이 직접 찾아야 한다.

## 완료 조건

1. 핸드오프할 수 있는 턴(Doan 연결, 캔버스 대화, Plan 아님, 핸드오프로 시작된 턴 아님)에서, 서로 다른 캔버스 경로에 대한 `doan handoff` 요청을 개수 제한 없이 받는다. 같은 턴에서 같은 경로를 다시 요청하면 `already_requested`로 거절한다.
2. 턴이 done으로 끝나면 요청마다 따로 판정한다(목록에 하나뿐인 캔버스인지, 새 캔버스인지, 현재 대화가 없는지). 시작 조건을 통과한 요청마다 새 대화를 하나씩 시작한다. 한 요청이 거절되어도 다른 요청에는 영향이 없다.
3. 소스 스레드는 요청마다 줄 하나를 요청한 자리에 보여 준다(“Hands off to <file> when this turn ends” → “Handed off to <file>” / “Didn’t hand off to <file>. …”). 기존 단일 핸드오프의 문구와 동작은 그대로다.
4. `handoff.resolved` 이벤트는 어느 요청의 결과인지 캔버스 경로로 밝힌다. 경로가 없는 기존 기록은 그 턴의 유일한 요청에 대한 결과로 읽는다.
5. 턴 프롬프트의 `HANDOFF_GUIDANCE`는 "이번 턴에 `.doan/canvases/`에 만든 새 캔버스마다 `doan handoff`를 한 번씩 실행하라"고 안내한다. Send now로 끼어든 메시지의 프롬프트도, 그 턴에 이미 요청이 있었더라도 이 안내를 유지한다.
6. 핸드오프할 수 있는 턴이 done으로 끝났을 때, 그 턴이 편집한(활동 기록의 edit 경로) 새 캔버스 중 핸드오프 요청이 없는 캔버스가 있으면 소스 스레드에 그 캔버스마다 줄을 하나씩 보여 준다. 문구는 “Made <file> without handing off.”이다(design D4). Doan은 이 캔버스에 대화를 시작하지 않는다.
7. 핸드오프 대기 중 소스에 쌓인 메시지(큐), 화면 이동과 토스트는 design D2, D3을 따른다. 요청이 하나뿐인 턴에서는 지금과 똑같이 동작한다.
8. 턴 하나가 시작하는 핸드오프 대화의 개수 상한은 design D1을 따른다(상한 없음).
9. PRODUCT §3 Out of scope 4와 §5 item 2 'Handoff', §5 item 6, ARCHITECTURE §4·§7의 핸드오프 서술이 "새 캔버스마다 하나"로 바뀐다.
10. `/agent-eval`에 새 캔버스 두 개를 만드는 핸드오프 시나리오가 추가되고, Claude Code와 Codex 실행 결과가 `docs/USABILITY-EVAL.md`에 기록된다.

## 비목표

- Doan이 핸드오프 메시지를 대신 쓰거나, 요청이 없는 캔버스에 대화를 시작하는 것. Doan이 스스로 에이전트를 깨우는 셈이라 Out of scope 4에 걸린다.
- 핸드오프로 시작된 턴의 연쇄 핸드오프. 지금처럼 `handoff_turn`으로 거절한다.
- 프로젝트 대화(캔버스 없는 대화)의 다중 승격. 프로젝트 대화는 지금처럼 승격으로만 캔버스에 붙는다.
- 레거시 외부 대화와 터미널 에이전트. `doan handoff`는 여전히 Doan 앱 대화에서만 동작한다.
- 앱 소켓 v5 형식 변경. 요청과 응답 모양은 그대로다.

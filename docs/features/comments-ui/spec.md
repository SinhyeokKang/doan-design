# comments-ui — 요구사항

2026-10-23. MVP #7. 기준: PRODUCT §3–5·§7, ARCHITECTURE §2·§3·§11–13. 선행 #6 select-inspect는 main `41f2cab`에 병합됐다. 이 문서는 구현 전 명세이며 구현 완료를 뜻하지 않는다.

## 사용자와 현재 문제

- 사람은 선택한 요소·프레임 또는 캔버스 전체에 지시를 남기고, 수정·삭제·해결·재열기한다.
- 에이전트는 기존 CLI/MCP로 열린 코멘트를 읽고 반영한 뒤 해결한다. 앱은 에이전트를 실행하지 않는다.
- 현재 `RightPanel.tsx`는 선택 시 Inspector, 미선택 시 Canvas info와 코멘트 개수만 표시한다. 본문 목록·작성·핀·복사는 없다.
- comment-event.v1과 TS/Go fold는 다섯 이벤트를 이미 지원한다. `doan comments`는 열린 코멘트만 반환하므로 앱의 해결된 코멘트 목록에 그대로 사용할 수 없다.

## 범위

코멘트 CRUD, open/resolved 전환, 대상별 핀, outdated 표시, 에이전트에게 보낼 문장 복사를 구현한다. PRODUCT §3의 범위 안이다. 답글·채팅·알림으로 에이전트 깨우기·계정·서버·Git 쓰기·실시간 공동 편집·승인·자유 좌표 코멘트는 추가하지 않는다. CLI/MCP의 생성·수정·삭제 권한도 추가하지 않는다.

## 완료 조건

1. 유효하고 유일한 canvas id를 가진 열린 캔버스에서 캔버스·프레임·요소 코멘트를 생성한다. 프레임은 렌더 DOM을 기준으로 한다. 선택 대상과 작성 대상을 분명히 표시한다. width 누락·오류 시 새 작성과 핀은 막되 기존 코멘트 읽기·수정·삭제·해결·재열기·열린 코멘트 복사는 유지한다. canvas id 누락·오류·중복은 모든 쓰기를 막고 이유를 안내한다.
2. 같은 패널에서 Inspector와 선택 대상 코멘트를 보고, 전체 목록으로 전환해 다른 대상·위치 없음 코멘트도 찾는다. Open/Resolved 목록을 분리하고 빈 상태·읽기 중·읽기 실패·저장 중·저장 실패를 표시한다.
3. 사람이 본문을 수정·삭제하고 해결·재열기한다. 각각 기존 v1 이벤트를 append하며 이전 줄을 바꾸지 않는다. 삭제한 코멘트는 재실행과 union merge 후에도 부활하지 않는다.
4. 작성자를 이름·선택적 이메일·이니셜로 표시한다. 이름 미설정·Git 조회 실패를 구별해 안내하고, 모든 쓰기는 유효한 human 작성자로 기록한다.
5. 대상 전환 전에 초안을 처리한다. 저장 실패 시 본문을 보존한다. 외부 reload·대상 삭제·프로젝트 닫힘으로 대상을 잃어도 다른 대상에 자동 저장하지 않는다. 신규 작성은 문서·대상 유효성을 요구하지만, 기존 코멘트 수정은 DOM 위치와 무관하게 원래 comment id와 최신 상태를 검증해 저장한다.
6. 위치를 찾은 열린 요소·프레임 코멘트에 대상별 개수 핀을 표시한다. 핀은 확대·축소에도 화면상 크기를 유지하고 대상과 함께 움직인다. 핀으로 목록을 열 수 있으며 키보드로도 접근한다. 프레임 코멘트와 같은 DOM 노드를 가리키는 요소 코멘트가 함께 있어도 핀 개수와 Selection의 Open 목록이 일치한다. 저장된 target은 바꾸지 않는다.
7. 대상 재탐색 실패·중복·invalid selector는 ‘위치 없음’으로 처리한다. 코멘트는 목록에서 계속 읽기·수정·삭제·해결·복사가 가능하다. 자동 재부착이나 target 변경 이벤트를 추가하지 않는다.
8. 생성 시 canvasHash와 현재 파일 바이트의 SHA-256이 다르면 Outdated를 표시한다. 위치 없음과 별개다. 본문 수정·해결·재열기로 생성 당시 hash를 갱신하지 않는다.
9. CLI resolve 또는 외부 JSONL 변경이 앱의 목록·핀·개수에 반영된다. 본문만 수정되어 개수가 같아도 갱신한다. 코멘트 변경 때문에 iframe을 다시 로드하지 않는다.
10. 복사 버튼은 Q6의 두 범위를 제공한다. 저장소 절대 경로·canvas id·해당 comment id를 담은 영어 지시문을 시스템 클립보드에 쓴다. 단일 복사는 open 코멘트만 허용하고 resolved 코멘트는 재열기가 필요하다고 안내한다. 에이전트 호출이나 명령 실행은 하지 않는다.
11. 손상된 줄·미지원 버전 경고를 숨기지 않되 유효한 코멘트는 계속 표시한다. 읽기 실패를 빈 목록으로 보이지 않는다. 파일·IPC 경계를 벗어난 쓰기와 캔버스 iframe의 쓰기 요청을 거부한다.
12. 초안 확인 후 구현하고, 실앱 입력·파일 round trip·CLI/MCP의 기존 계약·디자인 측정과 독립 리뷰를 통과한다.

## 비목표와 한계

코멘트 본문은 plain text다. 첨부·Markdown/HTML 렌더링·답글·검색·벌크 해결·대상 수동 재지정·삭제 복구·영구 초안 저장은 이 기능에 포함하지 않는다. 강제 종료 후 초안 복구는 보장하지 않는다. 시계 차이와 로컬 파일 append 동시성의 기존 한계를 유지한다. HTML·text 스냅샷은 사람·에이전트가 참고하는 데이터로 보존하지만 위치 추정에 쓰지 않는다. 같은 selector가 다른 요소를 가리킬 가능성은 Outdated 경고와 함께 남는다.

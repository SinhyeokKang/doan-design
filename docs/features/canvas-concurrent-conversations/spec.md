# canvas-concurrent-conversations — spec

상위 feature [canvas-multi-conversation](../canvas-multi-conversation/spec.md)의 하위 1이다. 상위의 공통 결정 1–8(보관 없음, 동시 실행, 동시 편집 허용, 기존 보관 대화를 보통 대화로, 기본 대화 고르기, 프로토타입 창의 대화 전환, handoff·승격 합류, `index.json` v3)을 그대로 따르고, 여기서는 런타임·저장 형식·캔버스 페이지와 대화 목록을 쓰는 화면을 정한다. 사이드바는 하위 2다.

## 사용자

- **사람**: 한 캔버스에서 대화 여러 개를 동시에 보내고, 보드와 패널에서 어느 대화가 무엇을 하는지 보고, 대화 사이를 오간다.
- **에이전트**: 앱 대화 안의 에이전트. 다른 대화가 같은 캔버스에서 동시에 돌 수 있다. `doan work update`, `doan handoff`의 CLI 동작과 출력은 바뀌지 않는다.

## 문제

- 새 대화를 시작하면 main이 같은 캔버스의 현재 대화를 보관하고, 돌고 있으면 그 턴을 끊는다(`app/src/main/conversation/service.ts:355`, `:366-370`, `:379`).
- 렌더러는 현재 대화가 작업 중이면 새 대화와 복원 보내기를 막는다(`app/src/renderer/canvasConversation.ts:107`, `dockedRules.ts:84` `dockedAvailability`).
- 보드 알림·Stop·작업 메모·배지·Overview 행·프로토타입 창은 모두 "현재 대화 하나"를 전제로 한다(상위 design.md '지금 구조').

## 정한 점

상위 공통 결정 1–8에 더해 다음을 정한다.

1. **보드 알림과 Stop은 패널이 보여 주는 대화를 따른다**. 보드의 glow, 점 무늬, "Agent is working"/"Agent needs your answer" 알림과 Stop은 패널에 보이는 대화를 따른다. 그 대화가 쉬고 있으면 그 캔버스에서 작업 중인 다른 대화 하나를 따른다(답을 기다리는 대화가 먼저, 지금 알림의 순서와 같다). 따르는 대화 말고도 작업 중인 대화가 있으면 알림에 "+2 working"처럼 수를 붙이고, 그 수를 누르면 그런 대화 하나로 패널이 간다. Stop은 따르는 대화 하나만 멈춘다.
2. **작업 메모와 Following은 보드 알림이 따르는 대화의 것만 따른다**. 다른 대화의 `doan work update`는 화면을 움직이지 않는다.
3. **접힌 패널의 Show conversation 배지는 그 캔버스 모든 대화 중 가장 강한 신호**를 보인다(답 필요 > 작업 중 > 안 본 종료). 사이드바 슬롯과 같은 순서다.
4. **Overview의 Canvas conversations는 대화당 한 행**이다. 같은 캔버스가 여러 행이 될 수 있으므로 행에 대화 제목을 보인다.
5. **패널 제목 메뉴**는 그 캔버스의 대화를 모두 최근 활동 순으로 보이고, 패널에 보이는 대화에 체크를 둔다. 행의 상태 표시(답 필요, 작업 중, 사용량 한도 대기, 안 본 종료)와 Delete는 그대로다. 메뉴가 열린 동안 순서는 바뀌지 않는다.
6. **보던 대화를 삭제하면** 남은 대화에서 상위 결정 5로 다음 대화를 고른다. 남은 대화가 없으면 새 대화 상태다.
7. **PoC를 먼저 한다**. 다섯 프로바이더(Claude Code, Codex, Cursor, Antigravity, GitHub Copilot) 모두 같은 계정으로 한 캔버스에서 턴 여러 개를 동시에 돌려 본다. 실제 로그인을 쓰고, provider 로그인 probe 관행을 따른다(실제 HOME, 브라우저 로그인은 사용자가 승인, 로그인된 프로필을 실행 내내 재사용, 병합 전에 로그아웃하고 지운다). 관찰은 이 feature 문서에 적는다.

## 완료 조건

- 같은 캔버스에서 대화 A가 작업 중일 때 새 대화 B를 보내면 A의 턴이 끝까지 돌고 B도 돈다. 둘 다 패널 제목 메뉴에 작업 중으로 보이고, 어느 것도 보관되지 않는다.
- A를 보면서 B로 보내기가 막히지 않는다. "The current conversation on this canvas is still running." 문구가 없어졌다.
- 보드 알림이 패널에 보이는 대화를 따르고, 다른 대화가 작업 중이거나 답을 기다리면 "+N working"이 붙는다(N은 그 둘의 합이다). 그 수를 누르면 패널이 그 대화로 간다. Stop은 따르는 대화만 멈춘다. 작업 메모와 Following도 그 대화만 따른다.
- 접힌 패널의 배지가 캔버스 전체에서 가장 강한 신호를 보인다.
- Overview의 Canvas conversations가 대화마다 한 행이고 행에 대화 제목이 있다.
- 프로토타입 창의 머리 제목이 그 캔버스의 대화를 고르는 메뉴이고, 거기서 새 대화도 시작한다. 알림 억제는 그 창이 보여 주는 대화를 따른다.
- `doan handoff`와 승격이 대화가 있거나 작업 중인 캔버스에도 대화를 더한다. 기존 대화는 그대로다.
- Move to Trash는 그 캔버스에서 작업 중인 대화가 하나라도 있으면 지금처럼 막힌다.
- 업데이트 전 `index.json` v2의 보관 대화가 v3에서 보통 대화로 목록에 나오고, 옛 이벤트 기록(`conversation.archived`·`restored` 포함)이 그대로 읽힌다. 이전 빌드는 v3 색인을 "Unsupported conversation index version"으로 거부한다.
- PoC 관찰이 다섯 프로바이더 모두 이 문서에 있다.

## 하지 않는 것

- 사이드바(하위 2).
- 동시 편집 충돌을 알리거나 해결하는 것.
- 프로젝트 대화(Overview·Home)의 모델. "작업 중인 프로젝트 대화는 루트당 하나"는 그대로다.
- `doan handoff`·`doan work`의 CLI 출력, 소켓 형식, guide·스킬 스텁.
- 대화 수나 동시 턴 수의 상한.

## 사용자 결정(2026-11-14 리뷰 전)

- **PoC 방식**: 지금 develop은 앱에서 동시 턴을 막으므로, PoC는 `.scratch` probe가 프로바이더별 실행 경로를 앱 밖에서 직접 돌린다.
- **"+N working"**: 작업 중인 대화와 답을 기다리는 대화를 함께 센다. 누르면 답을 기다리는 대화부터 간다.
- **스레드 표시**: 옛 기록의 'archived'·'restored' 표시는 업데이트 뒤 스레드에서 사라진다. 메시지와 다른 기록은 그대로다.

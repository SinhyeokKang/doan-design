# agent-conversation — spec

캔버스 위에서 에이전트와 실시간으로 대화하는 기능의 **기반**이다. 사람이 요소나 좌표를 찍고 말하면, 그 캔버스를 그린 에이전트 세션(또는 새 세션)이 답하면서 캔버스를 고치고, 앱은 바뀐 파일을 바로 다시 그린다. 이 feature는 UI 없이 기반만 만든다. 화면(오른쪽 패널의 대화·인스펙터 탭, 시작 팝오버, 대화 핀, 대화 목록 버튼)과 코멘트 제거는 `buzz-restyle`의 대화 UI 자식(기존 `buzz-comment` 자리)이 이 기반 위에서 만든다(2026-10-26 user).

## 범위 확인

PRODUCT §3 Out of scope 세 항목을 바꾼다. 사용자가 2026-10-26에 구현하겠다고 확인했다("이건 앱 사용 전반을 완전히 바꾸는 핵심 기능", "웬만하면 구현할 예정").

- 3 **Conversation**(앱 안에 에이전트·채팅·답글을 두지 않음): 앱이 에이전트와의 대화를 연다.
- 4 **Waking the agent**(주도권은 사람에게, doan은 에이전트를 깨우지 않음): 사람이 보낸 메시지로 앱이 에이전트 프로세스를 띄운다. 사람이 보내지 않으면 깨우지 않는다.
- 7 **Real-time co-editing**: 사람과 에이전트가 한 캔버스를 두고 실시간으로 주고받는다. 사람이 캔버스를 직접 편집하지는 않는다(§3 Out of scope 1 'Drawing'은 그대로).

tasks의 첫 결정 task가 PRODUCT §3과 §7을 고친다.

## 사용자

- **사람(앱 사용자)**: 이 feature가 main에 들어가도 화면은 바뀌지 않는다. 대화 UI 자식이 붙은 뒤에 다음을 얻는다.
  - 캔버스의 요소나 좌표를 대상으로 "이거 어떻게 해봐"라고 말하고, 에이전트의 답과 진행 상황을 실시간으로 받는다. 에이전트가 고친 캔버스는 바로 다시 그려진다.
  - 그 캔버스를 그린 세션의 맥락을 이어서 대화하거나, 새 세션으로 대화를 시작한다.
  - 에이전트를 연결한 사용자는 앱에서 바로 새 디자인을 시작한다(지금 FirstPrompt의 "복사해서 터미널에 붙이기"를 대신한다).
- **에이전트**: 지금처럼 `design/*.html`을 쓰고 `doan check`를 돌린다. 이때 doan이 어느 세션이 어느 캔버스를 썼는지 기록한다. 앱이 띄운 대화에서는 대상(캔버스·프레임·요소·좌표)과 사람의 말을 받아 캔버스를 고친다.

## 문제

- 지금 루프(PRODUCT §4 Loop 4·5)에서 사람은 앱에서 코멘트를 남기고 터미널로 가서 에이전트에게 말하고, 다시 앱으로 돌아와 확인한다. 수정 한 번에 창을 두 번 오간다.
- 앱은 에이전트 세션을 전혀 모른다. 어느 세션이 캔버스를 그렸는지, 그 세션을 이어받을 수 있는지 알 방법이 없다.
- 앱은 에이전트 프로세스를 띄우거나, 응답을 스트리밍받거나, 권한 요청에 답할 수단이 없다.

## 완료 조건

- PoC가 기록되어 있다(PRODUCT §6): 세션 id 확보, 전송 방식(직접 CLI 스트리밍과 ACP 어댑터 비교), 기존 세션 이어받기·갈라내기, 권한 요청, 중단, 수정 반영 지연, 같은 세션이 터미널에 열려 있을 때의 안전성. 통과 기준과 관찰값이 날짜와 버전과 함께 있다.
- PRODUCT §3 Out of scope 3·4·7과 §4 Loop가 새 범위로 고쳐져 있고, §7에 날짜와 근거가 있다.
- 에이전트가 `doan check`(그리고 MCP `check`)를 돌리면 doan이 그 캔버스와 세션(런타임, 세션 id, 작업 디렉터리, 시각)을 기기 로컬에 기록한다. 세션 id를 얻지 못하면 기록하지 않고 조용히 넘어간다. 확인: Go 테스트와 실제 Claude Code·Codex 관찰.
- 앱 main이 대화를 연다: (a) 기록된 세션을 갈라내어 이어받기, (b) 같은 repo에서 새 세션, (c) 새 디자인 시작(프로젝트와 주제). 메시지를 보내고, 응답·도구 활동·파일 변경·권한 요청·끝·오류를 순서대로 스트리밍하고, 권한 요청에 답하고, 중단할 수 있다. 확인: 가짜 에이전트로 도는 e2e suite와 실제 에이전트 관찰.
- 대화는 기기 로컬에 저장되고 앱을 다시 켜도 목록과 내용이 돌아온다. 확인: 순수 함수 테스트와 e2e 재시작 단계.
- 대화 중 에이전트가 쓴 캔버스 변경이 지금의 파일 감시와 다시 그리기로 반영된다. 확인: e2e에서 가짜 에이전트가 파일을 쓰면 캔버스가 다시 그려진다.
- 앱 종료 때 실행 중인 에이전트 프로세스가 정리되고, 대화 기록이 손상되지 않는다. 확인: e2e 종료 단계(실행 중 Quit).
- 렌더러에 노출하는 IPC 계약이 정해져 있고 ARCHITECTURE에 적혀 있다. UI 자식은 이 계약만 보고 화면을 만들 수 있다.

## 비목표

- 모든 화면 UI: 오른쪽 패널과 탭, 시작 팝오버, 대화 핀, 대화 목록 버튼, 메시지 표시, 권한 요청 표시, FirstPrompt의 Send 버튼. `buzz-restyle`의 대화 UI 자식이 한다.
- 코멘트 기능 제거(Comments 패널, Review, Hand off, Feedback, `.doan/comments` 쓰기). 대화 UI 자식이 대화 UI와 함께 한다. 이 feature 동안 코멘트는 지금처럼 동작한다.
- 대화를 repo 파일로 남겨 팀과 공유하는 일(이번 결정은 기기 로컬 저장, design 참고).
- Claude Code와 Codex 밖의 에이전트(PRODUCT §2 지원 범위 그대로).
- 사람이 캔버스를 직접 편집하는 일(PRODUCT §3 Out of scope 1).
- 에이전트 계정·인증 관리. 사용자가 이미 로그인한 CLI를 쓴다.

# agent-conversation — spec

캔버스 위에서 에이전트와 실시간으로 대화하는 기능의 **기반**이다. 사람이 요소나 좌표를 찍고 말하면, 그 캔버스를 그린 에이전트 세션(또는 새 세션)이 답하면서 캔버스를 고치고, 앱은 바뀐 파일을 바로 다시 그린다. 이 feature는 UI 없이 기반만 만든다. 화면(오른쪽 패널의 대화·인스펙터 탭, 시작 팝오버, 대화 핀, 대화 목록 버튼)과 코멘트 제거는 `buzz-restyle`의 대화 UI 자식(기존 `buzz-comment` 자리)이 이 기반 위에서 만든다(2026-10-26 user).

## 범위 확인

D1에서 PRODUCT §3·§7에 범위와 PoC 후속 계약을 반영했다(2026-10-27). In scope에 대화 항목을 더하고, Out of scope 세 항목을 고쳤다. 아래는 이전 범위에서 바뀐 내용이다. 사용자가 2026-10-26에 구현하겠다고 확인했다("이건 앱 사용 전반을 완전히 바꾸는 핵심 기능", "웬만하면 구현할 예정").

- 3 **Conversation**(앱 안에 에이전트·채팅·답글을 두지 않음): 앱이 에이전트와의 대화를 연다.
- 4 **Waking the agent**(주도권은 사람에게, doan은 에이전트를 깨우지 않음): 사람이 보낸 메시지로 앱이 에이전트 프로세스를 띄운다. 사람이 보내지 않으면 깨우지 않는다.
- 7 **Real-time co-editing**: 사람과 에이전트가 한 캔버스를 두고 실시간으로 주고받는다. 사람과 에이전트가 같은 파일을 동시에 편집하는 일은 여전히 하지 않고, 사람이 캔버스를 직접 편집하지도 않는다(§3 Out of scope 1 'Drawing'은 그대로).

D1의 계약은 PRODUCT §3·§7이 정본이다. §4 Loop 문장과 In scope 2·3(코멘트)은 대화 UI 자식이 코멘트를 걷어낼 때 고친다. 이 feature 동안 사람이 쓰는 루프는 여전히 코멘트 루프이기 때문이다.

## 사용자

- **사람(앱 사용자)**: 이 feature가 main에 들어가도 화면은 바뀌지 않는다. 바뀌는 것은 하나다: 앱 userData 디렉터리가 있는 기기에서 에이전트가 셸 `doan check`를 돌리고 유효한 세션 식별을 얻으면 `~/Library/Application Support/doan/sessions.jsonl`에 세션 기록이 쌓인다. 대화 UI 자식이 붙은 뒤에 다음을 얻는다.
  - 캔버스의 요소나 좌표를 대상으로 "이거 어떻게 해봐"라고 말하고, 에이전트의 답과 진행 상황을 실시간으로 받는다. 에이전트가 고친 캔버스는 바로 다시 그려진다.
  - 그 캔버스를 그린 세션을 같은 세션 그대로 이어서 대화하거나(fork하지 않아 터미널 쪽과 대화가 갈라지지 않는다), 새 세션으로 대화를 시작한다. 대화는 캔버스당 하나이고, 메시지 안에 요소나 좌표를 여러 개 넣어 가리킬 수 있다. 새 대화를 시작하면 이전 대화는 보관된다.
  - 에이전트를 연결한 사용자는 앱에서 바로 새 디자인을 시작한다(지금 FirstPrompt의 "복사해서 터미널에 붙이기"를 대신한다).
- **에이전트**: 하는 일과 받는 출력이 바뀌지 않는다. 지금처럼 `design/*.html`을 쓰고 셸 `doan check`를 돌리면, doan이 부수 효과로 어느 세션이 어느 캔버스를 바꿨는지 기록한다. 앱이 띄운 대화에서는 대상(캔버스·프레임·요소·좌표)과 사람의 말을 받아 캔버스를 고친다.

## 문제

- 지금 루프(PRODUCT §4 Loop 4·5)에서 사람은 앱에서 코멘트를 남기고 터미널로 가서 에이전트에게 말하고, 다시 앱으로 돌아와 확인한다. 수정 한 번에 창을 두 번 오간다.
- 앱은 에이전트 세션을 전혀 모른다. 어느 세션이 캔버스를 그렸는지, 그 세션을 이어받을 수 있는지 알 방법이 없다.
- 앱은 에이전트 프로세스를 띄우거나, 응답을 스트리밍받거나, 권한 요청에 답할 수단이 없다.

## 완료 조건

- PoC가 PRODUCT §6에 날짜·버전과 함께 기록되어 있다: 세션 id 확보(9a), 전송 방식(9b), 수정 반영 지연(9c), 터미널에 열린 세션과의 겹침(9d), 실행 환경(9e). 권한 요청을 앱으로 넘기지 못하는 전송 방식은 고르지 않았다.
- PRODUCT §3(In scope 추가, Out of scope 3·4·7)과 §7이 고쳐져 있다.
- 에이전트가 셸 `doan check`를 돌리면(MCP `check`는 기록하지 않는다), 내용이 바뀐 캔버스마다 세션 기록(런타임, 세션 id, 유효 설정 디렉터리 `configDir`, 작업 디렉터리, 해시, 시각)이 기기 로컬에 남는다. 세션 id를 얻지 못하거나 userData 디렉터리가 없으면 남기지 않고, 어느 경우든 `check`의 출력과 exit code는 그대로다. 확인: Go 테스트.
- 앱 main이 대화를 연다: `resume`(같은 세션 이어받기), `new`, `newDesign`. 이어받을 세션을 미리 볼 수 있고, 메시지를 보내고, 사람 메시지·응답·도구 활동·권한 요청·끝·실패·중단을 순번과 함께 스트리밍하고, 권한 요청에 답하고, 중단하고, 같은 캔버스에서 새 대화를 시작(이전 대화 보관)할 수 있다. 메시지 하나에 앵커를 여럿 넣을 수 있다. Claude Code 2.1.310 + SDK 0.3.310, Codex app-server 0.163.0이 초기 검증 대상이며 둘 다 resume한다. 기록이 없거나 실행 조건이 맞지 않으면 자동으로 새 세션을 만들지 않는다. 확인: 가짜 에이전트 e2e suite(tasks E1의 12단계).
- 매 resume/send 직전에 세션 점유와 버전을 확인한다(Claude는 registry·PID, Codex는 active-writer 소유권). 점유는 `session_in_use`, 확인 불가는 `session_unavailable`이다. 사용자(2026-10-27)가 Claude 검사 후 접속 경쟁을 수용했지만 원자적 배타성·동기화는 보장하지 않는다. Codex active-writer 거절도 `session_in_use`이며 사용자 daemon을 종료하지 않는다. 확인: T/A/E의 실패·재검사 테스트.
- 기록의 `configDir`은 현재 셸이 선택한 프로필과 같아야 하며 cwd는 실제로 같은 root 안에 있어야 한다. 잘못된 기록으로 다른 프로필·cwd에서 실행하지 않는다. 권한 정책을 상속하고 강제 bypass를 두지 않는다. 확인: C/T/A 테스트.
- 대화가 기기 로컬에 받는 즉시 저장되고, 앱을 다시 켜면 목록과 내용이 돌아온다. 끝나지 않은 턴은 중단으로, 답하지 않은 권한 요청은 만료로 보인다. 확인: 순수 함수 테스트와 e2e 재시작 단계.
- 대화 중 에이전트가 쓴 캔버스 변경이 지금의 파일 감시와 다시 그리기로 반영된다. 확인: e2e.
- 앱 종료(창 숨김 뒤 Quit, 권한 대기 중 Quit 포함) 때 에이전트 프로세스 그룹이 정리되고 exit 0이며, 대화 기록이 손상되지 않는다. 확인: e2e.
- 실제 사용자 상태 검사가 `sessions.jsonl`과 `conversations/`도 감시하고, 모든 e2e·eval 실행에서 바뀌지 않는다.
- 실제 Claude Code에서 캔버스를 쓰고 `check`를 돌린 세션을 앱이 이어받아 한 턴을 돌리면 `message.done`과 `turn.done`이 오고 캔버스가 다시 그려진다(Codex는 지원 범위 안에서, 사용자 허락 뒤). 확인: PRODUCT §6 관찰 기록.
- ARCHITECTURE §7에 design 'IPC 계약'의 채널, 입력, 오류 코드, 이벤트가 모두 있다. 확인: `grep -n 'conversation:start' docs/ARCHITECTURE.md`.

## 비목표

- 모든 화면 UI: 오른쪽 패널과 탭, 시작 팝오버, 대화 핀, 대화 목록 버튼, 메시지 표시, 권한 요청 표시, FirstPrompt의 Send 버튼. `buzz-restyle`의 대화 UI 자식이 한다.
- 코멘트 기능 제거(Comments 패널, Review, Hand off, Feedback, `.doan/comments` 쓰기). 대화 UI 자식이 대화 UI와 함께 한다. 이 feature 동안 코멘트는 지금처럼 동작한다.
- 대화를 repo 파일로 남겨 팀과 공유하는 일(이번 결정은 기기 로컬 저장, design 참고).
- Claude Code와 Codex 밖의 에이전트(PRODUCT §2 지원 범위 그대로).
- 사람이 캔버스를 직접 편집하는 일(PRODUCT §3 Out of scope 1).
- 에이전트 계정·인증 관리. 사용자가 이미 로그인한 CLI를 쓴다.

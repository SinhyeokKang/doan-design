# buzz-onboarding — spec

작성: 2026-10-27. 상태: 디자인 승인·HTML 검증 완료(2026-10-28), feature-review 진행 중. 사용자 지시로 design-draft를 먼저 검토했다. 구현은 시작하지 않는다.

## 전제와 범위

`buzz-restyle`의 온보딩 자식이다. `buzz-ds`·`buzz-shell`의 구현된 디자인 시스템을 사용하며, **agent-auth가 완료된 상태를 전제**해 기획한다. 이것은 현재 agent-auth 구현 완료를 기록하는 문장이 아니다. 구현 착수 때 실제 인증 API·다섯 실행기·보안 저장·취소 계약을 인수한다.

사람은 첫 실행 화면에서, 또는 자기 에이전트에게 CLI/MCP 온보딩을 요청해 도안 사용을 준비한다(2026-10-28 사용자 추가 승인). 고정 온보딩 명령·도구를 추가하되 기존 캔버스 작성 규칙과 명령 동작은 유지한다. OAuth·토큰 저장·갱신을 재구현하지 않고 agent-auth의 비밀 없는 main 서비스를 앱 preload와 인증된 로컬 CLI/MCP 어댑터에서 함께 소비한다.

2026-10-27 사용자 흐름: **Welcome 문구와 시작하기 → 에이전트 로그인 → 로컬 프로젝트 선택 또는 GitHub 레포 링크 → 홈 이동**. Welcome은 시작 화면이며 설정 단계는 두 개다. 완료 축하 화면이나 첫 프롬프트 단계를 추가하지 않는다. 홈의 대화 인풋창·프로젝트 선택 UI는 `buzz-home` 담당이다.

## 현재 문제와 변경

현재 `Onboarding.tsx`는 CLI → Agents → Project → First prompt 네 단계를 표시한다. Agents는 계정 로그인이 아니라 외부 CLI 스킬·MCP 설정이며, 프로젝트 설정에는 Token CSS 선택이 있다. Close·Escape로 닫을 때 `onboarding.json`에 빈 객체를 저장해 첫 실행을 종료한다. 새 흐름의 로그인·프로젝트 준비 완료와 이 닫힘 기록을 혼동하지 않아야 한다.

새 온보딩에는 외부 셸 CLI 설치·MCP 연결·복사할 첫 프롬프트 화면을 두지 않는다. 앱 내부 실행에 필요한 준비는 agent-auth가 맡는다. Settings와 다른 화면이 사용하는 기존 공용 설정·FirstPrompt 기능을 이 변경만으로 삭제하지 않는다.

## 화면 흐름

1. **Welcome**: `doan` 워드마크, “A place for your next idea.” / “Bring it to life on canvas.” 두 줄 문장, `Get started` 버튼. 신호등과 창 드래그 영역은 유지한다. 시작 버튼으로 로그인 화면에 들어간다.
2. **에이전트 로그인**: Claude Code, Codex, Cursor, Antigravity, GitHub Copilot을 이 순서로 표시한다. 플랫폼별 계정 하나이며 다섯 개 전부 로그인을 요구하지 않는다. 로그인 대기·취소·오류·연결됨·재인증·실행 준비 불가를 구분한다. 토큰·인증 파일 경로는 표시하지 않는다.
3. **프로젝트**: 로컬 폴더 선택과 GitHub URL 입력을 제공한다. 선택한 이름·경로·준비 결과를 확인하고 홈으로 이동한다. 로컬 폴더는 Git 리포가 아니어도 현재 지원 범위에서 사용할 수 있다. 파일 생성이 필요하면 그 결과를 설명하며 기존 설정 오류를 덮어쓰지 않는다.
4. **홈 인계**: 선택한 canonical 프로젝트 root를 앱에 등록하고 홈의 선택 컨텍스트로 넘긴다. 대화나 Canvas를 자동으로 생성하지 않는다. 홈 본문의 새 UI는 만들지 않는다.

## 이미 로컬에 있는 리포 — 사용자 승인

GitHub URL과 일치하는 등록 프로젝트가 있으면 기존 폴더를 제시한다. 여러 checkout이나 worktree가 있으면 로컬 경로를 보여 주고 하나를 고르게 한다. 아직 등록되지 않은 리포는 `Choose existing folder`로 사용자가 위치를 지정한다. URL만으로 디스크 전체를 검색하지 않는다.

URL을 근거로 찾은 폴더는 접근 가능 여부와 remote 일치를 다시 확인한 뒤 연결한다. 같은 리포 URL이라고 같은 로컬 폴더인 것은 아니다. 일치하지 않으면 기존 리포를 변경하지 않고 다른 폴더 선택 또는 URL 수정으로 돌아간다. 로컬 폴더를 직접 고른 경로에는 GitHub remote를 요구하지 않는다.

## 추가 확정 (2026-10-27)

- 에이전트 연결과 프로젝트 각각 하나 이상이 필수다. 건너뛰기를 제공하지 않는다. 중간 종료는 완료로 기록하지 않는다.
- GitHub URL에서 로컬 리포를 재사용하고 없으면 기존 Git/gh 인증으로 clone한다. PRODUCT의 Git 작업 제외에 온보딩 clone 예외를 승격한다. 별도 GitHub OAuth·토큰 보관·레포 목록은 제외한다.
- 접근 실패는 URL을 유지하고 다시 시도·로컬 폴더 선택을 제공한다. `gh auth login`으로 계정·권한을 확인하도록 안내하되 실패 원인을 단정하지 않는다.
- Welcome에만 accent 그라디언트와 alpha grain을 적용한다. 그라디언트는 움직이지 않는다(2026-10-28 사용자).
- 기존 프리미티브·AppShell 톤을 재사용한다. 사용자 지시로 디자인 초안 검토가 feature-review보다 먼저다.

2026-10-28 사용자 확정: 미완료 상태로 앱을 종료했다 다시 켜면 Welcome부터 시작한다. 저장된 에이전트 연결·프로젝트는 유지하고 각 단계에서 상태를 다시 확인한다. 기존 `{}` 닫힘 표식은 새 온보딩 완료 증거가 아니다. 최소 한 공급자의 ready와 정상 프로젝트 등록·완료 저장을 확인한 뒤 홈으로 이동한다.

## 에이전트에게 맡기는 온보딩 — 2026-10-28 사용자 승인

앱만 설치한 사용자가 자기 에이전트에게 setup을 요청할 수 있어야 한다. PATH의 doan, MCP 등록, skill 설치, `.doan/config.json`을 선행 조건으로 요구하지 않는다. 앱 번들 CLI의 절대 경로로 도움말·가이드와 onboarding start를 실행한다. MCP가 등록돼 있으면 같은 기능을 고정 도구로 호출한다. 이 범위에서 사용자의 외부 에이전트 설정을 자동 수정하거나 전역 MCP를 몰래 등록하지 않는다.

앱이 꺼져 있으면 번들 CLI가 자신이 속한 도안 앱만 눈에 보이게 실행한다. 일반 active 명령의 앱 미실행 동작은 바꾸지 않는다. 앱 UI와 CLI/MCP가 같은 main 세션·연결·프로젝트·진행 조건·완료 기록을 공유한다. 앱 실행이 필요하며 독립 headless 인증/clone 백엔드를 만들지 않는다.

에이전트는 상태 조회, 로그인 시작, 프로젝트 검사·선택·초기화·clone, 완료, 명시적 작업 취소를 요청한다. 로그인과 계정 동의는 사용자가 시스템 브라우저에서 한다. 비밀번호·OAuth 토큰·callback 인증 코드·인증 파일 경로를 에이전트에게 받거나 반환하지 않는다. 명령 접수·브라우저 열기·clone 시작을 온보딩 완료로 표시하지 않는다.

범용 앱 조작·임의 IPC 호출·임의 명령 실행·대화 전송은 이 인터페이스에 넣지 않는다. 프로젝트 경로와 저장소는 사용자가 요청한 범위를 사용하며, 캔버스/코멘트의 내용은 실행 권한이 아니다.

## 완료 조건

- 최소 한 공급자가 ready이고 선택한 canonical 프로젝트 root의 정상 재읽기·등록과 새 완료 표식 저장이 성공해야 홈으로 이동한다. 완료 저장 실패 시 프로젝트를 유지하고 저장을 재시도하며, 성공 전에는 홈으로 이동하지 않는다.
- 다섯 플랫폼 상태를 표시하고 최소 한 플랫폼이 ready일 때 Agent에서 진행하고 온보딩을 완료할 수 있다(2026-10-28 사용자 확정). ready는 로그인·보안 저장·계정 식별·지원 실행 버전·도구 준비 완료이며, 실제 모델 요청 성공이나 유료 구독 확인은 요구하지 않는다. UI가 인증 원문을 받지 않는다.
- 로그인 취소·브라우저 복귀·만료·재시도·종료 때 오래된 결과가 화면이나 연결을 덮지 않는다.
- 같은 로컬 root를 중복 등록하지 않고, 사라진 폴더·권한 오류·설정 오류를 복구할 수 있다.
- GitHub URL 경로는 승인된 범위만 구현한다. 기존 폴더의 파일·remote·branch를 암묵적으로 바꾸지 않는다.
- 앱만 설치한 상태에서 번들 CLI 또는 등록된 MCP로 시작해 브라우저 승인 외의 setup을 수행하고, 앱 UI와 같은 ready·프로젝트·완료 저장 조건으로 홈에 도달한다.
- CLI 종료/조회 연결 해제는 진행 중 작업을 끊지 않으며, 중복 요청과 늦은 결과가 새 로그인·clone을 만들지 않는다.
- 홈 인계에 프로젝트 선택을 보존하며 자동 요청·Canvas 생성·첫 프롬프트 UI가 없다.
- 키보드·포커스·중첩 모달과 긴 계정/경로 값을 검증하고 승인된 초안과 구현을 design-sync로 대조한다.

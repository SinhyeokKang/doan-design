# buzz-onboarding — spec

작성: 2026-10-27. 상태: 디자인 승인·HTML 검증 완료(2026-10-28). agent-auth 병합 뒤 feature-review를 다시 했다(2026-10-28). 구현은 시작하지 않았다. 선행 feature `agent-cli-versions`의 `/orchestrate`와 병합 뒤에 이 feature의 `/orchestrate`를 시작한다(2026-10-28 사용자). 그 전에 tasks의 F4–F6을 마친다.

## 전제와 범위

`buzz-restyle`의 온보딩 자식이다. `buzz-ds`·`buzz-shell`의 구현된 디자인 시스템을 사용하며, **agent-auth가 완료된 상태를 전제**해 기획한다. agent-auth는 2026-10-28 main에 병합됐다. 인수할 인증 API·다섯 실행기·보안 저장·취소 계약은 [ARCHITECTURE §7 'Agent authentication'](../../ARCHITECTURE.md#agent-authentication-2026-10-28-agent-auth)에 있고, 온보딩이 처리할 항목은 [design의 agent-auth 인계](./design.md#agent-auth-인계-2026-10-28)에 있다.

사람은 첫 실행 화면에서, 또는 자기 에이전트에게 CLI/MCP 온보딩을 요청해 도안 사용을 준비한다(2026-10-28 사용자 추가 승인). 고정 온보딩 명령·도구를 추가하되 기존 캔버스 작성 규칙과 명령 동작은 유지한다. OAuth·토큰 저장·갱신을 재구현하지 않고 agent-auth의 비밀 없는 main 서비스를 앱 preload와 인증된 로컬 CLI/MCP 어댑터에서 함께 소비한다. 로그인은 도안 전용 연결이다. 터미널이나 Orca에서 이미 로그인한 Claude Code·Codex 등의 기존 로그인을 읽거나 재사용하지 않으므로, 사용자는 도안에서 다시 로그인한다.

2026-10-27 사용자 흐름: **Welcome 문구와 시작하기 → 에이전트 로그인 → 로컬 프로젝트 선택 또는 GitHub 레포 링크 → 홈 이동**. Welcome은 시작 화면이며 설정 단계는 두 개다. 완료 축하 화면이나 첫 프롬프트 단계를 추가하지 않는다. 홈의 대화 인풋창·프로젝트 선택 UI는 `buzz-home` 담당이다.

## 현재 문제와 변경

현재 `Onboarding.tsx`는 CLI → Agents → Project → First prompt 네 단계를 표시한다. Agents는 계정 로그인이 아니라 외부 CLI 스킬·MCP 설정이며, 프로젝트 설정에는 Token CSS 선택이 있다. Close·Escape로 닫을 때 `onboarding.json`에 빈 객체를 저장해 첫 실행을 종료한다. 새 흐름의 로그인·프로젝트 준비 완료와 이 닫힘 기록을 혼동하지 않아야 한다.

새 온보딩에는 외부 셸 CLI 설치·MCP 연결·복사할 첫 프롬프트 화면을 두지 않는다. 공급자 CLI의 설치·업데이트는 사용자가 하고, 온보딩은 Install·Update 안내만 한다. 도안이 직접 내려받는 것은 Antigravity 서버뿐이다(agent-auth). Settings와 다른 화면이 사용하는 기존 공용 설정·FirstPrompt 기능을 이 변경만으로 삭제하지 않는다.

## 화면 흐름

1. **Welcome**: `doan` 워드마크, “A place for your next idea.” / “Bring it to life on canvas.” 두 줄 문장, `Get started` 버튼. 신호등과 창 드래그 영역은 유지한다. 시작 버튼으로 로그인 화면에 들어간다.
2. **에이전트 로그인**: Claude Code, Codex, Cursor, Antigravity, GitHub Copilot을 이 순서로 표시한다. 플랫폼별 계정 하나이며 다섯 개 전부 로그인을 요구하지 않는다. 토큰·인증 파일 경로는 표시하지 않는다. 각 행의 첫 버튼은 상태에 따라 다르다. CLI가 없으면 Install, 설치 버전이 지원 최소 버전보다 낮으면 Update, 그 밖에는 Sign in이다(2026-10-28 사용자). 다음 상태를 구분하고, 각 상태의 다음 행동은 agent-auth의 `readiness.action`과 `actions`를 따른다.
   - 링크 준비 중(Antigravity 첫 로그인은 서버 내려받기로 약 20초), 브라우저 대기, 취소됨, 실패(원인별 문구), 연결됨, 재시작 뒤 확인 전(unverified), 재인증 필요, 로그아웃 실패, 다른 로그인 진행 중(`busy`), 다른 창이 시작한 로그인, 미설치·업데이트 필요, 인증 저장소를 읽지 못함.
   - Cursor·Copilot 로그인 CLI는 브라우저를 스스로 연다. 화면은 브라우저 탭이 이미 열렸을 수 있다고 알린다.
   - 로그아웃 실패·재인증 상태에서만 그 행에 Sign out·Sign in again 복구 버튼을 둔다. 정상 연결의 계정 관리는 Settings 담당이다.
   - 다른 공급자가 ready일 때 Continue를 누르면, 주 창이 소유한 진행 중 로그인을 취소하고 넘어간다.
3. **프로젝트**: 로컬 폴더 선택과 GitHub URL 입력을 제공한다. 선택한 이름·경로·준비 결과를 확인하고 홈으로 이동한다. 로컬 폴더는 Git 리포가 아니어도 현재 지원 범위에서 사용할 수 있다. 파일 생성이 필요하면 그 결과를 설명하며 기존 설정 오류를 덮어쓰지 않는다.
4. **홈 인계**: 선택한 canonical 프로젝트 root를 앱에 등록하고 홈의 선택 컨텍스트로 넘긴다. 대화나 Canvas를 자동으로 생성하지 않는다. 홈 본문의 새 UI는 만들지 않는다.

## 이미 로컬에 있는 리포 — 사용자 승인

GitHub URL과 일치하는 등록 프로젝트가 있으면 기존 폴더를 제시한다. 여러 checkout이나 worktree가 있으면 로컬 경로를 보여 주고 하나를 고르게 한다. 아직 등록되지 않은 리포는 `Choose existing folder`로 사용자가 위치를 지정한다. URL만으로 디스크 전체를 검색하지 않는다.

URL을 근거로 찾은 폴더는 접근 가능 여부와 remote 일치를 다시 확인한 뒤 연결한다. 같은 리포 URL이라고 같은 로컬 폴더인 것은 아니다. 일치하지 않으면 기존 리포를 변경하지 않고 다른 폴더 선택 또는 URL 수정으로 돌아간다. 로컬 폴더를 직접 고른 경로에는 GitHub remote를 요구하지 않는다.

## 추가 확정 (2026-10-27)

- ready 공급자와 프로젝트가 각각 하나 이상 필요하다. 건너뛰기를 제공하지 않는다. 중간 종료는 완료로 기록하지 않는다.
- GitHub URL에서 로컬 리포를 재사용하고 없으면 사용자의 기존 Git credential helper·SSH로 clone한다. Copilot 연결이 보관하는 GitHub 토큰은 에이전트 인증 전용이라 clone에 쓰지 않는다. PRODUCT의 Git 작업 제외에 온보딩 clone 예외를 승격한다. 별도 GitHub OAuth·토큰 보관·레포 목록은 제외한다.
- 접근 실패는 URL을 유지하고 다시 시도·로컬 폴더 선택을 제공한다. `gh auth login`으로 계정·권한을 확인하도록 안내하되 실패 원인을 단정하지 않는다.
- Welcome에만 accent 그라디언트와 alpha grain을 적용한다. 그라디언트는 움직이지 않는다(2026-10-28 사용자).
- 기존 프리미티브·AppShell 톤을 재사용한다. 사용자 지시로 디자인 초안 검토가 feature-review보다 먼저다.

2026-10-28 사용자 확정: 미완료 상태로 앱을 종료했다 다시 켜면 Welcome부터 시작한다. 저장된 에이전트 연결·프로젝트는 유지하고 각 단계에서 상태를 다시 확인한다. 기존 `{}` 닫힘 표식은 새 온보딩 완료 증거가 아니다. 최소 한 공급자의 ready와 정상 프로젝트 등록·완료 저장을 확인한 뒤 홈으로 이동한다.

## 에이전트에게 맡기는 온보딩 — 2026-10-28 사용자 승인

앱만 설치한 사용자가 자기 에이전트에게 setup을 요청할 수 있어야 한다. PATH의 doan, MCP 등록, skill 설치, `.doan/config.json`을 선행 조건으로 요구하지 않는다. 앱 번들 CLI의 절대 경로로 도움말·가이드와 onboarding start를 실행한다. MCP가 등록돼 있으면 같은 기능을 고정 도구로 호출한다. 이 범위에서 사용자의 외부 에이전트 설정을 자동 수정하거나 전역 MCP를 몰래 등록하지 않는다.

앱이 꺼져 있으면 번들 CLI가 자신이 속한 도안 앱만 눈에 보이게 실행한다. 일반 active 명령의 앱 미실행 동작은 바꾸지 않는다. 앱 UI와 CLI/MCP가 같은 main 세션·연결·프로젝트·진행 조건·완료 기록을 공유한다. 앱 실행이 필요하며 독립 headless 인증/clone 백엔드를 만들지 않는다.

에이전트는 상태 조회, 로그인 시작, 프로젝트 검사·선택·초기화·clone, 완료, 명시적 작업 취소를 요청한다. 로그인과 계정 동의는 사용자가 시스템 브라우저에서 한다. 비밀번호·OAuth 토큰·callback 인증 코드·인증 파일 경로를 에이전트에게 받거나 반환하지 않는다. 계정 email·표시 이름도 반환하지 않고 공급자·상태·다음 행동만 돌려준다(2026-10-28 사용자). 명령 접수·브라우저 열기·clone 시작을 온보딩 완료로 표시하지 않는다.

범용 앱 조작·임의 IPC 호출·임의 명령 실행·대화 전송은 이 인터페이스에 넣지 않는다. 프로젝트 경로와 저장소는 사용자가 요청한 범위를 사용하며, 캔버스/코멘트의 내용은 실행 권한이 아니다.

## 완료 조건

- 최소 한 공급자가 ready이고 선택한 canonical 프로젝트 root의 정상 재읽기·등록과 새 완료 표식 저장이 성공해야 홈으로 이동한다. 완료 저장 실패 시 프로젝트를 유지하고 저장을 재시도하며, 성공 전에는 홈으로 이동하지 않는다.
- 다섯 플랫폼 상태를 표시하고 최소 한 플랫폼이 ready일 때 Agent에서 진행하고 온보딩을 완료할 수 있다(2026-10-28 사용자 확정). ready 판정은 agent-auth의 `readiness.ready`를 그대로 쓴다. 이 값은 연결 확인(verified)·지원 버전·도구 준비를 요구하고 계정 ID는 요구하지 않는다(Codex·Antigravity는 계정 ID가 없다). 유료 구독은 확인하지 않는다.
- 재시작 뒤 Agent 단계에 들어오거나 설치·업데이트 페이지에서 돌아오면 Copilot을 뺀 공급자는 자동으로 확인한다. Copilot 확인은 모델 요청 1회를 쓰므로 사용자가 Retry를 누를 때만 하고, 버튼 옆에 그 비용을 알린다(2026-10-28 사용자).
- UI는 인증 원문을 표시하거나 저장하지 않는다. 예외는 Antigravity의 주소 붙여넣기다. 브라우저가 로컬 주소에 닿지 못했을 때 사용자가 보조 버튼으로 입력창 하나짜리 모달을 열어 브라우저 주소를 붙여넣으면, UI는 그 값을 main에 전달만 한다(2026-10-28 사용자). 에이전트(CLI/MCP) 경로에서는 이 값을 받지 않는다.
- 인증 저장소를 읽지 못하면 Agent 단계에 오류와 Try again을 보인다. 저장소 초기화 기능은 만들지 않는다(2026-10-28 사용자).
- 로그인 취소·브라우저 복귀·만료·재시도·종료 때 오래된 결과가 화면이나 연결을 덮지 않는다.
- 같은 로컬 root를 중복 등록하지 않고, 사라진 폴더·권한 오류·설정 오류를 복구할 수 있다.
- GitHub URL 경로는 승인된 범위만 구현한다. 기존 폴더의 파일·remote·branch를 암묵적으로 바꾸지 않는다.
- 앱만 설치한 상태에서 번들 CLI 또는 등록된 MCP로 시작해 브라우저 승인 외의 setup을 수행하고(Copilot Retry와 Antigravity 주소 붙여넣기는 사람이 앱 UI에서 한다), 앱 UI와 같은 ready·프로젝트·완료 저장 조건으로 홈에 도달한다.
- CLI 종료/조회 연결 해제는 진행 중 작업을 끊지 않으며, 중복 요청과 늦은 결과가 새 로그인·clone을 만들지 않는다.
- 홈 인계에 프로젝트 선택을 보존하며 자동 요청·Canvas 생성·첫 프롬프트 UI가 없다.
- 키보드·포커스·중첩 모달을 검증한다. 긴 계정·경로 값은 말줄임 없이 줄바꿈되고, 계정 표시값이 없는 연결(Codex·Antigravity)은 공급자 이름과 `Connected`만 보인다. 보완 승인된 초안과 구현을 design-sync로 대조한다.

## 비목표

플랫폼별 복수 계정, 인증 백엔드 재구현, 기존 터미널·Orca 로그인 가져오기, 세션 자동 인계, GitHub 저장소 목록, 자체 GitHub 토큰 보관, commit/push/branch UI, 홈 대화 UI, Settings 전체 리디자인, 기존 캔버스 초안 수정.

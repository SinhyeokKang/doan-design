# buzz-onboarding — feature-review

실행일: 2026-10-28. 제품·기술·QA·UX 네 관점의 문서 리뷰를 마쳤다. 사용자 승인 디자인의 HTML 표시 검증은 통과했다. 두 제품 결정을 반영했고 동작·복구·검증 계약을 구체화했다. CLI/MCP 추가 범위까지 최종 기술·UX 재검토를 마쳤으며 남은 제품 질문은 없다. 구현은 시작하지 않았다.

## 디자인 검증과 반영

`design.md`의 「HTML 검증 근거」에 실제 Electron 측정 범위와 한계를 기록했다. 10개 프레임·33개 상태의 표시 검증은 인증·clone 기능 검증이 아니다.

이미 승인한 지시를 세 문서에 반영했다: clone 허용 범위, 최종 Welcome 문구, 말줄임표 제거, notice 12px/16px·로딩 spinner, lg CTA 48px, Back arrow, 원본 DS·Geist, 공통 프로젝트 썸네일. 철회된 translucent 버튼·입력창과 본문 전체 panel 작업은 제거했다. 뒤이은 사용자 답변으로 ready 진행과 미완료 재실행 Welcome을 확정했다. 나머지는 이 필수 조건과 기존 파일 보존·중복 방지를 만족하도록 동작 계약에 구체화했다.

## 질문과 결정

1. **진행 기준:** 최소 한 공급자의 인증·보안 저장·계정 식별·지원 실행 버전·도구 준비가 끝난 `ready`를 요구할지, 연결 저장만 끝나면 진행할지. 네 관점 모두 ready를 권장한다. 실제 모델 요청 성공·유료 구독은 새 조건으로 추가하지 않는다. **2026-10-28 사용자 확정: 실행 준비까지 완료돼야 진행한다.** spec·design·tasks에 반영했다.
2. **기존 사용자·재시작:** 기존 완료 파일의 `{}`는 닫힘도 의미한다. **2026-10-28 사용자 확정: Welcome부터 다시 시작하되 저장된 연결·프로젝트는 유지한다.** 기존 {}만으로 완료를 인정하지 않으며 각 단계에서 상태를 재확인한다. spec·design·tasks에 반영했다.

## 통합 발견 사항

### 제품

- 🔴 진행 기준·기존 완료 표식·재실행 정책이 미정이어서 완료 조건의 정답을 만들 수 없다.
- 🔴 clone 미승인 문구와 승인된 디자인에 어긋난 과거 값이 남아 있었다. 사용자 기존 승인으로 정리했다.
- 🟡 완료 조건의 “결정된 완료 조건대로”는 판정 기준이 아니다. 질문 확정 뒤 연결 조건·정상 프로젝트 재읽기/등록·완료 저장·선택 root 인계의 조건으로 바꾼다.

### 기술

- 🔴 GitHub URL 허용 문법, remote 선택, Git/gh 호출, 비대화식 인증 실패 반환 계약이 필요하다. 저장소 토큰을 직접 추출하거나 Copilot 에이전트 인증으로 대체하지 않는다.
- 🔴 clone 작업 ID·소유 창·프로세스 종료 확인·목적지 경합·부분 결과 정리·재시작 잔존 경로 처리를 정의해야 한다. 기존 파일을 삭제하거나 변경하는 구현으로 이어지면 안 된다.
- 🔴 프로젝트 등록 성공 후 완료 저장만 실패했을 때의 재시도와 홈 인계 순서가 없다. main이 현재 연결과 root를 재검사하며 이미 만든 프로젝트를 재사용하는 계약을 권장한다.
- 🟡 기존 `onboarding:open-project`의 stored/choose/confirm/refused/cancelled 및 단일 선택 스캔·비리포 확인을 어떻게 연결할지 명시해야 한다.

### QA

- 🔴 clone 취소 직후 늦은 성공, cleanup 실패, 목적지 경쟁 생성, 기존 파일 보존, 재시도 시 중복 clone/등록 방지, 인증 프롬프트 없는 실패 반환을 B1 검증에 추가해야 한다.
- 🔴 초기화·등록 완료 후 완료 표식 저장 실패를 별도 fixture로 만들고 재시도 결과를 명시해야 한다.
- 🟡 V1은 동작 목록뿐 아니라 기대 결과가 필요하다. 실제 지연 상태를 거친 버튼 disabled 후 포커스, 중첩 대화상자 Escape, 이전 URL 응답 폐기를 명시한다.

### UX

- 🔴 기존 최상위 Escape 닫기를 유지하면 필수 온보딩을 우회할 수 있다. 자식 대화상자 Escape, 최상위 Escape, Cmd+W/신호등, Cmd+Q 처리표가 필요하다.
- 🔴 인증 대기·저장·준비 중 Back/Cancel이 작업과 저장된 연결에 미치는 영향을 정의해야 한다.
- 🟡 단계 전환, 비활성 버튼, 폴더 선택 취소, 오류 이후의 포커스 위치와 상태 알림을 정해야 한다. 스피너 회전 자체를 반복 낭독하지 않는다.
- 🟡 외부 설치·업데이트·브라우저·터미널 인증 후 복귀에서 재조회할 상태를 정의해야 한다. 입력·프로젝트 선택을 유지하고 최신 결과만 반영한다.

## 확인된 경계와 근거

인증은 agent-auth, 홈 대화 UI는 buzz-home이 맡는다. 자체 GitHub OAuth·복수 계정·자동 대화/Canvas 생성은 제외한다. 로컬 폴더 identity와 remote identity를 구분하고 전체 디스크 검색·자동 pull은 하지 않는다.

참조 파일과 task의 검증 명령은 존재한다. 계약/fixture → 순수 함수 → main/UI → 실제 앱 → 정본 승격 순서와 영구 e2e suite를 추가하지 않는 정책은 유지한다.

관련 근거: `agent-auth/design.md`의 ready·attempt 소유권, `app/src/main/onboarding/machine.ts`의 needsOnboarding/markClosed, `app/src/renderer/Onboarding.tsx`의 Escape·중첩 대화상자 처리, `app/src/main/addProjects.ts`, ARCHITECTURE의 프로젝트 추가 계약, POSTMORTEM의 오래된 응답·위저드 세션 폐기·포커스·초기화 조기 성공·경쟁 파일 덮어쓰기 사례.

리뷰어는 문서와 참조 코드를 읽었으며 구현·빌드·테스트를 실행하지 않았다. HTML 렌더링 probe는 리뷰 시작 전에 별도로 수행했다.

## 반영 결과

위 발견 사항은 검토 당시 문서의 문제를 기록한 것이다. 최신 design에는 ready 진행, 재실행 Welcome, 완료 표식과 저장/인계 순서, Escape·창 숨김·종료·Back/Cancel, 포커스·외부 복귀, URL 문법·비대화식 Git 인증·clone 소유권/취소/경합, 기존 프로젝트 선택/초기화의 계약을 추가했다. tasks에는 대응 fixture와 판정 가능한 기대 결과를 연결했다.

2026-10-28 사용자 추가 승인: CLI/MCP 온보딩을 포함한다. 앱만 설치한 뒤 자기 에이전트에게 setup을 맡기는 사용자를 지원한다. product·tech·QA 관점에서 bootstrap 순환·프로젝트 없는 시작·동일 main 상태·긴 작업 polling·비밀/권한·기존 active 호환을 재검토했고 doan/tasks에 반영했다. 범용 앱 조작이나 별도 headless 인증 백엔드는 추가하지 않는다.

번들 CLI start는 소속 앱만 visible launch하며 기존 active에는 자동 실행을 붙이지 않는다. 명시적 DOAN_RUNTIME 실패는 기본 앱 실행으로 우회하지 않는다. 소켓 v2의 장기 작업은 operationId를 반환하고 짧은 status로 읽는다. session/request 중복 제거와 같은 세션 작업의 명시적 취소 권한을 정의했다. 공개 가이드·MCP 변경으로 최종 agent-eval은 필수다.

기술 재검토에서 발견한 손상 완료 표식의 Retry 반복, 미완료 프로젝트 선택의 저장 근거, 완료 저장과 종료 경합도 정리했다. 손상 원본은 완료 요청 때 백업 후 교체하고 미지 버전은 호환 앱 안내로 구분한다. 미완료 재시작은 등록 목록을 유지해 다시 선택받으며 새 선택 저장 장치를 만들지 않는다. 원자적 완료 기록 교체를 완료 시점으로 정의했다.

최종 재검토 반영: URL inspect에 선택적 목적지를 받고 clone은 목적지까지 검사한 결과만 사용한다. start/status의 session/request 필드 예외와 구 앱의 v1 bad_request → 신규 CLI의 protocol mismatch 매핑을 명시했다. start는 숨겨진 기존 창을 표시하되 같은 세션을 유지한다.

# revision-continuity — 에이전트가 수정하는 동안에도 리뷰가 끊기지 않게 한다

근거: [ux-audit-261025-2 보고서](../ux-audit-261025-2/report.md)의 L-2, L-4, L-13, L-17과 가설 T-11, W-9. 원 근거는 `.scratch/ux-audit/loop-261025-2/`(S2 #7–#17, S3 #6–#7)에 있다.

## 사용자

- **사람**: 앱에서 캔버스를 보고 댓글을 쓰는 사람이다. 에이전트가 같은 프로젝트의 파일을 고치는 동안에도 계속 리뷰하고 다음 피드백을 쓴다.
- **에이전트**: CLI·MCP·공유 형식은 바뀌지 않는다. 캔버스 파일을 옮긴 뒤에도 `doan active`가 대상을 (새 경로로) 돌려준다.

## 문제 (관찰한 사실)

1. **쓰던 새 댓글을 저장할 수 없게 된다(L-2).** 새 댓글을 쓰는 중에 `design/` 아래 **어느 파일이든** 바뀌면 열린 캔버스가 다시 로드된다. 그러면 편집기에 "Original document or target is unavailable."가 뜨고 Save가 영구히 비활성이 된다. 남는 길은 Cancel이나 Discard로 버리는 것뿐이다. 관찰한 경우는 열린 캔버스와 무관한 `account/profile.html` 변경이었다(S2 #9–#13). 메시지는 원인(캔버스가 다시 로드됨)을 말하지 않는다.
2. **캔버스 파일 이름이 바뀌면 리뷰 화면에서 밀려난다(L-4).** 에이전트가 열린 캔버스 파일을 옮기거나 이름을 바꾸면, id가 같아도 "<title> was removed from design/" 토스트가 뜨고 Overview로 돌아간다. 선택은 지워지고 초안은 막힌다(S3 #6). 다시 열면 댓글은 id를 따라 그대로 있다(S3 #7).
3. **사람이 고른 Canvas 범위가 되돌아간다(L-13).** 요소를 선택한 채 Comments 범위를 Canvas로 바꿔도, 에이전트가 캔버스를 저장하면 Selection으로 돌아간다(S2 #7→#8).
4. **바뀌는 것이 없는데 저장 확인이 뜬다(L-17).** 선택이 없고 초안이 열린 상태에서 Esc(또는 빈 여백 클릭)를 누르면 "Save your comment first?"가 뜬다(S2 #15).
5. **렌더된 문서가 없으면 위치가 모두 사라진 것으로 보인다(W-9, 코드 추적).** 폭 없음, 로드 실패, 목록에 없는 문서 상태에서는 모든 프레임·요소 댓글이 "Location unavailable"로 표시된다.
6. **(가설) 리로드 중 위치 정보가 잠깐 사라져 보인다(T-11).** 리로드하면 앵커 스냅샷이 비워진다. 새 문서가 응답할 때까지 "Location unavailable", 핀 사라짐, 빈 Selection 목록이 보일 수 있다(코드 추적). 실제 화면에서 보이는 시간은 관찰하지 못했다.

## 완료 조건

### 막힌 새 댓글 이어 쓰기
- 새 댓글을 쓰는 중에 같은 canvas id의 문서가 다시 로드되면, 편집기에 다음 안내가 `role="status"`로 보인다: "The canvas reloaded while you were writing. Your text is kept — continue on the current version to save it."
- 버튼 `"Continue on current version"`(primary 자리, 별도 요소)를 누르면 **원래 초안의 범위**로 새 초안을 시작한다:
  - Canvas 초안은 Canvas로 이어진다.
  - 선택 초안은 현재 선택으로 이어진다.
  - 성공 시점의 본문이 그대로 남는다. "To:"는 새 대상을 보이고, 포커스는 본문 끝으로 간다.
- 막힌 상태의 안내 줄은 이어질 대상을 미리 보인다: "Continues on <대상>."
- 진행 중이면 버튼이 "Starting…"으로 바뀌고 비활성이 된다. 본문은 계속 편집할 수 있다.
- 실패하면 "Couldn’t continue on the current version: <reason>. Your text is kept."가 `role="alert"`로 보인다. 막힌 초안과 본문은 그대로 남고, 버튼은 다시 활성이 되어 재시도할 수 있다.
- 새 문서가 아직 없거나(로딩, 폭 없음, 로드 실패, 목록에 없는 문서) 선택을 다시 찾는 중이면, 버튼은 비활성이고 이유를 `aria-describedby`로 연결한다.
- 선택 초안인데 현재 선택이 없으면 다음과 같이 보인다:
  - 안내: "Your selection is no longer in the canvas. Select an element or frame, or continue on the whole canvas."
  - 보조 버튼: `"Continue on canvas"`(Canvas 범위로 이어 쓰기)
  - 이때는 사람이 같은 캔버스 안에서 요소나 프레임을 클릭해도 저장 확인 대화상자 없이 선택이 바뀌고, 본문은 그대로 남는다. 다른 캔버스, Home, 다른 프로젝트로 가거나 Reload를 누르면 지금처럼 가드한다.
- 같은 canvas id의 문서가 아니라 원래 문서나 대상이 사라져 막힌 경우(`unavailable`)에는 기존 문구를 유지하고 이어 쓰기 버튼을 보이지 않는다.

### 다른 캔버스 변경에 리로드하지 않기
- `design/` 아래에서 열린 캔버스가 아닌 다른 캔버스 HTML만 생성·수정·삭제되면 열린 캔버스를 다시 로드하지 않는다. 이 경우 쓰던 새 댓글, 선택, 핀, 뷰가 그대로 유지된다. 판정은 `design/` 상대 경로가 `.html`(대소문자 무시)이고 점으로 시작하는 경로 구간이 없는지로 한다.
- 다음 경우에는 지금처럼 다시 로드한다:
  - 열린 캔버스 자신의 변경
  - HTML이 아닌 `design/` 파일(CSS, JS, 이미지)
  - 파일 이름을 알 수 없는 이벤트
  - `design/` 밖 served 경로
- Overview 썸네일은 바뀐 캔버스만 다시 만든다.

### 같은 id 따라가기
- 열린 캔버스 파일이 옮겨지거나 이름이 바뀌고, 같은 프로젝트에 같은 canvas id를 가진 캔버스가 정확히 하나 있으면, 앱은 그 캔버스를 계속 연다. 단, 진행 중이거나 저장 상태가 확인되지 않은 댓글 요청, 진행 중인 카드 변경, 열린 삭제 확인이 없을 때만이다.
  - 토스트와 Overview 이동은 없다.
  - 뷰(배율·위치), 트리 펼침과 포커스 행, 범위·상태 필터를 유지한다.
  - 선택은 다시 찾는다.
  - 요청이 없는 편집 초안은 그대로 저장할 수 있다.
  - Activity에 "Moved · from <이전 파일 이름>"이 남는다.
  - `doan active`는 새 경로를 돌려준다.
- 위 요청이 있으면 지금처럼 캔버스가 사라진 것으로 처리한다.
- 같은 id의 캔버스가 둘 이상이면 따라가지 않는다. 대신 토스트와 캔버스 영역에 "<title> moved, but <n> canvases now use the ID <id>. Run doan check in a terminal."이 보인다.
- 같은 id의 캔버스가 없으면 지금처럼 처리한다.
- 같은 경로에서 canvas id가 바뀐 리로드는 다른 캔버스를 연 것으로 보고 선택을 지운다.
- 재시작할 때 저장된 canvas id를 가진 캔버스가 하나 있으면, 경로가 바뀌었거나 같은 경로에 다른 id가 있어도 그 캔버스와 뷰를 복원한다. 저장된 id가 없는 이전 상태 파일은 지금처럼 경로로 복원한다.

### 범위와 Esc
- 사람이 고른 Comments 범위(Canvas/Selection)는 같은 대상을 다시 찾을 때(리로드, 캔버스 이동) 바뀌지 않는다. 선택의 정체성이 바뀔 때만 지금처럼 Selection으로 맞춘다. 요소는 doanId(없으면 selector)로, 프레임은 frame id로 판단한다.
- 선택이 없고 리로드 직후 선택을 다시 찾는 중도 아닐 때는, Esc나 빈 여백 클릭이 초안 대화상자를 띄우지 않는다. 이때 Esc의 기본 동작도 막지 않는다. 대기 중인 Open을 취소하는 기존 효과는 유지한다.

### 위치 표시
- 렌더된 문서가 없는 상태(폭 없음, 로드 실패, 목록에 없는 문서)에서는 "Location unavailable" 배지를 보이지 않는다. 대상 줄은 위치로 가기 없이 텍스트로 보인다. 이 조건은 측정과 상관없이 해결한다.
- 리로드 중 깜빡임(T-11)은 측정해서 재현되면 해결한다. 재현 기준은 한 샘플이라도 "Location unavailable"이나 빈 Selection 목록이 보이는 것이다. 해결 방법은 새 문서의 앵커가 응답할 때까지 이전 결과(배지, Selection 목록)를 유지하는 것이다. 재현되지 않으면 측정값만 기록한다.

## 범위 밖

- 해결자·해결 시각 표시, 수정 도착 알림, Activity의 Opened/Changed/Resolved 구분: `revision-recheck`. 이 기능은 `moved` 종류만 정한다.
- 위치 찾기의 화면 이동(L-1)과, 위치 찾기가 범위를 Selection으로 바꾸는 문제(L-20): `revision-recheck`
- 대상 표시 문구, 작은 창 배치: `comments-readability`
- 캔버스 id가 바뀌었을 때의 갈 곳 잃은 댓글: `project-feedback`
- 막힌 생성 초안을 다른 문서에 자동으로 다시 묶는 것. 사람이 누르는 이어 쓰기만 둔다.
- 다른 worktree로 옮겨진 캔버스 따라가기, 실제 의존 파일 추적(CDP)

## 받아들이는 위험

- 다른 `design/` HTML을 iframe·fetch 등으로 읽는 캔버스(공유 HTML 셸 포함)는 그 HTML이 바뀌어도 자동으로 다시 로드되지 않는다. ⌘R로 다시 불러온다. ARCH §3·§13에 기록하고, 승격할 때 skill에 "공유 셸은 CSS·JS 자산으로 둔다" 안내가 필요한지 판단한다.

## 결정 (2026-10-25 사용자)

- Q1: 막힌 새 댓글에 이어 쓰기 버튼을 두고, 다른 캔버스 HTML만 바뀐 경우에는 열린 캔버스를 다시 로드하지 않는다. CDP 의존 추적은 비용 때문에 택하지 않았다.
- Q2: 재시작 복원도 저장된 canvas id를 따라간다(기기 로컬 `ui-state.json`의 최상위 항목에 선택적 `canvasId`).
- 리뷰 R1: 이어 쓰기는 원래 초안의 범위를 쓴다. 선택이 없을 때를 위해 "Continue on canvas"를 둔다. `reloaded`로 막힌 생성 초안이 있는 동안 같은 캔버스 안의 선택 변경은 가드하지 않는다. 이는 PRODUCT §5 항목 5의 예외로 승격한다.
- 리뷰 R2: 캔버스 이동은 진행 중·불확실 요청, 카드 변경, 삭제 확인이 없을 때만 따라간다. main의 경로 기반 권한 검사와 불변 요청 규칙은 바꾸지 않는다.
- 리뷰 R3: 리로드 판정은 읽기 전에 파일 이름만으로 한다. 열린 캔버스와 썸네일의 갱신은 행별 rev로 한다. 구현 전에 에이전트의 실제 저장 방식을 측정한다.
- 리뷰 R4: 버튼과 문구, Activity "Moved", 중복 id 안내, (root, canvas id) 키 원칙, Esc 기본 동작, 선택 정체성, 렌더 문서 없음의 위치 표시를 위와 같이 정했다.

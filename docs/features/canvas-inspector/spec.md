# 캔버스 인스펙터 — spec

## 사용자

- **사람**: 앱의 캔버스 화면에서 프레임이나 요소를 선택하고, 에이전트에게 바꿔 달라고 하기 전에 지금 값(폰트 크기, gap, padding, 색)을 빠르게 확인한다. 토큰을 썼으면 토큰 이름을, 호버하면 그 값을 본다. 값을 복사해 대화에 쓴다.
- **에이전트**: 바뀌는 것이 없다. `doan active`와 선택 규칙은 그대로다.

## 문제

- PRODUCT §1 문제 3("Design drafts do not know the code")과 §3 In scope 5 'Tie to code'는 캔버스가 저장소의 실제 토큰 CSS를 쓰게 한다. 그런데 사람이 에이전트에게 "이 gap을 줄여 줘"라고 말하기 전에 지금 값이 몇인지, 어떤 토큰인지 앱에서 확인할 곳이 없다. 지금 캔버스 화면에는 선택한 요소의 값을 보는 곳이 없다(PRODUCT §5 item 4 "There is no Inspector"). 확인하려면 에이전트에게 묻거나 파일을 직접 읽어야 한다.
- 예전 Inspector(값마다 토큰·Hardcoded·Unknown source·Default 판정)는 캔버스 화면이 보드와 도구 줄 배치로 바뀐 뒤 보일 자리가 없었고, 2026-11-17에 코드째 지웠다(`67c222f71`, "a future one will be built for the app as it is then").

## 정해진 것 (사용자 결정)

- **레이아웃**: 보드와 대화 사이의 자기 열. 대화 패널처럼 접고 펴고 폭을 바꾼다. 초안 `.doan/canvases/canvas-inspector-layout.html`(`b781e5681`)으로 확정했다.
- **여닫기**: 사람만 연다. 열림 여부와 폭은 이 기기에 하나로 기억하고 모든 캔버스에 적용한다. 저장된 값이 없으면 닫혀 있다.
- **좁은 창**: 인스펙터와 대화를 둘 다 열면 보드가 360보다 좁아지는 창에서는 인스펙터가 양보한다. 인스펙터 열을 보이지 않고, 저장된 '열림'은 그대로 둔다. 창을 넓히면 다시 보인다. 그동안 Show inspector는 사용할 수 없고 툴팁으로 이유를 말한다.
- **빈 상태**: 열려 있는데 선택이 없으면 빈 상태를 보인다.
- **값 출처와 보기**: CDP로 매칭된 규칙을 읽어 값마다 출처를 판정한다(지운 리졸버 복원). 보기는 하나다(토큰/값 전환은 두지 않는다). 캔버스가 정한 값만 보이고, 토큰이면 토큰 칩, 아니면 값을 그대로 보인다. 출처 캡션(Hardcoded·Default 같은 말)은 붙이지 않고, 브라우저 기본값(캔버스가 정하지 않은 값)은 보이지 않는다. 토큰에 호버하거나 행에 포커스하면 툴팁 첫 줄에 computed 값이 나온다. 상속된 값은 토큰이 있든 없든 행 툴팁에 "Inherited from …"으로만 알린다. 쓰는 사람은 스타일을 뜯어보려는 것이 아니라, 에이전트에게 요청하기 전에 "폰트 크기가 몇이지, 이 gap이 몇이지"를 빠르게 확인하려는 것이다.
- **속성 그룹**: Layout, Box, Typography, Colors, Radius, Shadow. `data-doan-*` 속성은 보이지 않는다(Doan과 에이전트가 쓰는 식별자라, 값을 확인하려는 사람에게는 쓸모가 없다).
- **면이 나뉜 값**: padding·margin·radius처럼 면이 나뉜 행은 모든 면이 같은 토큰일 때만 토큰 칩으로 보인다. 일부 면만 토큰이면 값을 보인다(칩이 값 전체를 대표하는 것처럼 보이면 "padding이 몇이지"에 틀린 답을 준다).
- **요소 메뉴**: 인스펙터 제목 자리에 선택의 이름이 트리거로 온다. 누르면 선택이 들어 있는 가장 안쪽 프레임의 요소 트리(종류 아이콘, 들여쓰기 선)가 열리고, 행을 고르면 그 요소가 선택된다. 선택이 없으면 제목은 "Inspector"다.
- **행 동작**: 읽기 전용. 행을 누르면 보이는 값을 복사하고 공유 토스트로 알린다. 토큰이 있으면 토큰 이름(`--space-4`), 없으면 값. 행은 텍스트 선택 대상이 아니라 누르기로 복사한다(PRODUCT §5 item 0 'Text edit menu'의 "no extra Copy buttons"는 텍스트 옆의 복사 버튼 이야기라 이 행과 다르다. 승격 때 그 문단에 인스펙터 행을 적는다).
- **헤더 아이콘**: 패널이 접혔을 때 캔버스 헤더 끝 구분선 뒤에 Show inspector(lucide `sliders-horizontal`), Show conversation(lucide `message-square`) 순서로 나온다. 프로토타입 창의 대화 버튼도 `message-square`로 바꾼다(PRODUCT §5 item 2 'Prototype window'의 "the main window's icon" 규칙 유지). 각 패널 head의 Hide는 `panel-right-close` 그대로다.
- **안 읽음 배지**: 대화를 여는 버튼 두 곳(캔버스 헤더, 프로토타입 창)의 안 읽은 대화 배지는 말풍선 대신 답 대기와 같은 8px 액센트 점이다. 두 상태는 aria-label과 툴팁 문구로 구분한다. 작업 중 스피너는 그대로다. 사이드바 캔버스 슬롯과 Show sidebar의 말풍선은 바꾸지 않는다.

## 완료 조건

1. 캔버스 화면에 인스펙터 열이 보드와 대화 사이에 있고, Show inspector / Hide inspector로 접고 편다. 접고 펴는 움직임은 대화 패널과 같다(`--time-panel-enter`).
2. 인스펙터 열 시작 가장자리를 끌거나 ←/→를 누르면 폭이 바뀐다. 최소 280, 기본 280, 최대는 대화 폭을 뺀 뒤 보드에 360을 남기는 폭이다. 더블클릭은 280으로 돌린다. 대화 패널의 최대 폭도 열린 인스펙터 폭을 뺀 뒤 보드에 360을 남긴다. 둘 다 최소 폭이어도 보드가 360보다 좁아지는 창(사이드바가 보이면 약 1140 미만)에서는 인스펙터 열이 보이지 않고 Show inspector가 비활성이다.
3. 열림 여부와 폭이 앱을 다시 켜도, 다른 캔버스로 옮겨도 같다. 저장된 값이 없으면 닫혀 있다.
4. 선택 없음, 읽는 중, 실패(Retry), 값의 네 상태가 보이고, 각 상태의 문구와 모양은 tasks 1에서 확정한 패널 초안과 같다.
5. 패널은 캔버스가 정한 속성만, 토큰이면 토큰 칩으로, 아니면 값으로 보이고 출처 캡션과 보기 전환은 없다. 토큰에 호버하거나 그 행에 포커스하면 툴팁 첫 줄에 computed 값이 보인다.
6. 행을 누르거나 행에 포커스를 두고 Enter·Space·⌘C를 누르면 토큰 이름이나 값이 클립보드에 들어가고, 공유 토스트가 "Copied <복사한 텍스트>"를 알린다. 행의 값은 가려지지 않는다. 복사가 실패하면 토스트가 "Couldn’t copy the value. Try again."을 알린다.
7. 선택이 바뀌거나 캔버스가 다시 로드되거나 다른 캔버스로 바뀌는 사이에 늦게 온 응답은 새 선택의 값을 덮지 않는다. 같은 선택을 다시 읽는 동안(reload, Retry)에는 이전 행이 그대로 있다.
8. 인스펙터나 대화가 접혀 있으면 캔버스 헤더의 Reload 뒤에 구분선이 하나 있고, 접힌 것만 Show inspector(`sliders-horizontal`), Show conversation(`message-square`) 순서로 나온다. 안 읽은 대화가 있으면 Show conversation에 8px 액센트 점이 보인다.
9. 인스펙터가 닫혀 있거나 좁은 창이라 보이지 않으면 스타일을 읽지 않는다.
10. 선택이 있으면 인스펙터 제목이 선택의 이름이고, 누르면 가장 안쪽 프레임의 요소 트리가 열린다. 행에 호버하면 보드에 hover 표시가, 행을 고르면 그 요소가 선택되고 인스펙터가 그 요소를 읽는다. Esc는 메뉴만 닫는다.

## 범위 밖

- 값 편집, 토큰 바꾸기, 캔버스 쓰기(PRODUCT §3 Out of scope 1·7).
- 행을 대화에 칩으로 넣기. 대화에는 복사한 텍스트를 붙여 넣는다.
- 아무것도 선택하지 않았을 때의 Canvas info(경로, ID, 폭, 프레임).
- 여러 요소 동시 선택, hover 중인 요소의 값 보기.
- 프로토타입 창, export viewer, Overview의 인스펙터.
- 인스펙터 메뉴 항목과 단축키. 대화 패널도 메뉴 항목이 없어서 같은 방식으로 버튼만 둔다(판단 근거: 대화 패널과 같은 규칙).
- `doan active`나 CLI가 스타일 값을 돌려주는 것.

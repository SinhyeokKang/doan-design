# shell-panel-layout — spec

셸 레이아웃 네 가지를 한 번에 손본다. 하나의 `/ship`으로 진행하고, 항목별로 커밋을 나눈다([tasks.md](./tasks.md)).

1. Project Overview 헤더에 New conversation 아이콘 버튼을 더한다.
2. 캔버스 대화 패널의 최소 폭을 280px 고정으로 바꾼다. 기본 폭은 지금 그대로다.
3. Overview 오른쪽 패널(Canvas conversations 목록)의 폭을 사용자가 바꿀 수 있게 한다.
4. 헤더의 Back 왼쪽에 사이드바 숨기기/보이기 버튼을 둔다. 숨기면 사이드바가 화면에서 완전히 빠진다.

2·3·4의 결정 사항(280px, 폭 한계 공유와 패널별 폭 기억, 점 신호, ⌘B와 View 메뉴, 숨김 상태 기억)은 사용자가 정했다. 해석이 갈리던 나머지 점도 사용자가 정했고, 아래 '결정'에 적었다.

## 사용자

- **사람(앱 사용자)**: 네 항목 모두 사람이 쓰는 앱 화면의 변화다. 캔버스나 대화를 넓게 보려고 사이드바를 접고, 두 오른쪽 패널의 폭을 각자 맞추고, Overview에서 한 번의 클릭으로 새 대화를 시작한다.
- **에이전트**: 영향이 없다. CLI 출력, `doan check` 규칙, 스킬, 앱 소켓 메시지는 바뀌지 않는다.

## 문제 (지금 관찰되는 사실)

- **Overview에서 새 대화를 시작하는 길이 멀다.** 캔버스 대화 패널의 머리에는 New conversation 버튼(`SquarePen`)이 있지만, Overview 헤더에는 없다. Overview에서는 제목 메뉴를 열어 New conversation을 고르거나 ⌘N을 눌러야 한다(PRODUCT §5 항목 3 'Project Overview' 'Conversation menu').
- **캔버스 대화 패널을 좁힐 수 없다.** 지금은 최소 폭이 기본 폭과 같은 `max(320px, 28dvw)`이다(DESIGN 'Panel width'; `rightPanelSize.ts` `panelBounds`). 1238px 창에서는 347px보다 좁힐 수 없어서, 캔버스를 넓게 보려면 패널을 접는 수밖에 없다.
- **Overview 오른쪽 패널은 280px 고정이다**(DESIGN 'Project Overview' 'Panels'; `styles.css` `:root { --doan-right-width: 280px; }`). 썸네일과 미리보기를 넓게 보거나, 반대로 스레드를 넓게 보려고 폭을 바꿀 수 없다.
- **사이드바를 감출 수 없다.** 사이드바는 180–360px 사이에서 폭만 바꿀 수 있고 화면에서 뺄 방법이 없다(PRODUCT §5 항목 1). 960 × 600 창에서는 사이드바 220px와 오른쪽 패널을 빼면 캔버스 칸이 좁다.

## 동작

### 1. Overview의 New conversation 버튼

- Overview 헤더(`.ov-head`)의 끝에 32px New conversation 아이콘 버튼(`SquarePen`, 툴팁 "New conversation")을 둔다. 캔버스 대화 패널 머리의 버튼과 같은 모양이고 같은 규칙을 따른다.
- 누르면 제목 메뉴의 New conversation, ⌘N과 똑같이 새 대화 상태로 가고 입력창이 포커스를 받는다. 새 대화 상태의 초안은 그대로 남는다. 이미 새 대화 상태라면 입력창에 포커스만 준다(`startNewConversation`과 같은 규칙).
- 대화 목록을 읽는 중에도 버튼은 쓸 수 있다(캔버스 패널 버튼과 같다). 대화 전환은 Back/Forward 방문을 더하지 않는다(PRODUCT 기존 규칙).

### 2. 캔버스 대화 패널의 최소 폭

- 최소 폭은 280px이다. 창 폭을 따라 바뀌지 않는다.
- 기본 폭은 지금처럼 `max(320px, 28dvw)`이다(1238px 창에서 347, 960px 창에서 320). 저장된 폭이 없을 때와 핸들을 더블클릭했을 때 이 폭이 된다.
- 최대 폭은 지금 그대로 `min(50dvw, 캔버스에 360px를 남기는 폭)`이다. 창이 좁아 최대가 280보다 작으면 최소와 최대 모두 최대 폭을 쓴다(지금 규칙과 같다).
- 기본 폭이 한계 밖이면 한계 안으로 맞춘다. 저장된 폭이 최대보다 크면 최대로 보이고, 저장된 값은 다시 쓰지 않는다(지금 규칙과 같다).

### 3. Overview 오른쪽 패널의 폭 조절

- Overview 오른쪽 패널의 시작(왼쪽) 가장자리에 캔버스 대화 패널과 같은 리사이즈 핸들을 둔다. 드래그, ←/→(16px씩), Home/End, 드래그 중 Esc 취소, 더블클릭 복원이 캔버스 패널 핸들과 같다.
- 최소·최대 폭은 캔버스 대화 패널과 같은 한계를 쓴다(최소 280, 최대 `min(50dvw, 메인 칸에 360px를 남기는 폭)`).
- 기본 폭은 지금처럼 280px이다. 더블클릭하면 280으로 돌아간다.
- 두 패널은 이 기기에서 폭을 따로 기억한다. Overview에서 폭을 바꿔도 캔버스 대화 패널의 폭은 그대로이고, 반대도 같다. 재시작 뒤에도 남는다.
- Overview 패널은 접지 않는다. 접기는 캔버스 대화 패널에만 있다.

### 4. 사이드바 숨기기/보이기

- **버튼.** 공용 헤더의 Back 왼쪽에 32px 아이콘 버튼을 둔다. 사이드바가 보일 때는 "Hide sidebar"(`PanelLeftClose`), 숨겼을 때는 "Show sidebar"(`PanelLeftOpen`)이다. Back과 Forward는 오른쪽으로 한 칸 밀린다. 헤더가 있는 모든 화면(Home, 작업공간, Add Projects, Settings, Project Settings)에 같은 버튼이 있다.
- **숨김.** 숨기면 사이드바와 사이드바 리사이즈 핸들, 사이드바 뒤의 8px 간격이 화면에서 빠지고, 본문 패널이 셸의 왼쪽 안쪽 여백(8px)부터 시작한다. 보이면 이 기기에 저장된 사이드바 폭으로 돌아온다.
- **하나의 상태.** 숨김 상태는 화면마다 따로 두지 않는다. 한 화면에서 숨기면 모든 화면에서 숨겨진다. 이 기기에 기억되고 재시작 뒤에도 남는다(사이드바 폭과 같은 방식).
- **단축키와 메뉴.** ⌘B와 View 메뉴 첫 항목이 같은 동작을 한다. 메뉴 항목 이름은 상태를 따라 "Hide Sidebar" / "Show Sidebar"로 바뀐다. 모달(대화상자, Quick Open)이나 첫 실행이 열려 있으면 다른 메인 창 항목처럼 꺼진다.
- **숨긴 동안의 신호.** 사이드바 슬롯이 보여 줄 신호(권한 요청, 작업 중, 안 본 종료)가 하나라도 있으면 Show sidebar 버튼에 8px violet 점을 붙인다. 접힌 캔버스 대화 패널의 Show conversation 점과 같은 모양이다. 접근 가능한 이름은 가장 급한 신호 하나를 말한다: "Show sidebar, needs your answer"(권한 요청) → "Show sidebar, agent working"(작업 중) → "Show sidebar, new activity"(안 본 종료). 권한 요청 토스트는 지금처럼 따로 뜬다.
- **자동으로 열지 않는다.** 숨긴 사이드바는 사람이 버튼, ⌘B, 메뉴로 열 때만 돌아온다. 에이전트의 시작·질문·종료, Add Projects 완료의 행 강조, 프로젝트 제거, Quick Open, `doan://` 링크, Back/Forward는 사이드바를 열지 않는다.
- **포커스.** 사이드바 안에 포커스가 있을 때 숨기면 포커스는 Show sidebar 버튼으로 간다. 다른 곳에 포커스가 있으면 그대로 둔다. 보일 때는 포커스를 옮기지 않는다. 숨길 때 사이드바에서 열려 있던 메뉴(프로젝트 메뉴, 캔버스 행 메뉴)는 닫힌다.
- **다른 규칙은 그대로다.** Back/Forward 기록, Quick Open, 사이드바 펼침 상태, 그룹 열림 상태, 캔버스 notice와 본 것 기록은 숨김과 상관없이 지금처럼 동작한다. 숨김과 보이기는 Back/Forward 방문이 아니다.

## 완료 기준

검증할 수 있는 문장으로 쓴다. 숫자는 측정값이며, 실제 앱 확인은 `/runtime-test`(격리된 실제 앱의 짧은 probe)로 한다.

1. Overview 헤더 끝에 이름이 "New conversation"인 버튼이 있고, 누르면 대화가 보이던 Overview가 새 대화 상태가 되며 입력창이 포커스를 받는다. 새 대화 상태에서 누르면 상태는 그대로이고 입력창이 포커스를 받는다(단위 테스트, 실제 앱 probe).
2. 960 × 600과 1238 × 780에서, 워크트리가 셋인 칩과 긴 대화 제목이 있을 때 Overview 헤더의 프로젝트·칩·제목·New conversation 버튼이 겹치지 않고 버튼은 32 × 32로 남는다. 제목이 먼저 말줄임된다(실제 앱 probe).
3. `panelBounds`의 최소가 창 폭과 상관없이 280이고(창이 아주 좁으면 최대), 저장된 폭이 없을 때 캔버스 대화 패널 폭이 1238에서 347, 960에서 320이다(단위 테스트, 실제 앱 probe).
4. 캔버스 대화 패널을 280까지 줄일 수 있고, 280에서 패널 머리, 대화 메뉴, 스레드, docked 입력창, 터미널 세션 선택 카드, 추천 프롬프트가 가로로 넘치지 않는다(실제 앱 probe, 스크린샷).
5. Overview 오른쪽 패널 핸들로 폭을 280–최대 사이에서 바꿀 수 있고, 더블클릭하면 280이 된다. Overview 폭을 바꾼 뒤 캔버스를 열면 캔버스 대화 패널은 자기 폭이고, 재시작 뒤 두 폭이 각자 남는다(단위 테스트, 실제 앱 probe).
6. 헤더의 사이드바 버튼, ⌘B, View > Hide Sidebar가 모두 사이드바를 숨기고 다시 보인다. 숨기면 본문 패널이 x8에서 시작하고 사이드바·핸들이 DOM의 Tab 순서에 없다. 숨김 상태가 재시작 뒤에도 남는다(단위 테스트, 실제 앱 probe; ⌘B는 네이티브 키 입력으로 확인).
7. ⌘B는 입력창(contenteditable), 일반 텍스트 입력, 캔버스 iframe에 포커스가 있을 때도 한 번만 토글하고, 입력창의 글자에 서식이 생기지 않는다(T0 PoC와 실제 앱 probe의 네이티브 키 입력).
8. 사이드바를 숨긴 동안 다른 프로젝트의 Home 대화가 권한을 묻거나, 일하거나, 끝나서 안 본 상태가 되면 Show sidebar 버튼에 점이 붙고 이름이 위 순서대로 바뀐다. 신호가 사라지면 점도 사라진다. 권한 요청 토스트는 그대로 뜬다(단위 테스트, 실제 앱 probe).
9. 960 × 600에서 사이드바를 보일 때와 숨길 때 모두, 헤더의 신호등(traffic lights)·사이드바 버튼·Back·Forward·가운데 탭 캡슐이 겹치지 않고, 캔버스 페이지의 헤더·에이전트 notice·캔버스 notice·토스트·도구 줄이 겹치지 않는다(실제 앱 probe; POSTMORTEM 'Shell restyle lost navigation landmarks' 재발 항목).
10. 사이드바 안(트리 행, 프로젝트 메뉴)에 포커스가 있을 때 ⌘B로 숨기면 포커스가 Show sidebar 버튼에 있고, 열린 메뉴는 닫혀 다시 나타나지 않는다(단위 테스트, 실제 앱 probe).
11. `node .agents/skills/verify/scripts/verify.mjs`가 통과한다.

## 비목표

- 캔버스 대화 패널의 기본 폭과 최대 폭을 바꾸는 것.
- Overview 오른쪽 패널을 접는 기능.
- 사이드바를 창 폭에 따라 자동으로 숨기는 반응형 동작.
- 사이드바를 덮개(overlay)로 잠깐 띄우는 hover peek.
- 사이드바 숨김 상태를 화면별·프로젝트별로 따로 기억하는 것.
- 헤더 버튼 외의 새 단축키(예: 오른쪽 패널 토글 단축키)와 단축키 사용자 설정.
- 전체 화면(fullscreen)에서 신호등이 빠질 때 헤더 왼쪽 여백을 다시 잡는 것.
- buzz-restyle의 남은 자식(buzz-inspector)과 겹치는 인스펙터 자리 결정.

## 결정

해석이 갈리던 점을 사용자가 아래처럼 정했다.

1. **Settings 페이지에서도 숨긴다.** 숨김 상태 하나를 모든 화면에 똑같이 적용한다. Settings 페이지에서는 카테고리(Agents, Notifications, About)가 함께 사라지고, 같은 자리의 버튼으로 다시 보인다.
2. **점 신호의 범위.** 앱 대화의 권한 요청·작업 중·안 본 종료와, 터미널 에이전트 작업(`doan work`, '작업 중'으로 센다)을 넣는다. 캔버스 notice(새로 생기거나 바뀐 캔버스)는 넣지 않는다.
3. **텍스트 입력 안에서도 ⌘B는 사이드바를 토글한다.** 입력창(chip field)은 `format*` beforeinput을 모두 막으므로 굵게 쓰기에는 의미가 없다(`chipField.ts` `onBeforeInput`). Chromium이 contenteditable에서 ⌘B를 편집 명령으로 소비해 메뉴 단축키가 오지 않을 수 있으므로, T0 PoC로 먼저 확인하고 결과에 따라 입력창이 ⌘B를 직접 넘긴다(design.md 'PoC 의존').
4. **Overview New conversation 버튼은 헤더 끝(오른쪽 끝)에 둔다.** 제목 길이에 따라 버튼 자리가 움직이지 않는다.
5. **페이지 잠금 중에도 사이드바를 토글할 수 있다.** 토글은 화면을 떠나지 않는다.
6. **숨기고 보일 때는 캔버스 대화 패널 접기와 같은 전환**(`--time-panel-enter`, `--ease-settle`)을 쓰고, 동작 줄이기 설정에서는 없앤다.
7. **실행 직후의 깜박임은 사이드바 폭과 같은 방식으로 받아들인다.** ui-state를 읽기 전에는 사이드바가 기본(보임)으로 그려진다. 실제 앱 probe에서 깜박임이 보이는지만 기록한다.
8. **`/design-draft`는 하지 않는다.** 이미 main에 있는 화면에 작은 조각을 더하는 일이다. `/runtime-test` probe에서 잰 값으로 DESIGN.md를 고친다.

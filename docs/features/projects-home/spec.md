# projects-home — 홈과 프로젝트 작업공간, 프로젝트 추가·제거

> UX 감사(2026-10-24, main `9afc487`)에서 나온 재설계 세 기능 중 첫 번째다. 나머지 두 기능 `design-nav`(디자인 계층·검색·이동·복원)와 `app-setup`(설정·온보딩·첫 프롬프트)은 이 기능이 만든 홈과 작업공간 위에 올라간다.
> 근거 자료: 감사 보고서 `.scratch/ux-audit/report.md`, 스크린샷 `.scratch/ux-audit/shots/`. `.scratch/`는 커밋되지 않으므로, 이 문서에 필요한 관찰은 아래에 옮겨 적었다.

## 사용자

- 사람(앱을 쓰는 쪽): 홈, 작업공간, 추가·제거 흐름이 바뀐다.
- 에이전트: `doan ls`(CLI·MCP) 결과에 선택 필드 `git`(common dir, 브랜치 또는 detached, 같은 저장소의 워크트리 루트)이 더해진다. 기존 필드와 가이드 본문은 바뀌지 않는다(확인 질문 Q1 답, 2026-10-24).

## 문제 (관찰한 사실)

- **P1. 사이드바 하나가 모든 것을 담는다.** 프로젝트 목록, 각 프로젝트의 캔버스, 열린 캔버스의 Frames가 240px 고정 폭 사이드바 하나에서 함께 스크롤된다. 기본 상태에서 모든 프로젝트가 펼쳐져 있어서, 캔버스 14개짜리 프로젝트 하나가 화면을 다 차지하고 나머지 프로젝트와 Frames는 아래로 밀린다(c-projects/01·02).
- **P2. 프로젝트를 한눈에 보는 화면이 없다.**
  - 프로젝트 행은 이름과 ×뿐이다. 캔버스 수, 열린 코멘트 수, 최근 변경 시각, 브랜치가 없고, 경로는 툴팁에만 있다.
  - 열린 캔버스가 없으면 중앙은 "Pick a canvas from the list"만 보여준다.
- **P3. 같은 저장소의 워크트리를 구분하기 어렵다.** 이름이 같으면 부모 폴더를 붙인다(`code/acme-web`, `feat-billing/acme-web`). 브랜치도, 두 행이 같은 저장소라는 관계도 보이지 않는다(d-find-design/09).
- **P4. 추가 경로가 하나뿐이고, 위험한 기본값이 있다.**
  - 폴더 대화상자에서 한 번에 하나만 고를 수 있다. 드래그 앤 드롭, 최근 항목, 저장소 탐색이 없다.
  - `~/code`처럼 저장소 여러 개를 담은 폴더를 고르면 "code — Not initialized / Set Up…"이 생긴다(c-projects/10). Set Up을 누르면 그 상위 폴더에 `design/`과 `.doan/`이 생긴다.
- **P5. 제거·복구 동작이 제각각이다.**
  - ×를 누르면 확인도 되돌리기도 없이 목록에서 빠진다. 파일이 남는다는 말이 화면에 없다.
  - Not found 행에만 ×가 없고 텍스트 "Close"가 있으며, 같은 경로로 Reopen할 수만 있다.
  - 설정 파일이 깨진 행에서 할 수 있는 일은 ×뿐이다.

## 사용자와 합의한 결정 (2026-10-24 감사 Q&A)

1. 최상위 IA는 **홈 + 프로젝트 작업공간**이다. 홈은 프로젝트 목록을 보여준다. 프로젝트에 들어가면 사이드바는 그 프로젝트의 캔버스와 프레임만 보여준다.
2. 같은 저장소의 워크트리는 **홈 카드 하나로 묶고 브랜치 이름을 보여준다**. 작업공간 상단에 브랜치 전환기가 있다. `.git`(HEAD, 워크트리 포인터)은 읽기 전용으로 읽고, git 명령은 실행하지 않는다.
3. 프로젝트 추가: 대화상자나 드래그 앤 드롭으로 폴더를 받는다.
   - 받은 폴더가 저장소가 아니면, 안의 저장소를 찾아 체크 목록(doan 설정 여부 표시)으로 보여준다.
   - 저장소를 추가하면 같은 저장소의 다른 워크트리도 함께 추가할지 묻는다.
   - "이 상위 폴더를 설정하라"는 기본값은 없앤다.
4. 제거·복구:
   - 홈 카드의 … 메뉴에 Remove from doan, Show in Finder, Project settings를 둔다(Project settings는 `app-setup`이 Settings 창과 함께 연결한다).
   - 제거는 바로 하고 "Files stay in the repo" 문구와 Undo가 있는 토스트를 띄운다.
   - 사라진 폴더는 Locate…(새 위치 지정)와 Remove, 설정 오류는 Show in Finder와 Retry를 카드에서 바로 고른다.

## 완료 조건

- 앱은 두 화면을 가진다. 홈과 프로젝트 작업공간이다. 작업공간 상단의 ← 버튼과 ⌘⇧H(가칭, design에서 확정)로 홈에 간다.
- 홈은 저장 순서대로 저장소 카드를 보여준다. 카드에는 아래가 나온다.
  - 저장소 이름
  - 워크트리별 브랜치(또는 detached 표시)
  - 워크트리별 캔버스 수·열린 코멘트 수·최근 변경 시각
  - 문제 상태(설정 안 됨, 사라짐, 설정 오류, CLI 오류)
- 같은 저장소의 워크트리 둘(main 체크아웃과 linked worktree)을 추가하면 홈에 카드가 하나만 생기고, 그 안에 브랜치 두 줄이 보인다. git 저장소가 아닌 프로젝트는 브랜치 없이 카드 하나다.
- 작업공간 상단에서 현재 저장소의 다른 워크트리로 전환할 수 있다. 전환하면 그 워크트리의 작업공간이 열린다.
- Add project에 저장소 여러 개를 담은 폴더를 주면 하위 저장소 체크 목록이 나온다. 고른 것만 추가되고, 상위 폴더 자체는 저장되지 않는다.
- 저장소를 추가하면, 같은 저장소의 다른 워크트리가 있을 때 함께 추가할지 묻는다.
- 창에 폴더를 끌어다 놓아도 Add project와 같은 흐름을 탄다.
- Remove from doan은 저장 목록에서 바로 빼고, "<name> removed. Files stay in the repo." 토스트에 Undo를 보여준다. Undo를 누르면 원래 자리로 돌아온다. 디스크의 파일은 어느 경우에도 바뀌지 않는다.
- 문제 상태 카드에는 바로 쓸 동작이 있다.
  - 사라진 폴더: Locate…, Remove
  - 설정 오류: Show in Finder, Retry
  - 설정 안 됨: Set Up…, Remove
  - CLI 오류: Retry, Remove
- `doan ls --json`은 git 작업 트리 안의 저장소에서 `result.git`을 돌려준다. git이 아니거나 `.git`을 해석할 수 없으면 `git`을 생략하고, 명령은 실패하지 않는다. git 명령은 실행하지 않는다.
- 위 동작은 e2e(`npm --prefix app run e2e`)가 실제 창에서 역할·이름으로 확인한다. 실제 사용자 상태(real-state 검사)는 바뀌지 않는다. `/agent-eval`에서 새로운 실패가 없다.

## 비목표

- 작업공간 사이드바의 폴더 트리·프레임 중첩·개요 페이지·썸네일·⌘K 검색·재실행 복원 → `design-nav`
- 설정 화면, 홈의 연결 상태 표시, 온보딩 보완, 첫 프롬프트 입력란 → `app-setup`. 다만 홈에는 그 표시가 들어갈 자리만 둔다.
- 캔버스 화면, 오른쪽 패널(Canvas 정보·Inspector·Comments), 선택·코멘트·넘기기 루프 → 다음 감사 차례
- 카드 순서 바꾸기·고정·정렬 옵션(이번에는 저장 순서 고정)
- git 명령 실행, 브랜치 만들기·전환(PRODUCT §3 Out of scope 6). 작업공간의 "브랜치 전환기"는 이미 추가된 워크트리 사이를 오가는 것일 뿐, git checkout이 아니다.
- 워크트리 자동 감시(새 워크트리가 생기면 알아서 추가). 추가할 때 한 번 묻는 것까지만 한다.
- 최근 항목(Open Recent) 메뉴

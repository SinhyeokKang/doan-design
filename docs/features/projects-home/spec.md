# projects-home — 홈과 프로젝트 작업공간, 프로젝트 추가·제거

> UX 감사(2026-10-24, main `9afc487`)에서 나온 재설계 세 기능 중 첫 번째다. 나머지 두 기능 `design-nav`(디자인 계층·검색·이동·복원)와 `app-setup`(설정·온보딩·첫 프롬프트)은 이 기능이 만든 홈과 작업공간 위에 올라간다.
> 근거 자료: 감사 보고서 `.scratch/ux-audit/report.md`, 스크린샷 `.scratch/ux-audit/shots/`. `.scratch/`는 커밋되지 않으므로, 이 문서에 필요한 관찰은 아래에 옮겨 적었다.

## 사용자

- 사람(앱을 쓰는 쪽): 홈, 작업공간, 추가·제거 흐름이 바뀐다.
- 에이전트: `doan ls`(CLI·MCP) 결과에 선택 필드 `git`이 생긴다. 내용은 common dir, main 작업 트리, 브랜치 또는 detached, 같은 저장소의 워크트리별 doan 루트다(Q1, 리뷰 R2). 기존 필드와 가이드 본문은 바뀌지 않는다.

## 문제 (관찰한 사실)

- **P1. 사이드바 하나가 모든 것을 담는다.** 프로젝트 목록, 각 프로젝트의 캔버스, 열린 캔버스의 Frames가 240px 고정 폭 사이드바 하나에서 함께 스크롤된다. 기본 상태에서 모든 프로젝트가 펼쳐져 있어서, 캔버스 14개짜리 프로젝트 하나가 화면을 다 차지하고 나머지 프로젝트와 Frames는 아래로 밀린다(c-projects/01·02).
- **P2. 프로젝트를 한눈에 보는 화면이 없다.**
  - 프로젝트 행은 이름과 ×뿐이다. 캔버스 수, 열린 코멘트 수, 최근 변경 시각, 브랜치가 없고, 경로는 툴팁에만 있다.
  - 열린 캔버스가 없으면 중앙은 "Pick a canvas from the list"만 보여준다.
- **P3. 같은 저장소의 워크트리를 구분하기 어렵다.** 이름이 같으면 부모 폴더를 붙인다(`code/acme-web`, `feat-billing/acme-web`). 브랜치도, 두 행이 같은 저장소라는 관계도 보이지 않는다(d-find-design/09).
- **P4. 추가 경로가 하나뿐이고, 위험한 기본값이 있다.**
  - 폴더 대화상자에서 한 번에 하나만 고를 수 있다. 드래그 앤 드롭, 최근 항목, 저장소 탐색이 없다.
  - `~/code`처럼 저장소 여러 개를 담은 폴더를 고르면 "code — Not initialized / Set Up…"이 생긴다(c-projects/10). Set Up을 누르면 그 상위 폴더에 `design/`과 `.doan/`이 생긴다.
- **P5. 제거·복구 동작이 제각각이다.**
  - ×를 누르면 확인도 되돌리기도 없이 목록에서 빠진다. 파일이 남는다는 말이 화면에 없다.
  - Not found 행에만 ×가 없고 텍스트 "Close"가 있으며, 같은 경로로 Reopen할 수만 있다.
  - 설정 파일이 깨진 행에서 할 수 있는 일은 ×뿐이다.

## 사용자와 합의한 결정

감사 Q&A(2026-10-24):
1. 최상위 IA는 **홈 + 프로젝트 작업공간**이다. 홈은 프로젝트 목록을 보여준다. 프로젝트에 들어가면 사이드바는 그 프로젝트의 캔버스와 프레임만 보여준다.
2. 같은 저장소의 워크트리는 **홈 카드 하나로 묶고 브랜치 이름을 보여준다**. 작업공간 상단에 워크트리 전환기가 있다. `.git`은 읽기 전용으로 읽고, git 명령은 실행하지 않는다.
3. 프로젝트 추가:
   - 대화상자나 드래그 앤 드롭으로 폴더를 받는다.
   - 받은 폴더가 저장소가 아니면, 안의 저장소를 찾아 체크 목록으로 보여준다.
   - 같은 저장소의 다른 워크트리를 함께 추가할지 묻는다.
   - "이 상위 폴더를 설정하라"는 기본값은 없앤다.
4. 제거·복구:
   - 제거는 바로 하고 Undo 토스트를 띄운다.
   - 사라진 폴더는 Locate…, 설정 오류는 Show in Finder·Retry를 줄에서 바로 고른다.

`/feature` 확인 질문(2026-10-24):
- Q1: 브랜치·워크트리 정보는 Go `doan ls`의 `git` 필드로 준다.

`/feature-review` 답(2026-10-25):
- R1: 고른 폴더가 doan 저장소가 아니면 조상으로 올라가지 않는다. 판정은 세 단계다.
  - (1) 그 폴더에 `.git`이 있으면 Not set up으로 저장한다.
  - (2) 바로 아래에 저장소가 있으면 체크 목록을 보인다.
  - (3) 둘 다 아니면 "Set up <folder> as a doan project?"를 묻는다.
- R2: doan 루트가 git 루트의 하위 폴더(모노레포)이면 Go가 위로 `.git`을 찾는다. 각 워크트리의 같은 상대 경로를 그 워크트리의 doan 루트로 돌려준다.
- R3: 로드된 작업공간은 하나다.
  - 홈에 있는 동안에도 그 작업공간의 선택은 유지되어 `doan active`가 돌려준다. 홈의 해당 줄에 표시한다.
  - 다른 루트의 마지막 캔버스와 보기는 메모리에 기억한다.
  - 워크트리 전환기는 같은 canvas id가 있으면 그 캔버스를 연다.
- R6: 워크트리 제안은 기본 체크 해제다.

## 완료 조건

- **화면**
  - 앱은 두 화면을 가진다. 홈과 프로젝트 작업공간이다.
  - 작업공간 상단의 ←, 그리고 Go 메뉴의 Home(⇧⌘H)으로 홈에 간다.
- **홈 카드**
  - 홈은 저장 순서대로 저장소 카드를 보여준다. 카드에는 저장소 이름이 있고, 그 아래 워크트리마다 한 줄이 있다.
  - 줄에는 브랜치 또는 `detached <짧은 sha>`, 캔버스 수, 열린 코멘트 수(0보다 클 때), 최근 변경 시각(상대 시각, 툴팁에 절대 시각), 문제 상태가 나온다.
  - 지금 로드된 작업공간의 줄에는 "Open"이 표시된다. 그 작업공간에 선택이 있으면 "Selected: <프레임 또는 요소>"도 표시된다.
- **워크트리 묶기**
  - doan이 설정된 같은 저장소의 워크트리 둘(main 체크아웃과 linked worktree)을 추가하면, 홈에 카드가 하나만 생기고 그 안에 줄 두 개가 보인다.
  - 모노레포 하위의 doan 루트도 같은 규칙으로 묶인다.
  - git 저장소가 아닌 프로젝트는 브랜치 없이 카드 하나다.
  - 한 번 묶였던 워크트리가 사라지거나 설정 오류가 나도, 앱을 다시 켜기 전까지는 같은 카드에 남는다.
- **워크트리 전환기**
  - 작업공간 상단의 워크트리 전환기로 같은 카드의 다른 워크트리 작업공간을 연다.
  - 같은 canvas id의 캔버스가 있으면 그것을 열고, 없으면 그 작업공간의 첫 화면을 연다.
  - 전환에도 코멘트 초안 가드를 적용한다.
- **추가 흐름**
  - Add Project…(⌘O, 홈의 + 버튼)에 저장소 여러 개를 담은 폴더를 주면 하위 저장소 체크 목록이 나온다.
    - 이미 추가된 저장소는 비활성이다.
    - 고른 것만 추가되고, 상위 폴더 자체는 저장되지 않는다.
  - 저장소도, 저장소를 담은 폴더도 아닌 폴더를 주면 "Set up <folder> as a doan project?"를 묻는다. 확인해야만 저장된다.
  - 같은 저장소의 다른 워크트리는 체크 목록에 하위 항목으로 함께 나오고, 기본으로 체크되어 있지 않다.
  - 이미 저장된 프로젝트를 다시 추가하면 그 카드로 스크롤하고 강조한다.
  - 창이 숨겨져 있을 때 ⌘O를 누르면 창을 보이고 추가 대화상자를 연다.
- **드롭**
  - 창에 폴더를 끌어다 놓으면 "Drop folders to add" 오버레이가 창 전체(캔버스 위 포함)를 덮고, 놓으면 Add Project와 같은 흐름을 탄다.
  - 모달이 열려 있으면 드롭을 무시한다. 파일만 놓으면 토스트로 알린다.
- **제거**
  - 줄의 Remove와 카드의 Remove all은 저장 목록에서 바로 뺀다. 토스트는 "<name> removed. Files stay on disk."와 Undo다.
  - 토스트가 떠 있는 동안 Edit > Undo Remove(⌘Z)도 같은 동작을 한다. 마우스를 올리면 토스트 타이머가 멈춘다.
  - Undo는 원래 자리로 되돌린다. 열려 있던 작업공간과 선택은 되돌리지 않는다.
  - 지우는 대상에 로드된 작업공간이 있고 코멘트 초안이 있으면, 초안 가드를 먼저 거친다. 지운 뒤에는 홈으로 간다.
  - 디스크의 파일은 어느 경우에도 바뀌지 않는다.
- **문제 상태와 복구**
  - 문제 상태 줄에는 바로 쓸 동작이 있다.
    - 사라진 폴더: Locate…, Remove
    - 설정 오류: Show in Finder, Retry, Details(오류 문구 펼침)
    - 설정 안 됨: Set Up…, Remove
    - CLI 오류: Retry, Remove
  - 문제 상태 줄을 눌러도 작업공간으로 들어가지 않는다.
  - 로드된 작업공간의 프로젝트가 문제 상태가 되면, 작업공간에 머물며 상단에 상태 줄(해당 동작 + Go Home)을 보인다.
- **메뉴**
  - 줄 메뉴(… 버튼과 우클릭)에는 Show in Finder, Remove from doan이 있다. 카드 메뉴에는 Remove all이 있다.
  - 메뉴 항목은 화면별 활성 표를 따른다(design 참조).
- **CLI**
  - `doan ls --json`은 git 작업 트리 안의 저장소에서 `result.git`을 돌려준다.
  - git이 아니거나 `.git`을 해석할 수 없으면 `git`을 생략하고, 명령은 실패하지 않는다.
  - git 명령은 실행하지 않는다.
- **확인 방법**
  - 위 동작은 e2e(`npm --prefix app run e2e`)가 실제 창에서 역할·이름으로 확인한다. 실제 사용자 상태(real-state 검사)는 바뀌지 않는다.
  - 실제 Finder 드래그 앤 드롭은 수동으로 확인한다. main의 경로 처리(`folders:add-paths`)는 e2e로 확인한다.
  - `/agent-eval`에서 새로운 실패가 없다.
- **마법사 호환**
  - 이 기능이 들어간 뒤에도 마법사 3단계(Open Project…)는 지금처럼 동작한다. 단일 선택 대화상자를 쓰고, 루트 하나 또는 null을 돌려준다.
  - 마법사를 새 추가 흐름에 연결하는 일은 `app-setup`이 맡는다.

## 비목표

- 작업공간 사이드바의 폴더 트리·프레임 중첩·개요 페이지·썸네일·⌘K 검색·재실행 복원 → `design-nav`
- 설정 화면, 홈의 연결 상태 표시, Project settings 메뉴 항목, 온보딩 보완, 첫 프롬프트 입력란 → `app-setup`
- 캔버스 화면, 오른쪽 패널(Canvas 정보·Inspector·Comments), 선택·코멘트·넘기기 루프, 빈 크롬 정리(감사 N4) → 다음 감사 차례
- 카드 순서 바꾸기·고정·정렬 옵션(이번에는 저장 순서 고정)
- git 명령 실행, 브랜치 만들기·체크아웃(PRODUCT §3 Out of scope 6). 워크트리 전환기는 이미 추가된 워크트리 사이를 오갈 뿐이다.
- 워크트리 자동 감시(새 워크트리가 생기면 알아서 추가)
- 최근 항목(Open Recent) 메뉴

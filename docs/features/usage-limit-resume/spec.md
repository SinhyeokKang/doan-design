# usage-limit-resume — spec

## 사용자

- **사람**(앱에서 대화하는 사람)만 대상이다. 에이전트, CLI, 스킬은 바뀌지 않는다.

## 문제

- Claude Code나 Codex 계정이 사용 한도(5시간 창, 주간 한도 등)에 걸리면, 턴은 “<Provider> reached a usage limit”로 끝나고 Edit and resend만 남는다. 한도가 풀리기 전의 Send나 시작은 “<Provider> reached a usage limit. Send again after it resets.”로 거절된다(PRODUCT §5 item 3).
- 사람은 리셋 시각을 기억했다가 그때 앱으로 돌아와 다시 보내야 한다. 리셋이 밤이나 자리를 비운 시간이면 작업이 그만큼 멈춘다.
- 사용자 관찰: 터미널의 Claude Code는 한도 리셋 뒤 작업을 이어 갔다. 이 동작은 Doan에서 확인하지 않았다.

## 범위 (사용자 결정, 2026-11-13)

- **PRODUCT §3 Out of scope 4의 좁은 예외로 넣는다.** 사람이 한도 중에 보낸 메시지를 Doan이 리셋 시각까지 미뤘다가 보낸다. 보내는 글은 사람이 composer에 쓴 그대로이고, Doan이 문장을 만들거나 더하지 않는다. 대기열 메시지가 턴이 끝난 뒤 나가는 것과 같은 성격이다.
- **provider**: Claude Code와 Codex. 다른 provider(Cursor, Antigravity, GitHub Copilot)는 지금처럼 거절한다.
- **예약 방식**: 리셋 시각을 아는 동안 기존 대화에서 Send를 누르면, 거절하지 않고 보낼 내용을 대기열 행으로 넣는다. 행은 언제 나가는지 보여 주고 제거할 수 있다.
- **앱 종료**: 리셋 전에 앱을 끄면 예약은 사라지고, 다시 켰을 때 그 메시지는 초안으로 돌아온다(기존 대기열 규칙). 저절로 보내지 않는다.
- **다시 한도에 걸리면**: 리셋 시각에 보낸 메시지가 다시 한도로 거절되거나 실패하고 Doan이 더 늦은 새 리셋 시각을 알면, 같은 메시지를 새 리셋 시각으로 자동 재예약한다.

## 동작

- **한도 상태**: Doan은 provider 계정마다 "한도가 풀리는 시각"을 메모리에만 기억한다. 그 계정의 대화가 한도로 실패하거나 거절될 때 리셋 시각을 알게 되고, 그 시각이 지나면 잊는다. 리셋 시각을 모르면 한도 상태가 없고, 동작은 지금과 같다.
- **Send가 예약이 되는 경우**: 대화의 provider가 Claude Code나 Codex이고, 그 계정의 한도 상태가 있으며, 대화가 일하는 중이 아닐 때. 이때 Send는 composer의 내용(글, 칩, 첨부)을 대기열 행으로 옮긴다.
  - 행 문구: “Sends when the limit resets at <시각>.” 시각은 이 Mac의 시간대로, 오늘이면 시각만, 아니면 요일과 시각을 쓴다(정확한 형식은 `/design-draft`에서 정한다).
  - 행에는 제거만 있고 Send now는 없다. 여러 번 보내면 행이 순서대로 쌓인다.
  - 대화가 일하는 중이면 지금의 대기열 규칙이 그대로 적용된다(턴이 끝난 뒤 나간다).
- **보내는 시각**: 리셋 시각에 짧은 여유를 더한 때(PoC가 정한다), 대기열을 기존 대기열 전송과 같은 방식으로 한 턴으로 보낸다. Mac이 잠들어 있다가 그 시각이 지난 뒤 깨어나면, 깨어난 직후 보낸다.
- **보낼 수 없을 때**: 그 시각에 대화가 보관·삭제되었거나, 로그아웃되었거나, 다른 이유로 전송이 거절되면 지금의 대기열 규칙대로 메시지가 초안으로 돌아온다.
- **다시 한도**: 보낸 턴이 에이전트가 메시지를 읽기 전에 한도로 끝나거나 전송이 한도로 거절되고, 새 리셋 시각이 이전보다 늦으면 같은 메시지를 대기열 행으로 되돌려 새 시각으로 예약한다. 새 시각을 모르거나 이전보다 늦지 않으면 초안으로 돌아온다. 에이전트가 메시지를 읽은 뒤 한도에 걸린 턴은 평소처럼 실패로 끝난다(같은 메시지를 다시 보내면 이미 한 일을 되풀이하기 때문이다).
- **실패한 턴의 줄**: 리셋 시각을 알면 둘째 줄을 “Resets <시각>. Send to have it go then.”처럼 예약을 알려 주는 문구로 바꾼다(정확한 문구는 `/design-draft`와 clarify 프리셋으로 정한다). 리셋 시각을 모르면 지금 문구를 둔다.

## 완료 조건

- Claude Code 한도 거절과 Codex 한도 실패에서 리셋 시각을 읽는 순수 함수가 fixture로 고정되어 있다(단위 테스트).
- 리셋 시각을 아는 동안 기존 대화의 Send는 거절되지 않고 “Sends when the limit resets at …” 행이 생기며, 시각이 되면 그 메시지가 사람의 메시지로 한 턴에 나간다(단위 테스트와 가짜 시계, 실제 앱 확인).
- 다시 한도에 걸린 전송은 새 시각이 더 늦을 때만 재예약되고, 아니면 초안으로 돌아온다(단위 테스트).
- 앱을 다시 켜면 예약된 메시지는 초안으로 돌아오고 저절로 나가지 않는다(단위 테스트).
- Cursor·Antigravity·Copilot 대화와 새 대화 시작은 지금처럼 거절된다(단위 테스트).
- PRODUCT §3 Out of scope 4에 예외 문장이 들어가 있고, PRODUCT §5 item 3의 한도 문단이 새 동작으로 고쳐져 있다.

## 범위 밖

- 새 대화 시작(Home, New conversation)의 예약. 지금처럼 거절한다.
- Cursor, Antigravity, GitHub Copilot.
- 앱 종료 뒤에도 예약을 유지하는 것, 앱을 깨우거나 실행하는 것.
- Doan이 스스로 쓴 이어 가기 문구('Continue' 등)를 보내는 것.
- Home 대화 strip, 사이드바 슬롯, 알림에 예약 상태를 따로 표시하는 것(기존 Finished·Couldn’t finish 알림은 예약 턴에도 그대로 온다).

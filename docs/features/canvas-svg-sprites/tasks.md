# canvas-svg-sprites — 작업

## 작업 순서

- [ ] 1. **PoC: SVG `<use>`** (design.md 'PoC 의존' 1~3). `.scratch/canvas-svg-sprites/`에 임시 repo를 만들고, 외부 `<use>`(로컬 `href`, `xlink:href`, CDN, `data:`), 인라인 스프라이트(`<style>` 포함), 아이콘별 SVG의 `<img src>`·CSS `mask: url()`를 각각 다른 캔버스로 둔다. 격리 앱에서 각 캔버스가 보이는지와 서버 요청 여부를 기록하고, 같은 캔버스를 export해 Chromium·Safari에서 연다. 검증: `go build -o <tmp>/doan ./cli/cmd/doan` 후 `DOAN_CLI=<tmp>/doan npm --prefix app run dev -- -- --user-data-dir=<tmp>`(AGENTS.md의 HOME·SHELL·`CLAUDE_CONFIG_DIR`·`CODEX_HOME` 격리 적용), `go run ./cli/cmd/doan export <canvas> -o <tmp>/out.html --repo <tmp repo> --json`. 결과가 design.md 가정과 다르면 작업 3 이전에 설계를 고친다. 관찰은 이 문서에 날짜와 함께 남긴다.
- [ ] 2. **PoC: custom property `url()`** (design.md 'PoC 의존' 4). 레이아웃마다 페이지 하나로, 두 폴더의 사용처가 서로 다른 경로로 푸는 경우, 같은 경로로 푸는 경우, `@property` `<url>` 등록 경우를 격리 앱에서 확인한다. 검증: 작업 1과 같은 격리 앱 명령. 같은 경로로 풀리는 경우가 순서에 따라 달라지면 warning 조건을 "사용 폴더 둘 이상"으로 바꿀지 사용자에게 묻는다.
- [ ] 3. **`/tdd`: check 규칙과 공통 판정 함수.** `<use>` 비조각 판별, custom property 사용 경로 계산과 모호성 판정을 순수 함수로 테스트에 고정한다. 판정 함수의 위치(`cli/internal/canvas`)와 두 규칙의 code·수준·attribution을 `check_test.go`에 고정한다. `<template/>` 최상위·중첩, POSTMORTEM 2026-11-03의 디자인 시스템 패턴(사용 폴더 하나, 경고 없음)을 포함한다. 검증: `go test ./...`가 새 테스트에서 red, 기존 테스트는 green. **테스트 커밋 경계**.
- [ ] 4. **`/implement`: check와 export.** 판정 함수와 두 check 규칙을 구현하고, export의 `<use>` 거부·스프라이트 복사 제거·`replaceCustom` 조건 변경을 같은 함수 위에 올린다. 고아가 된 사유 상수·`sprite_test.go`·`exporttest/seed.go`의 스프라이트 시드는 정리한다. check와 export가 같은 입력에 같은 판정을 내는 테스트를 하나 둔다. 검증: `go test ./...`, `go vet ./...`, `node .agents/skills/verify/scripts/verify.mjs`. **구현 커밋 경계**.
- [ ] 5. **가이드.** `cli/internal/cli/skill.md`에 인라인 스프라이트(`<use href="#id">`, 스프라이트의 `<style>`은 캔버스 전체에 걸린다는 점), 작업 1에서 확인된 대체 형태, custom property `url()`을 한 폴더의 스타일시트에서만 쓰거나 `@property` `<url>`로 등록하는 방법을 짧게 넣는다. design preset `document.md`의 아이콘 문장("Draw an icon from the project's icon source (package, SVG file, sprite, …)")과 어긋나지 않는지 확인한다. 검증: `go test ./...`(`skill_test.go`), `go run ./cli/cmd/doan skill` 출력에서 문장 확인. **가이드 커밋 경계**.
- [ ] 6. **`/code-review` → `/refactor` → `/agent-eval`.** guide·check 규칙·CLI 출력이 바뀌었으므로 `/agent-eval` 라운드를 돈다. `eval/scenarios/`에 시나리오 하나를 추가한다: seed에 `.doan/assets/`의 외부 스프라이트 파일과, 두 폴더의 스타일시트가 같은 custom property `url()`을 쓰는 형태를 두고, 아이콘이 있는 화면을 그리게 한다. 통과 조건은 인라인 `<use href="#id">`(또는 작업 1에서 확인된 대체 형태)로 그리고 `doan check`에 `svg_use_not_inline`·`ambiguous_custom_url`이 남지 않는 것이다. pass·fail fixture를 함께 둔다. 시나리오 id는 기존 이름 규칙에 맞춰 구현 때 정한다. 검증: `node eval/run.ts --self-test --scenarios <id>`가 `self-test PASS`와 exit 0, `npm --prefix app run package` 후 `node eval/run.ts --round <name>`(가이드가 바뀌므로 전체 시나리오), `node --test 'eval/**/*.test.ts'` green, `node .agents/skills/verify/scripts/verify.mjs --eval`. 결과는 `docs/USABILITY-EVAL.md`에 기록한다. 앱 코드는 바뀌지 않으므로 `/runtime-test`는 하지 않고, 작업 1의 격리 앱으로 인라인 스프라이트 캔버스와 export 파일을 한 번 더 비교한다.

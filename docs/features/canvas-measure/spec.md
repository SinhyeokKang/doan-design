# 캔버스 거리 측정 — spec

## 사용자

사람이다. 앱에서 캔버스를 보는 사람이, 에이전트가 그린 초안의 간격을 숫자로 확인한다. 에이전트가 얻는 것은 없다. CLI, 스킬, `doan active`는 바뀌지 않는다.

## 문제

- 지금 캔버스에서 알 수 있는 숫자는 선택한 요소의 크기(크기 말풍선 `W × H`)뿐이다. 두 요소 사이의 간격이나 프레임 안쪽 여백은 앱에서 잴 방법이 없다.
- 간격을 확인하려면 개발자 도구를 열거나 캔버스 HTML을 직접 읽어야 한다. 초안 리뷰에서 "여기 간격이 몇이지?"는 자주 나오는 질문이다.
- Figma 사용자는 레이어를 선택하고 Option을 누른 채 다른 레이어에 포인터를 올려 거리를 잰다. 이 사람들은 Doan 캔버스에서도 같은 손동작을 기대한다.

## 동작 (Figma 관찰 결과를 따른다)

근거는 design.md '관찰 기록'에 있다. 모든 숫자는 캔버스 px이며, 크기 말풍선과 같은 단위다.

1. **트리거.** Select 도구에서 선택이 있을 때 Option(⌥)을 누른 채 포인터를 다른 대상에 올리면 측정이 나온다. Option을 떼면 측정이 바로 사라지고, 일반 hover 표시로 돌아간다.
2. **측정 대상.** 포인터 아래의 대상은 지금 hover 규칙(다음 클릭이 선택할 대상)을 그대로 따른다. ⌘을 함께 누르면 ⌘-click처럼 프레임 단계를 건너뛴 가장 안쪽 대상을 잰다(Figma의 ⌘+Option 중첩 측정과 같은 손동작).
3. **측정이 없는 경우.** 선택이 없을 때, 포인터 아래가 선택 자신일 때, 포인터가 모든 프레임 밖 빈 곳에 있을 때는 측정을 그리지 않는다. Hand, Picker, Capture area, 텍스트 드래그, Space 드래그 중에도 그리지 않는다.
4. **떨어진 두 대상.** 한 축에서 떨어져 있으면, 선택의 가까운 변에서 대상의 가까운 변까지 실선을 긋고 거리를 표시한다. 실선은 선택의 중심선 위에 놓인다. 그 중심선이 대상의 범위 밖에 있으면, 실선 끝에서 대상의 변까지 점선을 잇는다. 대각선 관계면 가로와 세로를 모두 표시한다.
5. **포함·교차.** 한쪽이 다른 쪽을 포함하거나 둘이 겹치면, 같은 쪽 변끼리의 거리(위-위, 오른쪽-오른쪽, 아래-아래, 왼쪽-왼쪽)를 0이 아닌 것만 표시한다. 선은 겹친 구간의 중심선 위에 놓인다.
6. **한 축만 겹칠 때.** 한 축으로는 떨어져 있고 다른 축으로는 범위가 겹치면, 4번의 간격에 더해 겹치는 축의 같은 쪽 변 차이를 일부 표시한다. 어느 변을 표시하는지는 관찰한 7개 사례로 아직 규칙을 확정하지 못했다(design.md '미확정 규칙'). 첫 작업에서 Figma를 더 관찰해 확정한다.
7. **표시 모양.** 선과 라벨은 빨간색 하나(관찰값 `#E34C2C`)로 그린다. 선 두께는 화면 1px이고, 점선 연장선도 같은 색이다. 라벨은 빨간 pill에 흰 숫자다. 가로선의 라벨은 선 아래 6px에, 가운데 맞춰 놓인다. 세로선의 라벨은 선 오른쪽 6px에, 가운데 맞춰 놓인다. 측정 중에는 선택과 대상의 외곽선 안쪽에 빨간 1px 선이 더해진다.
8. **숫자.** 크기 말풍선과 같은 반올림(소수점 둘째 자리까지, 뒤의 0 생략)을 쓴다. Figma는 `40.5`, `130.5`처럼 소수를 보여준다.
9. **줌.** 선과 라벨은 줌과 관계없이 화면에서 같은 두께와 크기로 그려진다. 숫자는 캔버스 px 그대로다.
10. **Option-click은 그대로다.** Option을 누른 채 클릭하면 지금처럼 선택을 바꾸지 않고 캔버스를 직접 쓴다. 측정은 표시만 하고 클릭 동작을 바꾸지 않는다.

## 완료 조건

- design.md '관찰 기록'의 사례마다, 순수 함수가 같은 선 개수·위치·거리·점선 연장선을 내놓는다는 테스트가 통과한다(`npm --prefix app test`).
- 실제 앱에서 사례 01·02·03·05·11(⌘+Option)을 재현하면 선과 라벨이 관찰값과 같은 자리에 같은 숫자로 나온다. 화면 기록이 남는다(`/runtime-test`).
- Option을 떼거나, 포인터가 캔버스를 벗어나거나, 다른 문서로 포커스가 옮겨 간 뒤 Option을 떼도 측정이 남지 않는다(2026-10-23 Alt focus transfer postmortem과 같은 경로).
- Option-click으로 캔버스의 버튼이나 입력란을 누르는 기존 동작과 그 테스트가 그대로 통과한다.
- 측정 중 크기 말풍선, 선택 표시, `doan active`는 바뀌지 않는다.

## 비목표

- 측정을 저장하거나 고정하는 것(Figma Dev Mode의 measurement). 이번 측정은 Option을 누르는 동안만 보인다.
- 여러 대상을 선택한 상태의 측정. Doan에는 다중 선택이 없다.
- 오토 레이아웃 패딩 표시, 회전한 요소의 회전 기준 측정. 측정은 bounding box 기준이다(Figma 공식 문서와 같다).
- 화살표 키 이동과 결합하는 것. Doan에서는 사람이 요소를 옮기지 않는다(PRODUCT §3 Out of scope 7).
- 선택이 없을 때 대상과 부모 프레임 사이를 재는 것. 2026-11-18에 관찰한 Figma에서는 측정이 나오지 않았다(사례 08).
- 선택 표시와 hover 표시의 모양 변경. 두 표시는 Doan의 accent 선을 그대로 쓴다. Figma의 파란 선을 따르지 않는다.

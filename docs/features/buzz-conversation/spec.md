# buzz-conversation — spec

`buzz-restyle`의 자식 10번이다. 대화 UI 가운데 캔버스에 묶이지 않은 공용 부분을 만든다. 캔버스 오른쪽 패널, 요소 피커, 앵커 칩, 코멘트 제거는 `buzz-canvas-conversation`이 맡고, 이 부분을 Overview에 배치하는 일은 `buzz-project`가 맡는다([부모 spec 표](../buzz-restyle/spec.md#자식-feature)).

이번 자식은 **프리미티브와 데이터만** 만든다(2026-10-31 user). 대화 스레드와 `docked` 입력창이 처음 보이는 화면은 `buzz-project`의 Overview다. 이 자식이 실제 앱에서 바꾸는 것은 두 가지다. Home 입력창은 새 프리미티브로 다시 조립하지만 모습과 동작은 그대로 유지한다. 그리고 임시 상태줄과 LNB 상태 슬롯은 다시 로드하거나 재시작해도 사라지지 않는다.

## 사용자

- **사람(앱 사용자)**
  - 이번 자식에서 Home의 겉모습은 바뀌지 않는다.
  - 다시 로드하거나 재시작해도 진행 중이거나 안 본 대화 표시가 LNB와 상태줄에 남는다.
  - 후속 자식(`buzz-project`, `buzz-canvas-conversation`)에서 다음 동작을 쓰게 된다.
    - 대화를 이어 보낼 때 첨부·모델·effort를 바꾼다.
    - 프로젝트 대화 여러 개 가운데 하나를 고른다.
    - 보관된 대화를 다시 연다.
    - 대화가 캔버스로 승격되는 흐름을 탄다.
- **에이전트**
  - 이어진 턴에서도 첨부를 경로로 받는다. 기존 시작 요청과 같은 데이터 경계를 쓴다.
  - 캔버스를 만들거나 고친 턴이 끝나면 그 대화가 캔버스 대화가 된다. 에이전트가 따로 할 일은 없다.

## 문제 (관찰된 사실)

1. **대화 목록을 프로젝트 단위로 읽을 방법이 없다.**
   - main은 대화 index(`<userData>/conversations/index.json`)에 root, canvas, title, state를 저장한다.
   - 하지만 renderer가 쓸 수 있는 조회는 캔버스 하나의 현재·보관 대화(`conversation:forCanvas`)뿐이다.
2. **상태가 renderer 메모리에만 있다.**
   - 대상: 상태줄, LNB 슬롯, 마지막 요청, 프로젝트당 Home 대화 1개 규칙(PRODUCT §5 항목 1).
   - 다시 로드하면 사라진다. 실행 중인 대화가 있어도 다시 로드한 뒤에는 Home에서 같은 프로젝트로 또 보낼 수 있다.
3. **이어 보내는 send는 텍스트와 앵커만 받는다.**
   - 첨부·모델·effort는 `newDesign` 시작에서만 받는다(ARCHITECTURE §7 'IPC contract').
4. **Home 대화는 첫 턴에서만 캔버스에 묶인다.**
   - 첫 턴이 캔버스를 만들지 않고 끝나면 그 대화는 영영 묶이지 않는다(ARCHITECTURE §7 'Canvas lifecycle').
   - 기존 캔버스를 고친 대화는 어떤 경우에도 묶이지 않는다.
5. **보관된 대화는 다시 쓸 수 없다.** send를 바로 거절하고(`service.ts`), fold는 `conversation.archived` 뒤의 이벤트를 무시한다(`state.ts`).
6. **입력창이 Home 전용 한 덩어리다.**
   - `HomeComposerView.tsx`(692줄)에 다음이 함께 섞여 있다.
     - Home 전용 부분: 프로젝트 선택, 워크트리 트레이, 히어로 배치 측정.
     - 공용 부분: 텍스트 칸, 칩, 도구 줄.
   - buzz-home 인계 (2): 미리 분리하지 않았다.

## 결정 (2026-10-31 user)

1. 이번 자식은 프리미티브와 데이터만 만든다. 화면 대조(`/design-sync`)는 `buzz-project`가 한다.
2. 이어 보내는 send는 첨부·모델·effort를 받는다. 공급자는 대화마다 고정이다.
3. 프로젝트 대화(캔버스에 묶이지 않은 대화)는 여러 개 둘 수 있다. 한 프로젝트에서 동시에 실행되는 프로젝트 대화는 하나다. 캔버스 대화는 지금처럼 캔버스마다 따로 실행된다.
4. 프로젝트 대화는 어느 턴에서든 캔버스로 **승격**된다.
   - 승격되는 경우: 그 턴이 캔버스를 만들었을 때, 또는 기존 캔버스를 고쳤을 때.
   - 승격되면 그 대화가 캔버스의 현재 대화가 된다.
   - 그 캔버스에 원래 있던 현재 대화는 보관된다.
5. 보관된 대화는 열어서 읽을 수 있다. 메시지를 보내면 다시 현재 대화로 복구되고, 그때의 현재 대화는 보관된다.
6. 입력창은 공용 프리미티브와 두 타입으로 나눈다.
   - `hero`(Home): 항상 box 모양이다. 프로젝트 선택, 워크트리 트레이, 히어로 배치를 둔다.
   - `docked`(Overview, 캔버스 대화 패널): capsule과 box를 오간다. 에이전트·effort는 카드 아래 줄에 둔다. 프로젝트 선택은 없다.

## 완료 조건

- **목록**: main이 root 하나의 대화 요약 목록을 돌려준다.
  - 요약 항목: 대화 id, canvas 유무, title, current/archived, 공급자, 모델·effort, 진행 상태(실행 중·응답 대기·끝남), 안 본 종료 여부, 마지막 활동 시각.
  - 확인: 대화 목록 단위 테스트와 IPC 검증 테스트가 통과한다.
- **안 본 종료**: 안 본 종료 표시는 기기 안에 저장되고 재시작 뒤에도 남는다. 확인: index 읽기·쓰기 테스트와 재시작 fold 테스트.
- **실행 제한**: 같은 root에서 프로젝트 대화가 실행 중이면, 다른 프로젝트 대화의 시작과 send를 main이 `project_busy`로 거절한다. 캔버스 대화와 다른 root는 영향을 받지 않는다. 확인: service 테스트.
- **send 범위**: send가 첨부·모델·effort를 받는다. 검증은 시작과 같은 규칙이다(그 root·공급자에서 이번 실행에 받은 모델 목록, 그 모델의 effort 단계, main이 발급한 첨부 id). 바꾼 모델·effort는 index에 저장되어 다음 send에도 쓰인다. 확인: ipc·service 테스트.
- **승격**: 승격은 다음 기준으로 판정한다.
  - 프로젝트 대화의 턴이 새 캔버스를 만들면 그 턴 안에서 묶인다. 몇 번째 턴인지는 상관없다.
  - 기존 캔버스를 고친 턴은, 그 대화의 `activity` edit 이벤트 경로가 목록의 캔버스 정확히 하나를 가리킬 때 턴이 끝나며 승격된다.
  - 후보가 둘 이상이거나, 대상 캔버스의 현재 대화가 실행 중이면 승격하지 않는다.
  - 승격하면 이전 현재 대화가 보관된다.
  - 확인: 승격 판정 순수 함수 테스트와 service 테스트.
- **복구**: 보관된 대화에 send하면 그 대화가 현재 대화로 돌아오고, 그때의 현재 대화는 보관된다.
  - 거절 조건과 코드는 다음과 같다.
    - 현재 대화가 실행 중이면 `busy`다.
    - 캔버스가 없거나 둘 이상이면 `canvas_not_found`다.
  - 거절되면 index와 기록이 바뀌지 않는다.
  - 재시작 복구 테스트를 포함한다.
- **fold와 형식**: fold가 복구된 대화의 이후 이벤트를 다시 반영한다. 새 이벤트 형식은 이전 빌드가 손상이 아니라 알 수 없는 버전으로 거절한다. 확인: state·store 테스트.
- **입력창**: 입력창 프리미티브와 `hero`·`docked` 타입이 생긴다.
  - `docked`의 capsule/box 전환은 다음 규칙을 따른다.
    - 텍스트가 줄바꿈되거나 칩이 생기면 box가 된다.
    - 텍스트와 칩이 모두 없을 때만 capsule로 돌아간다.
    - 전환 중에 textarea를 다시 마운트하지 않는다.
  - 확인: 모양 판정 순수 함수 테스트, 전환 중 포커스와 IME 조합이 유지되는 컴포넌트 테스트.
- **Home 회귀 없음**: Home 입력창이 `hero`로 다시 조립되고 회귀가 없다. 확인: 기존 Home·입력창 테스트 통과, 실제 앱 probe에서 Home의 computed style과 배치가 바꾸기 전과 같다.
- **다시 로드 유지**: 다시 로드한 뒤에도 상태줄과 LNB 슬롯이 실행 중·응답 대기·안 본 종료를 다시 보인다. 확인: 실제 앱 probe(격리 userData).
- **스레드 프리미티브**: 대화 스레드 프리미티브가 생긴다. 이벤트 기록을 메시지, 활동, 권한 요청, 끝 상태 항목으로 바꾸는 순수 함수와 그 표시 컴포넌트다. 확인: 순수 함수 테스트와 컴포넌트 테스트. 화면 배치는 `buzz-project`가 맡는다.
- **문서 반영**: PRODUCT §3 항목 6, §5 항목 1과 ARCHITECTURE §7 'Agent conversation runtime and IPC'가 현재 규칙으로 고쳐졌다.

## 비목표

- Overview 배치(메인 스레드, 헤더 대화 드롭다운, 오른쪽 캔버스 목록), 승격 뒤 프로젝트 대화에 남기는 링크 카드, 빈 대화의 추천. 이 항목은 `buzz-project`가 맡는다.
- 캔버스 오른쪽 패널, 대화·인스펙터 탭 틀, 요소 피커, 앵커 칩 입력, 보관 대화를 여는 캔버스 구석 버튼, 코멘트 화면 제거. 이 항목은 `buzz-canvas-conversation`이 맡는다.
- 사용자가 터미널에서 실행한 세션(legacy external, `sessions.jsonl` 연결)을 대화 목록에 넣는 일. 목록은 앱이 저장한 대화만 다룬다.
- 대화 제목 자동 생성. 제목은 지금처럼 첫 요청의 앞부분이다.
- 공급자 바꾸기. 대화의 공급자는 고정이다.
- 대화 기록의 보존 기간, 페이지 나누기, 검색.
- 상태줄과 LNB 슬롯의 모양 변경. 대체는 `buzz-project`가 한다.

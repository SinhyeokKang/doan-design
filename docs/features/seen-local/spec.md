# seen-local — 캔버스 읽음 상태를 기기 로컬로 옮긴다

## 사용자

- **사람**: 앱에서 캔버스를 보고 사이드바의 점(캔버스 알림)으로 새 캔버스와 바뀐 캔버스를 알아차리는 사람.
- **에이전트**: 직접 쓰지 않는다. 다만 지금은 사람이 캔버스를 볼 때마다 `.doan/seen/`이 바뀌어 에이전트의 작업 트리에도 변경이 생기는데, 이 변경이 사라진다.

## 문제

- 지금 읽음 기록은 `<root>/.doan/seen/<canvas-id>.json`에 있다(PRODUCT §5 item 1 'Canvas notice', ARCHITECTURE §7 'Seen canvases'). storage `repo`인 프로젝트에서는 캔버스를 보기만 해도 추적 중인 파일이 바뀐다.
- 그래서 캔버스를 볼 때마다 git 작업 트리가 더러워지고, 커밋·브랜치 전환·PR에 읽음 기록이 섞인다. 사용자는 머신 간 공유보다 이 불편이 더 크다고 판단했다.

## 완료 기준

- 캔버스를 캔버스 페이지로 보여도 프로젝트 안의 파일은 하나도 바뀌지 않는다(`.doan/seen/`을 만들지도, 쓰지도 않는다).
- 읽음 기록은 userData의 기기 로컬 파일에만 저장되고, 앱을 재시작해도 점의 상태가 유지된다.
- 점이 켜지는 규칙(HTML 내용 기준, 새 캔버스·바뀐 캔버스, 썸네일과 프로토타입은 보지 않은 것으로 침)은 지금과 같다.
- 처음 등록한 프로젝트는 지금처럼 모든 캔버스를 본 상태로 시작하고, 그 뒤 추가된 캔버스에 점이 켜진다.
- 이미 `.doan/seen/` 기록이 있는 프로젝트는 전환할 때 한 번만 그 기록을 읽어 로컬 기록의 시작값으로 쓴다. 전환 직전에 켜져 있던 점은 전환 뒤에도 켜져 있다. 이후에는 그 디렉터리를 읽지도 쓰지도 지우지도 않는다.
- 저장 실패 시 점을 숨기지 않고 툴팁·토스트·Retry로 알리는 규칙은 로컬 파일 기준으로 유지된다.

## 비목표

- 머신 간, 사람 간 읽음 상태 공유. 다른 머신에서는 처음 등록할 때의 규칙대로 시작한다.
- 기존 `.doan/seen/` 디렉터리 삭제나 `.gitignore` 수정. 사용자가 직접 git에서 지운다.
- 대화 읽음 상태(unseen ending) 변경.

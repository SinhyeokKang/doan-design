# composer-long-paste-chip — spec

## 사용자

- **사람**: 컴포저(Home, Overview의 docked 컴포저, 캔버스 대화 패널, 프로토타입 창 패널)에 스펙·로그·코드 같은 긴 글을 붙여넣는 사람. 필드가 긴 글로 채워지지 않고, 붙여넣은 글을 칩 하나로 본다.
- **에이전트**: 붙여넣은 글을 메시지 본문이 아니라 첨부 파일 경로로 받고, 파일 도구로 읽는다. 붙여넣은 이미지와 같은 길이다(PRODUCT §5 item 1 'Attachments').

## 문제 (관찰된 사실)

- 지금 컴포저에 텍스트를 붙여넣으면 길이와 상관없이 필드에 그대로 들어간다(`chipField.ts` `paste`). 필드는 여덟 줄에서 높이가 멈추고 스크롤되므로, 긴 글을 붙여넣으면 앞뒤에 직접 쓴 요청이 묻힌다.
- 메시지 본문은 32,768자로 제한된다(`messageText.ts` `LIMITS.text`). 이보다 긴 스펙은 한 메시지로 보낼 수 없다.
- 첨부는 경로만 넘기고, 경로가 없는 붙여넣은 이미지와 캔버스 캡처만 userData에 저장한다(PRODUCT §5 item 1 'Attachments', ARCHITECTURE §7 'Attachments'). 붙여넣은 텍스트를 파일로 넘기는 길은 없다.

## 완료 조건

1. 기준 길이(줄바꿈을 `\n`으로 맞춘 뒤 **1,000자 이상 또는 10줄 이상**) 이상의 일반 텍스트를 ⌘V, Edit > Paste, 텍스트 편집 메뉴의 Paste로 붙여넣으면, 필드에는 글이 들어가지 않고 첨부 칩 하나가 생긴다. 네 컴포저 모두 같다.
2. 기준 미만의 텍스트, 같은 캔버스에서 복사한 칩 클립보드, Finder 파일·이미지 붙여넣기는 지금처럼 동작한다.
3. 칩은 파일 아이콘과 "Pasted text", 줄 수를 보여 주고, 다른 첨부 칩처럼 지울 수 있다. 보내지 않고 지우면 저장한 파일도 지운다.
4. 보낸 메시지의 첨부는 다른 붙여넣은 첨부처럼 에이전트에게 경로 descriptor로 가고, 이번 턴의 fence가 그 디렉터리 읽기를 연다. Claude Code·Codex 실제 턴에서 에이전트가 붙여넣은 글의 내용을 읽고 답한다.
5. 첨부 10개 제한에 포함된다. 첨부가 이미 10개면 기준 이상의 글은 필드에 넣지 않고, 다른 첨부가 한도를 넘을 때처럼 그 컴포저 아래에 거절 문구를 보여 준다. 터미널 세션처럼 첨부를 받지 않는 컴포저에서는 글이 지금처럼 필드에 들어간다.
6. 큐·Send now·드래프트 복원·재시작·대화 삭제에서 붙여넣은 이미지와 같은 수명 규칙을 따른다(`sent` 마커 전에는 정리 대상, 뒤에는 유지).

## 비목표

- 칩 내용 미리보기, 칩 안 글 편집.
- 붙여넣은 글을 다시 필드 텍스트로 펼치기. 칩이 된 글을 필드에 넣으려면 칩을 지우고 기준 미만으로 나눠 붙여넣는다.
- 드롭한 텍스트(드래그 앤 드롭 텍스트 조각)의 칩 변환.
- 대화 스레드 말풍선에서 붙여넣은 글 내용 보기. 말풍선은 다른 첨부처럼 칩만 보여 준다.
- 붙여넣은 텍스트 파일 정리용 참조 카운트(BACKLOG의 붙여넣은 이미지 항목과 같은 한계를 그대로 둔다).

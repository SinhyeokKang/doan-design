# buzz-home — spec

buzz-restyle의 자식 C3이다(부모: [../buzz-restyle/](../buzz-restyle/spec.md)). 프로젝트를 고르기 전의 앱 홈을 **대화 시작 화면**으로 바꾼다. 홈에는 가운데 대화 입력창 하나만 두고, 이 과업에서 입력창의 기능을 완성한다(2026-10-29 user). 선행인 buzz-shell, agent-auth, buzz-onboarding, doan-design-skills(백엔드)는 main에 병합됐다.

## 사용자

- **사람(앱 사용자)**: 홈에서 프로젝트·에이전트·모델·디자인 프리셋을 고르고, 이미지나 파일을 첨부해 요청을 보낸다. 보낸 뒤에는 그 프로젝트 화면으로 이동해 진행·권한 요청·실패를 본다. 한계: 연결된 공급자가 하나도 없거나 모두 다시 로그인해야 하면 홈에서 로그인할 길이 없다. 온보딩은 완료 뒤 다시 열 수 없으므로 이 한계는 buzz-settings가 계정 UI를 만들 때까지 남는다.
- **에이전트**: 고른 공급자·모델(·effort)의 도안 연결에서 새 대화로 요청과 첨부 경로를 받는다. 프리셋을 고른 요청에는 프리셋 id가 명시돼 있으므로, 에이전트는 기존 가이드 규칙대로 그 프리셋을 읽는다([ARCHITECTURE §7 'Design preset reads'](../../ARCHITECTURE.md#design-preset-reads-2026-10-29-doan-design-skills)). CLI·MCP 표면 중 `doan design-skill` 목록·단건 결과와 MCP `design_skill`의 프리셋 요약에 `group`이 더해진다. 가이드·스텁·프리셋 본문은 바뀌지 않는다.

## 문제 (관찰된 사실)

1. 홈은 projects-home(2026-10-25)의 프로젝트 카드 목록이다. buzz-shell 이후 LNB에도 같은 프로젝트 목록·워크트리 선택·복구 동작이 있어 두 곳이 겹친다(`app/src/renderer/Home.tsx`, `ShellSidebar.tsx`).
2. 앱에서 에이전트에게 일을 시작시키는 UI가 없다. 대화 백엔드(`startConversation`, agent-auth의 다섯 공급자)와 프리셋 읽기 API(`designSkills.list/get`)는 있지만 renderer가 쓰지 않는다(PRODUCT §3 In scope 7, §5 Skills 13).
3. 온보딩을 마치면 홈이 그 프로젝트 카드를 강조만 하고, 키보드 포커스는 첫 카드로 간다(buzz-onboarding V 관찰, 부모 tasks C3).
4. 온보딩으로 Claude Code를 연결해도 홈 체크리스트가 'Finish setting up doan · 1 left · Connect Claude Code or Codex'를 보인다. 체크리스트가 agent-auth가 아니라 Settings의 외부 CLI 연결 상태(`homeAlerts`)를 읽기 때문이다(부모 tasks C3).
5. 사람이 고를 수 있는 디자인 프리셋 UI가 없다. 목록·검색·선택·전송 UI는 buzz-home 몫으로 정해졌다(PRODUCT §7 2026-10-29).

## 확정된 방향 (2026-10-29 user)

- 홈 본문은 대화 시작만 제공한다. 프로젝트 카드는 없앤다. 프로젝트 목록은 Home에도 보이는 LNB가 맡는다. Home은 워크스페이스와 같은 셸이고 본문에 입력창이 놓인다.
- 입력창의 완성도를 이 과업에서 끝낸다. 모든 상태를 초안에 그리고 실제 앱에서 측정해 맞춘다.
- 꾸밈 요소로 accent 그라디언트와, AI 채팅 앱처럼 바뀌는 인사 문구를 쓴다. 그라디언트는 Welcome과 달리 입력창 가운데에서 퍼지는 가로로 긴 violet 타원이다.
- 보낸 뒤에는 그 프로젝트로 이동하고, buzz-conversation이 대화 패널을 만들 때까지 워크스페이스에 **임시 대화 상태줄**(진행·권한 응답·중단·실패 복구)을 둔다. 메시지 본문 스트림은 보이지 않는다. 실패·중단되면 마지막으로 보낸 요청을 홈 입력창에 되돌릴 수 있다.
- LNB 행 오른쪽 상태 슬롯에 홈 대화 상태를 보인다. 우선순위는 권한 요청 아이콘 > 작업 중 스피너 > 미확인 Dot이다. 대화가 캔버스에 묶였으면 그 캔버스 행, 아니면 프로젝트 행에 보인다. 이번에는 홈 대화만, 실행 중 메모리로 판단한다.
- 홈 대화는 프로젝트당 동시에 하나다. 임시 상태줄이 하나만 보이기 때문에 생긴 임시 규칙이고, buzz-conversation이 다시 정한다.
- 프리셋은 입력창 도구 줄의 버튼 팝오버(검색·그룹 탭)와 입력 맨 앞의 `/`로 고른다. 고른 프리셋은 입력창 안의 칩으로 보이고, 한 번에 하나이며, 그 메시지 한 번에만 적용된다.
- 프리셋 팝오버의 Suggested 탭에 선택된 프로젝트에 맞는 프리셋을 올린다. 입력창 아래에는 같은 고정 규칙으로 만든 추천 프롬프트 3개를 둔다. 누르면 프리셋 칩과 문장이 입력창에 채워지고, 보내기는 사람이 한다. 이 결정은 PRODUCT §7 2026-10-27(doan-design-skills)의 '추천 UI 없음'과 같은 날의 '상태 기반 제안 카드 없음'을 대체한다. 자동 리뷰·대안 비교 UI가 없다는 결정은 그대로다.
- 프리셋 20개를 하려는 일 기준 다섯 그룹(Start, Review, Refine, Content, Explore)으로 묶는다. 그룹은 CLI 목록 결과의 `group` 키(`start` 등 소문자)로 나간다.
- 연결된 공급자에 따라 모델을 고르는 UI와, 모델이 단계를 알려줄 때 고르는 effort UI를 둔다. 공급자는 로고로만, 모델은 텍스트로 보인다. 둘 다 대화 IPC의 새 입력이다.
- 이미지와 파일 첨부를 둔다. 첨부는 파일을 보내는 것이 아니라 로컬 경로를 에이전트에게 알려주는 것이다(Orca 방식). 경로가 없는 붙여넣기 이미지만 기기 로컬(userData)에 저장하고 그 경로를 넘긴다. 첨부만 있는 요청도 보낼 수 있다.
- 외부 CLI 연결 'Needs attention' 배너와 'Finish setting up doan' 체크리스트는 홈에서 없앤다. 외부 CLI·MCP 연결 상태는 Settings > Connections에서만 보인다.
- 공용 토스트는 메시지와 동작을 한 줄에 두고 동작을 오른쪽 `prominent` 버튼으로, 위치를 창 오른쪽 아래로 바꾼다. 모든 토스트에 적용된다.

### PRODUCT §7에 기록할 결정

홈 카드 제거와 그 동작의 행방, Home의 LNB, 홈 대화 프로젝트당 1개(임시), LNB 상태 슬롯, 임시 상태줄과 마지막 요청 되돌리기, 진행 중 프로젝트 제거 확인, 외부 연결 배너·체크리스트 제거(PRODUCT §5 항목 0 변경), 추천 프리셋·추천 프롬프트(2026-10-27 '추천 UI 없음' 대체), 프리셋 그룹과 `group` 키, 프리셋 요청 머리말·홈 고정 문단·첨부 목록 형식, 프리셋 칩은 한 메시지에만 적용, 모델·effort 선택, 첨부의 로컬 경로 전달·붙여넣기 저장·한도, 첨부만 있는 요청, 홈 전용 그라디언트(Welcome 밖 accent 예외), 고른 프리셋 칩 accent, 인사 문구, 공용 토스트 변경, 공용 변형(`quiet`·`trigger`·icon `xs`·icon `accent`), 로그인 막다른 상태(buzz-settings까지의 한계).

## 완료 조건

각 항목은 단위 테스트, 또는 실제 앱의 짧은 probe(`/runtime-test`)로 확인한다.

1. 홈 본문에는 인사 문구, 입력창, 장식 배경, 추천 프롬프트만 있고 프로젝트 카드·체크리스트·외부 CLI 연결 배너가 없다. LNB는 `aria-current` 없이 보인다. 확인: Home 렌더 테스트에 `.card`·'Finish setting up doan'·'Connection problem'이 없다.
2. 입력창에서 프로젝트·공급자·프리셋을 고르고 텍스트를 쓴 뒤 Send(또는 Enter)를 누르면, 고른 공급자의 도안 연결에서 새 대화가 시작되고 창은 그 프로젝트의 워크스페이스로 이동한다. 확인: 순수 함수·컴포넌트 테스트, 공급자 하나로 실제 앱 probe.
3. 한국어 IME 조합 중 Enter는 전송하지 않는다. Shift+Enter는 줄을 바꾼다. 확인: 컴포넌트 테스트(`isComposing`).
4. 프리셋 목록은 홈에 들어올 때 `designSkills.list()`로 읽고, 팝오버에서 Suggested와 다섯 그룹 탭으로 보인다(`group`이 없는 이전 CLI면 탭 없이 한 목록). 검색, 키보드 이동, `/` 단축, 칩 제거가 동작한다. 목록을 읽지 못하면 실패 이유가 보이고 프리셋 없이 보낼 수 있다. 확인: 순수 함수·컴포넌트 테스트, 실제 앱 probe.
5. 입력과 칩이 비어 있으면 입력창 아래에 추천 프롬프트가 최대 3개 보이고, 누르면 프리셋 칩과 대상 캔버스를 명시한 문장이 채워진다. 확인: `suggestedPrompts` 단위 테스트.
6. 보낸 요청은 design §4.5·§4.6의 형식을 따른다. 프리셋을 고르면 사용자 텍스트 앞에 프리셋 머리말이 붙고, 홈에서 보낸 요청에는 main이 `doan active` 제외 고정 문단과 첨부 목록을 데이터로 붙인다. 확인: `composeRequest`·`prompt` 단위 테스트.
7. 모델 선택기는 이번 실행에서 고른 공급자가 알려준 모델만 보이고, 고른 모델로 첫 턴이 실행된다. 목록을 받지 못한 공급자는 'Default'만 보이고 model을 보내지 않는다. effort 단계를 알려주는 모델에서만 effort 캡슐이 보이고 그 값으로 실행된다. 확인: PoC 기록(PRODUCT §6), 백엔드 단위 테스트, 공급자 하나 이상으로 실제 앱 probe.
8. 파일 선택·붙여넣기·입력창 드롭으로 첨부하면 칩(이미지는 썸네일)으로 보이고 지울 수 있다. 보내면, P2를 통과한 공급자에서 기본 권한 설정으로 에이전트가 그 파일을 읽는다. 한도(10개, 붙여넣기 50 MB)를 넘거나 보내기 전에 파일이 없어지면 그 항목만 거절하고 이유를 보인다. doan은 사람이 고른 로컬 파일을 복사·수정·삭제하지 않고, 보내지 않고 지운 붙여넣기 파일은 기기에서 지운다. 확인: 순수 함수·main 단위 테스트, PoC 기록, 실제 앱 probe.
9. 보낼 수 없는 상태(프로젝트 없음·unhealthy, 준비된 공급자 없음, 텍스트·프리셋·첨부가 모두 없음, 한도 초과, `{{`·`}}` 포함, 첨부 확인 중, 진행 중인 홈 대화가 있는 프로젝트)마다 Send가 비활성이고 이유가 보인다(빈 입력은 문구 없음). 거절 응답에서는 입력이 유지되고 코드별 문구가 보인다. 확인: `sendAvailability`·`startErrorView` 단위 테스트.
10. 워크스페이스의 임시 상태줄이 시작·진행·권한 요청·실패·중단·완료를 보이고 `role="status"`로 알린다. 권한 요청에는 공급자가 준 선택지로 답할 수 있고, Stop은 `interruptConversation`을 부르며, 실패·중단에서 'Edit on Home'은 마지막 요청을 홈 입력창에 되돌린다. 확인: 상태 reducer·컴포넌트 테스트, 실제 앱 probe(권한 요청 하나).
11. 다른 화면에 있을 때 홈 대화가 권한 요청·작업 중·미확인 완료 상태가 되면 LNB 상태 슬롯이 우선순위대로 보이고, 권한 요청은 보조로 토스트도 띄운다. 확인: 슬롯 상태 단위 테스트, 실제 앱 probe.
12. 보낸 시점의 캔버스 목록에 없던 캔버스가 그 대화의 턴 동안 root에 나타나면 그 대화에 묶이고, 사람이 그 사이 다른 캔버스를 열지 않았으면 자동으로 열린다. 확인: main 바인딩 단위 테스트, 실제 앱 probe.
13. 온보딩 완료 뒤 홈은 완료 기록의 프로젝트를 입력창 프로젝트로 고르고, 포커스는 입력창에 간다(문제 3 해결). 확인: App 테스트.
14. 문제 4의 체크리스트는 없어지고, 준비된 공급자 여부는 공급자 선택기가 agent-auth readiness로 보인다. 확인: 컴포넌트 테스트.
15. 홈 대화가 진행 중인 프로젝트를 제거하면 확인을 묻고, 확인하면 대화를 멈춘 뒤 제거한다. 확인: App 테스트.
16. 인사 문구와 placeholder는 그라디언트가 가장 진한 자리에서 대비 4.5:1 이상이다(`/design-sync`에서 입력창 아래 타원 중심 근처를 측정). 인사 문구는 홈에 들어올 때 한 번 고르고 그 방문 동안 바뀌지 않는다(프로젝트 이름만 선택기를 따른다). 확인: `pickGreeting` 단위 테스트, `/design-sync` 측정.
17. 새 초안 `.doan/canvases/buzz-home.html`(26 프레임)과 구현을 `/design-sync`로 맞추고, DESIGN.md의 'Projects home'과 'Settings and Home setup'의 Home 부분을 새 기록으로 바꾼다.

## 비목표

- 대화 패널, 메시지 스트림, 앵커 칩·요소 피커, 보관 대화(buzz-conversation). 임시 상태줄·LNB 슬롯의 홈 한정 규칙은 buzz-conversation이 다시 정한다. 입력창을 대화 패널과 나눠 쓰는 구조도 그때 정한다(미리 분리하지 않는다).
- 홈 대화가 아닌 변경(터미널 에이전트 등)의 미확인 판별·저장(LNB Dot의 일반 의미, buzz-shell 후속).
- 프로젝트 Overview 안의 입력창·추천 프롬프트(부모 spec '프로젝트 홈 아이디어 메모', buzz-project 이후).
- 첨부 파일을 저장소나 userData로 복사하는 일(2026-10-29 user: 로컬 경로를 넘긴다). 경로가 없는 붙여넣기 이미지는 예외다.
- 폴더 첨부. 입력창 밖으로 폴더를 드롭하면 지금처럼 프로젝트 추가로 처리한다.
- 여러 프리셋 동시 선택, 프리셋 본문 미리보기, 보내기 전 매핑 미리보기(PRODUCT §7 2026-10-29: 매핑 미리보기 없음). 프리셋이 대상을 요구하는지 알리는 CLI 필드(doan-design-skills 후속).

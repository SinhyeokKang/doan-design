# buzz-home — spec

buzz-restyle의 자식 C3이다(부모: [../buzz-restyle/](../buzz-restyle/spec.md)). 프로젝트를 고르기 전의 앱 홈을 **대화 시작 화면**으로 바꾼다. 홈에는 가운데 대화 입력창 하나만 두고, 이 과업에서 입력창의 기능을 완성한다(2026-10-29 user). 선행인 buzz-shell, agent-auth, buzz-onboarding, doan-design-skills(백엔드)는 main에 병합됐다.

## 사용자

- **사람(앱 사용자)**: 홈에서 프로젝트·에이전트·모델·디자인 프리셋을 고르고, 이미지나 파일을 첨부해 요청을 보낸다. 보낸 뒤에는 그 프로젝트 화면으로 이동해 진행·권한 요청·실패를 본다.
- **에이전트**: 고른 공급자·모델의 도안 연결에서 새 대화로 요청과 첨부를 받는다. 프리셋을 고른 요청에는 프리셋 id가 명시돼 있으므로, 에이전트는 기존 가이드 규칙대로 그 프리셋을 읽는다([ARCHITECTURE §7 'Design preset reads'](../../ARCHITECTURE.md#design-preset-reads-2026-10-29-doan-design-skills)). CLI·MCP·스킬 표면은 바뀌지 않는다.

## 문제 (관찰된 사실)

1. 홈은 projects-home(2026-10-25)의 프로젝트 카드 목록이다. buzz-shell 이후 LNB에도 같은 프로젝트 목록·워크트리 선택·복구 동작이 있어 두 곳이 겹친다(`app/src/renderer/Home.tsx`, `ShellSidebar.tsx`).
2. 앱에서 에이전트에게 일을 시작시키는 UI가 없다. 대화 백엔드(`startConversation`, agent-auth의 다섯 공급자)와 프리셋 읽기 API(`designSkills.list/get`)는 있지만 renderer가 쓰지 않는다(PRODUCT §3 In scope 7, §5 Skills 13).
3. 온보딩을 마치면 홈이 그 프로젝트 카드를 강조만 하고, 키보드 포커스는 첫 카드로 간다(buzz-onboarding V 관찰, 부모 tasks C3).
4. 온보딩으로 Claude Code를 연결해도 홈 체크리스트가 'Finish setting up doan · 1 left · Connect Claude Code or Codex'를 보인다. 체크리스트가 agent-auth가 아니라 Settings의 외부 CLI 연결 상태(`homeAlerts`)를 읽기 때문이다(부모 tasks C3).
5. 사람이 고를 수 있는 디자인 프리셋 UI가 없다. 목록·검색·선택·전송 UI는 buzz-home 몫으로 정해졌다(PRODUCT §7 2026-10-29).

## 확정된 방향 (2026-10-29 user)

- 홈 본문은 대화 시작만 제공한다. 프로젝트 카드는 없앤다. 프로젝트 목록은 LNB가 맡는다.
- 입력창의 완성도를 이 과업에서 끝낸다.
- 꾸밈 요소로 온보딩 Welcome의 accent 그라디언트 스타일과, AI 채팅 앱처럼 바뀌는 인사 문구를 쓴다.
- 보낸 뒤에는 그 프로젝트로 이동하고, buzz-conversation이 대화 패널을 만들 때까지 워크스페이스에 **임시 대화 상태줄**(진행·권한 응답·중단·실패 복구)을 둔다. 메시지 본문 스트림은 보이지 않는다.
- 프리셋은 입력창 도구 줄의 버튼 팝오버(검색 포함)와, 입력 맨 앞의 `/`로 고른다. 고른 프리셋은 입력창 안에 칩으로 보이고 한 번에 하나만 고를 수 있다.
- 상태 기반 '다음 액션' 제안 카드는 두지 않는다. 대신 프리셋 팝오버 맨 위에 선택된 프로젝트에 맞는 프리셋을 올린다.
- 연결된 공급자에 따라 모델을 고르는 UI를 둔다.
- 이미지와 파일 첨부를 둔다. 첨부는 파일을 보내는 것이 아니라 로컬 경로를 에이전트에게 알려주는 것이다(Orca 방식). 에이전트가 자기 도구로 그 파일을 읽는다. 경로가 없는 붙여넣기 이미지만 기기 로컬(userData)에 저장하고 그 경로를 넘긴다.
- 입력창 UI의 완성도를 이 과업의 핵심 기준으로 삼는다. 모든 상태를 초안에 그리고 실제 앱에서 측정해 맞춘다.

## 완료 조건

각 항목은 단위 테스트, 또는 실제 앱의 짧은 probe(`/runtime-test`)로 확인한다.

1. 홈에는 인사 문구, 입력창, 장식 배경만 있고 프로젝트 카드·체크리스트·외부 CLI 연결 배너가 없다. 확인: Home 렌더 테스트에 `.card`·'Finish setting up doan'·'Connection problem'이 없다.
2. 입력창에서 프로젝트·공급자·프리셋을 고르고 텍스트를 쓴 뒤 Send(또는 Enter)를 누르면, 고른 공급자의 도안 연결에서 새 대화가 시작되고 창은 그 프로젝트의 워크스페이스로 이동한다. 확인: 순수 함수·컴포넌트 테스트, 공급자 하나로 실제 앱 probe.
3. 한국어 IME 조합 중 Enter는 전송하지 않는다. Shift+Enter는 줄을 바꾼다. 확인: 컴포넌트 테스트(`isComposing`).
4. 프리셋 목록은 `designSkills.list()`에서 온다. 검색, 키보드 이동, `/` 단축, 칩 제거가 동작한다. 목록을 읽지 못하면 실패 이유가 보이고 프리셋 없이 보낼 수 있다. 확인: 순수 함수·컴포넌트 테스트, 실제 앱 probe.
5. 프리셋을 고르고 보낸 요청의 텍스트에는 프리셋 id와 제목이 정해진 형식으로 들어간다. 확인: `composeRequest` 단위 테스트.
6. 모델 선택기는 고른 공급자가 알려준 모델만 보이고, 고른 모델로 첫 턴이 실행된다. 모델 목록을 읽지 못하는 공급자는 'Default'만 보인다. 확인: PoC 기록(PRODUCT §6), 백엔드 단위 테스트, 공급자 하나 이상으로 실제 앱 probe.
7. 파일 선택·붙여넣기·입력창 드롭으로 첨부하면 칩(이미지는 썸네일)으로 보이고, 지울 수 있고, 보내면 에이전트가 그 파일을 읽는다. 한도(개수, 붙여넣기 크기)를 넘거나 보내기 전에 파일이 없어지면 그 항목만 거절하고 이유를 보인다. doan은 사람이 고른 로컬 파일을 복사·수정·삭제하지 않고, 보내지 않고 지운 붙여넣기 파일은 기기에서 지운다. 확인: 순수 함수·main 단위 테스트, PoC 기록, 실제 앱 probe.
8. 보낼 수 없는 상태(프로젝트 없음, 준비된 공급자 없음, 빈 입력, 진행 중인 홈 대화가 있는 프로젝트)마다 Send가 비활성이고 이유가 보인다. 거절 응답에서는 입력이 유지되고, 오류 코드별 복구 문구가 보인다. 확인: `sendAvailability`·`startErrorView` 단위 테스트.
9. 워크스페이스의 임시 상태줄이 시작·진행·권한 요청·실패·중단·완료를 보이고, 권한 요청에는 공급자가 준 선택지로 답할 수 있으며, Stop은 `interruptConversation`을 부른다. 다른 화면에 있을 때 권한 요청이 오면 토스트로 알린다. 확인: 상태 reducer 단위 테스트, 실제 앱 probe(권한 요청 하나).
10. 대화가 만든 첫 캔버스가 목록에 나타나면 그 워크스페이스에서 자동으로 열린다. 확인: 실제 앱 probe.
11. 온보딩 완료 뒤 홈은 완료 기록의 프로젝트를 입력창 프로젝트로 고르고, 포커스는 입력창에 간다(문제 3 해결). 확인: App 테스트.
12. 문제 4의 체크리스트는 없어지고, 준비된 공급자 여부는 공급자 선택기가 agent-auth readiness로 보인다. 확인: 컴포넌트 테스트.
13. 배경 그라디언트는 reduced transparency·reduced motion에서도 글자 대비를 해치지 않는다. 인사 문구는 홈에 들어올 때 한 번 고르고 그 방문 동안 바뀌지 않는다. 확인: `pickGreeting` 단위 테스트, `/design-sync` 측정.
14. 새 초안 `.doan/canvases/buzz-home.html`과 구현을 `/design-sync`로 맞추고, DESIGN.md의 'Projects home'과 'Settings and Home setup'의 Home 부분을 새 기록으로 바꾼다.

## 비목표

- 대화 패널, 메시지 스트림, 앵커 칩·요소 피커, 보관 대화(buzz-conversation). 임시 상태줄은 buzz-conversation이 걷어낸다.
- 프로젝트 Overview 안의 입력창·추천 프롬프트(부모 spec '프로젝트 홈 아이디어 메모', buzz-project 이후).
- 상태 기반 다음 액션 제안 카드(2026-10-29 user가 제외).
- 추론 강도(effort) 선택. 모델 선택만 한다.
- 첨부 파일을 저장소나 userData로 복사하는 일(2026-10-29 user: 로컬 경로를 넘긴다).
- 폴더 첨부. 폴더를 드롭하면 지금처럼 프로젝트 추가로 처리한다.
- 여러 프리셋 동시 선택, 프리셋 본문 미리보기, 보내기 전 매핑 미리보기(PRODUCT §7 2026-10-29: 매핑 미리보기 없음).
- 앱 재시작 뒤 입력 초안 복원.
- LNB 구조 변경(buzz-shell 소유). 추가된 프로젝트 강조처럼 홈 카드가 하던 일을 옮기는 데 필요한 최소 변경만 한다(design.md §6).
- Settings 창의 계정 UI(buzz-settings).

# 헤더 브레드크럼과 워크트리 — spec

## 사용자

- **사람**: 캔버스 페이지와 Overview에서 지금 어느 프로젝트의 어느 워크트리를 보고 있는지 확인하고, 그 자리에서 다른 워크트리로 옮긴다. 이번 기능의 사용자는 사람이다.
- **에이전트**: 변화 없다. CLI 출력, `doan work`, 자동 등록은 그대로다.

## 문제 (관찰된 사실)

- 캔버스 헤더(`CanvasHeader.tsx:28-62`)는 캔버스 이름, 프레임 서랍, 줌, Reload, 접힌 패널의 Show 버튼만 보인다. 프로젝트와 워크트리는 어디에도 없다(PRODUCT §5 item 2 'Canvas header').
- 워크트리 표시와 선택이 화면마다 다르다.
  - 사이드바 프로젝트 행: 선택된 워크트리의 브랜치를 읽기 전용 칩으로 보인다. 워크트리가 여럿이어도 칩은 고를 수 없고, 고르려면 "…" 메뉴의 Worktrees 구역을 열어야 한다(`ShellSidebar.tsx:476`, `:487-493`).
  - Overview 헤더: 프로젝트 이름 옆 브랜치 칩. 워크트리가 둘 이상이면 메뉴 버튼, 하나면 읽기 전용이다(`ProjectOverview.tsx:369-439`, PRODUCT §5 item 3 'Header').
  - 캔버스 헤더: 없다.
- 세 메뉴가 같은 목록을 따로 만든다(사이드바, Overview, Home composer). 문제 워크트리 행의 처리도 다르다.

## 완료 조건

1. 캔버스 헤더가 브레드크럼(`nav`, 접근 이름 "Breadcrumb")으로 시작한다: `프로젝트 › 워크트리 셀렉트 › 캔버스 › 프레임 서랍`. 뒤의 줌, Reload, Show 버튼은 지금과 같다. Git이 아닌 프로젝트는 워크트리 셀렉트 없이 `프로젝트 › 캔버스 › 프레임 서랍`이다.
2. 프로젝트 조각은 버튼이고(접근 이름 "<프로젝트> Overview"), 누르면 그 워크트리의 Overview로 간다(사이드바에서 로드된 프로젝트 행을 누를 때와 같다).
3. 워크트리 셀렉트는 사이드바 프로젝트 행, Overview 헤더, 캔버스 헤더에서 같은 컴포넌트로 그려진다. Git 프로젝트에서는 등록된 워크트리 수와 상관없이 항상 셀렉트(메뉴 버튼)다. 워크트리가 하나면 메뉴에 그 한 행만 있다. 개수에 따라 버튼이 되었다 말았다 하면 헷갈리기 때문이다(2026-11-19 사용자 결정). 지금 Overview의 '하나면 읽기 전용' 규칙은 없어진다. Git이 아닌 프로젝트(브랜치 없음)에는 셀렉트가 없다(지금 Overview와 같다).
4. 라벨은 지금 Overview 칩과 같다(브랜치, 없으면 폴더 이름, detached HEAD는 `detached <sha7>`). 라벨이 줄임표로 잘리면 툴팁에 전체 라벨과 `~` 경로를 보인다. 접근 이름은 "Worktree: <라벨>"이다.
5. 셀렉트 메뉴: "Worktrees" 머리글, 행마다 브랜치(또는 폴더)와 `~` 경로, 현재 행 체크.
   - 사이드바·Overview: 문제 행은 그 복구 동작으로 바뀐다(지금 규칙).
   - 캔버스 헤더: 모든 등록 워크트리가 보이되, 지금 캔버스가 목록에 없는 워크트리는 비활성 행이고 행 안에 "No <canvas> here"를 보인다. 캔버스 목록을 아직 읽는 워크트리는 비활성 행 "Reading…", 문제 워크트리는 비활성 행에 그 상태를 보인다(복구는 사이드바·Overview에서 한다).
   - 현재 행을 다시 고르면 메뉴만 닫히고 이동하지 않는다.
6. 워크트리를 고르면:
   - 사이드바: 지금처럼 그 워크트리에서 마지막에 본 캔버스, 없으면 Overview.
   - Overview 헤더: 지금처럼 그 워크트리의 Overview.
   - 캔버스 헤더: 그 워크트리의 같은 경로 캔버스. 줌과 보던 위치는 유지하고 선택은 해제한다. 메뉴를 연 뒤 고르기 전에 그 캔버스가 사라졌으면 토스트를 띄우고 제자리에 머문다(지금 `openShellCanvas`, `App.tsx:838`).
7. 쓸 수 없는 셀렉트는 `aria-disabled`이고 이유를 툴팁과 접근 설명에 보인다: 프로젝트 문제일 때, 목록에 없는 페이지일 때(캔버스 헤더), 잠금 중일 때(사이드바, `docs/design/project.md` Lock).
8. 960×600 창에서 캔버스 헤더의 조각들이 겹치지 않고, 초안이 정한 줄임 순서대로 줄어든다.
9. export 파일의 뷰어 헤더도 같은 브레드크럼을 쓴다: `프로젝트 › 캔버스 › 프레임 서랍`(워크트리 셀렉트 없음, 2026-11-19 사용자 결정). 프로젝트 조각은 글자일 뿐 누를 수 없다(파일에는 Overview가 없다). 프로젝트 이름은 앱 사이드바와 같은 규칙(Git main 워크트리 폴더 이름, 없으면 루트 폴더 이름)으로 export 때 정한다. 반응형 규칙도 캔버스 헤더와 같다: 프로젝트 → 프레임 → 캔버스 이름 순서로 줄고, 헤더 폭 720 미만이면 Zoom out·Zoom in을 숨기고, 600 미만이면 프로젝트가 빠진다. JavaScript가 없을 때도 프로젝트와 캔버스 이름은 보인다.
10. 문제 오버레이가 Overview를 덮으면 그 아래 헤더의 셀렉트도 덮인다(지금 규칙). 사이드바 "…" 메뉴의 Worktrees 구역은 그대로 남아 복구 경로가 된다.

## 비목표

- Home composer의 워크트리 트레이. 고르면 화면을 옮기지 않고 composer의 root만 바꾸는 다른 동작이라 이번에 바꾸지 않는다.
- 워크트리 만들기, 브랜치 전환, 등록되지 않은 워크트리 추가(PRODUCT §3 Out of scope 6, BACKLOG 'Undecided'의 sidebar worktree 항목).
- 같은 이름 프로젝트 구분(PRODUCT §5 item 1: "same-named groups are not disambiguated").
- 프로토타입 창 헤더. `CanvasHeader`를 쓰지 않고 브레드크럼이 필요 없다(한 프레임을 재생한다).

# buzz-shell — spec

작성·디자인 확정: 2026-10-27. 부모: [buzz-restyle](../buzz-restyle/spec.md).

사용자가 “좋아 AppShell 확정하자”로 현재 Shell·LNB 디자인을 승인했다. 이 문서는 대화 중 누적된 이전 배치안을 대체한다. **디자인 확정이며 AppShell 구현 완료나 구현 시작 승인은 아니다.**

## 사용자와 문제

앱 사용자가 프로젝트와 캔버스를 찾고 워크트리를 전환할 때 같은 셸 안에서 맥락을 유지해야 한다. 기존 프로젝트 홈과 캔버스·프레임 트리 중심 탐색을 프로젝트 → 캔버스 LNB로 바꾼다. 에이전트의 CLI·MCP 계약은 변경하지 않는다.

## 확정 범위

- 창과 LNB는 투명·블러 재질로 이어지고, 본문만 흰색 둥근 패널을 가진다. LNB에는 별도 흰색 Panel이나 셸 점 격자가 없다.
- 56px 헤더 왼쪽에 이전·다음 Arrow 버튼을 항상 표시한다. 갈 곳이 있을 때만 활성화하고 신호등과 수평 중심을 맞춘다.
- 헤더 중앙에 **Add Projects → Projects → Settings** 캡슐형 버튼 그룹을 둔다. Projects만 선택된 모습이며 탭 패널이 아니다. 기존 프로젝트 추가 흐름과 별도 Settings 창을 연결한다.
- LNB 위에는 검색 아이콘과 Search만 있는 36px 캡슐 버튼을 둔다. 기존 Quick Open 모달을 열며 KBD 표시는 없다. 검색 범위와 단축키는 유지한다.
- LNB는 프로젝트 → 해당 프로젝트에서 선택한 워크트리의 캔버스 목록이다. 프레임 목록은 제거한다. 프로젝트 그룹을 여러 개 펼칠 수 있고, **현재 조회 중인 프로젝트는 접을 수 없다.**
- 프로젝트 행에는 16px 썸네일, 프로젝트 이름, 읽기 전용 브랜치 뱃지, 우측 … 아이콘 버튼을 둔다. 쉐브론과 디렉터리 캡션은 없다. 캔버스와 텍스트 시작선을 맞춘다.
- … 버튼의 드롭다운에서 워크트리를 선택하고 Show in Finder·Project Settings·Remove from doan을 실행한다. 브랜치 뱃지는 클릭 대상이 아니다.
- 캔버스 행은 Palette 아이콘과 확장자를 뺀 이름을 표시한다. 실제 파일명은 바꾸지 않는다. 우측의 6px Accent Dot은 이번에는 **시각 표시만** 확정한다.
- 행 높이와 클릭 높이는 32px다. 프로젝트 그룹 사이 간격은 16px다. 선택·hover는 무채색 음영이며 전체 대문자 레이블을 쓰지 않는다. 긴 이름의 말줄임은 허용한다.
- Geist를 번들에 포함해 로컬에서 제공한다. 캔버스·헤더 버튼은 14px/20px·400, 프로젝트 이름은 같은 크기·500이다. 폰트 안티앨리어싱을 적용한다.
- 썸네일이 없거나 로딩에 실패하면 이름 해시로 고른 고정 8색과 이니셜을 표시한다. Malmoi의 해시와 팔레트를 참고한다.
- 공통 `.doan-chip`의 기본 글자 크기는 12px, 상하 패딩 2px, 좌우 패딩 6px다. 워크트리는 중립색 6% 배경의 translucent 변형을 사용한다.

현재 확인한 기본 시안은 LNB 260px, 창 1238×780이며 최소 창은 960×600이다. 240px LNB 비교판은 이력으로 남기고 기본 구현 기준은 260px로 둔다. 오른쪽 패널의 기존 280px 도킹 자리는 유지하되 내부 재설계와 최종 표시 정책은 해당 자식에 남긴다.

## 완료 조건

1. 승인된 `design/buzz-shell.html`의 Shell·LNB를 실제 앱에서 대조하고 기본/최소 창의 정렬·말줄임·스크롤·클릭 영역을 검증한다.
2. 조회 프로젝트는 펼침을 유지하고, 다른 프로젝트의 접기·펼치기와 워크트리 선택은 기존 선택·미작성 내용 보호를 통과한다.
3. 드롭다운이 LNB 스크롤에 잘리지 않는다. 공간 부족 시 위로 열고, 메뉴 자체가 길면 내부 스크롤한다. 키보드 이동·Esc·외부 클릭·포커스 복귀가 동작한다.
4. 검색·프로젝트 추가·설정·프로젝트 관리 진입점이 실제 기존 기능으로 이어진다. 이전·다음의 비활성 상태가 실제 기록과 일치한다.
5. 네이티브 창의 투명·블러·비활성 상태·전체 화면·신호등·드래그와 no-drag를 실제 창에서 검증한다. HTML 배경 모형을 네이티브 검증으로 대신하지 않는다.
6. Geist가 개발·프로덕션·패키지에서 외부 요청 없이 로드되고, 공통 칩 변경이 기존 사용처를 깨뜨리지 않는다. 공유 runtime gate가 최종 PASS다.

## 비목표와 후속 과업

- **홈:** 프로젝트 선택 전 본문, 대화 입력창과 홈 진입 경험은 `buzz-home`에서 정한다. 기존 Home 비교판은 승인 기준이 아니다.
- **인증:** Claude Code·Codex·Cursor OAuth 및 인증 토큰 관리는 별도 후속 설계다. PRODUCT §3의 현재 자격 증명 비관리 경계를 이 과업에서 변경하지 않는다.
- Dot의 에이전트 변경 판별·확인 상태 저장·열었을 때 해제는 이번에 구현하지 않는다. 정적 예시를 실제 상태인 것처럼 앱에 표시하지 않는다.
- 원격 프로젝트 이미지의 조회·인증·캐시 정책은 미정이다. git 자체가 썸네일을 제공한다고 가정하지 않는다.
- 캔버스 내부 UI, Overview 본문, 검색 모달 내용, 대화·Inspector·Comments 내용, 온보딩, Settings 내용은 재설계하지 않는다.
- 워크트리 선택은 이미 존재하는 경로로 이동하는 것이며 git checkout·branch 생성·삭제를 수행하지 않는다.

## 구현 전에 정리할 동작

시각 디자인은 확정됐다. 이전·다음 기록 단위/저장 수명/사라진 대상 처리, 프로젝트 간 선택·스크롤 복구, Projects 버튼의 구체적인 이동 목적지는 구현 설계에서 명시해야 한다. 홈 내용 결정을 앞당기거나 새 동작을 승인된 것처럼 숨겨 넣지 않는다. [tasks](./tasks.md)의 첫 단계에서 기존 동작과의 연결을 정리한다.

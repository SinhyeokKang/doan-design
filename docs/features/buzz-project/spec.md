# buzz-project — spec

`buzz-restyle`의 자식 7번이다. 프로젝트 Overview를 **프로젝트 대화 화면**으로 바꾼다([부모 spec 표 7번](../buzz-restyle/spec.md#자식-feature), [부모 '프로젝트 Overview 방향'](../buzz-restyle/spec.md)). 대화 스레드, `docked` 입력창, 대화 목록 데이터는 선행 자식 [`buzz-conversation`](../buzz-conversation/spec.md)이 만든다. 이 자식은 그것을 Overview에 배치하고, 화면 대조(`/design-sync`)와 빌드한 앱의 실제 확인을 처음으로 한다. 프로젝트→캔버스 LNB와 Overview 진입점은 buzz-shell 결과를 그대로 쓴다.

## 사용자

- **사람(앱 사용자)**
  - 프로젝트를 고르면(LNB 프로젝트 메뉴의 Overview, Home에서 보낸 직후) 그 프로젝트의 대화가 메인에 보인다. 질문하거나 아이데이션을 이어 갈 수 있다.
  - 메인 헤더의 대화 제목 드롭다운에서 프로젝트 대화를 고르거나 새로 시작한다.
  - 오른쪽 패널에서 대화가 있는 캔버스를 최근 대화순으로 보고, 진행 상태(실행 중·응답 대기·안 본 종료)를 확인한다. 캔버스마다 현재 대화 하나만 나온다. 캔버스 대화는 항상 캔버스로 연다.
  - 대화가 캔버스로 승격되면 Overview는 새 프로젝트 대화 상태로 돌아가고, 그 캔버스가 오른쪽 목록 맨 위로 온다.
- **에이전트**: 바뀌는 것이 없다. 프로젝트 대화로 받는 요청과 데이터 경계는 buzz-conversation이 정한다.

## 문제 (관찰된 사실)

1. **Overview가 캔버스 카드 목록이다.** 폴더별 카드(썸네일, 제목·파일, 프레임 수, 최근 변경, 열린 코멘트, "N resolved to review")와 오른쪽 Feedback 패널을 보인다(PRODUCT §5 항목 3).
   - 프로젝트에 대해 묻거나 아이데이션하는 대화를 둘 곳이 없다.
   - Home에서 보내면 Overview로 넘어오지만, 그 대화는 임시 상태줄로만 보인다(PRODUCT §5 항목 1).
2. **Home과 Overview의 추천이 어긋난다.** Home은 `.doan/canvases/`만 화면 초안으로 세어 추천한다. Overview는 `.doan/ds/` 섹션을 보이고, 캔버스가 없을 때 FirstPrompt를 보인다(부모 spec 표 7번).
3. **코멘트는 걷어낼 예정이다**(부모 결정, 2026-10-31 user). Overview의 Feedback 패널과 카드의 코멘트 수는 그 흐름과 맞지 않는다.

## 결정 (2026-10-31 user)

1. **배치**: 메인은 프로젝트 대화 스레드와 하단 `docked` 입력창, 오른쪽 패널은 캔버스 목록이다(사용자가 공유한 Aside 스크린샷 구조).
   - 입력창이 하단에 붙은 대화 화면이라 빈 대화라도 Home(가운데 `hero` 입력창, Doany, 인사말, 그라디언트)과 구분된다.
   - Overview에는 Doany, 인사말, 그라디언트를 쓰지 않는다.
2. **대화 고르기**: 메인 헤더의 대화 제목이 드롭다운이다. 프로젝트 대화(캔버스에 묶이지 않은 대화) 목록과 New를 담는다.
3. **오른쪽 패널**: Feedback 패널 대신 **대화가 있는 캔버스만** 최근 대화순으로 보인다.
   - 행은 썸네일, 첫 줄(공급자 로고, 캔버스 이름, 진행 상태, 오른쪽 끝의 마지막 활동 시각), 현재 대화의 마지막 내용 미리보기(두 줄까지)다.
   - 캔버스마다 현재 대화 하나만 대표한다. 행을 펼치지 않는다. 지난 대화는 캔버스에서 연다(`buzz-canvas-conversation`의 보관 대화 버튼).
   - 대화가 없는 캔버스는 LNB에서 찾는다.
   - 코멘트 수와 "N resolved to review"는 보이지 않는다.
4. **캔버스 대화는 항상 캔버스로**: 오른쪽 목록의 캔버스 행을 누르면 그 캔버스를 연다. 캔버스 페이지의 대화 패널은 `buzz-canvas-conversation`(C12)이 만든다. 그전까지는 캔버스 대화를 화면에서 읽거나 이어 갈 수 없고, 캔버스 페이지에는 지금의 임시 상태줄만 남는다.
5. **기본 대화**: Overview를 열면 다음 순서로 고른다.
   - 이 기기에서 그 root로 마지막에 본 프로젝트 대화.
   - 없으면 가장 최근에 활동한 프로젝트 대화.
   - 그것도 없으면 새 대화 상태.
   - Home에서 보낸 직후에는 방금 시작한 그 대화를 연다. 승격되어 떠난 대화는 다시 열지 않는다.
6. **승격 뒤**: 보고 있던 프로젝트 대화가 승격되면 메인은 새 프로젝트 대화 상태로 초기화된다(buzz-conversation 결정 12). 승격된 대화는 그 캔버스의 현재 대화가 되므로 오른쪽 목록의 그 캔버스 행이 대표한다.
7. **빈 대화의 추천**: Home 추천과 같은 기준(`.doan/canvases/`만 화면 초안으로 셈)으로 고른 추천을 입력창 위에 보인다. 칩은 입력창만 채우고 사람이 보낸다. FirstPrompt는 Overview에서 빠진다.
8. **Feedback 패널 제거**: Overview의 Feedback 패널과 그 읽기(`comments:project`)를 Overview에서 뺀다. 캔버스 페이지의 Comments 패널과 Review는 C12가 걷어낼 때까지 그대로다.
9. **상태줄**: Overview에서는 임시 상태줄을 보이지 않는다. 스레드가 같은 정보를 보이기 때문이다. 캔버스 페이지에서는 C12까지 그대로 둔다.

## 완료 조건

- **메인 스레드**: Overview 메인에 선택한 프로젝트 대화가 buzz-conversation의 `ConversationThread`와 `docked` 입력창(기존·새 대화 모드)으로 보인다. 확인: 정적 마크업 테스트와 `/runtime-test`.
- **드롭다운**: 대화 제목 드롭다운이 다음을 지킨다. 확인: 순수 함수 테스트와 정적 마크업 테스트.
  - 프로젝트 대화를 최근 활동순으로, 진행 상태와 함께 보인다.
  - New로 새 대화 상태가 된다.
  - 승격된 대화는 목록에 없다.
- **기본 대화**: 결정 5의 순서로 고르고, 마지막에 본 대화는 이 기기의 ui-state에 root별로 저장된다. 확인: 순수 함수 테스트, ui-state 읽기·쓰기 테스트.
- **오른쪽 목록**: 대화가 있는 캔버스만 최근 대화순으로 보인다.
  - 행은 썸네일, 이름, 가장 높은 진행 상태 하나(권한 요청 → 작업 중 → 안 본 종료)를 가진다.
  - 캔버스마다 현재 대화 하나만 대표하고 펼치지 않는다.
  - 행을 누르면 캔버스가 열린다.
  - 캔버스가 지워지거나 ID가 겹치면 그 행은 이유와 함께 열 수 없는 상태로 보인다.
  - 확인: 순수 함수 테스트와 정적 마크업 테스트.
- **승격 뒤 초기화**: 보고 있던 대화가 승격되면 메인이 새 대화 상태가 되고, 그 캔버스 행이 목록 맨 위에 생긴다. 확인: 순수 함수 테스트와 `/runtime-test`.
- **추천**: 새 대화 상태에서 Home과 같은 추천 규칙(`suggestedPrompts`)으로 추천을 보인다. `.doan/ds/`만 있는 프로젝트에서도 Home과 같은 추천이 나온다. 확인: 순수 함수 테스트.
- **제거**: Overview에서 카드 목록, FirstPrompt, Feedback 패널, 코멘트 수와 "resolved to review"가 사라진다. Overview 상태줄도 보이지 않는다. 쓰지 않게 된 코드와 테스트는 지운다. 확인: `npm --prefix app test`, `npm --prefix app run typecheck`.
- **유지**: 캔버스 이동·삭제 때 Overview로 돌아오는 경로, 중복 ID 알림(토스트와 Overview 알림), LNB 진입점, 썸네일 캡처는 그대로 동작한다. 중복 ID 알림은 메인 위쪽에 보인다. 확인: 기존 테스트 통과와 `/runtime-test`.
- **화면 대조**: 초안 `.doan/canvases/buzz-project.html`과 `buzz-conversation.html`의 docked·스레드 보드를 빌드한 앱에서 `/design-sync`로 맞춘다.
- **실제 앱 확인**: `/runtime-test`로 다음을 확인한다.
  - buzz-conversation에서 넘긴 docked 입력창의 실제 포커스와 한글 조합 유지.
  - 스레드를 띄운 빌드 앱의 CSP(창이 비지 않음, Markdown 렌더링).
- **문서 반영**: 아래 문서가 현재 규칙으로 고쳐졌다.
  - PRODUCT §5 항목 1(Home에서 보낸 뒤의 Overview, 상태줄)과 항목 3(Overview, Feedback 제거).
  - ARCHITECTURE §7.
  - DESIGN.md의 'Design navigation'·'Feedback panel' 절.

## 비목표

- 캔버스 페이지의 대화 패널, 캔버스 대화 읽기·이어 가기, 코멘트 화면 제거. `buzz-canvas-conversation`(C12)이 맡는다.
- 대화가 없는 캔버스를 Overview에 보이는 일. LNB가 맡는다.
- 프로젝트 대화 이름 바꾸기, 지우기, 보관하기.
- 터미널 세션을 목록에 넣는 일.
- 코멘트 CLI·MCP·스킬·포맷의 제거(별도 feature).

# prototype-frame-links — spec (상위 feature)

한 캔버스에서 프로토타입 마크가 있는 프레임끼리 이동하는 연결을 만든다. 프레임 A 안의 요소에 "B로 이동"을 달면, 프로토타입 창에서 재생하다 그 요소를 눌렀을 때 창이 B로 바뀐다. 이 문서는 하위 feature들이 같이 따르는 결정과 조사를 담는 허브다. 코드를 바꾸지 않고 `/ship`·`/orchestrate`로 돌리지 않는다(AGENTS.md 'Terms').

## 사용자

- **사람**: 프로토타입 창에서 여러 화면으로 이뤄진 흐름(예: 가입 → 확인 → 홈)을 실제 앱처럼 눌러 본다. 내보낸 파일을 받은 사람도 브라우저에서 같은 흐름을 눌러 본다.
- **에이전트**: 화면 사이의 이동을 캔버스에 적는다. 연결이 맞는지 `doan check`로 확인한다.

## 문제

- PRODUCT §5 item 2 'Prototype window'는 "frames do not link to each other"라고 정했다. 프로토타입 창은 프레임 하나만 재생하고, 다른 프레임은 프레임 메뉴로만 고른다.
- 캔버스 안의 다른 페이지 링크, `location` 변경, 새 창은 막힌다(PRODUCT §5 item 2 'Content', `app/src/main/prototypeFrame.ts:17-35`). 그래서 에이전트가 화면 사이의 이동을 스크립트로 흉내 낼 방법도 없다.
- 내보낸 프로토타입 파일도 프레임 하나만 담는다(`cli/internal/export/assemble.go:78-124`, `viewer/isolate.js`의 `FRAME` 하나).

## 공통 결정(2026-11-14 사용자)

1. **"frames do not link to each other"를 바꾼다.** 같은 캔버스의 마크된 프레임끼리 연결할 수 있다. 연결은 프로토타입 창과 내보낸 프로토타입 파일에서만 동작한다. main 창의 캔버스 페이지와 캔버스 export viewer에서는 아무 일도 하지 않는다.
2. **속성은 `data-doan-goto="<frame id>"`다.** 마크된 프레임 안의 아무 요소에나 단다. 값은 같은 캔버스에 있는 프레임 id다. 마크처럼 선택 속성이라 에이전트가 단 곳에서만 계약이 생긴다(PRODUCT §3 Out of scope 2).
3. **클릭으로 이동한다.** 그 요소나 그 안의 요소를 누르면 이동한다. 버튼에서 Enter·Space를 누르는 것처럼 클릭을 만드는 입력도 같다. 캔버스 자체 스크립트가 먼저 돌고, 그 스크립트가 `preventDefault()`를 부르면 이동하지 않는다. 그래서 에이전트가 스크립트로 이동을 막는 흐름(예: 폼 검사)을 만들 수 있다.
4. **이동은 대상 프레임을 새로 시작한다.** 상태를 초기화하고, 창 크기를 대상의 마크에 맞추고, Back과 Forward 기록에 남는다. 지금 프레임 메뉴로 다른 프레임을 고르는 것과 같다.
5. **재생할 수 없는 대상**(프레임 없음, id 공유, 마크 없음)으로는 이동하지 않고, 짧은 토스트로 이유를 알린다. `doan check`도 이런 연결을 보고한다.
6. **내보내기는 연결된 묶음 전체를 담는다.** 재생 중인 프레임과 연결선으로 이어진 마크된 프레임을 모두 한 파일에 담는다. 연결 방향은 따지지 않는다. 파일은 재생 중이던 프레임에서 시작한다. 캔버스에 서로 끊긴 묶음이 여럿 있으면 재생 중인 프레임의 묶음만 들어간다.
7. **내보낸 파일의 뒤로 가기는 브라우저 Back과 Forward다.** 프레임 이동을 파일 안 hash 기록으로 남긴다. 파일에 헤더는 더하지 않는다.
8. **프로토타입 창의 프레임 서랍은 연결된 프레임끼리 묶어 보인다.** 묶음은 결정 6과 같은 규칙(방향 무시)이다. 묶음의 모양, 순서, 연결 없는 프레임의 자리는 하위 2가 초안으로 정한다.
9. **에이전트 쪽**: 가이드(`doan skill`)가 속성을 설명하고, `/agent-eval` 새 시나리오가 연결 쓰기를 잰다. 가이드는 출력 예산이 8 B만 남았으므로 줄일 곳을 함께 정한다.

## 하위 feature

1. **`prototype-link-convention`**: 규약(ARCHITECTURE §1 convention 15), Go 파싱(요소를 감싼 프레임), `doan check` 규칙, 묶음 계산(Go·TS), Go·TS가 함께 읽는 fixture, TS 파서. design.md '하위 1의 범위'.
2. **`prototype-link-play`**: 프로토타입 창에서 클릭을 받아 이동하고, 토스트를 보이고, Back과 Forward에 남기고, 프레임 서랍을 묶음별로 보인다. 가이드 문구와 `/agent-eval`도 여기서 한다. 하위 1이 병합된 뒤 시작한다. design.md '하위 2의 범위'.
3. **`prototype-link-export`**: `doan export --prototype`과 창의 Export가 묶음을 내보내고, 내보낸 파일이 프레임을 전환한다. 하위 2가 병합된 뒤 시작한다. design.md '하위 3의 범위'.

세 하위는 한 `/chain`으로 이어 사이에 릴리스가 끼지 않게 한다. 하위 1만 병합된 develop에서는 에이전트가 속성을 몰라 쓸 일이 없고(가이드는 하위 2가 바꾼다), 하위 2까지 병합된 develop에서는 내보낸 파일의 연결이 아무 일도 하지 않는다. 그래서 하위 3까지 병합한 뒤에 릴리스한다.

## 완료 조건

- 세 하위 feature가 develop에 병합되었다.
- PRODUCT §5 item 2에 "frames do not link to each other" 문장이 없고, 결정 1–8이 현재 규칙으로 적혀 있다.
- ARCHITECTURE §1에 `data-doan-goto` 규약이 있고, §1 `doan check` 표에 새 규칙이 있다.
- 가이드가 속성을 설명하고, `docs/USABILITY-EVAL.md`에 새 시나리오 결과가 있다.
- `docs/features/prototype-frame-links/`가 삭제되었다.

## 하지 않는 것

- 다른 캔버스로 가는 연결.
- 클릭 말고 다른 트리거(호버, 시간, 스크롤 위치).
- 전환 애니메이션(밀기, 겹치기)과 오버레이(모달처럼 위에 띄우는 프레임). 모달은 지금처럼 프레임 안에 둔다.
- main 창 캔버스 페이지에서의 연결 표시나 이동, 연결선 그리기.
- 프레임 사이에 상태(입력값 등)를 넘기는 것.

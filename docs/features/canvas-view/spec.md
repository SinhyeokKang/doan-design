# canvas-view — spec

PRODUCT §5 기능 분할 #5. 범위: sandbox iframe · 보드 크기 · 줌 인/아웃과 팬 · 프레임 목록과 점프 (+ MVP 2번 항목의 라이브 리로드).

## 사용자

- **사람**: 앱에서 캔버스를 연다. 줌 인/아웃과 팬으로 캔버스 전체를 훑고, 프레임 목록에서 프레임을 골라 그 위치로 이동한다. 에이전트가 캔버스를 고치면 다시 열지 않아도 화면이 바뀐다.
- **에이전트**: 이 기능으로 새로 얻는 것은 없다. `doan:width` 선언, `data-doan-frame` 표시 같은 기존 규약(ARCHITECTURE §1)이 앱 화면에 그대로 드러날 뿐이다.

## 문제 (현재 관찰된 사실)

- #4 `app-shell`의 앱은 폴더별 캔버스 목록(경로 · 제목 · 열린 코멘트 수)만 보여 준다. 캔버스를 여는 화면이 없고, 서빙 URL은 목록 항목의 `data-url` 속성에만 들어 있다.
- 그래서 사람은 앱에서 캔버스를 볼 수 없다. 줌·팬·프레임 이동·라이브 리로드도 없다.
- 캔버스 렌더링 구조(sandbox iframe + 주입 스크립트 + `postMessage`, ARCHITECTURE §3)는 결정만 됐고 PoC 1이 아직 돌지 않았다. 줌 중 핀 위치(PoC 3)도 미검증이다.
- ARCHITECTURE §3은 #5가 iframe에 캔버스를 올릴 때 deny-all 세션 권한 핸들러와 IPC `event.senderFrame` 확인을 함께 넣으라고 적어 두었다.

## 완료 조건

1. PoC 1과 PoC 3이 통과했고, 결과가 날짜와 함께 PRODUCT §6에 기록되어 있다. 실패하면 이후 작업을 멈추고 렌더링 구조를 다시 결정한다.
2. 목록에서 캔버스를 고르면 캔버스 뷰에 `sandbox="allow-scripts"` iframe으로 그 캔버스가 뜬다. `allow-same-origin`은 없다.
3. iframe 폭은 `doan ls`의 `width`이고, 높이는 주입 스크립트가 잰 콘텐츠 높이다. 창 크기를 바꾸면 배율과 위치만 바뀌고 캔버스 레이아웃은 그대로다.
4. `doan ls`에 `width`가 없는 캔버스(선언 누락 또는 잘못된 값)는 iframe 대신 `<meta name="doan:width">` 선언을 요청하는 안내와 `doan check`를 보라는 문구를 보여 준다.
5. 줌 인/아웃: 트랙패드 핀치(`ctrlKey` 휠)는 커서 위치를 기준으로 확대·축소한다. 툴바 버튼과 단축키(Cmd+= · Cmd+- · Cmd+0 맞춤)도 같은 동작을 한다. 배율은 정해진 범위 안으로 제한된다.
6. 팬: 두 손가락 스크롤(일반 휠)로 보드가 움직인다. 커서가 iframe 위에 있어도 동작한다.
7. 캔버스를 처음 열면 보드 폭이 뷰포트 폭에 맞춰진다(맞춤).
8. 프레임 목록: 열린 캔버스의 프레임을 `data-doan-title`(없으면 id)로 나열한다. 하나를 누르면 그 프레임이 뷰포트 안에 들어오도록 배율과 위치가 바뀐다.
9. 라이브 리로드: 열린 캔버스가 있는 폴더의 서빙 범위 안 파일(`design/` 아래, `tokenCss`, `serve` 경로)이 바뀌면, 감시 디바운스(200ms) 뒤 iframe이 다시 로드된다. 배율과 위치는 유지된다. 코멘트 파일(`.doan/`)만 바뀌면 리로드하지 않는다.
10. 보안: 세션 권한 요청과 확인은 모두 거부된다. IPC 핸들러는 앱 창의 메인 프레임에서 온 호출만 받는다. 캔버스 iframe은 로컬 서버 토큰 경로 밖으로 이동하지 못한다. 렌더러 CSP는 iframe에 `http://127.0.0.1` 출처만 허용한다.
11. `/runtime-test`(`npm --prefix app run e2e`)에 캔버스 뷰 단계가 추가되어 PASS한다.

- 요소·프레임 클릭 선택, 하이라이트, 인스펙터, `doan active` — #6 `select-inspect`. PoC 1 실험에서는 선택과 하이라이트까지 확인하지만 제품 코드에는 넣지 않는다.
- 핀과 코멘트 UI — #7 `comments-ui`. PoC 3은 실험으로만 확인한다.
- 폭 · 테마 · 상태 전환 (PRODUCT §5 'Deferred').
- 줌·팬 상태를 재시작 후에도 유지하는 것. 메모리에만 둔다.
- 리로드 때 깜빡임 없애기(숨긴 iframe을 미리 로드하고 바꿔 끼우기).
- UI 프레임워크 도입과 디자인 초안 — #6에서 결정한다(PRODUCT §5 Dogfooding). 이 기능은 plain DOM 최소 UI다.
- `/design-sync` 스킬 — 이 기능이 끝난 **뒤** 만든다(PRODUCT §5 Dogfooding). 이 기능의 범위가 아니다.
- 렌더 검사(겹침 · 넘침 · 콘솔 오류) — PRODUCT §5 'Deferred'.

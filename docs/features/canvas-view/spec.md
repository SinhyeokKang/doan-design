# canvas-view — spec

PRODUCT §5 기능 분할 #5. 범위: sandbox iframe · 보드 크기 · 줌 인/아웃과 팬 · 프레임 목록과 점프 (+ MVP 2번 항목의 라이브 리로드. PRODUCT §5 #5 행에는 없어 승격 때 더한다).

## 사용자

- **사람**: 앱에서 캔버스를 연다. 줌 인/아웃과 팬으로 캔버스 전체를 훑고, 프레임 목록에서 프레임을 골라 그 위치로 이동한다. 에이전트가 캔버스를 고치면 다시 열지 않아도 화면이 바뀐다.
- **에이전트**: 이 기능으로 새로 얻는 것은 없다. `doan:width` 선언, `data-doan-frame` 표시 같은 기존 규약(ARCHITECTURE §1)이 앱 화면에 그대로 드러날 뿐이다.
- **사람과 에이전트가 보는 프레임 목록이 다를 수 있다.** 앱은 렌더된 DOM의 프레임을 보여 주고, `doan ls` · `doan check`는 정적 HTML의 프레임을 본다. 스크립트로 그린 프레임은 앱에만 보인다. #6 `doan active`와 #7 프레임 코멘트가 어느 목록을 기준으로 삼을지는 #6에서 정한다(PRODUCT §8 열린 질문으로 남긴다).

## 문제 (현재 관찰된 사실)

- #4 `app-shell`의 앱은 폴더별 캔버스 목록(경로 · 제목 · 열린 코멘트 수)만 보여 준다. 캔버스를 여는 화면이 없고, 서빙 URL은 목록 항목의 `data-url` 속성에만 들어 있다.
- 그래서 사람은 앱에서 캔버스를 볼 수 없다. 줌·팬·프레임 이동·라이브 리로드도 없다.
- 캔버스 렌더링 구조(sandbox iframe + 주입 스크립트 + `postMessage`, ARCHITECTURE §3)는 결정만 됐고 PoC 1이 아직 돌지 않았다. 줌 중 핀 위치(PoC 3)도 미검증이다.
- ARCHITECTURE §3은 #5가 iframe에 캔버스를 올릴 때 deny-all 세션 권한 핸들러와 IPC `event.senderFrame` 확인을 함께 넣으라고 적어 두었다.
- 앱은 메뉴를 정의하지 않아 Electron 기본 메뉴가 쓰인다. 기본 보기 메뉴의 Cmd+= · Cmd+- · Cmd+0은 앱 전체 페이지 줌을, Cmd+R은 앱 리로드를 잡는다.

## 완료 조건

1. PoC 1과 PoC 3의 항목별 결과(통과·실패)가 날짜와 함께 PRODUCT §6에 기록되어 있다. 하나라도 실패하면 이후 작업을 멈추고 사용자에게 재결정을 요청한다. `executeJavaScript` 주입이 안 되고 서버 응답 삽입으로만 되는 경우도 실패로 본다(서버 동작을 바꾸는 결정 변경이기 때문).
2. 목록에서 캔버스를 고르면 캔버스 뷰에 `sandbox="allow-scripts"` iframe으로 그 캔버스가 뜬다. `allow-same-origin`은 없다.
3. iframe 폭은 `doan ls`의 `width`이고, 높이는 PoC 1에서 정한 측정 규칙에 따른 콘텐츠 높이다. 창 크기를 바꾸면 배율은 그대로이고, 뷰포트 왼쪽 위가 가리키는 보드 지점도 그대로다. 캔버스 레이아웃은 바뀌지 않는다.
4. `doan ls`에 `width`가 없는 캔버스(선언 누락 또는 잘못된 값)는 iframe 대신 이 안내를 보여 준다: "보드 폭 선언이 없거나 값이 잘못되었습니다. 에이전트에게 `<head>`에 `<meta name="doan:width" content="1440">`을 넣어 달라고 하세요. 터미널에서 `doan check`로 확인할 수 있습니다."
5. 줌:
   - 트랙패드 핀치(`ctrlKey` 휠)와 Cmd+휠은 커서 위치를 기준으로 확대·축소한다. 이벤트 한 번에 배율은 최대 1.25배까지만 바뀐다.
   - 앱 메뉴 '보기'에 확대(Cmd+=) · 축소(Cmd+-) · 실제 크기(Cmd+0, 100%) · 맞춤(Shift+1) · 캔버스 다시 읽기(Cmd+R)가 있다. 툴바 버튼(축소 · 확대 · 맞춤)도 같은 동작을 한다. 버튼과 메뉴의 줌은 뷰포트 가운데를 기준으로 한 단계에 1.25배씩 바뀐다.
   - 포커스가 iframe 안에 있어도 메뉴 단축키가 동작한다. 앱 전체 페이지 줌은 일어나지 않는다(`webContents.getZoomFactor()`가 1로 유지된다).
   - 배율은 0.05–4 범위로 제한된다. 툴바에 현재 배율을 정수 %로 보여 준다(읽기 전용).
6. 팬: 일반 휠(두 손가락 스크롤, 마우스 휠)로 보드가 움직인다. 커서가 iframe 위에 있어도, iframe 밖 여백 위에 있어도 같은 거리를 움직인다. 다만 커서 아래에 그 방향으로 더 스크롤할 수 있는 캔버스 안 요소(`overflow: auto` 목록 등)가 있으면 그 요소가 스크롤된다.
7. 캔버스를 처음 열면 보드 폭이 뷰포트 폭에 맞춰진다(맞춤). 맞춤 배율은 1(100%)을 넘지 않는다.
8. 프레임 목록:
   - 열린 캔버스의 렌더된 DOM에 있는 프레임을 문서 순서대로 나열한다. 라벨은 `data-doan-title`이고, 없으면 id(monospace), id가 비었으면 "(id 없음)"이다.
   - 프레임이 없으면 "이 캔버스에는 `data-doan-frame`이 없습니다"를 보여 준다.
   - 항목을 누르면 즉시(애니메이션 없이) 그 프레임으로 이동한다. 배율은 min(1, 프레임 폭 맞춤)이다. 프레임이 뷰포트보다 높으면 프레임 위쪽을 뷰포트 위쪽에 맞추고, 낮으면 가운데에 둔다. 중복 id가 있어도 누른 항목으로 이동한다. 마지막에 누른 항목이 표시된다.
   - 프레임이 1,000개를 넘거나 문자열이 200자를 넘으면 잘라서 보여 주고 "일부만 표시"를 띄운다.
9. 라이브 리로드:
   - 열린 캔버스가 있는 폴더의 서빙 범위 안 파일(`design/` 아래, `tokenCss`, `serve` 경로)이 바뀌면, 감시 디바운스와 다시 읽기가 끝난 뒤 iframe이 다시 로드된다. 배율과 위치는 유지되고, 새 높이를 잴 때까지 이전 높이를 유지한다.
   - `.doan/` 아래 파일만 바뀌면 리로드하지 않는다(`serve`가 `.doan`을 가리켜도 같다). 다른 폴더의 변경도 리로드하지 않는다.
   - 툴바에 마지막 리로드 시각을 보여 준다(예: "갱신 14:03:21").
   - config에 적혔지만 아직 없는 `serve` 경로가 나중에 생기면, 다음에 다시 읽을 때부터 감시하고 반영한다. 생기는 순간을 감지하지는 않는다.
10. 화면 상태:
    - 캔버스를 고르지 않았으면 "왼쪽 목록에서 캔버스를 고르세요"를 보여 준다.
    - 첫 로드 중에는 보드를 숨기고 "불러오는 중…"을 보여 준다. 5초 안에 높이 측정 결과가 오지 않으면 "캔버스를 불러오지 못했습니다"와 다시 읽기 버튼을 보여 준다.
    - 열린 캔버스가 다시 읽은 목록에서 빠지거나 폴더가 닫히거나 "폴더를 찾을 수 없음"이 되면 뷰를 비우고 "열려 있던 캔버스(`design/x.html`)가 목록에서 사라졌습니다. 파일이 지워졌거나 옮겨졌습니다."를 보여 준다.
    - 폴더가 잠깐 오류(`error` · `cliError`)가 되면 마지막 화면을 그대로 두고 그 위에 오류 줄을 띄운다. 오류인 동안에는 리로드하지 않는다.
    - 캔버스 안 링크로 같은 폴더의 다른 캔버스로 이동하면 사이드바의 열린 캔버스 표시도 그 캔버스로 바뀐다. 목록에 없는 문서로 이동하면 "목록에 없는 문서입니다"를 보여 준다.
11. 보안:
    - 세션 권한 요청 · 확인 · 장치 권한은 모두 거부된다. 앱 창의 메인 프레임에서 권한을 요청해도 `denied`가 된다.
    - IPC 핸들러는 앱 창의 메인 프레임에서 온 호출만 받는다.
    - 캔버스 iframe은 처음 연 폴더의 서빙 경로(`/t/<token>/<folder key>/`) 밖으로 이동하지 못한다.
    - 빌드된 렌더러 CSP에 `frame-src http://127.0.0.1:*`가 있고, 그 밖의 iframe 출처는 허용하지 않는다.
12. `/runtime-test`(`npm --prefix app run e2e`)에 캔버스 뷰 단계가 추가되어 PASS한다.

## 비목표

- 요소·프레임 클릭 선택, 하이라이트, 인스펙터, `doan active` — #6 `select-inspect`. PoC 1 실험에서는 선택과 하이라이트까지 확인하지만 제품 코드에는 넣지 않는다.
- 핀과 코멘트 UI — #7 `comments-ui`. 보드 위 overlay 층만 비워 두고, PoC 3은 실험으로만 확인한다.
- 드래그 팬(Space+드래그 등). 이번에는 휠로만 팬한다.
- 배율 % 직접 입력 — #6 디자인 초안에서 정한다.
- 폭 · 테마 · 상태 전환 (PRODUCT §5 'Deferred').
- 줌·팬 상태를 재시작 후에도 유지하는 것. 메모리에만 둔다.
- 리로드 때 깜빡임 없애기(숨긴 iframe을 미리 로드하고 바꿔 끼우기).
- config에 새로 적힌 `serve` 경로가 생기는 순간을 감지하는 것(완료 조건 9).
- UI 프레임워크 도입과 디자인 초안 — #6에서 결정한다(PRODUCT §5 Dogfooding). 이 기능은 plain DOM 최소 UI다.
- `/design-sync` 스킬 — 이 기능이 끝난 **뒤** 만든다(PRODUCT §5 Dogfooding). 이 기능의 범위가 아니다.
- 렌더 검사(겹침 · 넘침 · 콘솔 오류) — PRODUCT §5 'Deferred'.

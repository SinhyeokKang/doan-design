# 단일 프레임 프로토타입

## 순서와 사용자

다섯 기능 중 4번이다. 앞은 `canvas-rendering-stability`이다. 5번 `canvas-activity-notices`는 이 기능을 기다리지 않고 먼저 구현될 수 있다. `frame-first-selection`의 프레임 선택을 사용한다. 에이전트는 단독 실행을 지원하는 프레임을 명시적으로 표시하고, 사람은 별도 창에서 해당 프레임의 모션·입력·버튼 등 동작을 확인한다.

## 문제

현재 캔버스는 전체 보드를 표시한다. Select의 Option-click은 캔버스를 조작하지만, 프레임 하나를 독립 viewport로 실행하는 창은 없다(PRODUCT §5 items 2, 4).

## 확정 동작과 완료 조건

1. 에이전트가 지원 표시를 붙인 프레임만 실행할 수 있다. 표시의 구조 오류를 검사하되 임의 스크립트의 정상 실행까지 보장한다고 말하지 않는다.
2. Select에서 지원 프레임 자체를 선택하면 Export 왼쪽의 재생 버튼이 활성화된다. 요소 선택은 소속 프레임이 지원되더라도 활성화하지 않는다.
3. 헤더 프레임 서랍에는 지원 여부를 메타로만 표시한다. 행 클릭은 기존처럼 프레임으로 이동하면서 선택한다. 지원 프레임이면 도구 바 재생 버튼이 활성화되지만, 서랍 자체에서 실행하지 않는다.
4. 선택 크기 버블에는 지원 프레임을 선택한 때 작은 재생 버튼을 둔다. 캔버스 안에 별도 상시 표시나 hover 재생 표시는 추가하지 않는다.
5. 재생은 별도 OS 창 하나를 연다. 최초 생성과 다른 프레임으로 교체할 때마다 해당 프레임 크기를 기준으로 화면 작업 영역 안에 맞춘다. 사람이 창 크기를 바꾸면 반응형으로 다시 배치한다. 다른 프레임을 열 때도 창은 재사용한다. 같은 대상 재생은 창만 앞으로 가져오고 입력 상태와 창 크기는 유지한다.
6. 프레임 내부의 입력·버튼·모달·스크롤·애니메이션이 동작한다. 문서 이동·새 창·다운로드·HTML form submit은 차단한다. JavaScript fetch 등 리소스·API 요청은 기존 캔버스 정책을 유지하며 모든 데이터 전송 차단을 약속하지 않는다. 프레임 간 연결은 후속 범위다.
7. 원본 변경은 자동 반영하며 입력값·열린 메뉴 등 실행 상태를 초기화한다. 캔버스 선택이나 대화 초안은 바꾸지 않는다.
8. 대상 프레임 삭제·지원 표시 소실 시 기존 화면을 숨기고 이유와 닫기를 보여준다. 동일 대상이 복구되면 다시 표시한다. 로딩·실패 화면을 성공한 프로토타입으로 취급하지 않는다.
9. 프로토타입만 보는 것은 캔버스 읽음으로 처리하지 않는다(`canvas-activity-notices`). 그 기능이 먼저 병합됐다면 그때는 프로토타입 창이 없어 이 제외를 검증하지 못했으므로, 이 기능이 새로 만드는 문서 응답이 메인 캔버스의 실제 표시 근거로 쓰이지 않게 하고 직접 검증한다.
10. 메인 화면의 다른 캔버스·프로젝트·Home 이동이나 메인 창 숨김은 실행 대상을 바꾸거나 창을 닫지 않는다. 새로운 재생 요청만 대상을 교체하며 앱 Quit 때 함께 종료한다.
11. Tab은 프레임 컨트롤을 순회하고 V/H·Space·Esc는 콘텐츠에 전달한다. Select·Hand의 키 처리나 클릭 차단을 적용하지 않는다. Esc로 창을 닫지 않으며 ⌘W·네이티브 닫기는 프로토타입 창만 닫는다.

## 상태·포커스

| 상태 | 표시·동작 |
|---|---|
| 로딩 | 프레임 이름과 진행 상태. 창 제목은 프레임 이름과 `Prototype`으로 구별 |
| 읽기·초기화 실패 | 이유·Retry·Close. 임의 스크립트 내부 동작의 성공 여부까지 판정하지 않음 |
| 대상 소실·지원 표시 제거 | 이전 실행 화면을 숨기고 이유·Close. 같은 대상 복구 시 자동 재표시 |
| 원본 갱신·대상 복구 | 상태는 초기화하되 창을 활성화하지 않음. 사람의 재생 동작만 전면 활성화 |
| 창 닫기 | 현재 화면에 살아 있는 실행 버튼으로 포커스 복귀. 버블이 없으면 도구 바 재생 버튼을 사용하며, 숨긴 메인 창을 다시 열거나 화면을 바꾸지는 않음 |
| 실행 불가 | 도구 바에서 키보드로 접근 가능한 비활성 이유 제공. Hand·Picker·Capture 중에는 실행하지 않음 |

## 비목표

사람이 캔버스 내용을 편집하는 기능, 프레임 간 전환 연결, 프로토타입 파일 Export·호스팅, 다중 실행 창, 에이전트 자동 실행은 만들지 않는다.

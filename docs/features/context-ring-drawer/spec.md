# 컨텍스트 링 서랍 — spec

## 사용자

- **사람**: 대화 중인 사람. docked composer의 컨텍스트 링을 눌러, 지금 대화의 컨텍스트 사용량과 그 대화 프로바이더의 사용량 창(5h, Weekly 등)을 한곳에서 본다. 대상은 오버뷰, 캔버스 대화 패널, 프로토타입 창 대화 패널이다.
- **에이전트**: 바뀌는 것이 없다.

## 문제 (관찰)

- docked composer tray 끝의 컨텍스트 링은 컨트롤이 아니다. 누를 수 없고 Tab 순서에도 없으며, hover 툴팁으로 컨텍스트 사용량 두 줄만 보여준다(PRODUCT §5 'Context window ring').
- 대화 중인 프로바이더의 사용량 창(5h, Weekly 등)을 보려면 헤더 오른쪽의 Agent usage를 열어야 한다. 그 popover는 연결된 모든 프로바이더를 보여주므로, 지금 대화와 관계없는 프로바이더까지 섞여 있다.

## 완료 조건

1. **링은 버튼이다**
   - 링은 지금처럼 컨텍스트 사용량을 보여준다. 값, 색 규칙, 갱신 시점은 그대로다.
   - 클릭, Space, Return으로 서랍이 열린다. Tab 순서에서는 tray의 마지막 컨트롤이다.
   - 접근 이름과 설명은 지금과 같다("Context window 42% used · last turn", 토큰 줄). `aria-haspopup="dialog"`와 `aria-expanded`를 단다.
   - 전송 중에도 활성이다(tray의 다른 트리거와 다르다). 턴이 도는 동안 사용량을 볼 일이 가장 많기 때문이다.
   - hover 툴팁(두 줄)은 남는다. 서랍이 열려 있는 동안, 그리고 서랍을 닫아 포커스가 링으로 돌아온 직후에는 툴팁을 띄우지 않는다.
2. **레이아웃이 바뀌지 않는다**
   - 링의 보이는 크기(16px), tray 안 위치, tray의 다른 요소 위치와 크기, tray 높이가 기준 develop과 같다(tasks의 측정으로 차이 0px).
   - 누를 수 있는 영역만 링보다 넓다. 그 영역은 보이지 않고 이웃 컨트롤의 영역과 겹치지 않는다.
   - hover와 pressed 표시는 tray의 다른 트리거와 같은 채움으로 하되, 넓힌 영역에 그리고 레이아웃을 바꾸지 않는다. 링에 화살표 같은 표시는 더하지 않는다.
3. **링이 없으면 버튼도 없다**: 기록된 값이 없을 때(새 대화, 첫 턴 전, 링 이전의 턴, Cursor, 창 크기를 모르는 Antigravity 모델, status line으로 바뀐 composer)는 지금처럼 링도 버튼도 없다. 그래서 Cursor의 사용량 행은 이 서랍에 나오지 않는다.
4. **서랍 내용**
   - 서랍은 dialog다. 별도 제목 행은 없고, 첫 섹션 머리말 "Context window"가 서랍의 이름이 된다.
   - Context 섹션: "42% used · last turn"과 "84K of 200K tokens"(링 툴팁과 같은 값과 문구 규칙). 서랍이 열린 동안 턴이 끝나 값이 바뀌면 그 자리에서 바뀐다.
   - 사용량 섹션: 대화 프로바이더의 행. 헤더 Agent usage popover의 그 프로바이더 행과 같은 내용과 문구다("Updated …", 창마다 한 줄, "Limit reached …", "Reading usage…", "Couldn’t read usage…" 등). 행 머리 오른쪽에 Refresh usage가 있다.
   - Refresh usage는 헤더의 Refresh usage와 같다. 사용 가능한 모든 연결을 읽고, 이미 도는 읽기에 합류한다. 어느 읽기든 도는 동안 busy로 보인다(헤더와 같다).
   - 사용량 섹션이 없는 경우는 Context만 보여주고 Refresh도 없다. 대상은 다음과 같다.
     - Antigravity(헤더에도 나오지 않는다)
     - 레거시 외부 대화와 터미널 세션을 이어 쓰는 composer. 사용자의 CLI 프로필로 돌므로, Doan 연결 계정의 사용량은 그 대화의 사용량이 아니다.
     - 그 프로바이더에 Doan 연결이 없을 때(대화 뒤 로그아웃, 계정 제거)
5. **읽기 규칙**
   - 서랍을 여는 것은 헤더 popover를 여는 것과 같은 읽기 시점이다. 같은 5분 규칙, 실패나 reset 뒤 즉시 읽기 규칙을 따른다. 값은 헤더와 같은 메모리 값을 쓰므로 두 곳의 숫자가 어긋나지 않는다.
   - "창이 숨으면 읽지 않는다" 규칙은 메인 창이나 프로토타입 창 중 하나라도 보이면 읽는 것으로 넓힌다(사용자 결정). 메인 창을 닫고 프로토타입 창만 쓸 때도 서랍과 Refresh가 읽는다.
6. **열고 닫기**
   - 서랍은 non-modal이고 헤더 Agent usage popover와 같은 규칙으로 링에 붙어 열린다(끝 정렬, 4px 간격). 링이 창 아래쪽에 있어 위로 열리고 composer 카드를 가린다. 열면 포커스가 서랍 내용으로 간다. Tab은 내용 다음 Refresh다.
   - Escape나 바깥 누르기로 닫힌다. 닫히면 포커스는 링으로 돌아간다. 단, 바깥 누르기가 다른 컨트롤에 포커스를 줬으면 그쪽에 둔다.
   - 대화가 바뀌거나 링이 사라지면(대화 삭제, status line 전환) 서랍이 닫힌다. 포커스가 서랍 안에 있었으면 composer 입력으로 가고, 아니면 움직이지 않는다.
   - 열린 동안 로그아웃, 계정 교체, 마지막 연결 사라짐이 일어나면 사용량 행만 사라지고 서랍은 남는다. 포커스가 Refresh에 있었으면 서랍 컨테이너로 옮긴다. 헤더 popover의 "마지막 연결이 사라지면 닫는다" 규칙은 서랍에 적용하지 않는다.
   - 한 창에서는 헤더 popover와 서랍 중 하나만 열린다(한쪽이 열리면 다른 쪽은 바깥 누르기로 닫힌다). 메인 창과 프로토타입 창에 하나씩 열리는 것은 허용한다.
   - 프로토타입 창에서는 재생 중인 프레임을 눌러도 서랍이 닫히지 않는다. 그 창의 기존 피커와 같은 한계다.
7. **프로토타입 창**: 프로토타입 창의 대화 패널에서도 같은 서랍이 열리고 같은 사용량을 보여준다(사용자 결정).
8. **헤더 Agent usage**: 지금과 완전히 같다.

## 범위 밖

- 링이 없는 상태에서 서랍을 여는 방법(사용자 결정: 지금처럼 없음).
- 사용량 행에서 Agent settings로 가는 링크. 헤더 popover에만 둔다.
- Refresh를 그 프로바이더만 읽게 하는 것. 지금 읽기 IPC에는 전체 읽기만 있다. 다른 프로바이더를 읽는 동안에도 busy가 도는 것은 받아들인다.
- 서랍에서 대화 압축(compaction)이나 모델 바꾸기 같은 조작.
- 프로토타입 재생 프레임을 누를 때 서랍 닫기.
- Home composer(링이 없다).

# agent-reply-chips — spec

출처: 실사용 요청 "에이전트 출력 쓰레드. 에이전트가 Frame 또는 Element를 앵커로, 칩 UI로 출력할 수 있는지?". `docs/BACKLOG.md` 'Undecided'의 후보를 이 feature가 맡는다. 결정은 대화에서 사용자가 했다.

## 사용자

- **사람**: 에이전트 답에 나온 프레임·요소 이름이 자기 메시지의 칩과 같은 칩으로 보이고, 누르면 그 캔버스의 그 위치로 간다. "어디를 바꿨다"는 답을 글로 읽고 직접 찾지 않아도 된다.
- **에이전트**: 답에서 프레임이나 요소를 가리킬 때 쓸 링크 형식을 가이드(`doan skill`)에서 배운다. 쓰지 않아도 답은 지금처럼 보인다.

## 문제

- 사람이 보내는 메시지는 앵커 칩(프레임·요소·점)을 담고, 캔버스 패널에서는 누르면 그 대상으로 이동해 강조한다(PRODUCT §5 item 6 'Chip locate').
- 에이전트 답은 Markdown 텍스트로만 그려진다. `https:` 링크만 앵커가 되고 다른 링크는 글자로 남는다(ARCHITECTURE §7 'Agent replies render as Markdown…'). 그래서 에이전트가 "Editor 프레임의 Save 버튼을 바꿨다"고 써도 사람이 그 위치를 직접 찾아야 한다.
- 대화 이벤트에는 에이전트 답의 앵커를 담는 자리가 없다. 다만 답이 Markdown 텍스트라서, 텍스트 안의 정해진 링크 표기로 앵커를 나타낼 수 있다.

## 결정 (대화에서 확정)

1. 링크는 캔버스까지 가리킨다: `doan:<canvas-id>/frame/<frame-id>`, `doan:<canvas-id>/element/<doan-id>`. 캔버스가 열려 있지 않은 Overview의 프로젝트 대화에서도 칩이 어느 캔버스인지 안다. 요소 id는 캔버스 안에서 유일하므로(ARCHITECTURE §1 Conventions 8) 요소 링크에 프레임을 넣지 않는다.
2. 칩을 누르면: 같은 캔버스가 열려 있으면 사람 칩처럼 그 대상으로 이동해 강조한다. 다른 캔버스이거나 Overview이면 그 캔버스를 열고 대상으로 이동한다(Quick Open의 프레임 이동과 같은 방식). 어느 경우든 선택은 바꾸지 않는다(PRODUCT §5 item 6 "Picking and locating change neither the selection…").
3. 형식이 맞는 링크는 대상이 있는지 확인하지 않고 칩으로 그린다. 누른 뒤 대상을 찾지 못하면 사람 칩과 같은 "No longer in the canvas" 안내를 띄운다. 형식이 틀린 `doan:` 링크는 링크 글자만 평문으로 남긴다.

## 완료 조건

- 가이드에 링크 형식과 "프레임·요소를 가리킬 때 쓰라"는 안내가 있다.
- 에이전트 답의 `[Save](doan:drafts/element/save)`와 `[Editor](doan:drafts/frame/editor)`가 사람 메시지와 같은 모양의 요소 칩·프레임 칩으로 보인다. 칩 이름은 사람 칩과 같은 규칙(`chipLabel`)으로 id와 현재 프레임 제목에서 만든다.
- 캔버스 패널에서 같은 캔버스를 가리키는 칩을 누르면 대상으로 이동·강조하고, 선택과 `doan active`는 바뀌지 않는다.
- Overview나 다른 캔버스에서 칩을 누르면 그 캔버스가 열리고 대상으로 이동한다. 프로젝트에 그 캔버스 id가 없으면 이동하지 않고 안내를 띄운다.
- 대상을 찾지 못하면 "No longer in the canvas" 안내가 사람 칩과 같은 자리·시간 규칙으로 뜬다.
- 형식이 틀린 링크(`doan:x`, 빈 id, 규칙에 안 맞는 캔버스 id, 알 수 없는 종류)는 링크 글자만 평문으로 보인다. `https:` 링크는 지금처럼 동작한다.
- 링크 안의 id는 신뢰하지 않는 데이터로 다룬다. 칩은 렌더러가 아는 캔버스 목록과 열린 캔버스의 DOM 안에서만 대상을 찾고, id를 HTML·셀렉터 문자열로 끼워 넣지 않는다.
- `/agent-eval` 새 시나리오에서 Claude Code와 Codex가 수정한 대상을 올바른 형식과 실제 id의 링크로 가리킨다.

## 비목표

- 점(point) 앵커 링크. 에이전트가 좌표를 가리킬 이유가 적고, 칩 이름도 의미가 약하다.
- 칩을 그릴 때 대상이 실제로 있는지 미리 확인하기.
- 에이전트 답의 칩을 composer로 옮기기(복사해 다시 보내기).
- 대화 이벤트 형식에 앵커 필드를 더하기.
- 다른 프로젝트(root)의 캔버스를 가리키는 링크. 링크는 그 대화의 프로젝트 안에서만 찾는다.

# 프로토타입 재생에서 프레임만 보이기 — spec

## 사용자

- **사람**: 프로토타입 창(앱)과 내보낸 파일의 플레이어(브라우저)에서 프레임을 재생해 보는 사람. 프레임 바깥에 캔버스 보드의 배경이 비치지 않고 프레임만 본다.
- **에이전트**: 새로 할 일이 없다. 둥근 모서리 프레임을 그려도 재생 화면을 따로 맞출 필요가 없다. 가이드(`cli/internal/cli/skill.md` 14번)의 "elements outside it are hidden"은 그대로 맞다.

## 문제 (관찰한 사실)

- 재생할 때 격리 스크립트(`app/src/main/prototypeScript.ts`, `cli/internal/export/viewer/isolate.js`)는 프레임의 형제를 숨기고 조상의 레이아웃만 푼다. 조상(`html`·`body`·프레임을 감싼 요소)의 배경·그림자·외곽선과 `::before`·`::after`는 그대로 남는다.
- skillflo-web의 `mypage-learning-status-review` 캔버스에서 프레임 `section.rv-deck`은 `border-radius: 24px; overflow: hidden`이고 `body`는 gray-800이다. fit 모드에서 iframe은 마크(1920×1200)와 같은 크기여서, 프레임의 둥근 모서리 바깥 네 귀퉁이에 gray-800이 보인다(2026-11-23 사용자 스크린샷).
- 조상의 `::before`·`::after`가 흐름 안에 있으면 프레임을 밀어 내리고, 절대 위치면 프레임 위나 옆에 그려진다(코드에서 읽은 동작. 재현은 아직 하지 않았다).

## 완료 조건

1. 프레임이 자체 배경(배경색의 알파가 0보다 크거나 `background-image`가 `none`이 아님)을 가지면, 재생할 때 `html`과 모든 조상의 `background`·`box-shadow`·`outline`이 그려지지 않는다. 프레임의 둥근 모서리 바깥에는 호스트가 iframe 뒤에 칠한 색이 보인다. 앱의 fit·responsive에서는 `.pw-box`의 `--surface-panel`, 내보낸 프로토타입 파일에서는 페이지의 `--surface-inset`이다.
2. 프레임에 자체 배경이 없으면 조상의 배경·그림자·외곽선은 지금처럼 그려진다.
3. 1·2와 상관없이, 재생할 때 조상의 `::before`·`::after`는 그려지지 않고 레이아웃에도 자리를 차지하지 않는다.
4. 프레임 자신과 그 자손의 스타일(배경·둥근 모서리·그림자·의사 요소)은 바뀌지 않는다.
5. 앱 프로토타입 창, 내보낸 캔버스 파일의 플레이어, 내보낸 프로토타입 파일이 같은 규칙으로 그린다. 두 스크립트의 격리 시트와 판단 코드는 글자 그대로 같고, 테스트가 이것을 확인한다.
6. 보드(메인 창 캔버스, 내보낸 캔버스 뷰어의 보드)에서는 아무것도 바뀌지 않는다.

## 비목표

- 호스트가 iframe 뒤에 칠하는 색(`.pw-box`의 흰 배경과 그림자, 내보낸 파일의 페이지 배경)은 바꾸지 않는다. fit 박스는 브라우저의 빈 화면처럼 흰색으로 남는다.
- 자체 배경이 없는 프레임 안에서 자식이 둥근 모서리를 가질 때 생기는 모서리 비침은 고치지 않는다(사용자 결정: 투명 프레임은 조상 배경을 유지한다).
- 판단은 격리할 때 한 번만 한다. 그 뒤에 스크립트가 프레임 배경을 바꿔도 따라가지 않는다.
- 캔버스 루트가 `color-scheme: dark`라서 브라우저가 iframe에 불투명한 배경을 칠하는 경우는 막지 않는다. 실제로 그렇게 되는지 확인하고, 그렇다면 한계로 기록만 한다(tasks T4).
- 에이전트 가이드(`skill.md`)와 `doan check` 규칙은 바꾸지 않는다.

# Doany V2 — 외형과 모션 설계

## 기준과 현재 상태

[spec](spec.md)의 선택 Pebble이 V2 외형 기준이다. 같은 캔버스 상단의 V2 프레임은 정지 원본과 모션 명세를 보여준다. 기존 `mascot-home`, `mascot-welcome`, `mascot-motion`과 `.doan/assets/doany/motion/mascot.js`는 **V1**이다. 아래 탐색 시안도 최종 V2 모션의 근거로 삼지 않는다.

V2의 실행 초안은 `doany-v2-home`과 `doany-v2-welcome` 프레임에서 볼 수 있다. `.doan/assets/doany/v2/mascot.js`가 별도 몸통·베레모 텍스처를 그린다. 앱에는 아직 적용하지 않았다. 캔버스의 홉 단계는 정적 설명이며, 실제 프레임 출력·최대 이동량·베레모 지연을 측정한 결과가 아니다. 움직이는 V2 초안을 앱 구현 전에 이 캔버스의 V2 구역에서 검토한다.

## 모션 방향

사용자 행동에 답하는 작은 홉을 주 동작으로 유지한다. 대기 중 호흡·깜빡임·시선은 조용하게 이어진다. 몸통은 매끈한 조약돌 실루엣을 유지하며 눌리고 늘어난다. 베레모는 몸통을 약간 늦게 따라간다. UI 위치나 크기를 애니메이션하지 않는다.

### 기존 타이밍을 유지하는 명세

수치는 [doanyMotion.ts](../../../app/src/renderer/doanyMotion.ts)의 현재 구현을 확인했다. 새로 측정한 V2 결과가 아니다. 일반 UI 전환 토큰으로 이 물리 모션을 대체하지 않는다.

| 상태·입력 | V2 동작과 기준 |
| --- | --- |
| 대기 | `sin(t × 1.9) × .016`의 squash, 약 3.31초 호흡 주기. 몸통 전체가 부드럽게 변형된다. |
| 깜빡임 | 초기 예정 시점 2초. 다음 간격 2.5–6초, 한 번 260ms, 최대 96% 닫힘. 눈은 두 개이며 정지 원본의 간격을 유지한다. |
| 시선 | 포인터 목표를 −1…1로 제한하고 1.8초간 유지한다. 추종은 `1 − exp(−dt × 5)`. 이후 기존 느린 자율 시선으로 돌아간다. |
| Home 입력 | 마지막 입력부터 1.4초 동안 아래쪽 컴포저를 본다. 목표 y=.8, x는 기존 작은 움직임. 기울기 ×.6, squash +.025. |
| 홉 준비 | 0–180ms, squash가 최대 +.15까지 늘어난다. 슬롯 바닥을 기준으로 눌리는 인상을 준다. |
| 비행 | 180–750ms, 570ms의 사인 곡선. lift 최대 .22, squash 최대 −.085. 이 값은 모델 좌표이며 CSS px가 아니다. |
| 착지 | 750–1350ms, `.12 × exp(−a × 7) × cos(a × 17)`로 가라앉는다. 1.35초 뒤 대기로 돌아간다. |
| 베레모 | 기존 스프링 강도 45, 감쇠 `exp(−dt × 6)`, 홉 속도 충격 −.9를 유지한다. 새 원본의 베레모 중심에 맞춰 회전축을 다시 잡는다. |
| 중단·반복 | 홉 중 재입력은 현재 시간으로 시작점을 다시 잡는다. 기존 상태 우선순위는 reduced motion → 홉 → 입력 → 대기이다. 입력 상태는 홉 뒤 유지 시간이 남으면 이어진다. |
| reduced motion | 눈을 뜬 정지 포즈, 시선·호흡·홉·베레모 흔들림 없음. 전환 시 스프링 상태를 초기화한다. |
| 숨김·실패 | 숨김·비가시 상태에서는 시간 진행과 반복 draw를 중지한다. 복귀 시 큰 시간 점프를 하지 않는다(dt 상한 35ms). 실패·컨텍스트 손실은 V2 정지 이미지로 전환한다. |

모션은 60fps를 목표로 하되 실제 달성 여부는 런타임에서 측정한다. 기존 DPR 상한 2와 렌더 크기 상한 1024를 유지한다. 새로운 광원 이동이나 털 시뮬레이션은 만들지 않는다.

## 에셋과 렌더링

- 준비된 파일: `.doan/assets/doany/v2/`의 `doany.png`, `body.png`, `hat.png`, `mascot.js`, `source-prompt.txt`, `layer-prompts.json`, `README.md`, `LICENSE`.
- 실행 초안 좌표: 몸통·베레모 모두 원본과 같은 1254×1254 UV 공간, 눈 중심 (.421,.550)/(.619,.550), 반경 (.035,.056), 베레모 축 (.67,.30), 몸통 중심 (.5,.60), 렌더 배율 1.34. fallback 여백 16.5%로 중립 배율을 맞춘다. 이 값은 초안이며 실앱 승인값은 아니다.
- V2용 모션 초안은 `.doan/assets/doany/v2/` 아래에서 만든다. V1 `motion/`을 수정해 V2처럼 쓰지 않는다.
- 몸통과 모자 레이어를 중립 포즈로 합성했을 때 선택 원본과 맞아야 한다. 눈을 셰이더로 그리므로 몸통 텍스처에 원래 눈이 남아 네 눈처럼 보이지 않아야 한다.
- `Doany.tsx`의 여섯 방향 변형 `sin(angle*6.+time*2.3)` 및 홉 에너지에 따른 방사형 가장자리 물결을 그대로 가져오지 않는다. Pebble에서는 전체 squash·stretch·tilt로 매끈한 윤곽을 유지한다.
- 기존 눈 UV, 몸통 중심, 베레모 배율·오프셋·회전축은 V1 값이다. V2 레이어의 실제 좌표를 측정해 새 기준을 정한다. 추측한 UV를 확정값으로 적지 않는다.
- `doanyMotion.ts`의 시간 모델은 재사용한다. 외형 조정 때문에 시간 모델의 golden 데이터를 불필요하게 바꾸지 않는다. 렌더링 기준을 V2 초안으로 옮길 때에는 재현 가능한 fixture 생성 절차를 함께 남긴다.
- 기존 `Doany` 컴포넌트와 `DoanyHandle`을 유지한다. 범용 마스코트 엔진이나 버전 선택 설정을 추가하지 않는다.

## 순수 함수·테스트 대상

기존 `initialState`, `advance`, `pose`, `pointer`, `typing`, `hop`, `reducedChanged`, `canvasSize`가 `/tdd` 진입점이다. 변경 없는 수식은 기존 테스트를 재사용한다. V2 렌더 좌표·레이어 변환은 DOM/WebGL과 분리해 검증할 필요가 있는 최소 부분만 추출한다. 테스트는 실제 오류를 잡는 기준(중립 포즈 정렬, 눈 위치, 홉의 잘림, 방사형 돌출 제거)을 다루며 상수를 복사한 검증으로 끝내지 않는다.

## 화면과 생명주기

[DESIGN](../../DESIGN.md)의 Home·Welcome 슬롯과 배치를 유지한다. Home은 114×114, Welcome은 142.5×142.5이며 기존 보이는 크기는 약 64/80px이다. PNG의 투명 여백을 포함한 64/80px 이미지 상자와 실제 보이는 크기를 혼동하지 않는다. 비율은 유지하고 새 원본의 알파 경계로 보이는 크기를 맞춘다.

버튼 이름 `Make Doany hop`, `type="button"`, 포커스 링, 전송 availability guard 뒤의 홉을 유지한다. 앱에서 Home이 Welcome 뒤에 있을 때 `checkVisibility({ visibilityProperty: true })`로 draw를 막는 규칙, mount마다 canvas를 복제하는 규칙, dispose의 listener 해제→RAF 취소·연결 해제→context 해제 순서를 보존한다.

## 영향 범위와 결정

- 앱: `Doany.tsx`, 필요한 V2 렌더 좌표와 테스트, `public/doany/` 이미지, `app/resources/icon.png`. Home·Welcome 호출 계약은 유지한다.
- 캔버스: `doan-mascot`의 V2 프레임과 V2 에셋. 적용 후 `.doan/ds/doany.html`도 현행 V2에 맞춘다.
- CLI·공유 JSON Schema·버전 `v`·IPC·코멘트 형식·캔버스 규약·`doan check` 규칙 변경 없음.
- 새로운 의존성·serve 설정·sandbox 예외 없음. 정지 이미지와 텍스처는 기존 정적 자산 경로를 사용한다.
- PRODUCT/ARCHITECTURE/DESIGN은 구현 완료 시 현재 상태로 갱신한다. 지금 V2가 앱에 적용되었다고 바꾸지 않는다.

## 미검증 사항과 선행 검증

브라우저에서 V2 레이어 합성과 두 슬롯의 홉을 확인한다. 생성된 레이어는 선택 원본과 픽셀 단위로 같지 않으며, 최종 외형 승인과 실앱 검증은 남아 있다. V1에서 검증하지 못했던 포인터 추종·깜빡임 실제 타이밍·실제 컨텍스트 손실·텍스처 실패도 V2의 짧은 실앱 probe에 넣는다. 줄인 투명도·강제 색상에서의 표시도 확인하고, 실행하지 못하면 미검증으로 남긴다.

POSTMORTEM에는 Doany 전용 항목이 없다. 관련 주의점은 2026-10-26 오프스크린 iframe 항목의 “Chromium gives an iframe outside the visible area no animation frames.”이다. V2 스토리보드와 설명은 RAF 실행 여부와 무관하게 보이게 한다. 모션 동작 증거는 실제로 보이는 프레임에서 남긴다. Doany의 context·StrictMode 주의점은 [ARCHITECTURE §7](../../ARCHITECTURE.md)에 근거한다.

읽은 프리셋: `generate`(초기 시안), `animate`(이번 모션 명세). 외형 출처와 생성 프롬프트는 V2 에셋 README에 기록했다.


## 실행 초안 검증 결과

브라우저에서 Home·Welcome 텍스처 로딩과 WebGL error 0, 클릭 홉, Home 입력 반응·Enter 전송 홉, Welcome Enter·Space 홉, 포인터 목표, 숨김 중 draw 중지, reduced motion 정지, 주입한 컨텍스트 손실 후 정지 이미지 전환을 확인했다. 홉 82포즈와 베레모 ±.12rad를 샘플링한 렌더 검사에서 228/286 버퍼의 위쪽 여백이 최소 6/7px였다. 모든 입력 조합의 잘림을 증명한 결과는 아니다.

증거는 `.scratch/doany-shape/v2-live-final.png`와 이번 브라우저 probe 출력이다. 실제 깜빡임 간격 관찰, 텍스처 로딩 실패 주입, 지속 프레임 성능, 패키지·StrictMode·실앱 통합은 미검증이다. 생성 레이어의 중립 포즈는 선택 PNG와 픽셀 단위로 같지 않다. 최종 외형은 실행 초안에서 확인받는다.

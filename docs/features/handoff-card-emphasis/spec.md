# 핸드오프 카드 강조 — spec

기존 화면(받는 대화의 핸드오프 카드)을 새 모습으로 바꾸는 redesign feature다. 새 드래프트 파일을 그리고, 기존 드래프트 `.doan/canvases/canvas-handoff.html`은 고치지 않는다(AGENTS.md 'Workflow' `/design-draft` 예외).

## 사용자

- **사람**: 핸드오프로 시작된 대화를 캔버스 패널이나 프로토타입 창에서 여는 사람이다. 이 대화가 다른 캔버스(또는 Overview 대화)에서 넘어왔다는 것과 어디서 왔는지를 한눈에 알아본다. 턴이 그린 캔버스의 카드는 Overview에서도 본다.
- **에이전트**: 바뀌는 것이 없다. 핸드오프 명령, 메시지, 프롬프트는 그대로다.

## 문제

- 핸드오프 카드의 머리는 `--text-metadata` 색의 caption 한 줄("Handed off from drafts.html")이다(`styles.css` `.handoff-head`, `docs/design/conversation.md` 'Canvas handoff'). 바탕은 `--surface-inset`이고, 같은 스레드의 끝 노티스("Stopped" 등)도 같은 바탕을 쓴다. 그래서 사람에게는 카드가 아니라 노티스처럼 보인다(사용자 관찰, 2026-11-25).
- 보내는 쪽 스레드의 캔버스 카드는 아이콘, 굵은 파일 이름, 상태 줄, Open이 있는 머리 행을 가진다(`.canvas-card`). 그래서 카드로 읽힌다. 받는 쪽 카드에는 이런 머리가 없다.

## 확정한 결정 (사용자)

- 핸드오프 카드의 머리를 캔버스 카드의 머리 행처럼 바꾼다. 원본의 이름이 굵게 보이고, 상태 줄과 Open이 있다.
- 핸드오프 카드와 캔버스 카드(턴이 그리거나 핸드오프한 캔버스의 카드, `canvas-drawing-cards`)는 같은 스타일을 쓴다. 둘 다 캔버스를 뜻하기 때문이다. 바탕, 모서리, 머리 행의 구성과 크기가 같고, 핸드오프 카드에만 본문이 더 있다.
- 두 카드의 바탕은 흰색(`--surface-panel`)에 회색 보더다. 회색 바탕을 그대로 두면 노티스와 구분하려는 의미가 흐려지기 때문이다. 두 카드에 함께 적용한다.
- 두 카드는 지금보다 크게 보이고, 메타 정보를 더 많이 보여준다. 어떤 메타를 넣을지는 드래프트에 후보를 모두 그린 뒤 사용자가 덜어낸다. 후보는 design.md '메타'에 있다.
- 썸네일을 메타 후보로 남기면 모든 창(캔버스 패널, Overview, 프로토타입 창)에 보인다. 그래서 프로토타입 창의 썸네일 IPC를 연다.
- 보낸 쪽 대화의 제목과 provider는 넣지 않는다.
- 메타는 지금의 캔버스를 보여준다(핸드오프나 그리기 당시 값은 저장되어 있지 않다).
- 클릭 대상은 Open뿐이다. 카드 본문의 텍스트를 선택할 수 있어야 한다.

## 완료 조건

1. 핸드오프 카드의 머리는 캔버스 카드의 머리 행과 같은 구성이다. 왼쪽부터 상태 아이콘(`forward`), 원본 아이콘과 굵은 원본 이름, 그 아래 상태 줄, 오른쪽 끝 Open이다. 정확한 크기와 간격은 확정된 드래프트를 따른다.
   - 원본이 캔버스면 아이콘은 캔버스 아이콘(사이드바와 같은 `panels-top-left`)이고, 이름은 파일 이름이다(확장자 포함, 너무 길면 가운데를 자른다).
   - 원본이 Overview의 프로젝트 대화면 아이콘과 이름은 Overview의 것이다. 정확한 아이콘은 드래프트에서 정한다.
2. 본문(이전 에이전트의 메시지)은 지금처럼 agent Markdown으로 머리 아래에 보인다. 사람의 말풍선이나 칩으로 보이지 않는다.
3. 기존 동작을 모두 유지한다.
   - 원본 캔버스가 사라지면 Open을 숨기고 상태 줄에 " · No longer in <project>"를 더한다. 원본 프로젝트 대화가 지워지면 Open을 숨기고 " · Conversation deleted"를 더한다.
   - Open의 목적지(원본 캔버스와 그 대화, 또는 그 root의 Overview와 원본 대화), 프로토타입 창에서는 main 창을 거친다.
   - 카드는 `role="group"`이고, 두 카드 모두 "<이름>, <상태>"로 이름이 붙는다(메타는 이름에 넣지 않는다). 핸드오프로 이동한 뒤 키보드 포커스는 카드에 가고, 다음 Tab은 Open이다(2 px 포커스 링).
   - 카드가 시작한 턴이 실패하거나 멈추면 Edit and resend를 보여주지 않는다.
   - 본문 안 inline code는 카드 바탕과 구분되는 바탕을 쓴다.
   - 대화 제목은 메시지의 첫 줄이다.
4. 패널 347, 패널 최소 폭 280, Overview 720(캔버스 카드만), 프로토타입 창에서 머리는 이름이 잘려도 Open이 줄어들지 않는다. 상태 줄은 받는 쪽인지 보내는 쪽인지 방향을 말한다.
5. 두 카드의 바탕, 보더, 크기(확정된 드래프트의 type role과 여백), 메타가 드래프트, 앱, `docs/design/conversation.md`에서 같다. 두 카드의 머리 행은 같은 CSS 규칙을 공유한다(한쪽만 바뀌지 않는다).
6. 캔버스 카드의 모든 상태(Drawing, Drawn, Hands off when this turn ends, Handed off, Didn’t hand off…, No longer in <project>), 카드 묶음, 프로토타입 창에서도 같은 흰 카드로 보인다.
7. 메타 정보가 없거나 아직 준비되지 않은 경우에도 카드의 높이와 배치가 정해져 있다. 썸네일 캡처 전·실패, 캔버스가 사라짐(남은 캐시 썸네일도 보이지 않음), 프레임 없음, `mtimeMs` 없음, Drawing 중(썸네일과 프레임 수 없음, 높이는 Drawn과 같음)이 해당한다. 각 경우의 모습은 확정된 드래프트를 따른다.
8. 수정 시각은 1분에 한 번만 갱신하고 툴팁에 절대 시각을 보인다. 썸네일을 다시 캡처하면 같은 크기 그대로 자리에서 바뀐다. 메타가 바뀌어도 카드 높이는 바뀌지 않는다.
9. 카드 5장 묶음의 모습(347, 280)이 확정된 드래프트와 같다.

## 비목표

- 캔버스 카드의 상태 문구, 상태 아이콘, Open 동작. 바뀌는 것은 바탕, 크기, 메타 정보다.
- 토스트와 핸드오프 이동 동작.
- 핸드오프 메시지의 내용이나 길이 제한, 본문 접기.
- 노티스("Stopped" 등) 자체의 모습.

# canvas-multi-conversation — spec (상위 feature)

한 캔버스에서 앱 대화 여러 개를 동시에 돌린다. 보관(archive)을 없애고, 대화는 "있음" 아니면 "삭제"다. 이 문서는 하위 feature 둘이 같이 따르는 결정과 조사를 담는 허브다. 코드를 바꾸지 않고 `/ship`·`/orchestrate`로 돌리지 않는다(AGENTS.md 'Terms').

## 사용자

- **사람**: 한 캔버스에서 여러 대화를 동시에 굴린다(예: 한 대화는 편집, 다른 대화는 질문이나 다른 안 탐색). 각 대화의 상태를 보고, 대화 사이를 오간다.
- **에이전트**: 앱 대화 안의 에이전트. 같은 캔버스의 다른 대화가 같은 파일을 동시에 고칠 수 있다. Doan은 막지 않는다.

## 문제

- PRODUCT §5 item 2: "Each canvas has one current conversation; starting another archives the previous one." 새 대화를 시작하면 이전 대화가 보관되고, 그 대화의 턴이 돌고 있으면 main이 끊는다(`app/src/main/conversation/service.ts:366-379`).
- "While the canvas's current conversation works, a restore and a new-conversation send are held." 렌더러가 보내기를 막는다(`canvasConversation.ts:107-113`, `dockedRules.ts:92`).
- 그래서 한 캔버스에서 앱 대화 턴은 한 번에 하나만 돈다. 터미널 에이전트는 `doan work`로 여럿이 같은 캔버스를 고쳐도 막지 않는다. 앱 대화만 예외다.
- 사용자 보고: 한 캔버스에서 세션 여러 개를 굴리는 사람이 있고, 그때 각 세션의 상태를 보고 싶어 한다.

## 공통 결정

1. **보관을 없앤다**. 캔버스 대화는 있거나 삭제된다. 새 대화는 다른 대화를 건드리지 않는다. 보관 대화로 보내면 복원되던 규칙과 "현재 대화가 작업 중이면 복원 보류" 규칙이 없어진다.
2. **동시에 돌 수 있다**. 한 캔버스의 모든 대화가 각자 보내고 돌 수 있다. 동시 턴 수에 상한이 없다. 프로바이더의 계정 한도와 사용량이 실제 한도다.
3. **동시 편집은 막지 않는다**. 여러 대화가 같은 캔버스 파일을 고쳐도 Doan은 경고하거나 잠그지 않는다. 터미널 에이전트와 같은 원칙이고, 그렇게 쓰는 것은 사람의 선택이다.
4. **이미 보관된 캔버스 대화는 보통 대화가 된다**. 업데이트 뒤 최근 활동 순 목록에 들어간다. 아무것도 지우지 않는다. 필요 없는 대화는 사람이 삭제한다.
5. **기본으로 보여 줄 대화**: 캔버스를 열 때(main 창 패널, 프로토타입 창, 사이드바 캔버스 행 클릭) 다음 순서로 고른다. 요청된 대화(알림의 Open, Quick Open, 사이드바 대화 행)가 있으면 그것이다. 없으면 권한 요청·질문을 기다리는 대화, 그다음 이 기기에서 그 캔버스에서 마지막으로 본 대화, 그다음 최근 활동 순으로 첫 대화, 대화가 없으면 새 대화 상태다.
6. **프로토타입 창도 대화를 바꿀 수 있다**. 머리 제목이 그 캔버스의 대화를 고르는 메뉴가 되고, 새 대화도 시작할 수 있다. 기본은 결정 5를 따른다.
7. **handoff와 승격은 합류한다**. `doan handoff`가 새 캔버스에 대화를 시작할 때, 프로젝트 대화를 캔버스로 승격할 때, 그 캔버스에 대화가 있거나 작업 중이어도 대화 하나가 더해진다. 기존 대화는 그대로다. handoff의 "그 턴이 만든 새 캔버스" 조건은 바뀌지 않는다.
8. **저장 형식은 `conversations/index.json` v3로 올린다**. 처음 열 때 캔버스 대화의 `archived`를 모두 `current`로 바꿔 쓴다. 이전 빌드는 v3를 읽지 않으므로, 되돌린 앱이 여러 대화를 한꺼번에 보관하거나 턴을 끊는 일이 없다. 프로젝트 대화는 바꾸지 않는다.

## 하위 feature

1. **`canvas-concurrent-conversations`**: 정책과 런타임, 저장 형식, 캔버스 페이지, 그 밖에 대화 목록을 쓰는 화면. design.md '하위 1의 범위'.
2. **`sidebar-canvas-conversations`**: 사이드바에서 보고 있는 캔버스 아래 대화 목록과 대화별 상태. 하위 1이 develop에 병합된 뒤 시작한다. design.md '하위 2의 범위'.

하위 1만 병합되어도 제품이 앞뒤가 맞아야 한다(develop은 언제든 릴리스될 수 있다). 하위 1이 너무 커서 다시 나누면, 나눈 둘은 한 `/chain`으로 이어 사이에 릴리스가 끼지 않게 한다.

## 완료 조건

- 두 하위 feature가 develop에 병합되었다.
- PRODUCT §5 item 2의 "one current conversation"·"archives the previous one"·"held" 문장이 없고, 결정 1–8이 현재 규칙으로 적혀 있다.
- ARCHITECTURE §7의 대화 저장 형식이 v3이고, 보관·복원 경로가 없다.
- `docs/features/canvas-multi-conversation/`가 삭제되었다.

## 하지 않는 것

- 동시 편집 충돌을 해결하거나 알리는 UI.
- 프로젝트 대화(Overview, Home)의 모델 변경. "작업 중인 프로젝트 대화는 루트당 하나" 규칙(PRODUCT §5 item 3)은 그대로다.
- 터미널 세션 표시 방식 변경.
- 계정이나 프로바이더별 동시 실행 한도를 Doan이 따로 두는 것.

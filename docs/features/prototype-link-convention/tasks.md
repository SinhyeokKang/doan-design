# prototype-link-convention — tasks

상위 `prototype-frame-links` 체인의 첫 링크로, `/orchestrate`가 워커 배치로 돈다. 작업 1–4는 배치, 작업 5–6은 컨덕터가 한다(`/orchestrate` §5). 상위 문서의 체크는 리드가 develop에서 한다. 이 feature는 상위 문서를 고치지 않는다.

- [ ] 1. **공유 fixture**: `schema/fixtures/prototype-links/cases.json`(design.md '공유 fixture'의 경우를 모두).
  - 검증: 작업 2–4의 테스트가 이 파일을 읽는다. 파싱이 실패하면 그 테스트가 red다.
  - 커밋 경계: 작업 2의 `test:` 커밋에 함께 둔다.
- [ ] 2. **Go 파싱과 묶음**(`canvas.go` `Gotos`, `links.go` `Playable`·`LinkGroups`).
  - 테스트: `cli/internal/canvas/links_test.go`가 fixture의 `placements`(`frames`, `gotos`, `groups`)와 `groups`를 읽는다. 기존 `prototype_test.go`는 그대로 통과한다. `<head>`·`<body>`에 단 연결은 Go 전용 테스트로 둔다.
  - 검증: `go test ./...`, `go vet ./...`. `/tdd` 보고서가 새로 실패해야 할 테스트 이름을 적고, `/implement` 뒤 모두 green이다.
  - 커밋 경계: `test:` 하나, 구현 하나.

  - 테스트: `cli/internal/check/check_test.go`가 fixture `placements`의 `codes`를 읽는다. `prototypeCodes`처럼 네 코드만 거르는 도우미를 쓰고, 순서는 `Run()` 출력 순서다.

    - 판정 순서
    - 메시지 문자열(긴 id 메시지 포함)

  - 검증: `go test ./...`, `go vet ./...`.
  - 커밋 경계: `test:` 하나, 구현 하나.

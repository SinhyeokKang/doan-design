# 작업 표시 렌더링 부하 줄이기

## 사용자

앱에서 에이전트가 캔버스를 작업하는 동안 보드와 대화 패널을 보는 사람이다. 에이전트(CLI·스킬)가 받는 것은 없다.

## 문제

2026-11-11 실제 앱(0.1.5)에서 녹화한 영상(사용자 Desktop `화면 기록 2026-11-11 16.28.50.mov`, 8초, 60fps)에서 다음을 확인했다. 그때 머신은 load average 16–18(8코어)이었다.

- 작업 중 1–4프레임마다 한 프레임씩 작업 프레임 테두리, 대화 패널의 큐 행, 입력창 테두리·제출 버튼·모델 행, 스레드 끝부분이 함께 사라졌다. 입력창 placeholder만 테두리 없이 남았다.
- 작업 표시가 끝나자 깜빡임도 멈췄다. 사용자도 에이전트 작업이 시작될 때 깜빡임이 시작된다고 확인했다.
- 서로 다른 DOM의 요소가 같은 프레임에 빠지므로, React 재렌더가 아니라 렌더러가 프레임 예산을 넘겨 레이어를 늦게 그리는 현상으로 본다. 원인은 아직 확정하지 않았다.

작업 표시는 작업 중에 매 프레임 메인 스레드에서 다시 그리는 요소를 여럿 가진다(코드에서 확인).

- 작업 프레임 마커: `box-shadow` 키프레임(`doan-work-glow`)과 `background-position` 키프레임(`doan-work-travel`).
- 점 필드: 보드 전체 2D 캔버스를 `requestAnimationFrame`마다 지우고, 모든 점의 가장 가까운 spot 거리를 계산해 다시 그린다.
- 알림 pill의 `backdrop-filter: blur`가 계속 바뀌는 보드 위에 있다.
- 그 밖에 100ms 프레임의 타이핑 GIF, 스피너, 캐럿 깜빡임이 있다.

마커 재로드 숨김(재로드마다 마커가 사라지는 문제)은 체인 링크 1 `frame-first-selection`의 B2가 고친다. 이 기능은 그 수정을 전제로 한다.

## 완료 조건

1. PoC가 격리 앱에서 CPU 부하를 건 상태와 걸지 않은 상태로 작업 표시의 비용을 요소별로 측정했다. 측정값은 프레임당 메인 스레드 시간(스크립트·스타일·레이아웃·paint), 누락·지연 프레임, 렌더러 CPU다. 결과와 환경을 tasks.md에 남겼다.
2. PoC가 비용이 큰 요소부터 바꿀 순서를 정했고, 사용자가 그 결과를 보고 진행을 확인했다.
3. 바꾼 요소는 작업 중 매 프레임 메인 스레드에서 다시 그리지 않는다. 같은 부하 조건에서 바꾸기 전보다 누락 프레임과 메인 스레드 시간이 줄었다는 측정이 있다.
4. 화면은 PRODUCT §5 'Agent indicator'와 DESIGN.md 'Agent glow and dots'·'Working-frame marker'의 값과 같다. 색, 크기, 주기, still(대기)·reduced motion·reduced transparency·forced colours 상태가 유지된다. 눈으로 구별되는 차이가 생기는 변경은 사용자 확인을 받은 것만 넣는다.
5. 고부하 재현 조건에서 녹화한 영상에서 대화 패널과 마커가 프레임 단위로 사라지지 않는다. 사라짐이 남으면 그 원인 후보와 측정을 기록하고 사용자에게 돌아온다.

## 비목표

- 알림 pill의 블러는 PoC가 블러를 주요 비용으로 측정하고 사용자가 바꾸기로 할 때만 바꾼다.
- 작업 표시의 동작, 문구, 등장 조건, 마커 위치 규칙은 바꾸지 않는다.
- 대화 패널 스트리밍은 PoC에서 비용만 잰다. 바꾸는 것은 PoC 결과로 사용자가 정할 때만이다.
- 근거 없는 FPS 목표, GPU 플래그·하드웨어 가속 끄기, 큰 캔버스 iframe 렌더링(`canvas-rendering-stability`)은 다루지 않는다.
- 전체 e2e나 상시 성능 회귀 스위트를 추가하지 않는다.

# prototype-conversation-panel — spec

출처: 사용자 요청(2026-11-14, 원문: "프로토타입 대화 ui 생각이 바뀜. 실험해보고 괜찮으면 다음 feature로 진행. 지금 헤더의 대화 열기 버튼으로 프레임 패널 오른쪽에 붙지? 그렇게 하지 않고 오른쪽에 독립 패널. 대화는 헤더까지 밀고 들어옴. 대화가 열리면 대화 닫기 버튼은 대화 패널 헤더로. 대화 패널 헤더는 기존 프리미티브 재사용. 대화 변경은 안될테니 대화명만 대화 헤더에 출력."). 사용자가 "정확히 원하는 것"이라고 확인한 초안 `.doan/canvases/prototype-conversation-panel.html`(커밋 8cd00821e)의 캡션 숫자가 이 문서의 기준이다.

이 feature는 `prototype-conversation`(체인 261113-3 링크 3, `feat/prototype-conversation`, 구현 중)이 만드는 프로토타입 창 대화 패널의 **배치와 머리만** 바꾼다. 링크 3이 develop에 병합된 뒤 그 위에서 시작한다. 링크 3의 나머지(대화 범위, 재생 프레임 칩, 초안, 카드 답, 칩의 main 창 이동, 배지, seen과 알림, 패널 상태의 메모리 기억, 640으로 넓히기)는 그대로 둔다.

용어: **W**는 창 콘텐츠 폭, **P**는 대화 패널 폭, **L**은 패널 왼쪽 영역의 폭(= 패널의 x = W − P − 8), **R**은 헤더 오른쪽 무리의 폭이다. **프레임 패널**은 프레임이 그려지는 상자(지금 이름 `.pw-panel`, 링크 3 문서의 "콘텐츠 패널")다.

## 결정 (사용자 확인)

1. **독립 패널**: 대화는 프레임 패널에 붙은 열이 아니라 창 오른쪽의 독립 패널이다. 패널은 창 위쪽 8에서 시작해 헤더 줄까지 올라온다. 그래서 헤더는 패널 왼쪽에서 끝난다.
2. **닫기 버튼 자리**: 패널이 열리면 Hide conversation은 패널 머리에 있고, 헤더의 대화 버튼은 보이지 않는다.
3. **머리 재사용**: 패널 머리는 출시된 대화 패널 머리(`ConversationPanel.tsx`의 `.doan-conv-head`, `.doan-panel-hide`, `h2.phead.rp-head`)를 다시 쓴다.
4. **제목만**: 이 창에서는 대화를 바꿀 수 없으므로 머리에는 대화 제목만 있다. 제목 메뉴, chevron, New conversation 버튼은 없다.
5. **창 드래그 영역**: 왼쪽 헤더만 창을 끈다. 패널 머리는 드래그 영역이 아니다.
6. **나머지**: 초안의 다른 선택(숫자, 이름 줄 규칙, 640으로 넓히기, 포커스, 머리 높이 40)은 그린 대로 받아들인다.
7. **패널 최대폭**: `min(50 % W, W − 360)`(초안 그대로). 최대로 끈 640 창에서 프레임 패널이 336으로, 닫힌 360 창의 344보다 8 좁은 것을 받아들인다.
8. **머리 없던 상태의 제목**: 목록 읽는 중, 목록 읽기 실패, 캔버스 사라짐·ID 겹침에서는 셸의 기본 제목 "Conversation"을 보인다.
9. **패널을 연 채 Play**: 폭 = 표시 폭 + 24 + P(최소 640), 이름 줄은 맞춘 L(= 표시 폭 + 16)과 R 104로 정한다. 예: 390 × 844, P 320 → 734 × 952.
10. **640–735 창의 이름 줄**: 기본 폭으로 열면 이름이 둘째 줄로 가서 프레임 패널이 44 내려가는 것을 받아들인다(초안 프레임 02).
11. **열 때 포커스의 대체 대상**: composer가 포커스를 받을 수 없으면 머리 제목 `h2.rp-head`로 보낸다(main 창의 `focusPanel`과 같은 대상).
12. **토스트 자리**: Export 결과 토스트는 패널이 열려 있어도 창 오른쪽 아래에 둔다. composer를 가릴 수 있다.
13. **좁은 작업 영역**: 280 규칙을 지킨다. 작업 영역이 632보다 좁으면 열린 동안 헤더의 두 무리가 겹치는 것을 알려진 한계로 둔다.
14. **초안의 지위**: 이 feature는 redesign child처럼 다룬다. 이 초안이 병합 전까지 패널 배치와 머리의 기준이고, 링크 3의 초안은 고치지 않는다.

## 사용자

- **사람**: 프로토타입 창에서 프레임을 눌러 보며 대화한다. 대화 패널이 창 높이를 거의 다 쓰므로 thread가 56 더 길어지고, 패널을 닫는 버튼이 패널 안에 있다.
- **에이전트**: 바뀌는 것이 없다. 프롬프트, 앵커, CLI, guide, 스킬 stub은 그대로다.

## 문제

- 링크 3의 계획에서 대화 열은 헤더 아래에서 시작해 프레임 패널과 1 px 테두리로 붙어 한 면을 이룬다(모서리 R 0 0 R / 0 R R 0). 패널에는 머리가 없어서, 지금 무슨 대화를 보는지가 패널 안에 보이지 않고, 닫기는 헤더 끝의 같은 버튼이 맡는다.
- 사용자는 이 배치 대신 오른쪽 독립 패널을 원한다(위 원문).

## 범위

### 패널 배치

- 패널은 창 오른쪽의 독립 면이다. x = W − 8 − P, y = 8, 높이 = 창 높이 − 16. 네 모서리 모두 24(`--radius-container`), 그림자 `--shadow-panel`, 1 px 시작 테두리는 없다. 프레임 패널과 패널 사이, 패널과 창 오른쪽·위·아래 사이는 모두 8이다.
- 패널 폭 P는 280부터 min(50 % W, W − 360)까지이고, 기본은 max(320, 28 % W)를 최대로 자른 값이다(DESIGN.md 'Panel width'의 canvas 패널 규칙). 시작 쪽 가장자리의 손잡이는 출시된 것과 같다(DESIGN.md 'Resize handle'). 최대로 끌면 L은 352, 프레임 패널은 336이다(결정 7).
- 왼쪽 영역 L = W − P − 8. 헤더 요소와 프레임 패널은 x8에서 L − 8까지, 폭 L − 16이다. 프레임 패널은 y56(이름이 둘째 줄이면 y100)에서 창 아래 8까지다. 프레임 패널의 네 모서리 24는 출시된 모양으로 돌아간다(링크 3의 R 0 0 R이 아니다).
- 패널은 헤더 줄 수에 따라 움직이지 않는다. 언제나 y8에서 시작한다.
- 패널이 열려 있는 동안 창 최소폭은 640(360 + 280)이고, 닫혀 있으면 360이다. 640보다 좁은 창에서 열면 창이 작업 영역 안에서 640으로 넓어지고 패널은 280으로 열린다(링크 3 규칙). 작업 영역이 640보다 좁으면 창은 작업 영역 폭, 패널은 280이다. 632보다 좁으면 열린 동안 헤더의 오른쪽 무리가 왼쪽 무리와 겹치고, 이것은 알려진 한계다(결정 13). 640에서 L은 352, 프레임 패널은 336이다. 닫아도 창 크기는 그대로이고, 패널의 280과 그 간격 8이 프레임 패널에 돌아간다(640 창에서 624).
- 열고 닫을 때 이름 줄이 바뀌어 프레임 패널이 44 움직여도 애니메이션은 없다.

### 헤더

- 닫힘: 링크 3과 같다. 오른쪽 무리는 [모드 토글, Export, Show conversation]이고 R 140, 창 오른쪽 끝 16 안쪽에서 끝난다. 이름은 W ≥ 444에서 첫째 줄이다.
- 열림: 대화 버튼이 헤더에서 빠져 오른쪽 무리는 [모드 토글, Export]이고 R 104, L − 16에서 끝난다. 이름 캡슐은 x200부터 L − 128까지이고, L ≥ 408(헤더 요소 ≥ 392)이면 첫째 줄, 아니면 둘째 줄(x16부터 L − 16, y56, 헤더 100)이다. 예: 1024 창·패널 320 → L 696, 이름 368. 1024·512 → L 504, 이름 176. 736·320과 696·280 → L 408, 이름 80. 695·280 → L 407, 둘째 줄. 640·280 → L 352, 둘째 줄.
- 손잡이를 끌어 L이 408을 지나면 같은 캡슐이 줄을 옮기고, 포커스와 열린 프레임 메뉴는 캡슐에 남는다(출시된 규칙과 같다).
- 기본 폭으로 열면 640–735 창에서 이름이 둘째 줄로 가서 프레임 패널이 44 내려간다. 링크 3 계획에서는 첫째 줄에 남았지만 이 모습을 받아들인다(결정 10, 초안 프레임 02).
- 대화 버튼은 열려 있는 동안에도 DOM에 남되 보이지 않는다(Tab 정지도 없다). 같은 요소가 닫으면 다시 보인다.
- 창 드래그 영역은 왼쪽 헤더(`.pw-top`)뿐이다. 패널, 패널 머리, 패널 위·옆의 8 간격은 창을 끌지 않는다.

### 패널 머리

- 출시된 대화 패널 머리(`.doan-conv-head`)에 셸의 정적 제목 `h2.phead.rp-head`를 두고, 끝에 Hide conversation(`.doan-panel-hide`, `PanelRightClose`, 툴팁 "Hide conversation", `aria-expanded`, `aria-controls`)을 둔다. 제목 메뉴, chevron, New conversation은 없다.
- 머리 높이는 40이다(`calc(var(--size-chrome) - 2 * var(--space-2))`). y8에 놓인 패널에서 제목의 가운데가 y28, Hide가 y12–44로 헤더 컨트롤과 같은 높이에 온다. main 창 머리(56)와 다르다는 것을 DESIGN.md에 문서화된 차이로 적는다. thread는 main 창 머리 아래보다 16 위에서 시작한다.
- 제목은 그 캔버스 현재 대화의 제목이다. 목록이 이름을 주면 목록의 요약 제목, 그 전에는 첫 메시지 줄(칩은 이름으로, main 창의 `canvasConversationTitle`과 같다). 현재 대화가 없으면 "New conversation"이다(main 패널의 같은 상태 문구). 목록을 읽는 중, 목록 읽기 실패, 캔버스 사라짐·ID 겹침에서는 셸의 기본 제목 "Conversation"이다(결정 8). 이 상태들은 새 대화 상태가 아니기 때문이다. 제목 글은 패널 왼쪽에서 16 안쪽에서 시작한다.
- 한 줄, 넘치면 말줄임표. 잘렸을 때만 전체 제목을 native `title`로 준다(프레임 이름의 툴팁 규칙과 같은 조건).

### 포커스

- 헤더의 Show conversation(포인터든 키든)으로 열면 포커스가 composer로 간다(링크 3과 같다). composer가 포커스를 받을 수 없는 상태(링크 3의 막힌 composer 가운데 포커스를 받지 않는 것)에서는 머리 제목 `h2.rp-head`(tabIndex −1)로 간다(결정 11). 숨겨지는 헤더 버튼에 포커스가 남아 `body`로 떨어지지 않게 하기 위해서다.
- Hide conversation은 프레임 콘텐츠 다음, 패널의 첫 Tab 정지다. 키보드 포커스에 공유 2 px 링과 4 아래의 툴팁이 보인다.
- 닫으면(Hide conversation) 포커스가 다시 보이게 된 헤더의 Show conversation으로 돌아온다. Esc는 패널을 닫지 않는다(링크 3과 같다).
- Tab 순서: 헤더(Back, Forward, Reload prototype, 프레임 이름, 모드 토글, Export, 닫혀 있을 때만 Show conversation) → 프레임 콘텐츠 → 패널(Hide conversation, thread, composer).

### 패널을 연 채 Play

- 새 Play(main 창의 Play, 드로어, Back/Forward, `doan open --prototype`)가 창을 맞출 때 폭 = 표시 폭 + 24 + P(최소 640)이다. 그래서 프레임 패널이 표시 폭과 같다. 높이 = 표시 높이 + 64이고, 맞춘 L(= 표시 폭 + 16)에서 R 104로 이름이 둘째 줄이면 + 108이다. 표시 폭 392 이상이면 첫째 줄이다. 예: 390 × 844, P 320 → 734 × 952. 작업 영역보다 넓으면 패널을 먼저 280까지 줄이고 그다음 프레임 패널을 줄인다. 높이는 작업 영역 높이까지다(결정 9).

### 토스트

- Export 결과 토스트는 패널이 열려 있어도 창 오른쪽 아래(오른쪽과 아래에서 16)에 있고, 헤더 위에는 오지 않는다. 열린 패널의 composer를 가릴 수 있다(결정 12). PRODUCT의 "over the content panel"은 승격 때 "the window's bottom right"로 고친다.

### 변하지 않는 것

- 링크 3의 패널 내용 전부: thread, docked composer, 재생 프레임 칩, docked buddy, 새 대화 상태, 목록 읽기 실패 줄, composer 막힘, 카드 답, 칩과 main 창 전용 버튼, 배지, seen과 알림, 패널 상태의 메모리 기억, 대화 범위 검사와 IPC.
- 헤더의 왼쪽 무리, 프레임 메뉴, 모드 토글, Export, 상태 오버레이(프레임 패널만 덮는다), Fit과 Responsive 규칙.
- 프롬프트, 앵커, 이벤트 형식, CLI.

## 완료 조건

- 1024 창에서 Show conversation을 누르면 창 크기는 그대로이고, 패널이 x696 y8, 320 × (창 높이 − 16), 네 모서리 24와 `--shadow-panel`, 시작 테두리 없이 열린다. 헤더 요소는 x8–688(680), 오른쪽 무리는 R 104로 x592에서 끝나고, 이름은 x200–568(368), 프레임 패널은 x8 y56, 폭 680이다(단위 테스트와 `/design-sync`).
- 640 창에서 열면 패널 280(x352), 이름이 둘째 줄 x16–336, 헤더 100, 프레임 패널 x8 y100 폭 336이다. Responsive 모드의 프레임 `innerWidth`는 336이다. 360 창에서 열면 창이 640이 되고 같은 모습이다. 닫으면 창은 640으로 남고 프레임 패널은 624가 된다(단위 테스트와 실제 앱 확인).
- 손잡이로 패널을 280부터 최댓값까지 조절할 수 있고, L이 408과 407 사이를 지날 때 같은 이름 캡슐이 포커스를 지닌 채 줄을 옮긴다(696 창·280은 첫째 줄 80, 695 창·280은 둘째 줄)(단위 테스트와 실제 앱 확인).
- 패널 머리가 40 높이로 제목과 Hide conversation을 보이고, Hide는 y12–44, 제목 가운데는 y28이다. 제목은 현재 대화의 요약 제목, 목록이 이름을 주기 전에는 첫 메시지 줄, 현재 대화가 없으면 "New conversation", 목록 읽는 중·목록 읽기 실패·캔버스 사라짐·ID 겹침에서는 "Conversation"이다. 제목이 잘렸을 때만 native `title`이 있다(단위 테스트와 `/design-sync`).
- 열려 있는 동안 헤더 대화 버튼은 DOM에 남되 보이지 않고 Tab 정지가 아니다. 열면 포커스가 composer에(composer가 포커스를 받을 수 없으면 머리 제목에), Hide conversation으로 닫으면 헤더의 Show conversation에 있다(`document.activeElement`로 실제 앱 확인, POSTMORTEM 2026-11-03 조건). Tab이 헤더 → 프레임 콘텐츠 → Hide conversation 순으로 간다(단위 테스트).
- 패널이 열린 뒤 패널 머리의 Hide conversation과 제목을 네이티브로 누르면 창이 끌리지 않고 버튼이 동작한다. 왼쪽 헤더의 빈 곳을 네이티브로 끌면 창이 움직인다. 닫은 뒤에는 헤더 전체 폭이 다시 드래그 영역이다(네이티브 입력으로 실제 앱 확인, POSTMORTEM 2026-11-06).

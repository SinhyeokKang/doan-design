# 검사 범위 — spec

`doan check`에 편집한 파일 경로를 넘기면, CLI가 그 파일이 영향을 주는 캔버스로 범위를 정하고 그 범위의 결과만 돌려준다. 인자가 없으면 지금처럼 저장소 전체를 보고한다.

## 사용자

- **에이전트**: 캔버스나 CSS를 편집한 뒤 `doan check`를 돌리는 Claude Code, Codex 등이다. 편집한 캔버스, CSS, 설정 파일을 넘기고, 그 파일이 영향을 주는 캔버스의 결과만 받는다. 범위를 고르는 판단은 하지 않는다.
- **사람**: 터미널에서 `doan check`를 인자 없이 돌리면 지금과 같은 전체 결과를 본다. 앱에서는 대화 턴 프롬프트의 문구만 바뀐다. 앱이 보여 주는 "run `doan check`" 안내 문구는 그대로다.

## 문제

- `doan check`는 인자를 받지 않는다(`usage_error: check takes no positional arguments`). 언제나 저장소의 모든 캔버스를 검사하고, 모든 결과를 돌려준다(ARCHITECTURE §1 '`doan check` rules').
- 안내(가이드 E, `cli/internal/cli/skill.md`), 디자인 프리셋, 앱 대화의 턴 프롬프트(`app/src/main/conversation/prompt.ts`)는 모두 편집 뒤 `doan check`를 통과시키라고 한다.
- 다른 캔버스에 오류가 하나라도 있으면 exit 4가 된다. 그러면 에이전트는 "통과시켜라"를 지키려고 자기 작업과 관계없는 캔버스를 고치거나, 실패를 안고 끝낸다.
- 결과도 저장소 전체다. 2026-11-25에 이 저장소에서 돌리면 147개 캔버스를 검사해 경고 43개가 나왔다(JSON 약 5.5KB, 텍스트 약 7.7KB). 43개 모두 공유 파일 `.doan/assets/mock.css`의 `hardcoded_color`다.
  - 이 경고는 `mock.css`를 링크한 44개 캔버스에는 그 캔버스의 결과로 계속 나온다.
  - 나머지 103개 캔버스를 편집할 때는 나오지 않게 된다.
  - 이 기능의 주된 효과는 exit 코드가 다른 캔버스의 상태에 기대지 않게 되는 것이다.
- 저장소 전체를 보는 규칙도 있다(`duplicate_canvas_id`: 캔버스 id는 저장소 전체에서 유일해야 한다). 그래서 검사는 전체를 하고, 보고만 좁힌다.

## 확정한 결정 (사용자)

- 단계는 두 가지다. 인자가 없으면 저장소 전체, 경로를 주면 그 경로가 정하는 범위다. 프레임 단위와 여러 저장소 단위는 만들지 않는다.
- 에이전트에게 범위를 고르게 하지 않는다. 에이전트는 편집한 캔버스, CSS, 설정 파일을 넘기고, 범위는 CLI가 파일 종류로 정한다. 공유 CSS를 고쳤을 때 그 CSS에 닿는 다른 캔버스까지 보게 하기 위해서다.
- 인자 없는 전체 검사는 사람이 전체 점검을 부탁할 때 쓴다.
- 캔버스, CSS, 설정이 아닌 경로는 거절한다.
- 어떤 캔버스도 닿지 않는 CSS만 넘기면 실패한다. 검사한 캔버스가 0개인데 조용히 통과하지 않게 하기 위해서다.
- 다른 캔버스를 읽을 수 없으면 지금처럼 명령 전체가 실패한다.
- 디자인 프리셋과 앱 대화의 턴 프롬프트도 같은 형태로 바꾼다.
- 숨긴 결과의 수는 알리지 않는다.
- 효과를 재는 새 eval 시나리오를 더한다.

## 완료 조건

1. `doan check <경로>...`는 언제나 저장소 전체를 검사하고, 경로가 정하는 범위의 결과만 돌려준다. 범위는 넘긴 경로마다 다음 캔버스를 모은 합집합이다.
   - 캔버스: `doan ls`가 나열하는 캔버스(`.doan/canvases/`, `.doan/ds/`와 그 하위 폴더) 가운데 그 경로에 맞는 하나
   - CSS(소문자 `.css`, 저장소 안): 그 CSS에 닿는 모든 캔버스. 직접 링크와 `@import`로 닿는 것을 포함한다. 지운 CSS는 그 경로를 직접 링크하거나 `<style>`에서 import하던 캔버스다.
   - `.doan/config.json`: 인자 없는 실행과 같은 결과다.
2. 범위가 있을 때 돌려주는 결과:
   - 범위 안 캔버스를 처리하며 나오는 모든 결과. 그 캔버스 파일의 결과와 그 캔버스가 닿는 CSS의 결과이고, 그 캔버스를 기준으로 판정한다.
   - 범위 안 캔버스와 id가 겹치는 모든 파일의 `duplicate_canvas_id`
   - 저장소 설정의 결과(`token_css_not_found`, `serve_withheld`)
3. exit 코드는 돌려준 결과로만 정한다. 돌려준 결과에 오류가 있으면 4이고, 없으면 0이다. 범위 밖 캔버스의 오류는 exit에 영향을 주지 않는다.
4. `summary`의 모양은 그대로(`{canvases, errors, warnings}`)다. 범위가 있으면 `canvases`는 범위 안 캔버스 수이고, `errors`와 `warnings`는 돌려준 결과의 수다.
5. 텍스트 출력은 범위가 있으면 "N canvases in scope (M checked)"로 시작한다. 인자 없는 출력은 지금과 같다.
6. 인자 없는 `doan check`의 출력과 exit 코드는 지금과 바이트 단위로 같다. 세션 연결 기록은 같은 시각이라면 같은 줄을 쓴다.
7. 경로 규칙:
   - 캔버스는 `doan export`와 같이 나열된 캔버스와 맞춘다(ARCHITECTURE §12 export: 저장소 상대 경로나 저장소 안의 절대 경로, 대소문자와 유니코드 표기는 나열된 것으로 맞춘다). 나열되지 않은 캔버스 경로는 `canvas_not_found`(exit 2)다. 점으로 시작하는 파일, 심볼릭 링크, 확장자 대소문자가 다른 파일, 없는 파일이 여기에 든다.
   - CSS와 설정은 저장소 상대 경로나 저장소 안의 절대 경로로 받고, 심볼릭 링크와 루트 별칭은 실제 경로로 풀어 맞춘다.
   - 세 종류에 들지 않거나 저장소 밖인 경로는 `usage_error`(exit 2)다. 메시지는 받는 세 종류를 말한다.
   - 어떤 캔버스도 닿지 않는 CSS는 `usage_error`(exit 2) "No canvas links or imports <path>"다.
   - 같은 경로를 여러 표기로 넘겨도 한 번으로 친다.
   - 저장소 오류(`repo_not_found`, `invalid_config`, `unsupported_version`)가 경로 오류보다 먼저다.
8. 셸 `doan check`의 세션 연결 기록은 인자가 있어도 검사한 모든 캔버스를 대상으로 한다(ARCHITECTURE §4 'Shell check session associations'). 경로 오류로 끝나면 기록하지 않는다.
9. 에이전트에게 가르치는 문구:
   - 가이드 E: "After editing, make `doan check <edited canvas, CSS and config paths> --json` pass". 바로 뒤의 `doan work done <edited canvas paths>`(캔버스만)와 구분된다.
   - 명령 설명 줄: 경로를 주면 그 파일이 영향을 주는 캔버스만 보고하고, 인자가 없으면 저장소 전체를 보고한다. 인자 없는 형태는 사람이 전체 점검을 부탁할 때 쓴다. `summary.canvases`의 "0: none written yet"은 인자 없는 형태에만 해당한다.
   - 디자인 프리셋에서 `doan check`를 통과시키라는 문장은 모두 같은 형태가 된다.
   - 앱 대화의 턴 프롬프트도 같은 형태가 된다.
   - `doan help`의 usage는 `check [<path>...]`다.
10. 새 eval 시나리오가 다음을 판정하고, `--self-test`가 그 pass/fail fixture로 통과한다.
    - 관계없는 캔버스(이미 오류가 있다)를 건드리지 않았다.
    - 편집한 경로를 넘겨 `doan check`를 돌렸다.
    - 그 경로로 돌린 `doan check`가 exit 0이다.
11. `/agent-eval` 회차에서 새 시나리오가 Claude Code와 Codex 모두 통과한다. 직전 회차에 통과한 시나리오가 실패하면 `--repeat 2`로 다시 돌려, 재현되는 회귀가 없다.

## 비목표

- 프레임 단위 검사. 규칙 대부분이 캔버스 단위라서(`doan:width`, 캔버스 안의 `data-doan-id` 중복, `goto` 대상, 토큰이 닿는 범위), 프레임으로 좁히면 오류를 놓칠 수 있다.
- 여러 저장소를 한 번에 검사하기. CLI는 저장소 하나를 기준으로 돈다(`--repo`).
- 검사 속도. 범위를 줘도 전체를 검사한다.
- 숨긴 결과의 개수나 목록을 따로 알려 주는 필드. 전체가 필요하면 인자 없이 돌린다.
- 새 검사 규칙, 기존 규칙의 수준(error/warning) 변경, `mock.css`의 `hardcoded_color` 정리.
- 다른 명령의 `nextSteps`("Run `doan check --json` …")와 `no_canvases` 메시지, 앱의 "run `doan check`" 안내 문구. 사람이나 에이전트를 전체 검사로 보내는 자리라서 그대로 둔다.

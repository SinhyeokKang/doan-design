## 1. 관찰하지 못한 것과 한계

- **실제 에이전트는 실행하지 않았다.** 에이전트의 수정은 모두 **통제된 파일 편집**(캔버스 HTML 문자열 치환, 파일 이동, id 변경, 댓글 줄 추가)과 실제 `doan comment resolve --agent …`, `doan check`, `doan comments`, `doan active` CLI 호출로 흉내 냈다. 복사한 지시문을 Claude Code나 Codex가 실제로 어떻게 처리하는지는 확인하지 않았다(L-11, L-12, L-21). 이 부분은 `/agent-eval`로 확인해야 한다.
- **IME 조합 중 이동**(T-12), **VoiceOver**, **네이티브 메뉴 가속키 입력**(메뉴 항목은 main에서 직접 눌렀다), **macOS Light 모드**는 확인하지 않았다.
- **확인하지 못한 가설**:
  - 리로드 순간에 핀과 "Location unavailable"이 깜빡이는지(T-11, W-9). 0/300/800ms 샷은 찍었지만 다른 파일 변경 경우이고, 첫 샷 시점에 이미 리로드가 끝나 있었다.
  - 같은 모서리 핀이 겹치는지(P-11)
  - 대상 줄의 hover 표시(P-14)
  - nth-of-type 앵커가 다른 요소로 잘못 붙는 경우(T-16)
- **알려진 기존 한계(이번에 새로 재현하지 않음)**: 과거 정상 재시작 첫 레이아웃 실패 1회는 원인이 밝혀지지 않았다. 기존 Radix 메뉴 inline-style CSP 경고는 이번 실행 로그에도 나왔다(`s1.out` 2행). 이것도 기존 분류대로 별도 항목이다. 캔버스 미디어 선호도 관찰은 이번에 다루지 않았다.
- **격리**: 임시 HOME·userData·SHELL·`CLAUDE_CONFIG_DIR`·`CODEX_HOME`와 가짜 claude/codex를 썼다. 클립보드는 실행 전에 저장했다가 종료 때 복원했다. 네 장면 모두 `app.quit()` 정상 종료 exit 0이었고, `app/e2e/real-state.ts` 검사에서 실제 사용자 상태(`~/.local/bin/doan`, skill 링크, `~/Library/Application Support/doan/*`, 두 에이전트의 MCP 등록)는 바뀌지 않았다. 빌드는 `npm --prefix app run build`(exit 0)를 썼다.

## 2. 결론 요약

루프의 앞쪽(리뷰 → 작성)은 동작한다. 그러나 **넘긴 뒤와 돌아온 뒤**가 비어 있다. 수정본이 도착해도 앱은 "무엇이 바뀌었고 무엇이 처리됐는지"를 보여주지 않는다. 재확인의 핵심 동작인 "이 댓글의 위치로 가기"는 긴 캔버스에서 동작하지 않는다. 넘기기 표시("Copied")는 루프가 한 바퀴 돌면 사실과 어긋난다. 에이전트가 정상적인 범위에서 작업하는 동안에도 사람이 쓰던 댓글이 저장 불가로 막히고, 캔버스를 옮기거나 id를 바꾸면 댓글이 앱에서 사라진다.

#### L-1 — 목록에서 댓글 위치로 가기가 긴 캔버스에서 동작하지 않는다 (관찰)
- **과제**: F9. 수정본을 재확인하면서 카드마다 그 대상 위치로 간다.
- **재현**: S2 #2→#3. Cart에서 확대한 상태에서 화면 밖(Order placed) 열린 댓글의 대상 줄 "Element · success-eta"를 누른다. board transform이 `translate(-496.364px, -143.575px) scale(1.42561)`에서 그대로였고, 선택도 메시지도 없었다. 포커스는 버튼에 남았다.
- **원인**: 열린 댓글은 `activatePin`이 화면 안의 핀 목록에서만 찾고, 없으면 조용히 끝난다(`CanvasController.ts:180-184`, `projection.ts:64-68`). 해결된 댓글은 선택만 하고 뷰를 옮기지 않는다(`useComments.tsx:87-88`). 트리와 Quick Open은 `fitFrame`으로 이동한다(`CanvasController.ts:737-745,771-775`). Locate를 다루는 테스트는 없다.
- **추가 관찰**: 해결된 카드에서 위치로 가면 필터가 Selection으로 바뀐다. 그래서 다른 해결 카드가 목록에서 사라진다(S1 #23, "Resolved 1"). 하나씩 재확인할 때마다 Canvas를 다시 눌러야 한다.
- **영향**: 재확인의 기본 동작이 긴 캔버스에서 실패한다. 버튼은 활성인데 아무 일도 없다.
- **관련 결정**: PRODUCT §5 항목 5(대상을 doan-id→selector로 찾는다), ARCH "Anchors and pins". 화면을 옮기는 동작은 정해지지 않았다.
- **최소 개선**: Locate가 핀 표시 여부에 의존하지 않게 한다. 대상 노드를 선택하고 그 사각형으로 이동·강조한다. 기존 jump 강조를 재사용한다.
- **성공 확인**: e2e. 마지막 프레임의 댓글을 맨 위에서 Locate하면, 선택이 그 대상이고 사각형이 뷰포트와 겹친다. 해결된 댓글도 같다. 출처: A-1, T-1, P-14.

#### L-2 — 에이전트가 `design/`의 어느 파일을 바꿔도, 쓰던 새 댓글이 영구히 저장 불가가 된다 (관찰)

## 6. 결정이 필요한 질문 (하나씩 정할 순서)

1. **우선 묶음**: 1차로 "루프 끊김 수정"(L-1, L-2, L-4, L-8, L-9, L-13, L-17 — 기존 결정 안의 수정)을 먼저 하고, N1(재확인 모드)은 그다음 `/feature`로 할지.

3. **고아 댓글**: 앱에 보이기만 할지(N3 일부), 앱에서 삭제·해결까지 허용할지(L-3).
4. **Outdated의 의미**: 이름과 색만 바꿀지, 비교 기준을 해결 시점이나 넘긴 시점으로 바꿀지(L-14, 형식 변경).
5. **넘기기 범위**: Copy에 "현재 선택"이나 "이 프레임" 범위를 추가해 Q6 결정을 바꿀지(N2, L-10).
6. **에이전트 보고 규약**: skill과 지시문을 바꾸고 agent-eval을 돌릴지(N5).

L-5(댓글 파일 읽기 실패가 프로젝트 오류로 번짐)는 CLI `ls` 계약에 영향을 주므로 별도로 결정한다.

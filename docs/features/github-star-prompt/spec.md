# github-star-prompt — spec

Doan을 쓴 지 어느 정도 된 사람에게 GitHub 저장소에 별을 달아 달라고 묻는 작은 카드를 최대 두 번 보인다. 누르면 저장소 페이지를 브라우저로 연다.

## 사용자

- **사람**: 릴리스 빌드를 쓰는 사람. 카드를 보고 별을 달지, 지금은 넘길지 고른다. 두 번째 카드에서 넘기면 다시 묻지 않는다.
- **에이전트**: 바뀌는 것이 없다. CLI, 스킬, 가이드는 그대로다.

## 문제

- Doan은 공개 저장소(`https://github.com/SinhyeokKang/doan-design`)에서 배포되지만, 앱 안에서 저장소를 알리는 곳이 없다. 앱이 저장소 쪽으로 보내는 길은 업데이트의 Release Notes ↗(릴리스 페이지)뿐이다(PRODUCT §5 item 0 'About').

## 범위 (사용자 결정, 2026-11-13)

PRODUCT §3 Out of scope 5("the web only serves as the download path")에 걸리지 않는다고 본다. 이 기능은 요청을 보내지 않고, Release Notes ↗처럼 브라우저로 링크를 열 뿐이다. 승격 때 Out of scope 5에 브라우저로 여는 링크는 사람의 방문이라는 문장을 더해 오해를 막는다.

## 동작 (사용자 결정, 2026-11-13)

- **누구에게**: 업데이트를 확인하는 사본과 같은 조건의 릴리스 빌드(PRODUCT §5 item 0 'Updates': `/Applications` 또는 `~/Applications`에 직접 있고 translocate되지 않은 릴리스 빌드)에서만 세고 보인다. 개발 실행, 로컬 패키지, tester 빌드는 세지도 보이지도 않는다.
- **세는 것**: 이 기기에서 앱 대화의 턴이 성공으로 끝난 수(`turn.done`). 실패·중지·거절 턴은 세지 않는다. handoff로 시작된 대화의 턴과 큐에서 나간 턴도 각각 센다. 터미널 에이전트 세션(Doan 밖)은 세지 않는다.
- **언제**: 센 수가 기준(처음 20)에 닿은 그 턴이 끝나고, 사람이 1.2초 동안 키·포인터 입력을 하지 않으면 띄운다. 아래 중 하나라도 맞으면 띄우지 않고 다음 턴 끝으로 미룬다.
  - 창이 보이지 않거나 앞에 있지 않다.
  - 첫 실행(onboarding, 버디 소개) 중이다.
  - 모달, 팝오버, 메뉴가 열려 있다.
  - 다른 대화가 아직 턴을 실행하고 있거나 권한·질문 답을 기다린다.
  - 캔버스에서 pick이나 Capture area 중이다.
- **어디에**: 창 왼쪽 아래. 사이드바가 보이면 사이드바 아래쪽 위에 놓는다. 폭은 240px 고정이고 사이드바 폭을 따르지 않는다(사용자 결정, 2026-11-13). 숨겨져 있으면 같은 왼쪽 아래 모서리다. Home, Overview, 캔버스 페이지 어디서나 같은 자리다. 오른쪽 아래 토스트와는 따로 동작하고 서로 밀어내지 않는다.
- **카드**: Doan의 평이한 목소리로 짧은 문구 한두 줄(버디 목소리는 쓰지 않는다)과 버튼 둘. 문구는 `/design-draft`에서 clarify 프리셋으로 쓴다.
  - `Star on GitHub ↗`: 저장소 페이지를 브라우저로 열고 카드를 닫는다. 다시 묻지 않는다. 감사 문구는 보이지 않는다(Doan은 별을 달았는지 모른다). 여는 동안 반복 누름은 무시한다.
  - 브라우저를 열지 못하면 카드 안에 Release Notes ↗와 같은 형식의 실패 줄을 보인다. 저장소 주소를 선택해 복사할 수 있는 텍스트로 넣고, 줄은 한 번만 읽히며 포커스는 버튼에 남는다. 버튼을 다시 누르는 것이 재시도다.
  - 닫기 버튼: 첫 카드는 `Not now`, 두 번째 카드는 `Don’t ask again`. 첫 `Not now`면 그 순간의 수 + 40턴을 다음 기준으로 하고 적어도 3일 뒤에 다시 묻는다. `Don’t ask again`이면 다시 묻지 않는다. 실패 줄이 보이는 동안 누른 닫기도 같다.
  - Esc는 포커스가 카드 안에 있을 때만 닫기 버튼과 같다. 그 밖의 Esc는 원래 역할을 하고 카드는 그대로다. 카드는 바깥 누름이나 포커스 이동으로 닫히지 않는다.
- **포커스와 읽기**: 카드는 포커스를 가져가지 않는다. 앱 문서 끝의 `role="region"`(이름 있음)이라 Tab 순서의 마지막 정류장이다. 문구는 나타날 때 polite live로 한 번 읽힌다.
- **기록**: 이 기기의 userData에만 남긴다. 읽거나 저장할 수 없으면(깨진 파일, 미래 버전, 쓰기 실패) 묻지 않는다. 저장 실패를 따로 알리지 않는다. 카드가 떠 있는 동안 앱을 끄면 보인 것으로 세지 않는다.
- **네트워크**: 이 기능은 요청을 보내지 않는다. 별 개수를 읽지 않고, `gh`나 GitHub API를 쓰지 않으며, 원격 측정을 하지 않는다.

## 참고: Orca의 별 요청

출처: 설치된 `/Applications/Orca.app` 1.4.257의 `app.asar`(minified `out/main/index.js`의 `starNag`, `out/renderer/assets/App-*.js`의 `StarNagCard`·`StarNagToastHost`), 2026-11-13에 읽음. 소스 저장소는 보지 않았다.
- 띄우는 때: 실행한 에이전트 수가 기준점에서 35 늘었을 때(카드), 온보딩을 마쳤을 때(토스트), 에이전트 작업이 끝나고 1.2초 동안 입력이 없을 때(한 번만).
- 띄우기 전에 `gh` CLI로 이미 별을 달았는지 확인한다. `gh`가 있으면 버튼이 사용자의 GitHub 인증으로 바로 별을 단다. 없으면 브라우저로 저장소를 연다.
- `Later`/`Dismiss`/브라우저 열기 뒤에는 3일 쉬고 다음 기준을 2배로 늘린다. 직접 별을 달았거나 그만 묻기를 고르면 끝난다. 결과를 원격 측정으로 보낸다.
- Doan은 `gh` 확인·대리 별 달기·원격 측정·감사 문구를 가져오지 않는다(GitHub 토큰 규칙, Out of scope 5, 별 여부를 모름).

## 완료 조건

1. 조건을 만족한 릴리스 빌드에서, 성공한 앱 대화 턴이 20번에 닿은 턴이 끝나고 1.2초 동안 입력이 없으면 카드가 창 왼쪽 아래에 보인다. 개발 실행, 로컬 패키지, tester 빌드에서는 세지도 보이지도 않는다.
2. '언제'의 미루는 조건 중 하나라도 맞으면 보이지 않고, 다음 턴 끝에 다시 판단한다.
3. `Star on GitHub ↗`는 저장소 페이지를 브라우저로 열고 카드를 닫으며, 그 뒤 다시 보이지 않는다. 열지 못하면 저장소 주소가 든 실패 줄이 보이고 버튼이 재시도다.
4. 첫 카드의 `Not now`는 카드를 닫고, 그 순간의 수 + 40턴과 3일이 지난 뒤 `Don’t ask again`을 단 카드로 한 번 더 보인다. `Don’t ask again` 뒤에는 다시 보이지 않는다.
5. 카드가 떠도 `document.activeElement`가 바뀌지 않는다. Tab으로 카드의 두 버튼에 닿는다. 포커스가 다른 곳으로 옮겨 가거나 바깥을 눌러도 닫히지 않는다. 포커스가 카드 밖일 때의 Esc는 카드를 닫지 않는다. 문구는 나타날 때 한 번 읽힌다.
6. 오른쪽 아래 토스트가 떠도 카드는 그대로이고, 카드가 떠도 토스트는 그대로 뜬다.
7. 저장 파일을 읽거나 쓸 수 없으면 카드가 보이지 않는다.
8. 이 기능은 네트워크 요청을 보내지 않는다. 새 코드에 `api.github.com`, `fetch`, `net.request`, `gh` 호출이 없다.
9. `npm --prefix app test`, `npm --prefix app run typecheck`, `npm --prefix app run lint`가 통과한다.

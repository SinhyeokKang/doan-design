# 폴더 첨부

## 순서와 상태

다섯 기능 중 1번이다. 다음은 `frame-first-selection`이다. 기능 문서 적재 단계이며 구현하지 않았다.

## 사용자와 문제

사람은 대화에서 참고할 폴더를 지정하고, 에이전트는 전달받은 경로를 자신의 도구로 읽는다. 현재 파일만 첨부할 수 있고 폴더는 거부한다(PRODUCT §5 item 1 Attachments).

## 확정 범위

- 현재 첨부를 지원하는 Home·Overview·캔버스 대화의 입력창에서 폴더를 첨부한다. 기존 터미널 세션 이어하기의 첨부 금지는 유지한다.
- Attach는 macOS 선택창에서 파일과 폴더를 선택한다. 경로 입력은 선택창의 ⌘⇧G를 사용한다. 별도 경로 입력 UI는 만들지 않는다.
- 폴더 드래그앤드롭과 Finder에서 복사한 폴더 붙여넣기도 같은 첨부 칩을 만든다.
- 프로젝트 밖 폴더도 허용한다. 파일·이미지·폴더 합계로 요청당 10개 제한을 유지한다.
- 폴더 내용을 복사하거나 묶어서 보내지 않고 경로를 전달한다. 첨부는 에이전트의 접근 권한을 자동으로 확장하지 않는다.
- 초안·보낸 메시지는 폴더 아이콘·이름·`Folder` 메타를 표시하고 크기는 표시하지 않는다. 경로는 툴팁으로 확인한다. 큐는 기존 행의 메시지 앞에 폴더 아이콘·이름을 인라인으로 표시하고, 여러 첨부는 첫 폴더 이름 뒤 `+N`으로 나머지 개수를 표시한다. 긴 이름과 메시지는 말줄임을 허용한다. 큐 요약의 툴팁과 접근성 설명에는 나머지 항목을 포함한 전체 첨부 이름·경로를 제공한다. 큐의 Send now·전체 삭제 버튼은 유지한다.

## 완료 조건

1. 세 입력창에서 Attach·드롭·붙여넣기로 내부·외부 폴더를 추가하고 제거할 수 있다.
2. 파일과 폴더가 섞인 요청의 한도를 동일하게 검사하며, 거부 시 기존 초안을 유지한다.
3. 전송 직전 사라지거나 다른 종류·다른 디렉터리로 교체된 폴더, 심볼릭 링크 대상이 바뀐 첨부는 거부하고 재첨부를 안내한다. 같은 폴더 안 파일의 추가·삭제·수정은 허용한다.
4. 지원하는 다섯 제공자에게 폴더 경로가 전달된다. 실제 읽기 성공 여부와 권한 거부는 별도로 검증한다.
5. 기존 제공자별 지원 범위의 큐·Send now·초안 복원·대화 재시작에서도 폴더가 파일이나 이미지로 바뀌지 않는다. Send now는 Claude Code·Codex만 지원한다.
6. 폴더만 첨부하고 본문 없이 보내면 기존 첨부 전용 고정 요청을 폴더에도 적용한다.
7. 칩 제거·전송 실패·큐 폐기·초안 복원·대화 삭제·앱 재시작 어느 경로에서도 원본 폴더와 내부 파일을 수정하거나 삭제하지 않는다.

## 상태와 복구

| 상태 | 표시와 동작 |
|---|---|
| 검사 중 | 칩에 `Checking`, 전송 비활성. 제거된 칩의 늦은 검사 결과로 칩을 되살리지 않는다 |
| 일부 추가 실패 | 실패 항목만 추가하지 않고 이유를 표시한다. 정상 첨부와 기존 초안은 유지한다 |
| 전송 직전 소실·교체 | 문제 칩과 초안을 유지하고 제거하거나 재첨부하도록 안내한다 |
| 선택창 취소·추가 완료 | 기존 Attach의 입력창 포커스 복귀 규칙을 유지한다 |
| 칩 제거 | ×는 다음 칩 또는 입력창으로, 빈 입력창의 Backspace는 입력창으로 포커스를 돌리고 제거를 알린다 |

## 비목표

폴더 재귀 복사, 압축, 업로드, 자동 내용 삽입, 프로젝트 등록, 권한 모드 변경은 하지 않는다.

# 폴더 첨부 작업

1번 기능이다. 뒤의 기능은 이 기능 문서의 완료 여부와 별도로 자기 결정을 확인한다.

## 검증표

| 대상 | 통과 조건 |
|---|---|
| Home·Overview·캔버스 대화 × Attach·드롭·Finder 붙여넣기 | 내부/외부·빈 폴더와 `.png` 이름의 폴더가 directory 칩으로 추가된다. 터미널 이어하기는 여전히 첨부를 받지 않는다 |
| 다섯 제공자 | 경로 전달, 실제 읽기, 권한 거부, 미검증 결과를 각각 기록한다. 전달 성공만으로 읽기 성공이라 하지 않는다 |
| 수락·정체성 | 소실·파일로 변경·다른 디렉터리 교체·링크 대상 변경을 거부하고, 하위 파일만 변경한 경우 수락한다 |
| 혼합 입력·전송 | 0/10/11개, 기존 첨부와 합산, 일부 실패, 큐 합산 한도, 폴더만 전송을 확인한다 |
| 수명·복원 | 제거·실패·큐 폐기·초안 복원·대화 삭제·재시작 후 원본이 보존되고 directory 종류가 유지된다. Claude/Codex Send now 거부 시 큐 복원도 확인한다 |
| UI·입력 | 초안/보낸 메시지 칩과 큐 인라인 표시·툴팁을 확인한다. 큐는 첫 폴더 이름·나머지 첨부 개수·긴 이름/메시지 말줄임에도 Send now·전체 삭제를 유지한다. 취소/완료 포커스, ×/Backspace, 검사 중 제거·늦은 응답을 확인한다. 실제 Finder probe 후 클립보드를 복원한다 |

## 작업 순서

- [ ] 1. 실제 선택창·Finder 입력·제공자 전달 PoC를 수행하고 위 검증표의 결과를 기록한다. 검증: 격리 환경에서 `DOAN_CLI=<abs path to doan> npm --prefix app run dev -- -- --user-data-dir=<tmp>`로 확인하며 AGENTS.md의 HOME·SHELL·에이전트 설정 격리와 `app/runtime/` 클립보드 보존을 적용한다.
- [ ] 2. `/feature-review` 후 UI 초안을 `/design-draft`로 확인하고 사용자 확인을 받는다. 검증: `doan check --repo . --json`, `doan ls --repo . --json`.
- [ ] 3. 기존 대화 기록 호환 fixture와 폴더 attachment 타입을 정하고 순수 함수 회귀 테스트를 작성한다. 검증: `npm --prefix app test`로 혼합 한도·표시·프롬프트·복원 사례를 확인한다.
- [ ] 4. main 검사·수락 재검사·제공자 전달과 세 입력창을 구현한다. 검증: `npm --prefix app test`와 짧은 실제 앱 probe로 검증표의 정체성·혼합 입력·원본 보존·복원·포커스를 확인한다. **구현 커밋 경계**.
- [ ] 5. 첫 구현의 `/design-sync`·`/runtime-test`·코드 검토 후 정적 게이트를 통과한다. 검증: `node .agents/skills/verify/scripts/verify.mjs`와 작업 1의 격리 앱 probe.
- [ ] 6. PRODUCT의 폴더 금지 규칙과 ARCHITECTURE의 첨부 형식을 구현된 현재 규칙으로 영문 갱신하고 이 기능 디렉터리를 삭제한다. 검증: 완료 조건별 증거와 남은 실제 제공자 검증을 대조한다. **문서별 커밋 경계**.

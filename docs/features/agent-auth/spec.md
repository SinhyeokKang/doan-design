# agent-auth — spec

작성: 2026-10-27. 상태: 기획 완료, 실인증 PoC와 구현 전 검토 필요.

## 목적과 사용자

도안 사용자가 앱에서 에이전트를 선택하고 로그인한다. 도안은 외부 터미널이나 Orca와 독립된 인증을 보관하고, 그 연결로 에이전트를 실행한다. 첫 사용자는 한 플랫폼만 연결하면 된다. 플랫폼마다 연결할 수 있는 계정은 하나이다.

에이전트에는 도안이 준비한 실행 환경과 도안 도구가 제공된다. 에이전트용 CLI 사용법이나 캔버스 작성 규칙을 바꾸는 기능은 아니다.

범위 근거: [PRODUCT §3](../../PRODUCT.md#3-scope)의 계획된 agent authentication과 [PoC 10](../../PRODUCT.md#6-pre-implementation-poc-2026-10-21). OAuth 범위는 이미 승인됐고 복수 계정과 GitHub 저장소 연동은 제외됐으므로 범위 게이트를 통과한다.

## 관찰한 문제

- 현재 대화 백엔드는 로그인 셸에서 찾은 Claude Code·Codex 프로필을 사용한다. 도안에서 로그인하거나 자체 연결을 해제하는 UI는 없다.
- 현재 온보딩의 Connect는 스킬·MCP 설정이다. 서비스 계정 로그인과 구분되지 않는 이름을 그대로 OAuth 완료 상태에 쓸 수 없다.
- 현재 세션 재개는 `configDir` 일치와 실제 대화 기록을 요구한다. 별도 인증을 만든다고 Orca 세션을 자동으로 이어갈 수 있는 상태가 되지는 않는다.
- PoC 10은 공식 문서 조사와 Claude 도움말·Codex 미인증 프로토콜 확인까지 완료했다. 다섯 플랫폼 모두 실제 로그인·갱신·로그아웃 격리의 합격 근거는 없다.

구현 근거: `app/src/main/onboarding/machine.ts`, `app/src/main/setupBroker.ts`, `app/src/main/conversation/{prepare,environment,store,runners}.ts`, `app/src/renderer/{Onboarding,ConnectionRows}.tsx`.

플랫폼의 지원 완료는 로그인 버튼이 존재한다는 뜻이 아니다. 전용 인증으로 요청을 실행하고, 권한 요청에 답하고, 중단하고, 재시작 후 같은 세션을 재개할 수 있어야 한다. 지원 플랫폼 수는 이 조건을 만족하는 구현과 실제 검증으로 센다. 기존 외부 세션의 별도 인증 인계는 이 조건에 포함하지 않는다.

다섯 후보 모두 조사하되 추가 후보의 실행 검증·구현은 정해진 순서로 진행한다. 공식 지원 경로가 있고 기존 실행 경계에 연결할 수 있으면 다섯 개까지 포함한다. 비공개 OAuth 클라이언트 복제, 토큰 추출, 인증 서비스의 역공학, 권한 확인을 없애는 실행, 별도 호스팅 서버가 필요하면 그 후보는 이번 범위에 넣지 않는다. 설치된 버전과 공식 문서가 충돌해도 우회하지 않는다. 문서화한 해결 경로가 없으면 미지원 사유와 후속 조건을 기록한다.

Cursor가 미달이면 Antigravity, 그다음 Copilot을 검증한다. Claude Code·Codex 중 하나라도 미달이거나 총 지원 수가 3개 미만이면 완료 처리하지 않는다. 하한을 충족해도 나머지 후보를 조사 없이 생략하지 않는다. 남은 후보의 과도한 비용 여부가 불분명하면 근거와 예상 작업을 사용자에게 제시한다.

## 사용자 흐름

온보딩 첫 단계에서 지원이 확정된 플랫폼을 표시한다. 사용자는 하나를 선택하고 Sign in을 누른다. 시스템 브라우저에서 공식 인증을 완료하면 도안이 계정을 확인하고 연결에 필요한 도구를 준비한다. 외부 브라우저에서 취소하거나 닫아도 도안에서 Cancel과 Retry를 사용할 수 있다. 다른 앱의 로그인은 그대로 둔다.

로컬 CLI가 없거나 검증되지 않은 버전이면 해당 원인과 설치·업데이트 안내를 보여준다. 이번 기능은 에이전트 설치 관리자를 만들지 않는다. 로그인 성공과 실제 실행 준비가 끝난 상태는 따로 표시한다. 토큰이 저장되지 않았거나 도구 준비가 실패한 경우 완료로 표시하지 않는다.

프로젝트는 기존 로컬 폴더 선택·초기화 흐름을 사용한다. 도안 CLI·스킬·MCP 준비는 독립된 필수 온보딩 단계에서 빼고 에이전트 연결 과정에 필요한 범위만 포함한다. 전역 PATH 링크나 셸 수정이 앱 내부 실행의 필수 조건이 되지 않도록 PoC에서 확인한다. 기존 외부 터미널용 설정·복구 기능은 Settings에서 유지한다.

Settings의 Connections에서 각 플랫폼의 계정, 상태, 다시 로그인, 로그아웃을 제공한다. 여러 계정 목록이나 계정 선택기는 없다. 계정 교체는 로그아웃 후 다시 로그인하는 순서이다. 사용 중인 실행이 있으면 먼저 중단하도록 안내하고, 실행 종료가 확인되기 전에는 인증을 바꾸지 않는다.

로그아웃은 도안의 연결을 해제한다. 원격 토큰 폐기까지 제공하는지는 플랫폼의 공식 수단과 PoC로 확정하고, 로컬 삭제만 했는데 서버에서 폐기했다고 표시하지 않는다. 기존 대화 기록은 삭제하지 않는다. 새 계정으로 이전 대화를 자동 실행하지 않는다. 같은 계정의 재로그인은 저장된 소유자와 세션을 검증한 뒤 재개한다.

## 화면과 상태

| 상태 | 화면의 행동 |
|---|---|
| 확인 중 | 이전 계정 표시를 유지하며 확인 중 표시. 실패를 미연결로 덮지 않는다 |
| 미연결 | Sign in |
| CLI 없음·버전 미지원 | 구체적인 설치·업데이트 안내와 다시 확인 |
| 브라우저 인증 대기 | 브라우저로 돌아가기, Cancel. 발급한 인증 요청의 만료를 처리한다 |
| 연결 준비 중 | 현재 작업과 실패 시 재시도 지점 표시 |
| 연결됨 | 확인한 계정과 플랫폼 표시, Sign out |
| 만료·폐기됨 | 다시 로그인. 입력 중인 첫 요청·메시지는 보존한다 |
| 네트워크·저장소 오류 | 원인과 Retry. 기존 자격 증명을 임의로 지우지 않는다 |
| 로그아웃 중·실패 | 완료까지 새 요청 차단. 실패를 성공으로 표시하지 않는다 |
| 기존 대화의 계정 불일치 | 기록은 읽을 수 있고 실행은 차단한다. 다른 계정으로 자동 재개하지 않는다 |

인증 대기는 취소 가능해야 한다. Close·Escape는 진행 중인 로그인 시도를 취소·정리한 뒤 온보딩을 닫는다. Cmd+W는 기존처럼 창을 숨기며, 앱 종료는 앱이 소유한 인증 프로세스·리스너를 정리한다. 다른 확인 다이얼로그가 열린 경우 그 다이얼로그가 먼저 키를 처리한다. 인증이 없는 상태에서도 온보딩을 건너뛰고 기존 캔버스를 볼 수 있다.

## 완료 조건

1. Claude Code·Codex와 추가 후보 하나 이상이 동일한 실인증 검증표를 통과한다. 나머지 후보도 포함 또는 연기 근거가 남는다.
2. 플랫폼별 도안 계정은 최대 하나이고 Orca·기본 CLI의 인증을 복사하거나 변경하지 않는다. 도안 로그아웃 전후 외부 계정이 그대로 동작함을 확인한다.
3. 로그인 성공·취소·만료·재시도·앱 종료·재시작·저장 실패를 처리한다. 토큰 갱신과 만료 후 복구는 실제 공급자 경로에서 확인한다.
4. 계정 교체·로그아웃과 실행 중 요청이 경쟁해도 이전 인증 결과가 새 상태를 덮거나 다른 계정으로 실행되지 않는다.
5. 각 지원 플랫폼에서 실제 도안 캔버스 생성, 권한 허용·거절, 중단, 앱 재시작 뒤 같은 세션 재개를 확인한다. 일반 사용자 대화 UI가 아직 없으면 격리한 preload 소비자로 검증한다.
6. 인증 값은 renderer, 일반 로그, 대화 기록, 저장소 파일에 들어가지 않는다. 공급자 런타임의 저장 방식과 예외는 숨기지 않고 검증표에 기록한다.
7. 기존 Claude·Codex 외부 세션 경로는 같은 프로필·기록·점유 확인을 유지한다. 새 도안 인증으로 자동 전환하지 않는다.
8. 공유 정적·단위·빌드 게이트와 변경 범위의 실제 앱 확인을 통과하고, 제품 결정·구조·측정 결과를 정본 문서에 승격한다.

## 비목표와 다른 feature의 책임

- 플랫폼별 복수 계정, 자동 계정 회전, 사용량 기반 자동 전환, API 키 입력, 자체 OAuth 서버, 계정 동기화.
- GitHub 저장소 목록·복제·push·PR, 기존 `gh` 토큰 가져오기. Copilot 사용에 필요한 GitHub 인증은 에이전트 인증에 한정한다.
- Orca 토큰 읽기·복사, 별도 인증으로 기존 외부 대화를 인계하는 기능, 서로 다른 플랫폼 사이의 대화 변환, 동일 세션 동시 쓰기.
- `buzz-onboarding`의 워드마크·배경·전체 리디자인, `buzz-settings`의 설정 창 전체 리디자인.
- `buzz-conversation`의 대화 패널·요소 피커·FirstPrompt Copy→Send. 이 기능은 실행·인증 계약을 제공하고, 첫 요청의 실제 전송 UI는 해당 feature가 맡는다. 그 전에는 기존 Copy 동작을 유지한다.
- CLI 자동 설치·번들링, 지원 버전 범위의 추정 확대, 캔버스 규칙·`doan check` 규칙 변경.

## 구현 전 남은 확인

사용자 제품 결정은 위 표로 정리됐다. 공급자별 인증 방식·저장소·갱신·필요 권한·정확한 실행 버전은 PoC 후 확정할 기술 조건이다. [작업 P](./tasks.md)의 근거가 없으면 해당 공급자의 구현을 시작하지 않는다.

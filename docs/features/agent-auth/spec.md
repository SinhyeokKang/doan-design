# agent-auth — spec

작성: 2026-10-27. 상태: 백엔드 범위 확정, 실인증 PoC와 구현 전 검토 필요.

## 목적과 사용자

도안 사용자가 앱에서 에이전트를 선택하고 로그인한다. 도안은 외부 터미널이나 Orca와 독립된 인증을 보관하고, 그 연결로 에이전트를 실행한다. 이번 feature는 OAuth 로그인·인증 보관과 새 대화·Canvas 대화가 같은 인증을 사용하는 백엔드 기반을 만든다. 로그인 화면을 포함한 UI는 후속 feature가 맡는다. 첫 사용자는 한 플랫폼만 연결하면 된다. 플랫폼마다 연결할 수 있는 계정은 하나이다.

에이전트에는 도안이 준비한 실행 환경과 도안 도구가 제공된다. 에이전트용 CLI 사용법이나 캔버스 작성 규칙을 바꾸는 기능은 아니다.

범위 근거: [PRODUCT §3](../../PRODUCT.md#3-scope)의 계획된 agent authentication과 [PoC 10](../../PRODUCT.md#6-pre-implementation-poc-2026-10-21). OAuth 범위는 이미 승인됐고 이번 feature에서는 복수 계정과 GitHub 저장소 연동을 제외하므로 범위 게이트를 통과한다.

## 관찰한 문제

- 현재 대화 백엔드는 로그인 셸에서 찾은 Claude Code·Codex 프로필을 사용한다. 도안에서 로그인하거나 자체 연결을 해제하는 UI는 없다.
- 현재 온보딩의 Connect는 스킬·MCP 설정이다. 서비스 계정 로그인과 구분되지 않는 이름을 그대로 OAuth 완료 상태에 쓸 수 없다.
- 현재 세션 재개는 `configDir` 일치와 실제 대화 기록을 요구한다. 별도 인증을 만든다고 Orca 세션을 자동으로 이어갈 수 있는 상태가 되지는 않는다.
- PoC 10은 공식 문서 조사와 Claude 도움말·Codex 미인증 프로토콜 확인까지 완료했다. 다섯 플랫폼 모두 실제 로그인·갱신·로그아웃 격리의 합격 근거는 없다.

구현 근거: `app/src/main/onboarding/machine.ts`, `app/src/main/setupBroker.ts`, `app/src/main/conversation/{prepare,environment,store,runners}.ts`, `app/src/renderer/{Onboarding,ConnectionRows}.tsx`.

플랫폼의 지원 완료는 로그인 버튼이 존재한다는 뜻이 아니다. 전용 인증으로 요청을 실행하고, 권한 요청에 답하고, 중단하고, 재시작 후 같은 세션을 재개할 수 있어야 한다. 지원 플랫폼 수는 이 조건을 만족하는 구현과 실제 검증으로 센다. 기존 외부 세션의 별도 인증 인계는 이 조건에 포함하지 않는다.

다섯 후보 모두 조사하되 추가 후보의 실행 검증·구현은 정해진 순서로 진행한다. 공식 지원 경로가 있고 기존 실행 경계에 연결할 수 있으면 다섯 개까지 포함한다. 비공개 OAuth 클라이언트 복제, 토큰 추출, 인증 서비스의 역공학, 권한 확인을 없애는 실행, 별도 호스팅 서버가 필요하면 그 후보는 이번 범위에 넣지 않는다. 설치된 버전과 공식 문서가 충돌해도 우회하지 않는다. 문서화한 해결 경로가 없으면 미지원 사유와 후속 조건을 기록한다.

Cursor가 미달이면 Antigravity, 그다음 Copilot을 검증한다. Claude Code·Codex 중 하나라도 미달이거나 총 지원 수가 3개 미만이면 완료 처리하지 않는다. 하한을 충족해도 나머지 후보를 조사 없이 생략하지 않는다. 남은 후보의 과도한 비용 여부가 불분명하면 근거와 예상 작업을 사용자에게 제시한다.

## 백엔드가 제공할 동작

후속 로그인 UI가 플랫폼을 지정하면 main이 공식 인증 경로를 시작하고 시스템 브라우저 왕복을 관리한다. 상태 조회·취소·재시도·재인증·로그아웃을 preload로 제공하며 토큰은 renderer에 넘기지 않는다. CLI 없음·버전 미지원·도구 준비 실패와 인증 실패를 구분한다. 저장과 실행 준비가 끝나기 전에는 실행 가능으로 응답하지 않는다.

새 대화 시작과 Canvas 안의 대화는 동일한 계정 연결·실행 준비 경로를 사용한다. 호출자는 프로젝트·대화·플랫폼 식별자를 넘기고 main이 해당 연결의 인증을 적용한다. 세션 재개는 계정뿐 아니라 프로필·실제 기록·점유 상태도 검사한다. 입력 UI·프로젝트 선택 UI·Send 동작은 구현하지 않는다.

로그아웃은 도안의 연결을 해제한다. 실행 중인 요청이 있으면 중단 필요 상태를 반환하고, 실행 종료가 확인되기 전에는 인증을 바꾸지 않는다. 원격 토큰 폐기 여부는 공식 수단과 PoC로 확정한다. 로컬 삭제만 했는데 서버에서 폐기했다고 응답하지 않는다. 기록은 보존하며 다른 계정으로 이전 대화를 자동 실행하지 않는다.

로그인 시도는 요청한 창과 시도 ID에 귀속한다. 명시적 취소·소유 창 종료·앱 종료 시 정리하고 늦은 결과를 차단한다. 짧은 저장 작업이 진행 중이면 정리가 끝나기 전 새 쓰기를 허용하지 않는다. 다른 창의 시도를 취소하지 않는다. 화면 이동·Escape·창 숨김의 UI 정책은 소비 feature가 이 계약에 맞춰 정한다.

인증 상태와 실행 준비 상태는 별도로 제공한다. 확인 오류가 기존 연결을 지우지 않고, 만료는 재인증 필요로, 저장·네트워크 오류는 재시도 가능한 오류로 구분한다. 로그아웃이 실패하면 새 실행을 차단하고 실패를 성공으로 표시하지 않는다.

## 완료 조건

1. Claude Code·Codex와 추가 후보 하나 이상이 동일한 실인증 검증표를 통과한다. 나머지 후보도 포함 또는 연기 근거가 남는다.
2. 플랫폼별 도안 계정은 최대 하나이고 Orca·기본 CLI의 인증을 복사하거나 변경하지 않는다. 도안 로그아웃 전후 외부 계정이 그대로 동작함을 확인한다.
3. 로그인 성공·취소·만료·재시도·앱 종료·재시작·저장 실패를 처리한다. 토큰 갱신과 만료 후 복구는 실제 공급자 경로에서 확인한다.
4. 계정 교체·로그아웃과 실행 중 요청이 경쟁해도 이전 인증 결과가 새 상태를 덮거나 다른 계정으로 실행되지 않는다.
5. 각 지원 플랫폼에서 실제 도안 캔버스 생성, 권한 허용·거절, 중단, 앱 재시작 뒤 같은 세션 재개를 확인한다. 새 대화와 Canvas 대화 경로 모두 격리한 preload 소비자로 검증한다.
6. 인증 값은 renderer, 일반 로그, 대화 기록, 저장소 파일에 들어가지 않는다. 공급자 런타임의 저장 방식과 예외는 숨기지 않고 검증표에 기록한다.
7. 기존 Claude·Codex 외부 세션 경로는 같은 프로필·기록·점유 확인을 유지한다. 새 도안 인증으로 자동 전환하지 않는다.
8. 공유 정적·단위·빌드 게이트와 변경 범위의 실제 앱 확인을 통과하고, 제품 결정·구조·검증 결과를 정본 문서에 승격한다.

## 비목표와 다른 feature의 책임

- 플랫폼별 복수 계정, 자동 계정 회전, 사용량 기반 자동 전환, API 키 입력, 자체 OAuth 서버, 계정 동기화.
- GitHub 저장소 목록·복제·push·PR, 기존 `gh` 토큰 가져오기. Copilot 사용에 필요한 GitHub 인증은 에이전트 인증에 한정한다.
- Orca 토큰 읽기·복사, 별도 인증으로 기존 외부 대화를 인계하는 기능, 서로 다른 플랫폼 사이의 대화 변환, 동일 세션 동시 쓰기.
- 로그인·온보딩·Settings·Home의 모든 UI. `buzz-onboarding`은 로그인 → 프로젝트 선택 → 홈 이동을, `buzz-home`은 프로젝트 선택을 포함한 대화 인풋창을 맡는다.
- `buzz-conversation`의 Canvas 대화 패널·요소 피커. 이번 feature는 이들 화면이 사용할 인증·실행 계약만 제공한다. 온보딩에 첫 요청 단계를 추가하지 않는다.
- CLI 자동 설치·번들링, 지원 버전 범위의 추정 확대, 캔버스 규칙·`doan check` 규칙 변경.

## 구현 전 남은 확인

사용자 제품 결정은 위 표로 정리됐다. 공급자별 인증 방식·저장소·갱신·필요 권한·정확한 실행 버전은 PoC 후 확정할 기술 조건이다. [작업 P](./tasks.md)의 근거가 없으면 해당 공급자의 구현을 시작하지 않는다.

## Canvas area and right panel

Reference: `.doan/canvases/doan-canvas.html` (17 frames; `conversation-menu` is a reference frame for the canvas conversation panel's menu and was not compared). Measured at 1238 × 780 and 960 × 600 (frames, and each tile of `states` and `agent-waiting`). The Hand tool, the tools' key tooltips and the drag layer were measured against `.doan/canvases/canvas-hand-tool.html` (6 frames) at 1280 × 800: no difference, 3 documented (below; the picking hint's hidden sentence is the third); the agent notice over the drag layer was checked with real Claude Code turns (hit-testing and clicks, not styles). States without a provider come from fixture projects in an isolated app (a real selection-lost notice, a real toast, a canvas busy for 20 s for Loading and the failed first layout, a missing project folder); the agent indicator comes from real Claude Code turns on the signed-in test profile, its canvas conversations started through the preload API (the app could not start one when this was measured). In the default state the development server and the production build matched every compared computed style within 0.5 px (one 0.28 px text-measurement margin), the production reading also holding a jump highlight left by the fixture. The overlay marks, the size bubble and the jump highlight follow `.doan/canvases/canvas-mark-accent.html` (frames `marks`, `bubble`, `jump`, `buddies`, `backgrounds`), measured at 2x: the implementation on a fixture canvas brought to each state for real (clicks, pointer hover, keyboard focus, `doan open --frame`, `doan work start/update`), each buddy through `<html data-buddy>` as `buddyPaint.ts` sets it; no difference, 4 documented (below: the bubble tooltip's two placement rows and the working marker's gradient and breathing glow).

The breadcrumb measurements use the six canvas-header frames of `.doan/canvases/header-breadcrumb-worktree.html`. For the canvas and Overview single-worktree menus, the fixture repository sits outside the isolated home directory. Both menus show its absolute path (`/private/tmp/…/single/acme-web`), while the draft shows `~/code/acme-web`. The row measures 270 × 50 px with either path.

### Documented deviations from the draft

- <a id="worktree-header-type"></a>**Inherited header type.** The header containers, icon buttons and worktree menu box inherit the app body’s 13 px font size and normal line height. The draft uses 14/20 px for these elements. Each visible text part sets its own typography and matches the draft.
- **Unavailable header.** In `canvas-header-unavailable`, hovering the switch on an unlisted page produced a 384 × 40 px tooltip. Its DOM reason and CDP description both read “Switching worktrees isn’t available on a page that isn’t a listed canvas.” The project-problem tile illustrates the other tooltip, but the live problem overlay covers an inert workspace. At the switch centre, hit-testing returned `.problem-overlay`, the switch had `aria-disabled="true"`, and its DOM reason read “Switching worktrees isn’t available while the canvas can’t be shown.” CDP reported `inertElement`, with no accessible description or pointer tooltip. A missing project folder supplies its folder name as the worktree label.
- **Header context.** The frame drawer includes the frame number (“1. Payment step”), adding 15.05 px to the draft label. At a header width of 875 px that much space comes from the project name. The live board supplies the zoom percentage, or an em dash when unavailable. The inspector takes disabled ink when the open conversation leaves too little room. The panel has square end corners next to a column. The shared portal centres tooltips on their triggers within the window. The highlighted destination can draw the shared 2 px inset focus outline. These differences preserve the frame drawer, inspector, panel and menu behavior measured elsewhere on this page.
- **Notice icon.** The draft draws the canvas notices without an icon; the app keeps the shared Notices rule, so each leads with the alert icon. The row stays 44 px.
- **Drawer scroll.** Opening the list centres the viewed row (the draft shows it at the top), and focus starts on it, so it takes the focus fill until the pointer or a key moves focus.
- **Top column.** The column is always in the page (empty when nothing shows) and passes the pointer through; it sets the notices' width, so a screen sets only margins on a notice (`ds/controls.test.ts`).
- **Handle cursor.** The hand-written handle sets `col-resize` itself; the draft leaves the cursor to a library.
- **Tool tooltip offset.** The shared tooltip sits 4 from its trigger ('Tooltip offset'), and the row's top edge is 5 above a tool (4 inset and the 1 px ring), so the tools' tooltips end 1 inside that edge; `canvas-hand-tool` draws a 4 px gap above the row.
- **Hand cursors.** `canvas-hand-tool` draws grab and grabbing as illustrations; the app sets CSS `grab` and `grabbing` on the drag layer.
- **Overlay marks.** For the selection, hover, dimension and jump highlight look the reference is `canvas-mark-accent.html`, not `doan-canvas.html`, which is kept as history.
- **Mark box.** `canvas-mark-accent` draws each mark as a border box grown by its line; the app keeps the element's rect as the padding box (`content-box` with a negative margin), so the placement code is unchanged. The outer boxes measured equal.
- **Bubble tooltip.** The draft's tooltip capsules are placed by hand (3.5 above the button); the app's is the shared tooltip, 4 above and centred (measured 4.06 and −0.24: floating-ui rounds to device pixels).
- **Working marker gradient and glow.** `canvas-mark-accent` draws the working marker with the plain jump gradient and a still glow; the app keeps its travelling gradient and breathing glow ('Work updates on the canvas'), as the draft's notes say its CSS is unchanged.
- Context, not deviations: tabular figures inherited by containers; fixture names, provider wording (Claude Code for the draft's Codex) and percentages; animation phases; state tiles the draft draws at 420 × 320.

## Work updates on the canvas

Reference: `.doan/canvases/work-update.html` (6 frames: `notice-states`, `notice-typing`, `marker-states`, `marker-moves`, `follow`, `reduced-motion`). Built app at 1238 × 780: the draft read in the app's canvas iframe, the implementation on a fixture canvas whose frames match the draft's tiles (160 × 200 at scale 1), driven by a real `doan work start/update/done` against the isolated runtime. App conversation states (a project conversation naming the canvas, this canvas's own conversation working and waiting) were injected through main's conversation-list and conversation-work channels. Every difference is either listed under 'Documented differences from the draft' or is one of these: context (positions on a different stage; the hover mark wrapping a different element; the hidden status's static position), animation phase at the moment of reading (dot scale, caret blink step, glow alpha), the draft's own keyframe names, the shared tooltip's open animation and layer, the shipped selection size label, reduced-motion states the draft tiles draw without reduced motion (dot, caret), and transitions of 0 s on both sides. The behaviour checks in the same window passed.

### Documented differences from the draft

- **Viewer font and text widths.** The draft draws the recipient's system face; the page draws the embedded Geist ('Canvas row menu and export viewer' 'Viewer font'). Text-sized widths move with the face, such as the bubble's size text, and have not been measured against the draft with Geist.
- **Frame trigger gap.** The draft's trigger is the design system's `sm` button with an 8px gap; the page keeps the app's title trigger, 6px ('Viewer header').
- **Selection mark.** The draft draws a scaled mock frame with an accent outline; the page's mark is the inspector's 1.5px accent border ('Canvas inspector').
- **Empty canvas.** The draft's `frame-drawer` sample opens a list with one disabled "No frames" row; the page, like the app's main header (`frameDrawer.ts`), turns the trigger off and has it read "No frames" ('No frames' above).
- **Unavailable Play's reason.** The draft prints the reason as a line beside the button; the page shows the same text as Play's tooltip and description, as the app does ('Prototype links' 'Description in every state').
- **Playing row focus.** The draft's static rows are unfocused; the page focuses the playing row as the drawer opens, as the app's drawer does, so it shows the inset ring.
- **Construction.** The draft insets its panel with absolute positioning and paints its header transparent on the white panel; the page uses the margins and the white header of 'Viewer panel' and 'Viewer header'. The fixture's frame count makes the drawers taller than the draft's examples (bottom-anchored, so the play drawer's top moves).

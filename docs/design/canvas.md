## Canvas area and right panel

Reference: `.doan/canvases/doan-canvas.html` (17 frames; `conversation-menu` is a reference frame for the canvas conversation panel's menu and was not compared). Measured at 1238 × 780 and 960 × 600 (frames, and each tile of `states` and `agent-waiting`). The Hand tool, the tools' key tooltips and the drag layer were measured against `.doan/canvases/canvas-hand-tool.html` (6 frames) at 1280 × 800: no difference, 3 documented (below; the picking hint's hidden sentence is the third); the agent notice over the drag layer was checked with real Claude Code turns (hit-testing and clicks, not styles). States without a provider come from fixture projects in an isolated app (a real selection-lost notice, a real toast, a canvas busy for 20 s for Loading and the failed first layout, a missing project folder); the agent indicator comes from real Claude Code turns on the signed-in test profile, its canvas conversations started through the preload API (the app could not start one when this was measured). In the default state the development server and the production build matched every compared computed style within 0.5 px (one 0.28 px text-measurement margin), the production reading also holding a jump highlight left by the fixture. The overlay marks, the size bubble and the jump highlight follow `.doan/canvases/canvas-mark-accent.html` (frames `marks`, `bubble`, `jump`, `buddies`, `backgrounds`), measured at 2x: the implementation on a fixture canvas brought to each state for real (clicks, pointer hover, keyboard focus, `doan open --frame`, `doan work start/update`), each buddy through `<html data-buddy>` as `buddyPaint.ts` sets it; no difference, 4 documented (below: the bubble tooltip's two placement rows and the working marker's gradient and breathing glow).

### Documented deviations from the draft

- **Notice icon.** The draft draws the canvas notices without an icon; the app keeps the shared Notices rule, so each leads with the alert icon. The row stays 44 px.
- **Drawer scroll.** Opening the list centres the viewed row (the draft shows it at the top), and focus starts on it, so it takes the focus fill until the pointer or a key moves focus.
- **Top column.** The column is always in the page (empty when nothing shows) and passes the pointer through; it sets the notices' width, so a screen sets only margins on a notice (`ds/controls.test.ts`).
- **Handle cursor.** The hand-written handle sets `col-resize` itself; the draft leaves the cursor to a library.
- **Tool tooltip offset.** The shared tooltip sits 4 from its trigger ('Tooltip offset'), and the row's top edge is 5 above a tool (4 inset and the 1 px ring), so the tools' tooltips end 1 inside that edge; `canvas-hand-tool` draws a 4 px gap above the row.
- **Hand cursors.** `canvas-hand-tool` draws grab and grabbing as illustrations; the app sets CSS `grab` and `grabbing` on the drag layer.
- **Overlay marks.** For the selection, hover, dimension and jump highlight look the reference is `canvas-mark-accent.html`, not `doan-canvas.html`, which is kept as history.
- **Mark box.** `canvas-mark-accent` draws each mark as a border box grown by its line; the app keeps the element's rect as the padding box (`content-box` with a negative margin), so the placement code is unchanged. The outer boxes measured equal.
- **Bubble tooltip.** The draft's tooltip capsules are placed by hand (3.5 above the button); the app's is the shared tooltip, 4 above and centred (measured 4.06 and −0.24: floating-ui rounds to device pixels).
- **Working marker gradient and glow.** `canvas-mark-accent` draws the working marker with the plain jump gradient and a still glow; the app keeps its travelling gradient and breathing glow ('Work updates on the canvas'), as the draft's notes say its CSS is unchanged.
- Context, not deviations: tabular figures inherited by containers; fixture names, provider wording (Claude Code for the draft's Codex) and percentages; animation phases; state tiles the draft draws at 420 × 320.

### Documented differences from the draft

- **Slide timing.** The draft keeps the slide transition on the marker at all times; the app applies it only for the 220 ms after the working frame changes, because the marker is re-placed in screen px on every view change and a standing transition would make it trail the board.
- **Marker layer.** The draft orders the marks by DOM order; the app puts the marker at `z-index: -1` inside the overlay, because it appends marks in any order. The visible result is the same: selection and hover draw on top.
- **Width floor.** The draft's static tiles draw the floor as a hidden copy of the shorter text; the app's floor adds the caret and its gap, so the card does not grow by 4 px when the change ends.
- **Status with a frame.** Draft tiles with a marker show the note alone in their status; the app's status adds " — <frame title>" when the update has both a note and a frame, so a screen reader hears where the agent works.

### Not verified

- The composer and conversation menus (`role="menu"`) were not opened; the zoom menu exercises the same selector part. Dialogs other than Quick Open were not opened.

### Documented differences from the draft

- **Menu fill.** The draft's menu is the translucent glass `rgba(255,255,255,0.9)`; the app's is opaque white through `shell-side-menu`, because the window's native vibrancy gives a web backdrop-filter nothing to blur (decided with the sidebar menus; the shipped project menu is the same). The class list also lacks the draft's `shell-project-menu` (its focus-return effect keys on it); `shell-canvas-menu` repeats the four rules.
- **Keyboard ring on a menu item.** The app's shared menu item paints a 2px inset ring on the focused item; the draft draws the highlight fill alone. Opened from the keyboard, the first item is focused; the draft's unreadable-row and exporting menus highlight Move to Trash, which the real menu reaches with one arrow from the unavailable Export….
- **Placement.** The draft hangs menus on their tile and draws the dialog static in a scrim and toasts absolutely in a stage; the app uses Radix's popper, the top layer and a fixed toast. Position, margins and z-index are not compared.
- **Icon-only button tracking.** The app's `button { font: inherit }` reset lets the row button inherit −0.035px letter-spacing; the draft's button shows `normal`. There is no text to space.
- **Fixture names wrap.** A temp canvas needs a unique name, so a toast can wrap one line differently from the draft's "checkout". With the draft's words in the real toast the heights match (probe).
- **Viewer font.** The viewer bundles no Geist (about 93 KB per file), so its chrome falls to the system stack the token names. Computed `font-family` is the same string; the rendered face and every text-sized width (name, trigger, zoom keys, drawer names) differ and are not equality claims. Icon-only parts and the fixed widths (32px buttons, 72px value, 320px drawer, 184px menu) match.
- **Viewer, `/` separator.** `.ov-sep` is `display: flex` where the draft's blockified span computes `block`; a text-only span lays out the same, and a test pins the shared `display: flex` rule.
- **Viewer board.** The draft paints the inset grey on its `.vw` tile and leaves `.vw-board` transparent; the page paints it on `#board`. The draft's viewed row is a fixed example (frame 1); the page marks the frame nearest the board's centre.
- **Viewer tile.** The draft's `.vw` tile carries the panel shadow and, as a grid item, `min-width`/`min-height: auto`; the page's `body` has no shadow and computes 0px. The panel's `min-width: 0` is the app's panel rule; the draft leaves `auto`. Neither changes the measured boxes.
- **Viewer header stacking.** The page's header is `position: relative` with z-index 5 so the Frames and zoom menus open over the tools row and its tooltip (in a short window an open Frames list reaches them); the draft draws no open menu and leaves the header static.
- **Viewer tooltip placement.** The page places its one tooltip from the tool's box (`top` and `translate(-50%, -100%)`) where the draft uses CSS `bottom` and `translateX(-50%)`; the measured gap (4) and centring (0) are equal. The tooltip has `pointer-events: none`: it closes when the pointer leaves its tool, and should not take a press just above the tool from the board.
- **Viewer text widths.** As 'Viewer font': the name, the frame trigger, the zoom value, the auto margin before the zoom controls and the tooltip's width move with the system face (in Chromium the tooltip is 74.8 against the draft's 80.3).
- **Fixed in the implementation.** Three viewer rules the measurement caught: the zoom value lost its 72px minimum and 4px gap to `.doan-button`'s later one-class rule; the body lacked the app's tabular digits; buttons kept `border-style: solid` (width 0).

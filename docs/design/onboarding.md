# Design measurements — Onboarding and adding projects

> Part of [DESIGN.md](../DESIGN.md), which holds the evidence and verification policy, the design system and the index of every screen section.

## Onboarding

Reference: `.doan/canvases/doan-onboarding.html`, 73 full-window frames at 1238 × 780 with the first-run chrome and stepper: Welcome, 40 Agent states and 32 Project states. Each frame's markup is the real components (`Welcome`, `SetupSteps`, `AgentStep`, `ProjectScreen`) rendered with controlled props, and the onboarding rules of `styles.css` are copied into the canvas verbatim next to the linked `tokens.css` and `ds/index.css`. Because the frames copy the code, they check the copy, not the design; the measured contracts below come from a `/design-sync` run against the approved tile draft. Welcome follows `.doan/canvases/buddy-welcome.html` frames `bleed-bottom-780` and `bleed-bottom-600` instead, and the Buddy step and the buddy screen follow `.doan/canvases/buddy-choice.html` (see Buddy step and buddy screen). doan-onboarding's Welcome frame and stepper draw an outdated Welcome (no photo) and two steps; they are not the reference for either. The Project step's notices, their actions, the Add Projects page's footer and the intermediate buttons' size follow `.doan/canvases/new-project-folder.html` (frames `card-busy` and `shipped-notices-*`, see Add Projects page 'Project step notices and Add project'); doan-onboarding's and doan-add-projects' Project frames no longer match the code there.

- Canvas-only parts: the wallpaper and glass behind Agent and Project (not a native measurement), schematic traffic lights, modals drawn in place over a scrim, and dialogs without `autofocus` so the canvas does not scroll on load. Announcements and focus moves are in the captions.
- Every frame is 1238 × 780 with no horizontal overflow; its `data-doan-id` values are unique. Every Agent and Project frame's markup placed in the running app's onboarding overlay (dialogs opened by `showModal()`) had no computed-style or box difference from the canvas when measured with the two-step stepper. The scene scrolls at 780px in 33 frames, as in the app; their captions say so.

### Behaviour and copy beyond the measured draft

Frame ids name the canvas frames that draw each state.

- **'Your projects'** (`project-your-projects`, `project-your-projects-selected`). When projects are registered, they are listed above the local folder card under the caption 'Your projects', as choice cards with the project thumbnail, followed by an sm Use this folder.
- **Choice cards instead of radio rows.** Used for 'Your projects' and for repositories found inside a picked folder (`project-repositories-in-folder`), both with the project thumbnail. A native radio still sits in each card, so the arrows and Space work, and Enter also picks. The card draws a 2px `--border-focus` outline, offset 2px, while its radio has keyboard focus.
- **No checkout choice on the URL path.** When a GitHub URL matches several local checkouts or worktrees, the app does not show 'Multiple local checkouts'. It picks one and shows it as the single 'Already on your Mac' card, with Choose another folder and Edit repository URL.
  - Pick order: a checkout that needs no setup; then the main checkout, whose `.git` is the common directory, read from the folder list's git facts without running git; then the most recently registered project.
  - If the picked checkout needs setup (`repository-found-setup`), the setup screen keeps the URL context: the 'Already on your Mac' heading, the read-only URL, Choose another folder (remote check) and Edit repository URL; Back returns to the editable URL.
  - Other worktrees are switched to later from the shell project card's Worktrees menu.
  - `onboarding project inspect` (CLI) still returns every candidate.
- **Clone destination default** (`repository-clone`): `<parent of the most recently registered project>/<repository>`, else `~/<repository>`. Change picks a parent.
- **Copy outside the measured draft** (`agent-install-page-failed`, `agent-paste-too-long`, `repository-cleanup-failed`):
  - Install and Update failures are row notices. When Terminal cannot open: "Couldn’t open Terminal to install <Provider>. Open the install page to install it yourself." (update: "to update <Provider>", "to update it yourself") with Open install page. When the install page cannot open: "Couldn’t open the <Provider> install page." Antigravity has no install page.
  - After Terminal opens, the row's helper reads "Terminal is open with the install command. Press Return there, then come back to Doan." (update: "update command"); the install page path keeps the before-click helper.
  - A paste over 16,384 characters shows "This address is too long to submit." as the shared inline error (`settings-msg error`: the 16 px alert icon, body-sm `--text-danger`) 8px under the field, in one group with it (`.field-group`).
- **Paste dialog while submitting.** The field turns read-only (not disabled), Cancel takes the disabled look (`aria-disabled`, `data-disabled`) and Escape is refused, and Submit keeps its fill with the 14 px in-button spinner, `aria-busy` and `aria-disabled`, so focus stays where Enter or the press left it. Not checked in the real app (it needs a provider sign-in that asks for a pasted address); pinned by markup tests.
  - Main's fixed messages are shown for refusals without draft copy, for example a kept clone folder: "Couldn’t remove <path>. Remove it, then try again."
- **Cancelled and failed clone** (`repository-cancelled`, `repository-clone-failed`). The cancelled clone's notice holds Choose local folder and, in first run, Retry (the page's Add project clones again, so its notice drops Retry); an sm subtle Edit repository URL sits under it. Back from a cancelled or failed clone returns to the editable URL and drops the old inspection; otherwise Back→Continue would bring the same clone screen back with no way to change the URL. "Cloning was cancelled" is a role=status notice panel (`doan-notice doan-panel ob-project-notice`, alert icon in the text ink), not plain help text.
- **Folder inspection progress** (`project-checking-folder`). Inspecting a picked or listed folder shows "Checking this folder" with the path (role=status). Nothing is written then; the 'Setting up your project' progress is kept for the select that writes.
- **Clone destination inside a Doan project** (`repository-inside-project`). Main refuses it as `path_unavailable`. When the destination sits under a registered project, the clone screen says "This location is inside the Doan project <name>. Choose a location outside it." with Change location (prominent). Otherwise the generic 'no longer available' notice stays, because the renderer cannot name an unregistered project.
- **Focus.** Edit repository URL and Back from a cancelled or failed clone move focus to the URL field. A failure after a folder sheet (Choose folder, Change, Choose existing folder) or after a Doan files radio's new plan moves focus to its notice; a sheet closed without a new failure returns focus to the button that opened it, and a sheet opened from a notice's own button returns there while that notice stays (else, on the choose screen, to the card's New folder for New folder's notices and to Choose folder for the rest).
- **Notice slots on the choose screen.** A folder's failure (Choose folder, New folder, a drop, first run's 'Your projects') sits under the local folder card, in the drop notice's slot; the drop notice and a folder's failure replace each other. A URL's failure stays after the URL field.
- **Existing folder from the URL path** (`repository-mismatch`). Every folder action on the URL screens sends the folder together with the repository URL, so main checks its remote: Choose existing folder, Use existing folder, Choose another folder, and the notices' Choose folder / Choose another folder / Choose local folder recoveries. A mismatch stays on that screen, its notice holding Edit repository URL and Choose another folder at one weight; on a cancelled clone's screen a folder's failure replaces the cancelled status notice. On both URL screens a mismatch reads "<folder name> belongs to a different repository.", so on the clone screen it is not read as the destination; without a known folder it keeps "This folder …".
- **A notice's actions are never repeated beside it.** When a Project notice offers an action, the screen hides its own copy of it, and Use existing folder counts as Choose existing folder:
  - 'No agent is ready' (`project-no-agent`) offers only Back to agents; the screen keeps its Choose another folder.
  - On the clone screen, the destination card's Change is hidden while a notice offers Change location (`repository-destination-exists`, `repository-inside-project`, `repository-clone-failed`). 'Already have this repository?' and its Choose existing folder are hidden when the notice offers Choose another folder or Use existing folder (`repository-mismatch`, `repository-destination-exists`). Edit repository URL stays unless the notice offers it too, as the mismatch does.
  - The same holds on the found and folder screens (a URL setup that failed keeps only Edit repository URL below its notice). Cleanup failed (`repository-cleanup-failed`) offers only Retry, so nothing is hidden there.
- **Subtle buttons on the Agent/Project glass.** A subtle button standing directly on the glass takes the step capsule's `--affordance-backdrop-hover` fill, because mid-window the glass is about the colour of `--affordance-subtle` (#f5f5f6) and the button looked unfilled. Buttons inside panels and dialogs, the Welcome surface, and the DS hover, pressed and disabled fills are unchanged. Checked only on the canvas glass in headless Chromium; the native vibrancy is not measured.

### Documented differences from `buddy-welcome`

- **Window, not a card.** The frame is a card; the app's Welcome is the full-window modal `<dialog>` (`position: fixed`, radius 0, no shadow; the native window supplies its corners).
- **Font stack.** The frame shortens the family to `Geist, sans-serif`; the app keeps `--type-family`. Size, weight, line height and tracking are equal.
- **Get started icon.** The frame draws a 20px arrow; the app keeps the shared `lg` button's 16px icon, so the button is 4px narrower. Size and style of the words and the button stay the shipped ones.
- **Photo blend.** The frame draws the photo with `multiply`; the app does not, because the photo's backdrop is white.
- **Taller windows.** The frames are 780 and 600 high; the photo's growth past them, its 1.4 × width cap and the bottom anchor are the app's (Welcome photo).

### Limits and regression pointers

- Markup runs prove the CSS against chosen props only. They do not prove that `ProjectStepSession` reaches those states (its unit tests do), and they do not show live focus. Notice spacing inside Project screens was checked only on the repository-error frame.
- Not measured: the native vibrancy material itself, reduced transparency and forced colours (DOM screenshots show the transparent overlay as white); hover and focus rings of the onboarding controls; real sign-in, the real paste and stop dialogs as modals (measured as open dialogs in a column). The Project step was reached in the real app only with a forged ready-agent snapshot (scroll container, card drop, cloning line against a local git server).
- Welcome's layout and focus order were measured in the built app; `Onboarding.test.tsx` and `Welcome.test.tsx` pin the Welcome markup order (wordmark, sentence, Get started, photo) and CSS, and `openOverlay` focusing the heading right after `showModal()`, and `onboardingView.test.ts` the DOM-order Tab rule. The overlay always opens on Welcome (`initialScene(false)`).
- The buddy picker: `BuddyPicker.test.tsx` (markup, keys, the short-window rule), `coverFlow.test.ts` (offsets, scroll position, follow and snap), `buddyChoice.test.ts` (Continue waiting for a save), `ds/checks.test.ts` (the chosen card as an Accent place). Not pinned: that the `[data-o]` CSS and `cardLayout`'s steps agree, and the buddy screen's focus after Continue on Home.
- Regression tests (`app/src/renderer/Onboarding.test.tsx`, `ds/controls.test.ts`, `ShellSidebar.test.tsx`) pin the stepper markup and capsule rule, the overlay's `font-variant-numeric: normal` (fails when the declaration is removed) and the paste help ink; the `lg`, notice-on-panel and thumbnail rules; and the markup of every Project phase.

### Behaviour and copy

- **`~/…` paths.** Recovery text and the worktree menu abbreviate paths under the HOME value supplied by main as `~/…`. Matching is boundary-aware; other roots remain absolute, and full-path tooltips keep the original path. Main prefers its process HOME, with Electron's home path as fallback, so isolated development runs do not use the machine user's home.
- **Recovery copy and Locate.** Locate on a loaded workspace keeps that workspace visible while main replaces its root; the renderer waits for the located root's list before opening its canvas, and a located root that is still a problem shows its overlay. The overlay's heading and line are the recovery copy (`problemView.ts`); the labels are Locate, Set up, Retry, Show in Finder, Details and Remove from Doan, with no trailing ellipsis.

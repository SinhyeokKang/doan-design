## Home

Reference: `.doan/canvases/doan-home.html` (30 frames); Doany and the stage's vertical layout follow `.doan/canvases/doan-mascot.html` frame `doany-v2-home` (layout shared with V1's `mascot-home`). `.doan/canvases/buddy-home.html` draws Home with each buddy and its accent; it was not measured by `/design-sync`. ### Documented differences

- **Status chips in menus.** The draft's project and worktree menus use `.ob-chip`, which the canvas does not style, so its chips render as plain gray text. The implementation uses the shipped status chip (Missing `warn`, Not set up neutral) at its content width: caption 12/16, 20 high, padding 0 / 8, pill radius; in the worktree menu Not set up is 74.9 px and Missing 59.4 px wide, flush with the row's end (measured). The Project Overview's worktree menu draws the same chip.
- **Pickers while sending.** The implementation disables every picker and chip × while a start is pending (the draft leaves the project and worktree triggers enabled-looking): a changed target cannot apply to a start already sent.
- **No projects.** Model lists are read per project root, so with no project the picker shows "Model" and no effort capsule (the draft shows "Opus 5.5 · High").
- **Strip width.** The workspace's right panel takes 280 px, so the strip is 650 px wide (the draft omits the right panel: 930 px). The strip shows only while the problem or reading overlay covers the workspace, above it and uncovered, without its Open; otherwise the Overview and the canvas page show conversations themselves.
- **Menu placement.** Menus open from their own trigger (Radix, `align` start or end, 4 or 8 px offset). The draft places the agent and effort menus at one fixed spot 40 px inside the tool row's right edge, so the agent picker sits 85 px further left in the app (right edge at its trigger) while the effort menu is within 4 px; the project and worktree menus are within 8 px. The composer, card and tray positions match the draft at both window sizes.
- **Trigger pressed.** A Radix menu trigger opens on pointerdown, so a pressed trigger shows the open fill (`--affordance-backdrop-hover`); the pressed fill applies only without a menu.
- **Stage position (doan-mascot).** The draft centres the stage with `justify-content: center` and a fixed bottom padding of 160 (32 + 128), so at 780 its group top is 57.4 like the app's; elsewhere its offset is fixed and a short panel scrolls by 128 px of empty padding. The app sets a computed top inset and a 32 bottom padding instead (see 'Stage position').
- **Greeting.** Home shows one of its fixed questions, picked per visit, where the draft has "What should we design today?"; the greeting's width and x follow the text, and its y and every other box of the group equal the draft's.
- **Kept suggestion space.** The draft's demo removes the suggestions while typing; the app keeps their place so typing does not move the group.
- **Stage children shrink.** The draft gives the stage's children `flex-shrink: 0`; the app's stage has an automatic height (`min-height: 100%`), so they never shrink: the group is 473.2 high at 600, 780 and 1240.
- **Doany is `type="button"`.** Not in the draft; it keeps Doany from submitting a form.
- **Still image `max-width: 100%`.** The app's base styles cap images at their container; the still is `width: 100%` already, so its box (114 square with 20% padding) equals the draft's, measured with it shown on both sides.
- **Context, not deviations.** The draft's placeholder drawn as text, caret-mock line heights, the draft's fixed sample text, highlighted first menu rows, spinner boxes while rotating, and the sidebar row's inherited ink.
- **Conversation primitives board.** `.doan/canvases/doan-conversation.html` frame `hero-composer` redraws this composer as the regression reference for its rebuild from the shared primitives. Measured against it at 1238 × 780 (the focused empty composer and the running reason line): beyond the context listed above, the implementation equals the board except these.
  - **Reason-line Open stays `subtle`.** The board draws Open as `panel` (white fill); Home keeps `subtle` (rgb(245,245,246)): on Home the reason line changes only its wording and Open's name, not how it looks. Both name it "Open the running conversation".
  - **Model label 0.73 px narrower.** The app body's tabular figures reach the agent trigger's label, so "Opus 5.5" is 57.13 px wide instead of the board's 57.85 and the trigger 117.13 instead of 117.85. Font family, size, weight, tracking, kerning and smoothing are equal; the same text in a bare span is 57.85 in both documents, and 57.13 in both with `tabular-nums`. The shipped Home had the same width before the rebuild.
  - **Board context.** The board's tile makes the composer 720 px wide (Home: `min(680, 100%)`), draws its placeholder as text where the app's field draws its `aria-placeholder` with `::before`, and leaves out the reason line's `role="status"`, the buttons' `type`, popup and tooltip attributes, the field's `contenteditable` and `tabindex`, and the icons' SVG attributes.

### Limits

- Strip, sidebar slots and Edit on Home come from main's conversation list. After a reload or restart the strip shows only conversations with work left (running, waiting, an unseen end, a crash-folded turn as stopped); a failed or stopped conversation already seen through a visit is not shown again, so Edit on Home is not reachable for it (PRODUCT §5 item 1). Reload, restart, crash folding and Edit on Home with a missing attachment were reached with real Claude Code runs.
- A start can wait for its runner (Antigravity's first download included) and has no cancel while pending.
- A pasted image or text stays under `<userData>/attachments/` until the next start when it was not sent.
- After a permission answer focus goes to Stop. When a turn ends while Stop holds focus (a Copilot Deny was seen to end it in about 300 ms; a stop or a send's arrival focus can do the same), Stop goes away and focus moves to Dismiss instead of falling to the page. Focus the person moved elsewhere stays there; the strip is keyed by its conversation, so another project's strip starts fresh.
- Not verified: preset list loading, CLI timeout and refused; the older-CLI tile (unit tests only); the agent board row for an unverified provider; attachment checking, pasted image, more than 10 files, over 50 MB and folder-drop notices (they share the measured notice); strip starting, done and not_logged_in tiles; a slot on a bound canvas row; reasons 'project unhealthy', 'agent can't run' and 'checking'.

### Doany motion in the app

Checked in the built, packaged and development (`StrictMode`) apps with a probe that records each frame's uniforms:

- Loading: the still PNG with no `data-state`, then the canvas and `idle` (packaged: textures from `app.asar` file URLs).
- A click, Enter or Space hops once: one beret impulse of about −0.81 (one `hatV -= .9`), and Enter or Space dispatches no button click. A held key hops once: key repeats are ignored (unlike the draft), so the beret stays inside the canvas. Typing gives `attentive`.
- A Send, submit key or notice Retry that starts a send hops once; a disabled Send or an empty submit key neither hops nor starts.
- A notice Retry keeps its notice while the send it started is out, busy (spinner, `aria-busy`, `aria-disabled`) and described by the notice text; the reply then clears it or replaces it. The docked composer's notice Retry does the same. Unit tests only, not a real-app probe.
- Reduced motion: `reduced-motion`, a click neither hops nor draws, the field still takes input, and switching it off returns to `idle`.
- Behind the first-run Welcome, Home's Doany draws no frame and its canvas pixels do not change.
- 24 Home visits leave no "Too many active WebGL contexts" warning, and the last Doany still draws; a control that leaks 20 contexts does print it.
- V2 (Pebble) in the built, packaged and StrictMode apps: the gaze follows the pointer to ±.99; a lost context or a failed texture leaves the still; packaged images load from `app.asar/out/renderer/doany/` and `icon.icns` is V2.
- Every buddy: a fur lid blinks over the shared eye bead for 420 ms every 4–8 s (`doanyMotion.test.ts` blink scenario); Home recorded beside the `buddy-assets.html` motion preview for all five buddies (eyes, blink, hop shadow) was judged the same by the maintainer; at the hop's apex the floor shadow measured scale .550 and opacity .400, and `--hop-lift` returns to 0 on landing.
- Not verified in the app: sustained frame rate beyond an 8 s idle sample (60 fps) and the bounded hop's apex by eye (the bound is checked by the unit model).

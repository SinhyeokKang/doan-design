### Behaviour beyond the measured draft

- Click, Space and Return open the popover and focus the list. Escape closes it and focus returns to the button; on Settings the page stays. One Escape also closes it while a title-row button's tooltip shows (the tooltip passes its Escape on, as conversation-delete's Delete tooltip does).
- An outside press closes it. Focus returns to the button when the press left focus on `<body>` (a blank part of the window), without opening the button's tooltip; a press that focused a control keeps it there, and a press in the canvas keeps focus in the canvas. Radix's non-modal popover alone returned focus only when nothing was pressed outside, and focus handed back after a press opened the tooltip under the button. Escape's return still shows the tooltip, as the shared tooltip does on keyboard focus.
- When the last provider leaves while it is open, it closes and focus goes to the header's current tab.

### Documented differences from the draft

- **Edge-values tile.** The draft draws Cursor above Claude Code there, against its own fixed order; in the app Claude Code comes first, so the 1 px rule moves to the other row (row heights 97/128 against 96/129).
- **Placement.** The button's `margin-left` is `auto` in the draft's flex row and 0 in the app; the box lands at the same x. The popover's `z-index` is the shared popper layer's 50.
- **Can't-be-used wording.** The draft's reason line and button description for a connection that can't be used are its own sentences ("Claude Code’s sign-in expired.", frame `ring-states` and `popover`); the app uses the same line as that connection's Settings > Agents row (`connectionLine` in `agentAuthView.ts`), with the provider's name leading the description when the line lacks it. The blocked tiles above were measured with the earlier wording; re-measure them at the next `/design-sync` of this screen.

- Real limit reached, unlimited, not supported, no plan limits and the Claude Code / Codex can't-be-used causes: no signed-in account produced them; they were sent to the window by the probe. A real sign-out or sign-in under the open popover (frame `popover-live`) was reached the same way.

## Design navigation

Reference for Quick Open: `.doan/canvases/doan-search.html`, and `.doan/canvases/quick-open-conversations.html` for conversations. The project Overview is in 'Project Overview'.

### Overview placement

- The Overview covers the canvas cell (`grid-column: 2`, last row) over the still laid-out canvas area, which is `inert` while covered: opening a canvas fits it to the area's size immediately, so the area never leaves layout.
- Roles: `region` "Overview"; the canvas area under the Overview is ignored (`inert`); toasts are a polite `status` holding the message.
- **Toast for a canvas gone at relaunch:** the saved state keeps the canvas path and id but no title, so the message uses the file name without `.html` ("billing is no longer in .doan/canvases/" (or `.doan/ds/`)).
- **Thumbnail visibility** travels in both directions, including when the Overview's right panel unmounts; main keeps visibility updates received during asynchronous cache reads.
- **Navigation recovery:** unreadable width is reported without guessing a parser error; an explicit Open distinguishes unavailable projects from absent canvases; a problem root's overlay names the problem whether or not a canvas was open.
- Unpinned (no current test): restore across relaunch (canvas, view and tree expansion; a frame selected before quit, with `doan active` set, comes back without it and is absent from `ui-state.json`; Home, a gone canvas, a gone project, a broken `ui-state.json`) and Quick Open from the menu on Home and in a workspace.

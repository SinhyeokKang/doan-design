# Directory layout

- `go.mod` and `go.sum`: root Go module and pinned dependencies.
- `cli/cmd/doan/`: the `doan` binary; `main` only calls `cli.Run`.
- `cli/internal/cli/`: `Run`, argument splitting, envelopes and exit codes, command bodies, human output, the embedded `doan skill` body (`skill.md`, whose preset id line `skill.go` fills from the catalog), `design_skill.go` (`doan design-skill`), the assembly of `check` input (Reach), and the `doan mcp` stdio server (`mcp.go`), plus `active.go` (runtime read, bounded unix-socket client and app-error mapping), `config.go` (config reads, path validation and writes) and `config_ops.go` (pure config operations); `sessions.go` records best-effort shell check associations in device-local sessions.jsonl, with MCP explicitly excluded; `onboarding.go` holds the `doan onboarding …` commands, the app-socket v2 client and reply filtering, and the bundled-app bootstrap.
- `cli/internal/designskill/`: the design presets embedded in the CLI — `catalog.json` (ids, titles, descriptions, scopes and upstream sources, in catalog order), `presets/<id>.md` (one adapted body per preset), `notices/` (Impeccable `LICENSE` and `NOTICE.md`, the ehmo MIT `platform-design-skills-LICENSE` and Doan's `MODIFICATIONS.md`) and `designskill.go` (loading, validation, lookup and end markers), with tests. `SOURCES.md` maps the 69 upstream sources to presets and is not embedded.
- `cli/internal/repo/`: repo discovery, config parsing, in-repo path resolution, canvas and comment file listing, the serving scope (`scope.go`, shared by `ls` and `check`) and the orphan comment file rule (`orphans.go`, shared by `ls` and `check`); read-only Git metadata discovery (`git.go`) and pure parsing (`git_parse.go`).
- `cli/internal/canvas/`: pure HTML canvas model and CSS scanner.
- `cli/internal/check/`: pure `doan check` rules.
- `cli/internal/comments/`: resolve-event construction (pure) and the one-write append.
- `cli/internal/formats/`: Go validation and comment-event folding, with tests.
- `app/`: npm project and TypeScript test/type-check configuration; `package.json` also carries the app name, version and electron-builder settings.
- `app/scripts/package.mjs`: `npm --prefix app run package` — builds the arm64 CLI into `app/build/bin/` and the unsigned `app/dist/mac-arm64/doan.app` (`app/build/` and `app/dist/` are ignored).
- `app/src/comments/`: pure human event construction, list/pin projection and draft transitions, comment target labels (`targetLabel.ts`) and Comments panel text and state (`panelText.ts`), resolution lines, Resolved order and focus after a card leaves (`resolution.ts`), the Review rules (`review.ts`), the id-change notice (`orphans.ts`) and the Hand off rows, quick select, Handed off and worktree notice rules (`handoff.ts`), with tests.
- `app/src/formats/`: TypeScript validation and comment-event folding, with tests.
- `app/electron.vite.config.ts`: build of main (including the isolated `mkdir-child` entry), the main and Settings preload/renderer entries with per-page CSP into `app/out/` (ignored).
- `app/src/main/`: Electron main process — window, app menu, IPC, session permissions, canvas frame navigation and injection (`index.ts`), folder lifecycle (`shell.ts`), the name-based `.doan/canvases/` change decision (`designChange.ts`), CLI runner, folder state, `folders.json` store, watcher, IPC view shapes, canvas frame and navigation rules (`canvasFrame.ts`), and the script injected into canvas iframes (`canvasScript.ts`, shipped as function source); `runtime.ts` (runtime file, socket protocol and selection filtering), `inspector.ts` (CDP session and request lifecycle), and `inspect.ts` (pure inspector provenance/value rows, recorded `inspect.fixture.json`); project addition/classification (`addProjects.ts`, `addFlow.ts`), removal (`removal.ts`), menu enablement (`menuState.ts`), recent-change aggregation (`latestChange.ts`), the device-local review state store (`reviewState.ts`), project comments for the Home and Overview counts and the Feedback panel (`projectComments.ts`) and focus-refresh throttling (`throttle.ts`); navigation persistence (`uiState.ts`), static frame caps (`frameCap.ts`), thumbnail service (`thumbnails.ts`), hidden Electron capturer (`thumbnailWindow.ts`), pure cache/signature rules (`thumbnailCache.ts`) and queue reducer (`thumbnailQueue.ts`); Settings window/projection (`settings.ts`), per-window IPC allowlist (`senderAllowed.ts`), setup broker/lock/causes (`setupBroker.ts`, `setupLock.ts`, `setupCauses.ts`) and Go config bridge (`configBridge.ts`); pure helpers have unit tests.
- `app/src/setup/`: shared pure connection summary and Home setup-alert rules, with tests.
- `app/src/firstPrompt/`: shared subject/sentence validation and first-canvas arrival/wait reducer, with tests; used by main and renderer.
- `app/src/restore/`: shared pure UI-state parsing (`uiState.ts`) and startup navigation planning (`restorePlan.ts`), with tests; main validates saves and renderer plans restoration.
- `app/src/main/designSkills.ts`: the app's design preset read contract — types, IPC channel names, the refusal reply and the pure interpretation of `doan design-skill` runs into envelopes or app failures (doan-design-skills); `cli.ts` holds `runDesignSkill`.
- `app/src/main/onboarding/`: first-run onboarding (buzz-onboarding) — the session service shared by the window and the socket v2 adapter (`service.ts`), completion record v1 (`completion.ts`, fixtures in `fixtures/completion/`), `.git/config` remote reading (`gitConfig.ts`), pure GitHub URL and remote identity (`repository.ts`, also imported by the renderer), project inspection, selection and confirmation (`projects.ts`) and the approved clone (`clone.ts`); and machine setup used by Settings — login-shell probe, CLI link, shared skill stub, Claude skill link and MCP state/actions (`machine.ts`), pure state rules (`states.ts`), the bundled stub `SKILL.md` (imported with `?raw`, declared in `raw.d.ts`; agent-auth writes the same bytes into its profiles), sanitized PoC 7 agent-CLI outputs and the pre-preset stub `SKILL-c994913.md` in `fixtures/`, and tests for timeouts, process settlement and write races.
- `app/src/main/comments/`: comment service and immutable request/status lifecycle, safe file append and isolated missing-directory creation (`mkdir.ts`, `mkdir-child.ts`), Git author lookup, identity/document evidence and close/quit transitions, the write judgment for comments without a canvas (`orphanWrite.ts`), with regression and round-trip tests.
- `app/src/main/conversation/`: the UI-less agent conversation backend — shared types and pure session selection, environment, prompt/anchor, state/folding/merge, ownership and transport rules (`types.ts`, `sessions.ts`, `environment.ts`, `prompt.ts`, `state.ts`, `ownership.ts`, `transport.ts`); new-session handshake compatibility rules (`handshake.ts`); filesystem/registry/session checks and shell/version preparation (`io.ts`, `prepare.ts`); installed Claude SDK/CLI and direct Codex app-server runners, correlated RPC dispatcher and owned process groups (`runners.ts`, `dispatcher.ts`, `process.ts`); the Agent Client Protocol connection and per-turn runner for Cursor, Antigravity and Copilot (`acp.ts`, `acpRunner.ts`); local JSONL/index v2/undo recovery (`store.ts`), admission/lifecycle service (`service.ts`) and validated IPC (`ipc.ts`); `prepare.ts` also routes a run to the legacy external profile or the Doan account connection. Tests and sanitized protocol `fixtures/` sit alongside them; no conversation renderer is implemented here.
- `app/src/main/agentAuth/`: Doan-owned agent sign-in (agent-auth) — provider list, state and DTO types (`types.ts`), auth metadata v1 validation (`metadata.ts`), the pure state machine, readiness and status DTO (`state.ts`), resume judgment for a conversation owner (`connection.ts`), the child environment allowlist (`environment.ts`), per-provider login/status/storage adapters (`providers.ts`), tool facts from the login shell (`facts.ts`), the vault, profiles and atomic writes under `<userData>/agent-auth/` (`storage.ts`) with Electron `safeStorage` (`cipher.ts`), the sha-pinned Antigravity ACP server download, sign-in link and `BROWSER` hook (`antigravity.ts`), the attempt/lease/sign-out lifecycle (`manager.ts`) and the main/Settings auth IPC (`ipc.ts`); tests sit alongside them, with `fixtures/` holding auth metadata v1 samples and a test cipher.
- `app/src/main/serve/`: local server — path parsing and scope checks (pure) and the HTTP server.
- `app/src/preload/`: the narrow `window.doan` API (built as CJS), including `setSelection` and `inspect` alongside folder operations and subscriptions, plus typed comments read/begin/mutate/status/author/copy calls, mutate/status for comments without a canvas, project comments, review markers, and draft-transition/invalidation subscriptions; onboarding, setup, project-init, thumbnail and UI-state calls are also typed here, together with conversation preview/list/start/send/interrupt/permission/read and event subscription, the agent account read/check/sign-in/cancel/submit-code/open-link/sign-out calls with their snapshot and prompt subscriptions, and the design preset reads `designSkills.list/get` (§7 of ARCHITECTURE.md). `settings.ts` builds the separate `settings.cjs` preload exposing only `window.doanSettings` setup, projection, config and the same agent account methods.
- `app/src/renderer/`: React renderer (app-ui) — entry `main.ts` (no JSX), `App.tsx`, `Sidebar.tsx` (folder/canvas/frame tree), `RightPanel.tsx` (Canvas info, Activity and the read-only Inspector), `components/ui/` (shadcn components), `CanvasController.ts` (imperative board and iframe), `styles.css` (Tailwind, the shadcn theme mapped to roles and screen rules), `tokens.css` (palette, roles and legacy aliases shared with the draft canvases) and `app/src/renderer/ds/` (design-system CSS `index.css`/`controls.css`/`surfaces.css` and the pure design-system checks `checks.ts` with tests); pure helpers with tests: view math (`viewport.ts`), canvas message validation (`canvasMessage.ts`), what a list update or layout does to the open canvas (`canvasView.ts`), project row display (`projectRow.ts`), Activity (`activity.ts`) and Canvas info values (`canvasInfo.ts`), selection lifecycle/anchors (`selection.ts`), inspector display notes/tokens (`inspector.ts`) and machine-setup copy/actions for Settings (`onboardingView.ts`). `Onboarding.tsx` is first run (Welcome, Agent and Project steps), driven by `onboardingScene.ts` (scene and session merge rules), `agentStep.ts` and `projectStep.ts` (step sessions over the onboarding IPC), with the shared provider view-model `agentAuthView.ts`; provider marks live in `public/provider-logos/` and the Welcome grain in `public/onboarding-grain.svg`. `ProjectSetupDialog.tsx` is the project setup form for Home recovery actions. `Home.tsx`, `AddProjectsDialog.tsx`, `DropOverlay.tsx` and `Toast.tsx` provide the project overview and add/remove surfaces; `homeCards.ts`, `projectDisplay.ts`, `switchTarget.ts` and `toastState.ts` hold their display, switching and toast rules. `ProjectOverview.tsx` and `QuickOpenDialog.tsx` provide folder-grouped canvas cards/thumbnails and the Quick Open modal, with Overview card order in the pure `overviewOrder.ts`; `FeedbackPanel.tsx` is the Overview's right panel, with its groups, tree rows and focus rules in the pure `feedbackGroups.ts`; `ErrorDetails.tsx` is the shared Details toggle for read errors; `canvasTree.ts`, `quickOpen.ts` and `currentFrame.ts` hold tree/typeahead, search and viewed-frame rules with tests. The controller draws screen-space hover/selection/jump marks outside the transformed board; `Sidebar.tsx` includes the selected-element child row.
- `app/src/renderer/settings.html`, `settings.ts`, `settingsWindow.tsx`, `settingsProjects.tsx` and `settings.css`: Settings entry, Connections/Projects panes, config actions and styles. `SettingsDialog.tsx` owns their confirmation primitive; `ConnectionRows.tsx`, `connectionRowView.ts` and `connectionRows.css` are its Connections rows (shared with the wizard until 2026-10-29). `FirstPrompt.tsx` and `firstPromptView.ts` provide the shared composer, waiting/arrival UI and view rules, with tests.
- `app/src/renderer/CommentsSession.ts`, `useComments.tsx`, `CommentsPanel.tsx`, `ReviewBar.tsx`, `HandOffDialog.tsx` and `CommentPins.ts` (with comment anchor snapshots for pins and Review in the pure `commentAnchors.ts`): comment request/draft state (including `OrphanSession` for comments without a canvas), App/controller integration, list/editor/dialog presentation, the Review notice, bar and Done summary, the Hand off dialog, and screen-space count pins.
- `app/runtime/`: reusable support for focused real-Electron probes: isolated environments, bounded waits/owned-app cleanup, real-user-state fingerprints, native desktop/window/menu helpers, clipboard preservation and same-renderer intrinsic sizing. Node tests cover the support and run in the shared static gate. Screen-specific e2e scenarios were removed on 2026-10-27; one-off probes live under `.scratch/`.
- `app/components.json`, `app/.npmrc`: shadcn configuration and exact version pinning (`save-exact=true`).
- `.doan/canvases/`: draft canvases of doan's own UI (`app-shell.html`, `select-inspect.html`, `comments-ui.html`, `onboard.html`, `projects-home.html`, `design-nav.html`, `app-setup.html`, `revision-continuity.html`, `comments-readability.html`, `revision-recheck.html`, `agent-handoff.html`, `project-feedback.html`, `buzz-ds.html`, `buzz-shell.html`, `buzz-onboarding.html`); `.doan/assets/` holds canvas-only assets (`mock.css`, onboarding grain, provider marks and the existing shell draft font fixture); `.doan/assets/mock.css` defines colors of the example canvases drawn inside the draft; `.doan/config.json` points `tokenCss` at `app/src/renderer/tokens.css`.
- `.agents/skills/`: development skills (`.claude/skills/<name>` are symlinks to them).
- `.agents/skills/audit/`, `doc-check/`, `ux-audit/` and `verify/`: whole-codebase audit, bidirectional documentation maintenance, cross-screen UX audit, and shared executable verification. `verify/scripts/verify.mjs` runs sequential gates with regression tests in `verify.test.mjs`; per-run context, logs and results are retained under `.scratch/verify/`.
- `schema/`: shared JSON Schema 2020-12 definitions (comment-event, config, CLI envelope, runtime, app-socket v1 and v2, and sessions); `embed.go` embeds them for Go.
- `schema/fixtures/`: shared valid/invalid JSON (including runtime and app-socket request/response/selection) and JSONL folding fixtures used by both languages; `sessions/` supplies the shared sessions.v1 valid/invalid records, `app-socket-v2/` the onboarding socket's, `cli-envelope/onboarding/mapping.json` the onboarding envelope and exit mapping, and `cli-envelope/design-skill/` the design preset list, body and `usage_error` envelopes with `cases.json`.
- `eval/`: agent-eval tooling run by `/agent-eval` (ARCHITECTURE §14) — `run.ts` (real rounds and `--self-test`), `lib/` (workspace isolation with an optional second worktree, agent and judge commands, fake app socket, check context, transcript command extraction, the known-condition table (`known-conditions.ts`), sanitized rollout fixtures in `lib/fixtures/`, result records, with `node --test` tests; `types.ts` is the check contract) and `scenarios/<id>/` (W1, W2, H1–H8, R1–R7, R6b, MCP-enabled R2b, MCP-only R1b the onboarding scenarios O1 and O2, which share the request-log checks in `O1/log.ts`, and the design preset scenarios D1–D12 with successors D2b, D3b, D4b, D7b, D10b, D10c, D11b and D11c, which share the lookup checks in `D1/presets.ts`; H4's `answer.ts` extracts the final answer for H4–H8; H6's `copy-text.ts` loads the app's `copyText` for the H6 and H7 tests; the self-test-only `_example`, and `regression.test.ts` and `audit.test.ts` for scenario checks). Results go to `.scratch/agent-eval/<round>/`.
- `docs/`: product, architecture, and working documents.
- `.scratch/`: ignored experiments and local handoff evidence.

Schemas define the wire formats. Both implementations read the same fixtures;
there is no schema copy or type-generation step.

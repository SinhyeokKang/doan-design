# Directory layout

- `go.mod` and `go.sum`: root Go module and pinned dependencies.
- `cli/cmd/doan/`: the `doan` binary; `main` only calls `cli.Run`.
- `cli/internal/cli/`: `Run`, argument splitting, envelopes and exit codes, command bodies, human output, the embedded `doan skill` body (`skill.md`), the assembly of `check` input (Reach), and the `doan mcp` stdio server (`mcp.go`), plus `active.go` (runtime read, bounded unix-socket client and app-error mapping), `config.go` (config reads, path validation and writes) and `config_ops.go` (pure config operations).
- `cli/internal/repo/`: repo discovery, config parsing, in-repo path resolution, canvas and comment file listing, and the serving scope (`scope.go`, shared by `ls` and `check`); read-only Git metadata discovery (`git.go`) and pure parsing (`git_parse.go`).
- `cli/internal/canvas/`: pure HTML canvas model and CSS scanner.
- `cli/internal/check/`: pure `doan check` rules.
- `cli/internal/comments/`: resolve-event construction (pure) and the one-write append.
- `cli/internal/formats/`: Go validation and comment-event folding, with tests.
- `app/`: npm project and TypeScript test/type-check configuration; `package.json` also carries the app name, version and electron-builder settings.
- `app/scripts/package.mjs`: `npm --prefix app run package` — builds the arm64 CLI into `app/build/bin/` and the unsigned `app/dist/mac-arm64/doan.app` (`app/build/` and `app/dist/` are ignored).
- `app/src/comments/`: pure human event construction, list/pin projection and draft transitions, comment target labels (`targetLabel.ts`) and Comments panel text and state (`panelText.ts`), resolution lines, Resolved order and focus after a card leaves (`resolution.ts`), the Review rules (`review.ts`) and the Hand off rows, quick select, Handed off and worktree notice rules (`handoff.ts`), with tests.
- `app/src/formats/`: TypeScript validation and comment-event folding, with tests.
- `app/electron.vite.config.ts`: build of main (including the isolated `mkdir-child` entry), the main and Settings preload/renderer entries with per-page CSP into `app/out/` (ignored).
- `app/src/main/`: Electron main process — window, app menu, IPC, session permissions, canvas frame navigation and injection (`index.ts`), folder lifecycle (`shell.ts`), the name-based `design/` change decision (`designChange.ts`), CLI runner, folder state, `folders.json` store, watcher, IPC view shapes, canvas frame and navigation rules (`canvasFrame.ts`), and the script injected into canvas iframes (`canvasScript.ts`, shipped as function source); `runtime.ts` (runtime file, socket protocol and selection filtering), `inspector.ts` (CDP session and request lifecycle), and `inspect.ts` (pure inspector provenance/value rows, recorded `inspect.fixture.json`); project addition/classification (`addProjects.ts`, `addFlow.ts`), removal (`removal.ts`), menu enablement (`menuState.ts`), recent-change aggregation (`latestChange.ts`), the device-local review state store (`reviewState.ts`), Home and Overview comment counts (`projectComments.ts`) and focus-refresh throttling (`throttle.ts`); navigation persistence (`uiState.ts`), static frame caps (`frameCap.ts`), thumbnail service (`thumbnails.ts`), hidden Electron capturer (`thumbnailWindow.ts`), pure cache/signature rules (`thumbnailCache.ts`) and queue reducer (`thumbnailQueue.ts`); Settings window/projection (`settings.ts`), per-window IPC allowlist (`senderAllowed.ts`), setup broker/lock/causes (`setupBroker.ts`, `setupLock.ts`, `setupCauses.ts`) and Go config bridge (`configBridge.ts`); pure helpers have unit tests.
- `app/src/setup/`: shared pure connection summary and Home setup-alert rules, with tests.
- `app/src/firstPrompt/`: shared subject/sentence validation and first-canvas arrival/wait reducer, with tests; used by main and renderer.
- `app/src/restore/`: shared pure UI-state parsing (`uiState.ts`) and startup navigation planning (`restorePlan.ts`), with tests; main validates saves and renderer plans restoration.
- `app/src/main/onboarding/`: machine setup for onboarding — login-shell probe, CLI link, shared skill stub, Claude skill link and MCP state/actions, `onboarding.json` (`machine.ts`), pure state rules (`states.ts`), the bundled stub `SKILL.md` (imported with `?raw`, declared in `raw.d.ts`), sanitized PoC 7 agent-CLI outputs in `fixtures/`, and tests for timeouts, process settlement and write races.
- `app/src/main/comments/`: comment service and immutable request/status lifecycle, safe file append and isolated missing-directory creation (`mkdir.ts`, `mkdir-child.ts`), Git author lookup, identity/document evidence and close/quit transitions, with regression and round-trip tests.
- `app/src/main/serve/`: local server — path parsing and scope checks (pure) and the HTTP server.
- `app/src/preload/`: the narrow `window.doan` API (built as CJS), including `setSelection` and `inspect` alongside folder operations and subscriptions, plus typed comments read/begin/mutate/status/author/copy calls and draft-transition/invalidation subscriptions. `settings.ts` builds the separate `settings.cjs` preload exposing only `window.doanSettings` setup, projection and config methods.
- `app/src/renderer/`: React renderer (app-ui) — entry `main.ts` (no JSX), `App.tsx`, `Sidebar.tsx` (folder/canvas/frame tree), `RightPanel.tsx` (Canvas info, Activity and the read-only Inspector), `components/ui/` (shadcn components), `CanvasController.ts` (imperative board and iframe), `styles.css` (Tailwind and the shadcn theme mapped to tokens) and `tokens.css` (design tokens shared with the draft canvas); pure helpers with tests: view math (`viewport.ts`), canvas message validation (`canvasMessage.ts`), what a list update or layout does to the open canvas (`canvasView.ts`), project row display (`projectRow.ts`), Activity (`activity.ts`) and Canvas info values (`canvasInfo.ts`), selection lifecycle/anchors (`selection.ts`), inspector display notes/tokens (`inspector.ts`) and onboarding copy/actions (`onboardingView.ts`). `Onboarding.tsx` is the setup wizard and `ProjectSetupDialog.tsx` the project setup form shared by the wizard and Home recovery actions. `Home.tsx`, `AddProjectsDialog.tsx`, `DropOverlay.tsx` and `Toast.tsx` provide the project overview and add/remove surfaces; `homeCards.ts`, `projectDisplay.ts`, `switchTarget.ts` and `toastState.ts` hold their display, switching and toast rules. `ProjectOverview.tsx` and `QuickOpenDialog.tsx` provide folder-grouped canvas cards/thumbnails and the Quick Open modal; `canvasTree.ts`, `quickOpen.ts` and `currentFrame.ts` hold tree/typeahead, search and viewed-frame rules with tests. The controller draws screen-space hover/selection/jump marks outside the transformed board; `Sidebar.tsx` includes the selected-element child row.
- `app/src/renderer/settings.html`, `settings.ts`, `settingsWindow.tsx`, `settingsProjects.tsx` and `settings.css`: Settings entry, Connections/Projects panes, config actions and styles. `SettingsDialog.tsx` owns their confirmation primitive; `ConnectionRows.tsx`, `connectionRowView.ts` and `connectionRows.css` are shared with the wizard. `FirstPrompt.tsx` and `firstPromptView.ts` provide the shared composer, waiting/arrival UI and view rules, with tests.
- `app/src/renderer/CommentsSession.ts`, `useComments.tsx`, `CommentsPanel.tsx`, `ReviewBar.tsx`, `HandOffDialog.tsx` and `CommentPins.ts`: comment request/draft state, App/controller integration, list/editor/dialog presentation, the Review notice, bar and Done summary, the Hand off dialog, and screen-space count pins.
- `app/e2e/`: Playwright `_electron` runtime suite used by `/runtime-test`: app shell, canvas view, app UI, selection/inspector and the real CLI/socket lifecycle. Comment helpers cover actual filesystem boundaries (`comments-filesystem.ts`), controlled anchor/performance checks (`anchors.ts`) and mounted-App comment workflows (`comments-ui.ts`). `onboarding.ts` drives the setup wizard with a temporary HOME, fake shell and fake agents; `real-state.ts` fingerprints the real setup targets and userData files (key by key) around the suite; `tooltip.ts` holds the shared `hoverTooltip`. `design-tree.ts` supplies tree selectors; `design-nav.ts` verifies Overview, Quick Open and restart restoration; `thumbnails.ts` checks capture/cache/security/quit; `quit-capture.ts` forces quit during thumbnail window construction, load and capture, asserting a clean process exit; `revision-continuity.ts` verifies continuing a blocked comment, following a moved canvas, duplicate IDs, restart restore by ID, kept scope, unguarded Escape/blank clicks, the no-document target line and a per-frame reload trace; `revision-recheck.ts` verifies locate, Review and its notice across hide and relaunch, resolution lines, status lines, Save and reopen, Comment on selection instead, bottom labels and Home/Overview counts; `agent-handoff.ts` verifies the Hand off dialog (keys, copy states, refusal, worktree notice), Handed off, the “fix this” hint and the Review Done entry; `settings.ts` verifies Settings lifetime, Connections, Home setup alerts and project config edits; `windows.ts` distinguishes main, Settings and thumbnail windows. `presentation.ts` checks computed styles, focus, stacking, long content and sandbox iframe media preferences in production and a real Vite renderer; onboarding runs both modes sequentially after its own cleanup. `harness.ts` bounds polling, suite settlement and cleanup; `renderer-probe.ts` observes renderer completion, and `intrinsic.ts` compares a button with its natural-height reference. Their Node regression tests run separately from app Vitest. It uses temporary repos/userData.
- `app/components.json`, `app/.npmrc`: shadcn configuration and exact version pinning (`save-exact=true`).
- `design/`: draft canvases of doan's own UI (`app-shell.html`, `select-inspect.html`, `comments-ui.html`, `onboard.html`, `projects-home.html`, `design-nav.html`, `app-setup.html`, `revision-continuity.html`, `comments-readability.html`, `revision-recheck.html`, `agent-handoff.html`) and `mock.css` (colors of the example canvases drawn inside the draft); `.doan/config.json` points `tokenCss` at `app/src/renderer/tokens.css`.
- `.agents/skills/`: development skills (`.claude/skills/<name>` are symlinks to them).
- `.agents/skills/audit/`, `doc-check/`, `ux-audit/` and `verify/`: whole-codebase audit, bidirectional documentation maintenance, cross-screen UX audit, and shared executable verification. `verify/scripts/verify.mjs` runs sequential gates with regression tests in `verify.test.mjs`; per-run context, logs and results are retained under `.scratch/verify/`.
- `schema/`: shared JSON Schema 2020-12 definitions (comment-event, config, CLI envelope, runtime and app-socket); `embed.go` embeds them for Go.
- `schema/fixtures/`: shared valid/invalid JSON (including runtime and app-socket request/response/selection) and JSONL folding fixtures used by both languages.
- `eval/`: agent-eval tooling run by `/agent-eval` (ARCHITECTURE §14) — `run.ts` (real rounds and `--self-test`), `lib/` (workspace isolation with an optional second worktree, agent and judge commands, fake app socket, check context, transcript command extraction, sanitized rollout fixtures in `lib/fixtures/`, result records, with `node --test` tests; `types.ts` is the check contract) and `scenarios/<id>/` (W1, W2, H1–H7, R1–R7, MCP-enabled R2b; H6's `copy-text.ts` loads the app's `copyText` for its test; the self-test-only `_example`, and `regression.test.ts` for scenario checks). Results go to `.scratch/agent-eval/<round>/`.
- `docs/`: product, architecture, and working documents.
- `.scratch/`: ignored experiments and local handoff evidence.

Schemas define the wire formats. Both implementations read the same fixtures;
there is no schema copy or type-generation step.

# Directory layout

- `go.mod` and `go.sum`: root Go module and pinned dependencies.
- `cli/cmd/doan/`: the `doan` binary; `main` only calls `cli.Run`.
- `cli/internal/cli/`: `Run`, argument splitting, envelopes and exit codes, command bodies, human output, the embedded `doan skill` body (`skill.md`, whose preset id line `skill.go` fills from the catalog), `design_skill.go` (`doan design-skill`), the assembly of `check` input (Reach), plus `active.go` (runtime read, bounded unix-socket client and app-error mapping), `config.go` (config reads, path validation and writes) and `config_ops.go` (pure config operations); `sessions.go` records best-effort shell check associations in device-local sessions.jsonl; `onboarding.go` holds the `doan onboarding …` commands, the app-socket v2 client and reply filtering, and the bundled-app bootstrap.
- `cli/internal/designskill/`: the design presets embedded in the CLI — `catalog.json` (ids, titles, descriptions, scopes and upstream sources, in catalog order), `presets/<id>.md` (one adapted body per preset), `notices/` (Impeccable `LICENSE` and `NOTICE.md`, the ehmo MIT `platform-design-skills-LICENSE` and Doan's `MODIFICATIONS.md`) and `designskill.go` (loading, validation, lookup and end markers), with tests. `SOURCES.md` maps the 69 upstream sources to presets and is not embedded.
- `cli/internal/repo/`: repo discovery, config parsing, in-repo path resolution, canvas and comment file listing, the serving scope (`scope.go`, shared by `ls` and `check`) and the orphan comment file rule (`orphans.go`, shared by `ls` and `check`); read-only Git metadata discovery (`git.go`) and pure parsing (`git_parse.go`).
- `cli/internal/canvas/`: pure HTML canvas model and CSS scanner.
- `cli/internal/check/`: pure `doan check` rules.
- `cli/internal/comments/`: resolve-event construction (pure) and the one-write append.
- `cli/internal/formats/`: Go validation and comment-event folding, with tests.
- `app/`: npm project and TypeScript test/type-check configuration; `package.json` also carries the app name, version and electron-builder settings.
- `app/scripts/package.mjs`: `npm --prefix app run package` — builds the arm64 CLI into `app/build/bin/` and the unsigned `app/dist/mac-arm64/Doan.app` (`app/build/` and `app/dist/` are ignored).
- `app/resources/icon.png`: the packaged app icon source (`build.mac.icon`), kept outside the ignored `app/build/`.
- `app/src/comments/`: `projection.ts`, the Hand off instruction `copyText` that eval H6 and H7 import, with its target matching helpers and tests.
- `app/src/formats/`: TypeScript validation and comment-event folding, with tests; `canvasPath.ts` is the shared main/renderer classifier for `.doan/canvases/` and `.doan/ds/` paths (directory = canvas type).
- `app/src/brand/`: test-only product-name classifier (`candidates.ts`) and the check that app text says Doan (`appText.test.ts`); the Go counterpart is `cli/internal/cli/brand_test.go`.
- `app/electron.vite.config.ts`: build of main, the preload and the renderer entry with its CSP into `app/out/` (ignored).
- `app/src/main/`: Electron main process — window, app menu, IPC, session permissions, canvas frame navigation and injection (`index.ts`), folder lifecycle (`shell.ts`), the name-based change decision for both canvas directories (`designChange.ts`, repo-relative paths), CLI runner, folder state, `folders.json` store, watcher, IPC view shapes, canvas frame and navigation rules (`canvasFrame.ts`), and the script injected into canvas iframes (`canvasScript.ts`, shipped as function source); `runtime.ts` (runtime file, socket protocol and selection filtering), `inspector.ts` (CDP session and request lifecycle), and `inspect.ts` (pure inspector provenance/value rows, recorded `inspect.fixture.json`); project addition/classification (`addProjects.ts`, `addFlow.ts`), removal (`removal.ts`), menu enablement (`menuState.ts`), recent-change aggregation (`latestChange.ts`), the device-local review state store (`reviewState.ts`), project comments for the Overview counts and the Feedback panel (`projectComments.ts`) and focus-refresh throttling (`throttle.ts`); navigation persistence (`uiState.ts`), static frame caps (`frameCap.ts`), thumbnail service (`thumbnails.ts`), hidden Electron capturer (`thumbnailWindow.ts`), pure cache/signature rules (`thumbnailCache.ts`) and queue reducer (`thumbnailQueue.ts`); fixed external URLs and the Settings section/target types (`settings.ts`), the main-frame IPC allowlist (`senderAllowed.ts`), Settings preferences in `<userData>/preferences.json` (`preferences.ts`), notification decision and click resolution (`notifications.ts`, pure) and sending (`notifyService.ts`), Settings > About's reads and Copy details text (`about.ts`) and rows (`aboutView.ts`, renderer-safe) and Go config bridge (`configBridge.ts`); Home attachments (`attachments.ts`, buzz-home: path and image checks, thumbnails, pasted-image files under `<userData>/attachments/`, `sent` markers and launch cleanup); pure helpers have unit tests.
- `app/src/main/agentSetup/`: launch-time agent setup — pure eligibility, layout, ownership and plan rules and the Codex rule text (`plan.ts`), the I/O runner and the administrator dialog (`runner.ts`), in-place link replacement (`swap.ts`) and the setup result type and About notice (`notice.ts`, renderer-safe), with tests.
- `app/src/firstPrompt/`: shared subject/sentence validation and first-canvas arrival/wait reducer, with tests; used by main and renderer.
- `app/src/restore/`: shared pure UI-state parsing (`uiState.ts`) and startup navigation planning (`restorePlan.ts`), with tests; main validates saves and renderer plans restoration.
- `app/src/main/designSkills.ts`: the app's design preset read contract — types, IPC channel names, the refusal reply and the pure interpretation of `doan design-skill` runs into envelopes or app failures (doan-design-skills); `cli.ts` holds `runDesignSkill`.
- `app/src/main/onboarding/`: first-run onboarding (buzz-onboarding) — the session service shared by the window and the socket v2 adapter (`service.ts`), completion record v1 (`completion.ts`, fixtures in `fixtures/completion/`), `.git/config` remote reading (`gitConfig.ts`), pure GitHub URL and remote identity (`repository.ts`, also imported by the renderer), project inspection, selection and confirmation (`projects.ts`) and the approved clone (`clone.ts`); the login-shell probe and process runner (`machine.ts`) with pure probe parsing, PATH lookup, translocation and `doan init` arguments (`states.ts`); the skill stub `SKILL.md` (packaged into `Resources/skills/doan/`, imported with `?raw` for agent-auth's profiles, declared in `raw.d.ts`) with `stub.test.ts`, which also compares it with the pre-preset stub `fixtures/SKILL-c994913.md`; and tests for timeouts and process settlement.
- `app/src/main/comments/`: canvas document evidence (`document.ts`, the served-response and CDP document bindings) and the shared object guard (`identity.ts`), with tests.
- `app/src/main/conversation/`: the UI-less agent conversation backend — shared types and pure session selection, environment, prompt/anchor, state/folding/merge, ownership and transport rules (`types.ts`, `sessions.ts`, `environment.ts`, `prompt.ts`, `state.ts`, `ownership.ts`, `transport.ts`); new-session handshake compatibility rules (`handshake.ts`); filesystem/registry/session checks and shell/version preparation (`io.ts`, `prepare.ts`); installed Claude SDK/CLI and direct Codex app-server runners, correlated RPC dispatcher and owned process groups (`runners.ts`, `dispatcher.ts`, `process.ts`); the Agent Client Protocol connection and per-turn runner for Cursor, Antigravity and Copilot (`acp.ts`, `acpRunner.ts`); local JSONL/index v2/undo recovery (`store.ts`), admission/lifecycle service (`service.ts`), validated IPC (`ipc.ts`), per-provider model lists for Home (`models.ts`, buzz-home) and the provider CLI minimums (`minimumVersions.ts`, renderer-safe); `prepare.ts` also routes a run to the legacy external profile or the Doan account connection. Tests and sanitized protocol `fixtures/` sit alongside them; no conversation renderer is implemented here.
- `app/src/main/agentAuth/`: Doan-owned agent sign-in (agent-auth) — provider list, state and DTO types (`types.ts`), auth metadata v1 validation (`metadata.ts`), the pure state machine, readiness and status DTO (`state.ts`), resume judgment for a conversation owner (`connection.ts`), the child environment allowlist (`environment.ts`), per-provider login/status/storage adapters (`providers.ts`), tool facts from the login shell (`facts.ts`), the vault, profiles and atomic writes under `<userData>/agent-auth/` (`storage.ts`) with Electron `safeStorage` (`cipher.ts`), the sha-pinned Antigravity ACP server download, sign-in link and `BROWSER` hook (`antigravity.ts`), the attempt/lease/sign-out lifecycle (`manager.ts`) and the auth IPC (`ipc.ts`); tests sit alongside them, with `fixtures/` holding auth metadata v1 samples and a test cipher.
- `app/src/main/serve/`: local server — path parsing and scope checks (pure) and the HTTP server.
- `app/src/preload/`: the narrow `window.doan` API (built as CJS), including `setSelection` and `inspect` alongside folder operations and subscriptions; onboarding, install-page, project-init, thumbnail and UI-state calls are also typed here, together with conversation preview/list/start/send/interrupt/permission/read and event subscription, the agent account read/check/sign-in/cancel/submit-code/open-link/sign-out calls with their snapshot and prompt subscriptions, and the design preset reads `designSkills.list/get` (§7 of ARCHITECTURE.md), plus Home's model list and attachment calls (`listConversationModels`, `chooseAttachments`, `addAttachmentFiles`, `addPastedImage`, `removeAttachment`, `recheckAttachments`, `releaseAttachments`; buzz-home). It also carries the Settings page's preferences, test notification, notification settings, About, Project Settings config-session and config calls, and the open-Settings and notification-click subscriptions (buzz-settings).
- `app/src/renderer/`: React renderer (app-ui) — entry `main.ts` (no JSX), `App.tsx`, `ShellSidebar.tsx` (project/group/canvas tree), `sidebarGroups.ts` (Design system and Canvases grouping, visible rows, keyboard targets and closed-state rules), `RightPanel.tsx` (Canvas info, Activity and the read-only Inspector), `components/ui/` (shadcn components), `CanvasController.ts` (imperative board and iframe), `styles.css` (Tailwind, the shadcn theme mapped to roles and screen rules), `tokens.css` (palette, roles and legacy aliases shared with the draft canvases) and `app/src/renderer/ds/` (design-system CSS `index.css`/`controls.css`/`surfaces.css` and the pure design-system checks `checks.ts` with tests); pure helpers with tests: view math (`viewport.ts`), canvas message validation (`canvasMessage.ts`), what a list update or layout does to the open canvas (`canvasView.ts`), project row display (`projectRow.ts`), Activity (`activity.ts`) and Canvas info values (`canvasInfo.ts`), selection lifecycle/anchors (`selection.ts`), inspector display notes/tokens (`inspector.ts`) and shared copy-state, focus and project-form rules (`onboardingView.ts`). `SettingsPage.tsx` is the Settings page with one component per category (`SettingsAgents.tsx`, `SettingsNotifications.tsx`, `SettingsAbout.tsx`), its categories, target parsing and incoming-target queue in `settingsSections.ts`; `agentSignIn.ts` is the App-level sign-in controller shared by first run and Settings > Agents; `ProjectSettingsDialog.tsx` is the Project Settings dialog with its pure rules in `projectSettingsRules.ts`; `rendererImports.test.ts` keeps the renderer's value imports away from the ajv validators and Node builtins. `Onboarding.tsx` is first run (Welcome, Agent and Project steps), driven by `onboardingScene.ts` (scene and session merge rules), `agentStep.ts` and `projectStep.ts` (step sessions over the onboarding IPC), with the shared provider view-model `agentAuthView.ts`; provider marks live in `public/provider-logos/` and the Welcome grain in `public/onboarding-grain.svg`. `ProjectSetupDialog.tsx` is the project setup form for the sidebar's recovery actions. `Home.tsx` is Home's body (greeting and Home-only gradient around the composer; buzz-home), `HomeComposerView.tsx` the conversation composer with its pure rules in `homeComposer.ts`, `ConversationStripView.tsx` the workspace's temporary conversation strip with its reducer and copy in `conversationStrip.ts`, `homeConversations.ts` the pure sidebar slot, last-request, one-per-project and removal-confirmation rules, and `homeRun.ts` the run's Home conversations that App drives (send and move, events, strip, slots, canvas binding, toasts). The component files end in `View` because macOS's case-insensitive resolution sent `./ConversationStrip` to `conversationStrip.ts`. `AddProjectsDialog.tsx`, `DropOverlay.tsx` and `Toast.tsx` provide the add/remove surfaces; `homeCards.ts` (project grouping, still used by the sidebar and Quick Open), `projectDisplay.ts`, `switchTarget.ts` and `toastState.ts` hold their display, switching and toast rules. `ProjectOverview.tsx` and `QuickOpenDialog.tsx` provide folder-grouped canvas cards/thumbnails and the Quick Open modal, with Overview card order in the pure `overviewOrder.ts`; `FeedbackPanel.tsx` is the Overview's right panel, with its groups, tree rows and focus rules in the pure `feedbackGroups.ts`; `ErrorDetails.tsx` is the shared Details toggle for read errors; `canvasTree.ts`, `quickOpen.ts` and `currentFrame.ts` hold tree/typeahead, search and viewed-frame rules with tests. The controller draws screen-space hover/selection/jump marks outside the transformed board; `Sidebar.tsx` includes the selected-element child row.
- `app/src/renderer/doanyMotion.ts`, `doanyRig.ts`, `Doany.tsx`, `doany.css` and `doany.golden.json`: the Doany mascot — pure motion, injected controller, WebGL component and its sheet, and the expected values recorded from the draft script; `stageInsets.ts`: the centred Home and Welcome stage inset rule; `public/doany/`: the still image and textures with their provenance README.
- `app/src/renderer/SettingsDialog.tsx`: the confirmation primitive of the Project Settings dialog. `FirstPrompt.tsx` and `firstPromptView.ts` provide the shared composer, waiting/arrival UI and view rules, with tests.
- `app/src/renderer/CanvasConversationPanel.tsx` and `canvasRun.ts`: the canvas page's conversation panel and its per-canvas state, with pure rules in `canvasConversation.ts` and `rightPanelOpen.ts`; `conversationStore.ts`: threads, drafts, queues and returned drafts shared with the Overview; `chipField.ts` and `anchorField.ts`: the contenteditable composer field with inline anchor chips and its segment model; `canvasPicker.ts`: picker availability, picked and point anchors and chip target resolution. The shared one-line message text, chip labels and input limits are `app/src/main/conversation/messageText.ts`.
- `app/runtime/`: reusable support for focused real-Electron probes: isolated environments, bounded waits/owned-app cleanup, real-user-state fingerprints, native desktop/window/menu helpers, clipboard preservation and same-renderer intrinsic sizing. Node tests cover the support and run in the shared static gate. Screen-specific e2e scenarios were removed on 2026-10-27; one-off probes live under `.scratch/`.
- `app/components.json`, `app/.npmrc`: shadcn configuration and exact version pinning (`save-exact=true`).
- `.doan/canvases/`: draft canvases of Doan's own UI (`buzz-shell.html`, `buzz-onboarding.html`, `buzz-home.html`, `select-inspect.html`, and others); `.doan/ds/`: design-system canvases of Doan's own UI, one per token group, shared component or shared surface (`color.html`, `button.html`, `notice.html`, `shell-layout.html`, …); `.doan/assets/` holds canvas-only assets (`mock.css`, onboarding grain, provider marks and the existing shell draft font fixture); `.doan/assets/mock.css` defines colors of the example canvases drawn inside the draft; `.doan/config.json` points `tokenCss` at `app/src/renderer/tokens.css`.
- `.agents/skills/`: development skills (`.claude/skills/<name>` are symlinks to them).
- `.agents/skills/audit/`, `doc-check/`, `ux-audit/` and `verify/`: whole-codebase audit, bidirectional documentation maintenance, cross-screen UX audit, and shared executable verification. `verify/scripts/verify.mjs` runs sequential gates with regression tests in `verify.test.mjs`; per-run context, logs and results are retained under `.scratch/verify/`.
- `schema/`: shared JSON Schema 2020-12 definitions (comment-event, config, CLI envelope, runtime, app-socket v1 and v2, and sessions); `embed.go` embeds them for Go.
- `schema/fixtures/`: shared valid/invalid JSON (including runtime and app-socket request/response/selection) and JSONL folding fixtures used by both languages; `sessions/` supplies the shared sessions.v1 valid/invalid records, `app-socket-v2/` the onboarding socket's, `cli-envelope/onboarding/mapping.json` the onboarding envelope and exit mapping, and `cli-envelope/design-skill/` the design preset list, body and `usage_error` envelopes with `cases.json`; `brand/cases.json` the product-name classification cases (doan-naming).
- `eval/`: agent-eval tooling run by `/agent-eval` (ARCHITECTURE §14) — `run.ts` (real rounds and `--self-test`), `lib/` (workspace isolation with an optional second worktree and the project Codex rule imported from the app by `codex-rule.ts`, agent and judge commands, fake app socket, check context, transcript command extraction, the known-condition table (`known-conditions.ts`), sanitized rollout fixtures in `lib/fixtures/`, result records, with `node --test` tests; `types.ts` is the check contract) and `scenarios/<id>/` (W1, W2, H1–H8, R1–R6, R6b, R7b, R8, the onboarding scenarios O1 and O2, which share the request-log checks in `O1/log.ts`, and the design preset scenarios D1, D2, D4–D12 with successors D2b, D4b, D7b, D10c, D11b, D11c and D11d, which share the lookup checks in `D1/presets.ts`; H4's `answer.ts` extracts the final answer for H4–H8; H6's `copy-text.ts` loads the app's `copyText` for the H6 and H7 tests; R8 (app-sent anchors) mirrors `turnPrompt` through `turn-prompt.ts` and checks layout in the app's Electron through `layout.cjs`; the self-test-only `_example`, and `regression.test.ts` and `audit.test.ts` for scenario checks). Results go to `.scratch/agent-eval/<round>/`.
- `docs/`: product, architecture, and working documents.
- `.scratch/`: ignored experiments and local handoff evidence.

Schemas define the wire formats. Both implementations read the same fixtures;
there is no schema copy or type-generation step.

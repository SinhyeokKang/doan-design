# Backlog

What Doan has not settled or not shown yet: product questions without a decision, product surfaces not verified in the real app, and known defects without a fix. PRODUCT.md and ARCHITECTURE.md describe the product as it is; this file is where an idea, a gap or a defect waits until a feature takes it up (`/feature`) or a fix lands (`/ship`). Remove an item when that happens; git keeps its history. Items are not plans: a planned change lives in its `docs/features/<slug>/`.

## Undecided

- Anchor chips in the agent's replies: the agent could name a frame or element in its answer and the thread would draw the same chip as the person's, with locate. Feasible without a format change: replies are already Markdown text, so the guide would teach a link form (for example `doan:frame/<id>`, `doan:element/<id>`) and the thread's Markdown components would draw it as a chip that resolves only inside the open canvas, treating the ids as untrusted data. Needs a `/feature` (guide wording, `/agent-eval` scenario, Overview behaviour where no canvas is open).
- Release packaging (#9 `dist`, no feature started; deferred until after the whole-app cycle quality work): Developer ID signing and notarization including the nested CLI binary, a notarized dmg from doan.design or `brew install --cask`, `electron-updater` with GitHub Releases CI (the CLI updates with the app), x64/universal builds and `docs/OPERATIONS.md`. The current package's ad-hoc signature is invalid (`codesign --verify`: "code has no resources but signature indicates they must be present"), so tester dmgs are re-signed by hand (AGENTS.md 'Commands'). Signing is also what notifications need: macOS refused an unsigned local package's notifications without a prompt (electron-builder keeps Electron's ad-hoc signature, identifier `Electron`) while an earlier ad-hoc copy with the same bundle id held the permission, and only a copy re-signed with identifier `design.doan.app` showed them (DESIGN.md 'Settings'). Reference: Orca ships the same combination — an Electron app with a bundled CLI, Developer ID notarization, dmg (arm64, x64), a Homebrew cask and `electron-updater` with `provider: github` (verified in its local bundle 1.4.230).
- Showing where on the canvas the agent is working as it happens: the person wants to see it live, not only after a reload. Which canvas a terminal agent works on now comes from its own `doan work` signals (PRODUCT §5 items 1–2); which frame or element it edits has no evidence for a live source yet. A PoC would start by tying the input of an edit tool call in the conversation events to the rendered DOM; comparing the frames' content at each reload is the fallback if that fails. Not done: marking the frames an agent changed, following them with the view, and any marking while a project conversation edits the canvas (which canvas it edits is known only after the turn ends) or while a file watcher sees a change without a work signal (nobody knows who edited, so no Stop could be offered).
- Whether to route `cursor-agent login` and `copilot login` through main so they stop opening the system browser themselves (no feature started; ARCHITECTURE §7 'Agent authentication').
- Whether the preset list should say which presets need a target: the UI cannot tell, so Home, the Overview composer and the canvas conversation panel show “Which canvas or screen? Add details…” for every preset chip without text (`presetPlaceholder`), even where the canvas is already known. A CLI field would let it ask only for presets that need one; it changes CLI output and needs an `/agent-eval` round.
- Codex `item/permissions/requestApproval` without `reason` falls back to the JSON of `params.permissions` as the permission summary: uncapped (a review measured 2,034 characters) and unreadable. A readable form and a policy for serializing arbitrary objects into summaries need a decision.
- How the distributed app ships the design preset notices in a readable form (decide in #9 `dist`): the Impeccable `LICENSE` and `NOTICE.md`, the ehmo MIT license and the modifications note are embedded in the CLI binary only, no command prints them, and electron-builder copies neither them nor the root `LICENSE` into the app. Apache-2.0 §4(d) asks for a readable copy of the NOTICE attributions; whether bytes inside a binary meet that is open. The final review recommends copying `LICENSE` and `cli/internal/designskill/notices/` into the app's `Resources/` when packaging and recording the location in ARCHITECTURE §9. Each preset body already carries its source and modification line.
- Copilot and Claude Code permission requests may not show the command: Cursor and Antigravity show the command (`` `doan skill` ``) in the permission summary, Copilot shows a description ("Read the copy-clarification preset"), Claude the tool's `description` when it gives one and the command only without it (`claudePermissionSummary`), and Codex a natural-language question, so with Copilot and Claude the user often cannot see which command they approve. A presentation question for the conversation UI.
- Whether legacy external (shell connection) Claude should pass `CLAUDE_CONFIG_DIR` when the shell leaves it unset: the app normalizes an empty value to `$HOME/.claude` and passes it explicitly, so Claude Code reads the hashed Keychain item `Claude Code-credentials-<hash>` rather than the default item the shell uses; when that item is missing or expired, app resume fails with `OAuth session expired` while the shell works. Not passing the variable would change the stored `configDir` identity rule (PRODUCT §3 'Session identity and paths'), so it needs a decision.
- Whether Antigravity's Google `sub` should become a stable account ID. It would let a new sign-in to the same account resume earlier conversations, but a stored ID makes a check whose lookup failed read as `account_mismatch` (not retryable), so it needs a separate "identity unavailable" state first (ARCHITECTURE §7 'Agent authentication').
- Whether Codex needs a per-person account ID. App-server `workspaceRouting.chatgptAccountId` is a workspace ID that Team members can share, and is experimental. A person-level ID (`chatgpt_user_id`, unconfirmed in real tokens) would mean keeping `auth.json` as a vault working copy (`cli_auth_credentials_store="file"`): plaintext tokens on disk while a conversation's app-server runs, a write-back that can lose a rotated refresh token, a re-login for every keychain connection, and re-verifying sign-in, refresh and staged replacement.
- Showing each connected agent account's remaining usage or rate limits (a later feature). Codex's app-server exposes `account/rateLimits/read` (seen on 0.163.0); Orca 1.4.240 reads Antigravity usage through the `agy` CLI; official routes for Claude Code, Cursor and Copilot are unverified.
- Whether the `doan skill` guide should tell agents to keep shared shells as CSS/JS assets rather than HTML another canvas loads through an iframe or fetch, since such a canvas is not reloaded when that HTML changes (an accepted risk of the reload rule in PRODUCT §5 item 2; ⌘R or the canvas header's Reload button reloads it). Adding it changes the guide and needs an `/agent-eval` round.
- A comment event `at` that matches the schema pattern but is not a calendar time (`2026-02-30`, `T24`, a `:60` second) can only come from a hand-edited file; if it is a file's max `at`, `doan comment resolve` on that file fails with `internal_error`. Options: a calendar check in the schema (TS and Go together), or a dedicated error code.
- Whether agents act on `lastResolution` or only on the comment body: R6b's checks catch an agent that re-resolves the rejected label unchanged, and its first round passed 4/4, but they cannot tell an agent that understood `lastResolution` from one that read only the body and judged “Save changes” still vague. A causal test, such as a control round with `lastResolution` hidden, has not been run (USABILITY-EVAL.md).
- After a click in the canvas, Tab walks through the canvas's own inputs and buttons before it reaches the agent notice, the toolbar and the conversation panel; whether to change that needs a decision (Tab inside the canvas is allowed behavior).
- Adding Git-discovered but unregistered worktrees from the sidebar's worktree selection: the Add Projects page adds worktrees one at a time and no longer suggests them, and the sidebar shows only registered worktrees.
- Whether the Overview's “<title> moved to <canvas>.” line should survive leaving the Overview: after a promotion that happened while the person was on the new canvas page (the app opened it during the turn), returning to the Overview showed no line, possibly because the Overview clears it when it is left; this was observed once in a signed-in run, not traced, and no rule says either way.
- Whether to remove the document-origin chain now that nothing reads it: `DocumentBindings.current()` lost its only reader with the app's comment screen, but the inspector still observes documents (Network/Page domains and `waitForDebuggerOnStart`, which pauses each new canvas iframe until main resumes it) and the serve path still publishes response records. Removing the chain would also change canvas load timing, so it needs its own change and a check of load behaviour.
- Whether to lower the provider CLI minimum versions (`conversation/minimumVersions.ts`: Claude Code 2.1.312, Codex 0.164.0): they are the oldest versions checked live, a few releases behind the latest (Codex 0.166.0, Claude Code 2.1.316 on 2026-11-02), so a slightly older CLI is refused with Update. Lowering one needs a live check of that version in the real app (PRODUCT §3 'Transport and evidence boundary'); the permission-mode PoC ran Codex 0.163.0's app-server without a protocol problem, but that covered only its probes.
- Per-frame viewports (each frame in its own iframe with a declared screen size, as Figma frames have one): the only way `100vh` could mean a screen height inside a canvas. Revisit when device-size mockups need it. It would move frame placement from the canvas document to the app (PRODUCT §3 Out of scope 2), add a frame size to the conventions, and rework everything built on one board iframe (selection, picks, locate, anchors, inspector, height measurement, thumbnails).
- Showing a terminal agent's conversation in the app's canvas conversation list: today a canvas with a shell `doan check` association only offers continuing that session. A likely route is drawing the history the provider returns when the session is resumed (Codex `thread/resume`, the Claude Agent SDK), not reading transcript files, which ARCHITECTURE §7 'Shell activity' rules out. Unverified for both providers; a PoC comes first.
- Whether 5 minutes is the right expiry for terminal work without `doan work done` (`WORK_EXPIRY_MS`): the guide asks agents to repeat `start` after several minutes between edits, but every `/agent-eval` run so far made one edit, so there is no edit-gap sample (USABILITY-EVAL.md 'Terminal-work signals: first W3 round'). Measuring it needs a new multi-edit scenario.

## Known defects

- Runtime probes with an isolated HOME still write to the real `~/.gemini/antigravity-cli/` (logs, a crash log, `cli.log`): the app's Antigravity tool-fact check starts the language server, which does not follow HOME. Seen on 2026-11-02 in every dogfooding probe; ARCHITECTURE §7 'Known limits' names only `~/.codex` and cursor. `real-state.ts` flags it as a changed fingerprint.
- Content wider than `doan:width` overflows the board horizontally; nothing addresses it (seen while investigating the `buzz-project-settings` clip, which had other causes). Whether `doan check`, the guide or the app should handle it is undecided.
- Text fields have no right-click edit menu (Cut, Copy, Paste). It is app-wide, so buzz-home left it out; no feature owns it.
- Quick Open on Home does not say that results are missing while some projects are still being read: the list fills in live as projects finish, yet the reading text “Try again shortly.” suggests reopening, which the live update makes unnecessary.
- A project registered through a symlinked path fails every Doan-connection start: with `/tmp/<x>`, Codex starts from Home failed (“Couldn't start with Codex right now”, `session_unavailable`) while `/private/tmp/<x>` worked; probably `prepare.ts`'s `canonicalDirectory(request.root) !== request.root` check, not confirmed, and Claude was not tried. Projects added through the UI are stored by real path, but one added under a symlinked home folder would fail the same way.
- Quitting the app while a sign-out answers `stop_required` leaves the profile's Keychain item: `signOutAgent` refused because the Codex run still held its lease, the app was then quit, and the profile's `Codex Auth` item stayed in the real Keychain; deleting userData does not remove it (`codex logout` on that profile path removes it). Whether quit should finish or record a pending sign-out is open.
- `active.go` `readLine` returns a line whose newline arrives as byte 65,537 without checking its length, so `doan active` and `doan onboarding …` accept one byte over the 64 KiB reply cap (ARCHITECTURE §4 'Connection contract'); `doan work` checks the length itself.
- A `doan://` link that arrives while a page is locked (Add Projects selecting or cloning, a locked Settings or Project Settings page) or while a dialog refuses its cancel (Set Up while running, first run) is dropped with no toast, so the person sees nothing happen.
- A Locate on another worktree from a page's sidebar does not move that page's origin: the Project Settings page (and the Add Projects page) move the origin only when it was the rerooted worktree itself, so leaving after locating the origin's workspace from the sidebar goes Home instead of to the moved workspace.

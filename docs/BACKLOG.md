# Backlog

What Doan has not settled or not shown yet: product questions without a decision, product surfaces not verified in the real app, and known defects without a fix. PRODUCT.md and ARCHITECTURE.md describe the product as it is; this file is where an idea, a gap or a defect waits until a feature takes it up (`/feature`) or a fix lands (`/ship`). Remove an item when that happens; git keeps its history. Items are not plans: a planned change lives in its `docs/features/<slug>/`.

## Undecided

- Opening a prototype from the CLI (a separate feature, its `/feature` round starts once frame-prototype is implemented, alongside `prototype-conversation`): frame-prototype lets an agent mark a frame playable but gives it no way to open the prototype window, so a request such as "open this as a prototype" has no tool. A likely shape is a `doan open <canvas> --frame <id> --prototype` option, which changes the app-socket open request; `doan open` would still only move and show, never write or start work (PRODUCT §5 item 3 'Deep links', §3 Out of scope 4).
- Exporting a prototype (a separate feature, its `/feature` round starts once frame-prototype is implemented; it may pair with opening a prototype from the CLI): an Export button in the prototype window's header saves only the playing frame as one HTML file that opens in a browser at the frame's prototype size, so a person can send a playable prototype (PRODUCT §3 In scope 8). Cutting the frame out alone can break shared CSS and scripts that reach outside it, so the likely shape bundles the whole canvas as Export does today and has the viewer show only that frame the way the prototype window does (the frame fills the viewport, the rest is hidden). A CLI form such as `doan export --frame <id>` would let an agent answer "send this prototype as a file".
- Prototype conversation (a separate feature and canvas, `prototype-conversation`; its `/feature` round starts once frame-prototype is implemented): a button at the top right of the prototype window header opens a conversation panel that reuses the canvas conversation panel without its header. The conversation is the canvas's current conversation, so it streams in the main canvas panel too; with none, a new canvas conversation starts. Every send carries the playing frame as an anchor. The person's leanings so far (to settle in that round): the prototype window keeps its own composer draft, separate from the main one; approval and question cards answer from either window, first answer wins; the panel splits the window's width (the frame renders in a narrower viewport) rather than widening the window; the playing frame shows as a fixed chip above the composer and follows a frame switch.

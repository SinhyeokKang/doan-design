# Backlog

What Doan has not settled or not shown yet: product questions without a decision, product surfaces not verified in the real app, and known defects without a fix. PRODUCT.md and ARCHITECTURE.md describe the product as it is; this file is where an idea, a gap or a defect waits until a feature takes it up (`/feature`) or a fix lands (`/ship`). Remove an item when that happens; git keeps its history. Items are not plans: a planned change lives in its `docs/features/<slug>/`.

## Undecided

- Replacing promotion with handoff for project conversations (PRODUCT §5 item 1 'Project conversations', item 2 'Handoff'): a project conversation's turn would ask `doan handoff` for each new canvas instead of being bound to one, so the Overview conversation stays and each canvas gets a new conversation. It would drop the promotion judgement rules, but loses the same-session continuity promotion gives, depends on the agent running the command, and widens the handoff exception in Out of scope 4. Open: what a turn that only edits an existing canvas does, and whether promotion stays as a fallback. Planned as its own feature after the Overview conversation list.
- Antigravity's `/plan` stays a card (PRODUCT §5 item 1 'Built-in commands'). Observed with Antigravity ACP server 1.3.0 (probe and one real-app send, later reverted): the turn writes the plan as a file under the profile's `.gemini/antigravity-acp/brain/<session>/` through one ordinary permission request, ends its reply asking to "click Proceed", and a next message "Proceed" runs the plan, also after `session/load`; nothing on the wire marks the approval. Sending it needs three things settled first: a new conversation's first-message `/plan` is read as text before the server lists the command (a preset line stops it being a command; anchors or attachments fail the send), a conversation started with it is titled by the next message, and the plan body never shows in the thread (only the file path), so the person would approve a plan they cannot read. The agent also listed and read other sessions' brain folders in a shared profile, each asking a permission.
- A Claude Code plan approval that clears the context (`conversation_reset` with `trigger: "plan_mode_exit"`) moves the run to a new session, which Doan does not follow, so that turn ends as `session_unavailable` (PRODUCT §3 'Resume and permissions'). Following it like the person's `/clear` would need a decision that the approval is the person choosing a new session.
- Processes Doan itself starts outside the userData fence run files an agent can change, since the outer fence allows writes outside userData: the login-shell environment probe (`$SHELL -lic`) runs the person's `~/.zshrc`; provider binaries are resolved on that shell's `PATH` and run for version checks, sign-in and status (the readiness `--version` runs with the person's HOME, so Copilot's package cache and Cursor's Node compile cache under that HOME, which an outer-fenced agent can write, load there); clone and `--git-init` run git with the person's `~/.gitconfig`. ARCHITECTURE §7 accepts settings an agent leaves elsewhere (`~/.zshrc` named) running later outside the fence; closing these paths (for example a fixed environment instead of the login shell, pinned provider binary paths, `GIT_CONFIG_GLOBAL=/dev/null` for Doan's own git) changes what the person's setup can influence. No decision. Source: audit 2026-11-16 round 3 B3-4.
- Two anonymous terminal agents (no session ID) in one root are one anonymous session to Doan (ARCHITECTURE §4 'State'), so neither is listed in the other's `doan work` `others`; telling them apart would need an identity Doan does not have. No decision.

- In real Safari, reloading the browser player (⌘R, the toolbar's reload or View > Reload) after the board's tab or window has closed shows Safari's “Cannot open file” error page instead of restarting the frame; reopening the file works. The cause is WebKit's process model: the opener-linked player shares the board's WebContent process, which loses file:// read access when the board's tab closes (Playwright WebKit fails the same reload with the old page left on screen; Chromium restarts the frame). Only opening the player with `noopener` avoids it, and that gives up window reuse, blocked pop-up detection and the board–player channel; a ⌘R key handler cannot help, since Safari reloads before the page sees the key (ARCHITECTURE §3 'Exported canvas and viewer').

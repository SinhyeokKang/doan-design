# Backlog

What Doan has not settled or not shown yet: product questions without a decision, product surfaces not verified in the real app, and known defects without a fix. PRODUCT.md and ARCHITECTURE.md describe the product as it is; this file is where an idea, a gap or a defect waits until a feature takes it up (`/feature`) or a fix lands (`/ship`). Remove an item when that happens; git keeps its history. Items are not plans: a planned change lives in its `docs/features/<slug>/`.

## Undecided

- Release packaging (#9 `dist`, no feature started; deferred until after the whole-app cycle quality work): Developer ID signing and notarization including the nested CLI binary, a notarized dmg from doan.design or `brew install --cask` (Homebrew install is wanted at commercial launch, not before), `electron-updater` with GitHub Releases CI (the CLI updates with the app), x64/universal builds and `docs/OPERATIONS.md`. The current package's ad-hoc signature is invalid (`codesign --verify`: "code has no resources but signature indicates they must be present"), so tester dmgs are re-signed by hand (AGENTS.md 'Commands'). Signing is also what notifications need: macOS refused an unsigned local package's notifications without a prompt (electron-builder keeps Electron's ad-hoc signature, identifier `Electron`) while an earlier ad-hoc copy with the same bundle id held the permission, and only a copy re-signed with identifier `design.doan.app` showed them (DESIGN.md 'Settings'). Reference: Orca ships the same combination — an Electron app with a bundled CLI, Developer ID notarization, dmg (arm64, x64), a Homebrew cask and `electron-updater` with `provider: github` (verified in its local bundle 1.4.230).
- Showing where on the canvas the agent is working as it happens: the person wants to see it live, not only after a reload. Which canvas a terminal agent works on now comes from its own `doan work` signals (PRODUCT §5 items 1–2); which frame or element it edits has no evidence for a live source yet. A PoC would start by tying the input of an edit tool call in the conversation events to the rendered DOM; comparing the frames' content at each reload is the fallback if that fails. Not done: marking the frames an agent changed, following them with the view, and any marking while a project conversation edits the canvas (which canvas it edits is known only after the turn ends) or while a file watcher sees a change without a work signal (nobody knows who edited, so no Stop could be offered).
- Whether to route `cursor-agent login` and `copilot login` through main so they stop opening the system browser themselves (no feature started; ARCHITECTURE §7 'Agent authentication').
- Whether the preset list should say which presets need a target: the UI cannot tell, so Home, the Overview composer and the canvas conversation panel show “Which canvas or screen? Add details…” for every preset chip without text (`presetPlaceholder`), even where the canvas is already known. A CLI field would let it ask only for presets that need one; it changes CLI output and needs an `/agent-eval` round.
- Codex `item/permissions/requestApproval` without `reason` falls back to the JSON of `params.permissions` as the permission summary: uncapped (a review measured 2,034 characters) and unreadable. A readable form and a policy for serializing arbitrary objects into summaries need a decision.
- How the distributed app ships the design preset notices in a readable form (decide in #9 `dist`): the Impeccable `LICENSE` and `NOTICE.md`, the ehmo MIT license and the modifications note are embedded in the CLI binary only, no command prints them, and electron-builder copies neither them nor the root `LICENSE` into the app. Apache-2.0 §4(d) asks for a readable copy of the NOTICE attributions; whether bytes inside a binary meet that is open. The final review recommends copying `LICENSE` and `cli/internal/designskill/notices/` into the app's `Resources/` when packaging and recording the location in ARCHITECTURE §9. Each preset body already carries its source and modification line.
- Copilot and Claude Code permission requests may not show the command: Cursor and Antigravity show the command (`` `doan skill` ``) in the permission summary, Copilot shows a description ("Read the copy-clarification preset"), Claude the tool's `description` when it gives one and the command only without it (`claudePermissionSummary`), and Codex a natural-language question, so with Copilot and Claude the user often cannot see which command they approve. A presentation question for the conversation UI.
- Whether legacy external (shell connection) Claude should pass `CLAUDE_CONFIG_DIR` when the shell leaves it unset: the app normalizes an empty value to `$HOME/.claude` and passes it explicitly, so Claude Code reads the hashed Keychain item `Claude Code-credentials-<hash>` rather than the default item the shell uses; when that item is missing or expired, app resume fails with `OAuth session expired` while the shell works. Not passing the variable would change the stored `configDir` identity rule (PRODUCT §3 'Session identity and paths'), so it needs a decision.
- Whether a terminal session recorded under a per-terminal agent profile can be continued in the app. Tools such as Orca start each terminal agent with its own `CLAUDE_CONFIG_DIR`/`CODEX_HOME` (for example `~/Library/Application Support/orca/claude-profiles/<id>/home`), so shell `doan check` records that profile, while the app selects the login shell's profile; the profiles differ, resume is `session_unavailable` and the continue choice stays hidden (PRODUCT §3 'Session identity and paths'), even with the same account. A likely route is asking once whether to continue with that recorded profile and remembering only profiles the person approved on this device, because records are untrusted and a record that picks a profile could run another configuration's hooks.
- Whether Antigravity's Google `sub` should become a stable account ID. It would let a new sign-in to the same account resume earlier conversations, but a stored ID makes a check whose lookup failed read as `account_mismatch` (not retryable), so it needs a separate "identity unavailable" state first (ARCHITECTURE §7 'Agent authentication').

A person-level ID (`chatgpt_user_id`, unconfirmed in real tokens) would mean keeping `auth.json` as a vault working copy (`cli_auth_credentials_store="file"`): plaintext tokens on disk while a conversation's app-server runs, a write-back that can lose a rotated refresh token, a re-login for every keychain connection, and re-verifying sign-in, refresh and staged replacement.
- Showing each connected agent account's remaining usage or rate limits (a later feature). The person's sketch: one small progress ring per connected provider with its logo in the centre; the rings together form a single button that opens the details. Three placements to draw and compare: stacked vertically at the app shell's bottom right (in a narrow space at the right of the content panel), in a horizontal row at the right end of the header, and in a horizontal row at the app shell's bottom right. Codex's app-server exposes `account/rateLimits/read` (seen on 0.163.0); Orca 1.4.240 reads Antigravity usage through the `agy` CLI; official routes for Claude Code, Cursor and Copilot are unverified.
- Whether the `doan skill` guide should tell agents to keep shared shells as CSS/JS assets rather than HTML another canvas loads through an iframe or fetch, since such a canvas is not reloaded when that HTML changes (an accepted risk of the reload rule in PRODUCT §5 item 2; ⌘R or the canvas header's Reload button reloads it). Unverified for both providers; a PoC comes first.

The open question is the cost: no hooks run (commit-msg rules and pre-commit checks are skipped). Also unverified: whether `commit-tree` honours `commit.gpgSign` on its own or needs `-S` passed.

## Known defects

- Escape on Settings > Agents' Agent picker leaves Settings for Home (focus lands in the Home composer) instead of only closing the menu: the picker's `DropdownMenu.Content` (`SettingsAgents.tsx`) does not stop Escape, and App's window keydown handler decides to leave the page by whether a menu is in the DOM after Radix has already removed it. The Claude desktop app's bundled claude-code (2.1.309) writes such records into `~/.claude/sessions/`, so with a desktop Code session open no Claude terminal session can be continued. - A Codex turn that fails because the configured default model does not exist for the account (`model_not_found`, seen with `gpt-6-astra` on a ChatGPT account) shows as “Codex stopped unexpectedly” and that it may have changed files, which misstates both the cause and the risk.

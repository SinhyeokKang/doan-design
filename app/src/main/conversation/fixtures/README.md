# Transport fixture provenance

Derived on 2026-10-27 from the reviewed conversation PoC worktree's
`.scratch/agent-conversation/` files:

- `claude.json`: `claude-sdk-probe.jsonl`, SDK 0.3.310 / installed CLI 2.1.310.
- `claude-interrupted.json`: `claude-sdk-interrupt.jsonl` (actual `terminal_reason: aborted_tools`).
- `codex.json`: `fp-codex-decline.jsonl`, installed app-server 0.163.0; file approval was answered with `decline`, then completed.
- `codex-interrupted.json`: `codex-interrupt.jsonl`.

Only representative message, activity, approval and terminal records are retained;
SDK bookkeeping/usage fields are omitted. Wire field names and nesting are preserved.
All paths, IDs and transcript content are synthetic. Equal wire IDs retain equal
synthetic IDs across stream and completion records. Numeric RPC ID 0 is preserved
because treating it as falsy would lose a real approval request. Tests separately
construct callback arguments and failure cases; those are synthetic, not additional
real-runtime observations. These fixtures do not establish packaging, authentication,
all permission policies, process ownership or real app integration.

Synthetic command-policy and additional-permission cases use the PoC-generated
`codex-schema/CommandExecutionRequestApprovalParams.json` and
`codex-schema/PermissionsRequestApproval{Params,Response}.json` from 0.163.0.
These exercise schema mappings, not observed live permission-policy combinations.

On 2026-10-27, F-T restored `phase` and `itemsView` enum values by inspecting
only those protocol fields in the original source records: decline commentary /
final_answer and summary; interruption commentary and notLoaded. Synthetic private
fields were left intact. `codexIngress.test.ts` also constructs form elicitation
with omitted/null turnId and global attestation from the generated 0.163.0
`McpServerElicitationRequestParams.json` and `ServerRequest.json`, plus the R-T
reviewer's extra-error notification probes. These are synthetic boundary tests.

`index-v1.json` and `index-v2.json` are synthetic conversation index documents
(2026-10-28, agent-auth), not runtime observations. The v1 file includes a forged
`owner` to pin that v1 entries are never attributed to a doan account.

On 2026-10-28 (agent-auth, Codex 0.164.0), schemas generated by
`codex app-server generate-json-schema` from 0.163.0 and 0.164.0 were compared.
The request, response, notification and approval types that the runner and
these fixtures use (initialize, thread/start, thread/resume, turn/start,
turn/interrupt, agent message delta, error, the three approval requests,
elicitation and `ServerRequest`) are identical. `ThreadItem` differs only in the
`imageGeneration` variant, which doan does not read. The fixtures were not
re-recorded; live 0.164.0 behaviour was checked separately in the real app.

On 2026-10-28 (agent-cli-versions) doan moved from exact CLI versions to verified
minimums with a run-time handshake check (then Claude Code 2.1.312, Codex 0.164.0; both lowered since,
see `minimumVersions.ts`).
The fixtures above stay as recorded: Codex from 0.163.0 (schemas compared with
0.164.0, the minimum at that time) and Claude from CLI 2.1.310 / SDK 0.3.310.
They are newer than today's minimums (Codex 0.158.0, Claude Code 2.1.284), so the
minimums themselves rest on the real-app check that lowered them
(cli-minimum-versions, 2026-11-05), and any version the fixtures do not record is
judged only by the new-session handshake shape at run time.

`index-v2-home.json` (2026-10-29, doan-home) is a synthetic v2 index whose
`newDesign` entry carries the optional `model`, `effort` and `canvasesAtStart`
fields; the version stays 2.

`acp-cursor.json` and `acp-copilot.json` are ACP traffic recorded by the B3
exploration probe on 2026-10-28 (each file's `source` field).
`fake-acp-server.cjs` replays one of them for `acpRunner.test.ts`; its header
lists the test-only `FAKE_ACP` modes.

On 2026-10-29 (doan-home) `fake-acp-server.cjs` gained `FAKE_ACP_MODELS`, a
`models` member for session/new and session/load in the shape the P1 PoC
recorded (`{currentModelId, availableModels: [{modelId, name}]}`), an answer to
`session/set_config_option`, `FAKE_ACP_LOG` to record client requests and
`FAKE_ACP_NO_IMAGE` for a server without `promptCapabilities.image`. The
model IDs the tests pass are synthetic; the recorded turns are unchanged.

`codex-home.json` (2026-10-30, doan-home BF1) is trimmed from the BV1 real-app
run with Codex app-server 0.164.0: the raw records come from the redacted spawn
tap `.scratch/runtime-test/buzz-home/ev/real/tap/007-codex.jsonl`, and the doan
events that run produced are in `ev/real/events-d.json` (raw item types as
activity and permission summaries). Kept: a `commandExecution` start with
`commandActions`, an `imageView` start, a `fileChange` start, the
`item/fileChange/requestApproval` with `reason: null` that refers to it only by
`itemId`, its completion and `turn/completed`. Paths, IDs and the diff are
synthetic; output, `rootTurnId` and the turn's items are omitted.

`codex-mcp-startup-status.json` and `codex-mcp-elicitation.json` (mcp-connectors task A0) come from the
2026-11-04 Codex 0.166.0 app-server probe whose sanitized logs were committed with the mcp-connectors feature
documents: one thread's `mcpServer/startupStatus/updated` window from `probe.log`, and the
`mcpServer/elicitation/request` from `probe-accept.log`. The committed log had every server name redacted; the
startup names (`doan-notion`, `doan-atlassian`, `doan-figma`, `codex_apps`) are put back from the probe notes and
the `not logged in` error text, so which ready event belongs to which remote server is a reconstruction. The probe
log does not record JSON-RPC ids; the elicitation's id is synthetic.

`claude-ask-user-question.json` (agent-questions A2) is reduced from the 2026-11-05 P1 probe records
`.scratch/agent-questions/out/p1-*.json` (Agent SDK 0.3.312, Claude Code 2.1.312, the probe's own `p1-claude.mjs`
notes, not raw SDK frames): `init` is the `system/init` capabilities list of `p1-answer-default.json` in a
`system/init` frame's field names; `toolUse` is that run's `AskUserQuestion` call in an assistant frame (the message and
tool-use ids are synthetic); `canUseTool` holds the inputs `canUseTool` received in `p1-answer-default.json` and
`p1-multi-default.json`; `results` pairs the answers the probe sent (`answer`, `other`, `multi`, `unanswered2`, `deny`)
with the tool result text the model received. The question texts and labels are the probe model's own.

`claude-context.json`, `codex-context.json` and `acp-context.json` (context-window-ring) come from the 2026-11-05
context-usage probes whose method and results are recorded in commit `5a327f38`. `codex-context.json` and
`acp-context.json` are the probe's already prompt- and account-free fixture material with the thread,
session and turn ids replaced by synthetic ones and `emittedAtMs` dropped: `turns` is one Codex 0.166.0 thread's
plain turn and tool turn (two `thread/tokenUsage/updated`), `resume` the first turn after `thread/resume`, which
replays the previous turn's notification before the new `turn/start` reply; the ACP members are Copilot 1.0.105
(`copilot`, `copilotTool`), Copilot 1.0.89 after `session/load` (`copilotLoaded`) and Antigravity 1.3.0 before and
after `session/load`. Frame order and every token value are as recorded. `claude-context.json` is rebuilt in the SDK
frame shape from the probe's Claude Code 2.1.318 (Sonnet) record, which kept each top-level
assistant call's `model` and `usage` and the result's `modelUsage`, not the raw frames: `tool` is its tool turn,
`compact` its `/compact` turn (no top-level call). Token values, model keys and `contextWindow` are as recorded;
message ids, content, the tool input and the omitted `modelUsage` fields are synthetic. Tests change single fields
of these fixtures for the boundary cases; those variants are synthetic.

`claude-thinking.json`, `codex-read.json` and `acp-copilot-thought.json` (turn-activity A1) are reduced from recorded
spawn frames (`{t, d, s}` stdout chunks, reassembled into lines) of the turn-activity PoC, whose method and results
are recorded in commit `ea36aece`, and of the context-window-ring P2 probe (commit `5a327f38`):

- `claude-thinking.json`: Claude Code 2.1.318 through the app. `thinking` is the Haiku (`claude-haiku-5-5`), effort high
  turn (three thinking blocks, two Bash calls, the first answered allow-once, a text reply); `task` is the Sonnet
  (`claude-sonnet-5-5`), effort medium turn whose Agent call ran a subagent (frames with `parent_tool_use_id`, the
  `system/task_*` frames, no subagent `stream_event`).
- `codex-read.json`: Codex app-server 0.166.0 through the app. `read` is the context-window-ring tool turn (one
  `listFiles` command with a null path, then one `read` command); `search` is the turn-activity P2 turn (two instant
  `reasoning` items and one command whose `commandActions` hold a `search` and a `listFiles`).
- `acp-copilot-thought.json`: Copilot through the app (`agentInfo.version` 1.0.106) in bypass: `usage_update`, 83
  `agent_thought_chunk`s, a pending `execute` `tool_call`, a status-less `tool_call_update` and its completion 5 s
  later, a pending `read` `tool_call` with `locations` and its completion, the reply and the `session/prompt` result.

Kept: the frames the transports read and their envelopes, in recorded order: Claude `stream_event`, `assistant`, `user`,
`system/status`, `system/thinking_tokens`, `system/task_*` and `result`; Codex `turn/started`, `item/started`,
`item/completed`, `item/agentMessage/delta`, `thread/tokenUsage/updated` and `turn/completed` of the one turn; ACP
`session/update`s from the prompt on and the prompt result. Dropped: Claude `system/init`, `session_state_changed`,
`commands_changed`, `rate_limit_event` and `input_json_delta` stream events (the tool input as it streams, the
command included); Codex `turn/moderationMetadata`, rate limit, status and read-state notifications; ACP
`session_info_update` (the prompt as title) and `config_option_update`. Each turn's reply text was joined into three
deltas or chunks per message. Session, thread, turn, message, tool, item and call ids are synthetic; the probe repo's
root is `/repo`. Prompts, thinking signatures, thought text, commands (`COMMAND_TEXT`), Copilot's tool titles (the
read title keeps the recorded "Viewing <path>" form), tool inputs other than paths and descriptions, and tool outputs
are synthetic; reply text, Codex `query` values, token values, model keys and `contextWindow` are as recorded.
`turnActivityFixtures.test.ts` pins each turn's whole event list.

`acp-copilot-parallel.json` (turn-activity FX) is reduced the same way from the turn-activity R1 `/runtime-test`
spawn frames of one Copilot 1.0.106 turn in Full access (`copilot-ov`): 165 `agent_thought_chunk`s in two runs, three
`tool_call`s within 4 ms (a search with kind `other`, a `read` glob, an `execute` of a 6 s command), the search and
glob completing 72 ms later while the command still ran, its status-less update and completion, a `read` and a second
search, the reply and the `session/prompt` result. Frame order, kinds, statuses and token values are as recorded;
ids, the root (`/repo`), thought text, the command and queries (`COMMAND_TEXT`, `QUERY`), tool titles (each keeps its
recorded form) and outputs are synthetic, `rawOutput` is dropped, and the reply is as recorded in three chunks.

`codex-model-not-found.json` (2026-11-07) is synthetic, not a

(`message`, optional `codexErrorInfo`, `additionalDetails`) carried by the `error`
notification and by `turn/completed`'s failed `turn.error`, with `CodexErrorInfo`
including `"modelNotFound"`. The message text is the one a 0.166.0 turn printed

`skills-claude-2.1.284.json`, `skills-claude-2.1.318.json`, `skills-codex-0.158.0.json` and `skills-codex-0.166.0.json` (2026-11-07) are recorded project-skill listings: Claude Code's `initializationResult().commands` and Codex app-server `skills/list`, at the minimum and the then-current version of each. `claude-rate-limit-transcripts.json` (2026-11-13, usage-limit-resume) holds three usage-limit refusals from Claude Code
session transcripts on one Mac (2.1.296, 2.1.319, 2.1.323): the person's message right before each (content
replaced by `<removed>`; no assistant line came between them) and the synthetic assistant message Claude Code wrote for
the limit (`error: "rate_limit"`, `isApiErrorMessage`, model `<synthetic>`, its text as recorded). Of each line only
the type, timestamps, the error fields, the `rate_limit_info` status, reset (seconds) and type, and the message's
model, role, stop reason and content are kept; ids, paths, the session and every other field were dropped. The
transcript is not the SDK stream: a test that feeds the assistant line through `normalizeClaude` constructs the
`result` frame that ends the turn.

`codex-rate-limits-session.json` (2026-11-13) is one `token_count` record of a Codex 0.144.2 session rollout
(`~/.codex/sessions`) with `used_percent: 100.0`; only its timestamp and `rate_limits` are kept. The rollout uses
snake_case; `account/rateLimits/read` answers the same fields in camelCase (`agentAuth/fixtures/codex-usage.json`), and
`rate_limit_reached_type` was null although the window was full.

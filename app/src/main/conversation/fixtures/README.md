# Transport fixture provenance

Derived on 2026-10-27 from the reviewed conversation PoC worktree's
`.scratch/agent-conversation/` files:

- `claude.json`: `claude-sdk-probe.jsonl`, SDK 0.3.310 / installed CLI 2.1.310.
- `claude-interrupted.json`: `claude-sdk-interrupt.jsonl` (actual `terminal_reason: aborted_tools`).
- `codex.json`: `fp-codex-decline.jsonl`, installed app-server 0.163.0; file approval was answered with `decline`, then completed.
- `codex-interrupted.json`: `codex-interrupt.jsonl`.

Only representative message, activity, approval and terminal records are retained;
SDK bookkeeping/usage fields are omitted. Wire field names and nesting are preserved.
All paths, IDs and transcript content are synthetic. Equal wire IDs retain equal
synthetic IDs across stream and completion records. Numeric RPC ID 0 is preserved
because treating it as falsy would lose a real approval request. Tests separately
construct callback arguments and failure cases; those are synthetic, not additional
real-runtime observations. These fixtures do not establish packaging, authentication,
all permission policies, process ownership or real app integration.

Synthetic command-policy and additional-permission cases use the PoC-generated
`codex-schema/CommandExecutionRequestApprovalParams.json` and
`codex-schema/PermissionsRequestApproval{Params,Response}.json` from 0.163.0.
These exercise schema mappings, not observed live permission-policy combinations.

On 2026-10-27, F-T restored `phase` and `itemsView` enum values by inspecting
only those protocol fields in the original source records: decline commentary /
final_answer and summary; interruption commentary and notLoaded. Synthetic private
fields were left intact. `codexIngress.test.ts` also constructs form elicitation
with omitted/null turnId and global attestation from the generated 0.163.0
`McpServerElicitationRequestParams.json` and `ServerRequest.json`, plus the R-T
reviewer's extra-error notification probes. These are synthetic boundary tests.

`index-v1.json` and `index-v2.json` are synthetic conversation index documents
(2026-10-28, agent-auth), not runtime observations. The v1 file includes a forged
`owner` to pin that v1 entries are never attributed to a doan account.

On 2026-10-28 (agent-auth, Codex 0.164.0), schemas generated by
`codex app-server generate-json-schema` from 0.163.0 and 0.164.0 were compared.
The request, response, notification and approval types that the runner and
these fixtures use (initialize, thread/start, thread/resume, turn/start,
turn/interrupt, agent message delta, error, the three approval requests,
elicitation and `ServerRequest`) are identical. `ThreadItem` differs only in the
`imageGeneration` variant, which doan does not read. The fixtures were not
re-recorded; live 0.164.0 behaviour was checked separately in the real app.

On 2026-10-28 (agent-cli-versions) doan moved from exact CLI versions to verified
minimums with a run-time handshake check (then Claude Code 2.1.312, Codex 0.164.0; both lowered since,
see `minimumVersions.ts`).
The fixtures above stay as recorded: Codex from 0.163.0 (schemas compared with
0.164.0, the minimum at that time) and Claude from CLI 2.1.310 / SDK 0.3.310.
They are newer than today's minimums (Codex 0.158.0, Claude Code 2.1.284), so the
minimums themselves rest on the real-app check that lowered them
(cli-minimum-versions, 2026-11-05), and any version the fixtures do not record is
judged only by the new-session handshake shape at run time.

`index-v2-home.json` (2026-10-29, buzz-home) is a synthetic v2 index whose
`newDesign` entry carries the optional `model`, `effort` and `canvasesAtStart`
fields; the version stays 2.

`acp-cursor.json` and `acp-copilot.json` are ACP traffic recorded by the B3
exploration probe on 2026-10-28 (each file's `source` field).
`fake-acp-server.cjs` replays one of them for `acpRunner.test.ts`; its header
lists the test-only `FAKE_ACP` modes.

On 2026-10-29 (buzz-home) `fake-acp-server.cjs` gained `FAKE_ACP_MODELS`, a
`models` member for session/new and session/load in the shape the P1 PoC
recorded (`{currentModelId, availableModels: [{modelId, name}]}`), an answer to
`session/set_config_option`, `FAKE_ACP_LOG` to record client requests and
`FAKE_ACP_NO_IMAGE` for a server without `promptCapabilities.image`. The
model IDs the tests pass are synthetic; the recorded turns are unchanged.

`codex-home.json` (2026-10-30, buzz-home BF1) is trimmed from the BV1 real-app
run with Codex app-server 0.164.0: the raw records come from the redacted spawn
tap `.scratch/runtime-test/buzz-home/ev/real/tap/007-codex.jsonl`, and the doan
events that run produced are in `ev/real/events-d.json` (raw item types as
activity and permission summaries). Kept: a `commandExecution` start with
`commandActions`, an `imageView` start, a `fileChange` start, the
`item/fileChange/requestApproval` with `reason: null` that refers to it only by
`itemId`, its completion and `turn/completed`. Paths, IDs and the diff are
synthetic; output, `rootTurnId` and the turn's items are omitted.

`codex-mcp-startup-status.json` and `codex-mcp-elicitation.json` (mcp-connectors task A0) come from the
2026-11-04 Codex 0.166.0 app-server probe whose sanitized logs were committed with the mcp-connectors feature
documents: one thread's `mcpServer/startupStatus/updated` window from `probe.log`, and the
`mcpServer/elicitation/request` from `probe-accept.log`. The committed log had every server name redacted; the
startup names (`doan-notion`, `doan-atlassian`, `doan-figma`, `codex_apps`) are put back from the probe notes and
the `not logged in` error text, so which ready event belongs to which remote server is a reconstruction. The probe
log does not record JSON-RPC ids; the elicitation's id is synthetic.
